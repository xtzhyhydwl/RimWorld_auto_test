# 提交信息范例集（2026-10-25 实测整理）

配合 `SKILL.md`：标题 `type[scope]: 中文短句`，正文三段人话（为什么改 / 怎么改 / 现在的效果），段间空一行。

## 正例 1：真实已用的提交（1.6 与 1.7 都实跑验证过）

```text
fix[rhah/events]: 离场来客优先走门，走不通再凿墙

为什么要改：访客到了该走的时候没有走——他们被困在房间里；即使房间有门，也没法像正常访客或商队那样离开，玩家必须把门完全敞开，他们才能出去。

怎么改：先给他们一条正常的离开路径（进入「要离开」状态就放行门）；在此基础上，如果真的无路可走，再像商队那样凿墙往外走。顺手删掉一个两头都不合理的设置项。

现在的效果：有门时从门口正常离开，门和墙不会受损；完全无路时才凿墙出去。1.6 与 1.7 都实跑验证过。
```

## 正例 2：工具类，三段各一行（格式示范）

```text
fix[cli]: 启动子进程的工作目录改为游戏根

为什么要改：从别的目录启动时游戏起不来，还得翻日志才知道是目录不对。

怎么改：启动子进程时固定用游戏根目录，不再跟着命令行的当前目录走。

现在的效果：在哪个目录下启动都落在游戏根，不用先切目录。
```

## 反例

**1. 没 scope、没信息**：`fix: 修了个 bug` —— 哪个模块、玩家感知到什么，一条都没说，以后查历史只看到一堆同样的行。

**2. 自造英文小标题**：`fix[cli]: 修启动目录`，正文写成 `Why / What / Now` —— 段名必须是「为什么要改 / 怎么改 / 现在的效果」，换掉就断了统一检索。

**3. 正文堆类名、框架名和数字**：

```text
fix[rhah/events]: 修 Pawn.Flee 与 ModSettings

为什么要改：Pawn.Flee 走 JobDriver 时没检查门，Harmony 补丁顺序错。

现在的效果：tick 从 120 降到 40，扣血现象消失。
```

类名、框架名、tick 与数值，非技术读者一句读不懂；而且三段只剩两段。
