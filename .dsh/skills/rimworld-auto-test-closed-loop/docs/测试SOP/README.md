# 测试 SOP 目录

> 本目录 = 一次测试的**阶段序列**（先做什么、每步什么时候算完成）。
> skill `rimworld-auto-test-closed-loop` 只管"怎么想、什么时候停手"，阶段细节在这里，skill 里只有指向本目录的指针。
> 生长方式：**加一个文件 + 加一行登记**。skill 不动。

## 怎么选

1. 先看[标准六阶段](标准-六阶段.md)——覆盖大多数：起实例 → 进图 → 摆场景 → 推时间 → 等判据 → 取证。
2. 再看下面「特殊流程」表，按**适用条件**挑一条。
3. 都不匹配 ⇒ 自建一条（见末节），跑通后登记。

任何一条 SOP 开跑前，先过一遍[环境自检](环境自检.md)的**全部检查项**（硬性 3 项 + 按需 3 项，共 6 项）。

## 特殊流程

| SOP | 适用条件 | 证据等级 | 文件 |
| --- | --- | --- | --- |
| 存档读档-往返验证 | 需求涉及「存档 / 读档 / 读回来的状态 / 跨存档」、或要证明桥接读不到的字段真写进了存档时用 | 阶段 2–7 已真机跑通、阶段 1 未验（`list_saves` 已补验） | [存档读档-往返验证.md](存档读档-往返验证.md) |

证据等级四档（与 `wait --list` / `conditions.json` 的 `verifiedLevel` 一致）：`wait-verified`（真机命中）/ `field-verified`（字段真机读过、条件没跑）/ `doc-example`（仅文档示例）/ `inferred`（推断）。
注：`doc-example` 目前没有场景使用，所以 `node src/cli.js atoms` 的 `byLevel` 里看不到它（**具体计数别背，跑 `atoms` 看**；共 17 个场景）。写报告时用 `wait-verified/field-verified/inferred` 这三个词；"整份没真跑过"就直接说这句话，不要造第五档。

## 自建与登记

1. 照下面的骨架新建 `<类型>-<名字>.md`（例：`多实例-对撞.md`、`存档读档-往返验证.md`、`长时推进-分段.md`）。
2. 在「特殊流程」表加一行：**一句话适用条件 + 证据等级 + 文件名**。适用条件写"什么需求该用它"，不写"它做了什么"。
3. 跑通一次后再登记为可用；没跑通的写 `inferred`；"整份没按序真跑过"就直接写这句话，**不要造第五档**。

## SOP 骨架

```
# <SOP 名字>
## 0 什么时候用：适用条件 / 不适用时去哪
## 1..N 阶段：每阶段 = 动作 + 完成判据 + 证据落哪
## 失败怎么读：指向 失败判读.md 的具体一节
## 收工：停实例、清理残留
```

没有完成判据的阶段不算阶段；判据不过不进入下一阶段。

失败（动作返错、等待超时、探针挂住、断言不成立）统一在[失败判读](失败判读.md)里找处置，不写回 SOP。
