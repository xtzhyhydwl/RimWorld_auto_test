# 埋点协议（agent ↔ mod 约定）

> 2026-10-24 用户定：日志是**主张据**，但"哪条日志算过、哪条算错"必须**事先约定**，否则每个 agent 都得重新猜一遍。
> 这份文件是约定本身；怎么读日志见 [日志与事件取证.md](日志与事件取证.md)。**判定由 agent 做，不是脚本**——脚本只会匹配串，不会判语义。

## 1 两种埋点，两种用途

| 种类 | 谁埋 | 回答什么问题 |
| --- | --- | --- |
| **① 内部埋点** | 自动化测试系统（桥接 / 测试脚本 / agent 自己的步骤记录） | 我们自己跑到哪一步了、每步多久、哪步失败 |
| **② 外部埋点** | **被测 mod 开发者**（在 mod 代码里） | 被测功能"做了没有 / 做对没有" |

两者都不能缺：只有外部埋点 ⇒ 不知道是 mod 没做事，还是我们没把场景摆对；只有内部埋点 ⇒ 只能证明我们调了 API，不能证明 mod 行为。

## 2 内部埋点（自动化测试系统自身）

**最小要求：任何一次测试，结束时要能回答"跑到第几步、每步耗时、哪一步失败"。**

现状能用的载体（都已核过字段）：

1. **操作日志** —— 每次 `call` 的返回里都带 `operation` 段（`runs/tools.json` 的工具统一形状）：
   `OperationId`（形如 `op_8251aa6c…`）、`CapabilityId`、`Status`、`Success`、`StartedAtUtc` / `CompletedAtUtc`、**`DurationMs`**、`Warnings[]`、`Error`、`Result` / `HasResult`。
   事后可回查：`rimbridge/list_operations{limit, includeResults}`、`rimbridge/get_operation{operationId}`、`rimbridge/wait_for_operation{operationId, timeoutMs, pollIntervalMs}`。
2. **步骤结果里的 `stepId`**：`step_game_ticks` 之类的长任务返回 `stepId`（`step_e1d2b6…`）+ `requestedTicks` / `completedTicks` / `remainingTicks` / `advancedTicks` / `advancedFrames` / `startTicksGame` / `endTicksGame` / `initialTimeSpeed` / `startedAtUtc` / `completedAtUtc` / `message`。
3. **事件流** `runs/live/<profile>.ndjson`：`kind=heartbeat`（实时每 3 秒，带 `tick` / `programState` / `speed`）可当"还在跑"的心跳；`kind=window` 带 `opened` / `type` / `forcePause`；`kind=error` 带 `where` / `message`。

落地要求：报告里**每一步一行**，至少 `步骤名 / 请求参数摘要 / OperationId / DurationMs / Status|Success / 该步回读结果`；失败步要写清 `Error` 或 `Warnings` 原文。

## 3 外部埋点（被测 mod）

### 3.1 前缀与事件名

- 统一前缀 **`[DSH-TEST]`**（建议值；定下后不改，agent 的判据依赖它）。
- 事件名用 **`点.动作`**：`letter.dismissed`、`job.issued`、`pawn.left_map`、`haul.completed`。
- 一行一条，**结构化到能被字符串稳定匹配**：

```
[DSH-TEST] letter.dismissed ok tick=12034 letter=I-012 pawn=Thing_Human132
[DSH-TEST] letter.dismissed MISSING tick=12034 letter=I-012
[DSH-TEST] letter.dismissed ERROR tick=12034 letter=I-012 err=NullReference
```

- **必带字段**：`tick`（`Find.TickManager.TicksGame` 原值）、**稳定 id**（`pawn`/`thing` 用 `ThingID` 这类重启后不变的 id，不要用 index、不要用名字）、关键数值（距离 / 数量 / def 名）。
- **禁止自由文本**：不要写"看起来还行""大概成功了"，也不要把变量拼成一句中文话——agent 要靠 `live --until 'kind=log text~[DSH-TEST] letter.dismissed ok'` 稳定命中。

### 3.2 正负成对（硬要求）

**每个埋点必须有两条**，缺一条就不算可验收：

| 侧 | 语义 | 例 |
| --- | --- | --- |
| 正面 | **做了**，且关键值符合预期 | `letter.dismissed ok tick=… letter=… branch=resident` |
| 负面 A | **该做却没做**（前置条件没满足 / 走到 fallback / 超时放弃） | `letter.dismissed MISSING tick=… letter=… reason=no-pawn` |
| 负面 B | **做错了**（异常、参数非法、结果与预期不符） | `letter.dismissed ERROR tick=… err=…` |

只埋正面 = 只能证明"发生过"，不能证明"没出错"（同 [日志与事件取证.md](日志与事件取证.md) §2 的铁律）。

### 3.3 通道（现有实现的两个约束，先说清）

- GameLink 的 ndjson `log` 通道当前**只转发含 `[VD]` 的 `Log.Message`/`Log.Warning` + 全部 `Log.Error`**（`mods/DSH_GameLink/Source/LogTap.cs`）。
  ⇒ 纯 `[DSH-TEST]` 的 `Log.Message` **进不了 ndjson**。三条现成出路：
  1. 让 GameLink 的过滤器加上 `[DSH-TEST]` 前缀（要改 `mods/`，**属另一批**）【待落地】；
  2. 被测 mod 自己写 jsonl（foodprobe 的路子：`foodprobe/telemetry_tail{lines}` 读它的 `telemetry.jsonl`）；
  3. 走桥接内存日志 `rimbridge/list_logs{minimumLevel:'info', afterSequence}`——**是否覆盖第三方裸 `Log.Message` 未核**【待核】。
- 埋点**不要**用 `Log.Error` 充数：它虽然全转发，但会污染"红字 = 0"这条负面判据。

## 4 验收流程（用户口径）

1. **摆环境**：开测试实例、开调试殖民地、用原版 debug action 把场景摆成"埋点本该触发"的样子。
2. **跑时间**：按 [推时间.md](推时间.md) 分段推；窗口敏感就 100–300 tick/段，段间不判、只推。
3. **回来验收日志**：本场景的**预期正面埋点全齐**，且**所有负面埋点一条都不出现** ⇒ **通过**。
4. 缺任一条 ⇒ **不通过**，并且必须指出**缺的是哪条**（事件名 + 期望字段值），不许只写"验收失败"。
5. 顺带查机械兜底：`rimbridge/list_logs{minimumLevel:'warning', afterSequence:<推之前的游标>}` 无新增。

## 5 谁是权威

**埋点清单由被测 mod 的开发者维护**（写在 mod 目录里，或写进票据/需求文档），agent **只读不猜**：

- agent 不得自己发明埋点名去反推 mod 行为；清单里没有的埋点，只能记为"该行为无埋点 ⇒ 不可断言【未验证】"。
- 清单要给出：事件名、触发条件、必带字段、正面串样例、负面串样例。
- mod 改埋点 = 改协议：清单版本变了，agent 的判据要跟着改，旧判据作废。
