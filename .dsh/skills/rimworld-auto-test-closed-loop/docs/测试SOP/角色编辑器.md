# 角色编辑器（Character Editor，`void.charactereditor`）

> **什么时候用**：要把小人摆成任意状态（技能 / 特质 / 健康 / 断肢 / 基因 / 外貌 / 名字 / 整只克隆），或要读一只 pawn 的全量状态。
> **什么时候不用**：只改技能、特质、hediff 时，原版 debug action 已经覆盖（`Actions\Max Skill…` / `Give Trait…` / `Add Hediff…` / `Set Backstory…` / `Add Gene…`），零依赖。
> 本体在工坊 `294100/1874644848`，依赖只有 `brrainz.harmony`（`modVersion 1.7.1`，支持 1.0–1.7）。

## 0 两条路线

| 路线 | 入口 | 能做什么 | 代价 |
| --- | --- | --- | --- |
| **反射（优先）** | `ce/*` 工具（`bridge\DSH.CEBridge` 伴生 DLL） | 精确、批量、文本化读写，不依赖 UI | 要先部署 DLL；CE 升级后反射字符串可能失效 |
| UI 驱动 | `src\ce.js` | "看着界面"操作、验证 UI 本身 | 慢、脆；改不了滑块和文字（桥接没有输入工具） |

## 1 反射路线：`ce/*` 工具

```powershell
node src/cli.js call ce/probe                            # 自检：CE 加载了？内部 API 还在？
node src/cli.js call ce/colonists                        # 列殖民者 + 稳定 pawnId
node src/cli.js call ce/get_skills  --args-file a.json   # {"pawnId":"Thing_115"}
# 正确流程：先 ce/get_skills 读出 result.raw 全串 → 只改你要改的那一段 → 把整串原样写回
node src/cli.js call ce/set_skills  --args-file b.json   # {"pawnId":"…","skills":"<get_skills 给的 raw，改完>"}
node src/cli.js call ce/get_traits  --args-file a.json
node src/cli.js call ce/body        --args-file a.json   # 身体部位树 + 缺失状态
node src/cli.js call ce/amputate    --args-file b.json   # {"part":"Leg","index":0,"pawnId":"…"}
node src/cli.js call ce/restore     --args-file b.json
node src/cli.js call ce/ce_api      --args-file c.json   # {"tool":"HealthTool"} dump CE 内部方法
```

技能是**自描述文本**，一次读全部、一次写全部：`DefName|等级|激情|xpSince|xpMidnight`（**恰好 5 列**，段用 `:`）。
下面几条是 2026-10-24 真机定标（`runs\2026-10-25-回归\C2-CE技能\C2-报告.md`）：

- **等级列能写**【实测】：`Shooting|5|1|0|0:Melee|6|2|0|0` 写进去就是 5 级 / 6 级。**早先本文"等级列写不进"的说法是误判，已撤回。**
- **按 `DefName` 精确匹配**（大小写敏感、顺序无关）；等级上限 **20**，超出**静默 clamp**（不报错）。
- 【实测】**整表覆盖**：串里没列出的技能，5 列**全按 0 重建** ⇒ 永远从 `ce/get_skills` 的 `raw` 出发，只改目标段的第 2 列，**整串**回写；12 段一段都不能少。
- 【实测】**坏段被静默丢弃**：列数 ≠ 5、或名字拼错/大小写错的那一段会被整条扔掉（只毁它自己）；如果整串的段全是坏段，表现就是"什么都没写进去 + 整表清零"。**这才是"等级看着没生效、其余全归零"的真实原因。**
- **判据**：`readback == wrote` 且 `changed == false`。注意 `changed = !Equals(readback, wrote)`，语义是**反的**——`true` 表示"读回来和写进去不一样"= 没写对；而工具此时**仍返回 `success:true`** ⇒ 别拿 `success:true` 当"写成功"。

写工具的参数名以 `describe` 为准；参数里有反斜杠或中文就走 `--args-file`。

### 断肢实测语义（Human 共 64 个部位）

| 操作 | 结果 |
| --- | --- |
| `amputate {"part":"Leg",…}` | **9 个部位**变缺失：Leg + Femur + Tibia + Foot + 5 个 Toe |
| `amputate {"part":"Foot",…}` | **6 个部位**变缺失：Foot + 5 个 Toe |
| `restore` | 清掉**整棵子树**，回到 0 缺失 |

- `part` 匹配的是**当前语言**的标签或 `defName`（大小写不敏感的子串）。中文包下没有英文标签：写 `"left leg"` **必失败**，写 `"Leg"`（defName）才稳。
- `index` 从 **0** 起，且 **index 0 = 右腿**（真机 `matched: ["右腿 [Leg]", "左腿 [Leg]"]`，右在前）——要左腿就 `index:1`。
- 匹配失败时返回值里带 `candidates` / `matched`：**先看候选再改参数**。**不要**用中文 label 调 `restore`（真机挂满 60 s 超时）。
- 父部位缺失时子部位通过 `PartIsMissing()` 也算缺失 ⇒ **读状态用 `ce/body`，不要只看有没有 `MissingBodyPart` 这个 hediff**。
- 实际截肢走原版健康 API（`HediffMaker.MakeHediff(HediffDefOf.MissingBodyPart, …)` + `health.AddHediff`），CE 的 UI 只是前端 ⇒ 测「断肢后逻辑」的 mod **不依赖 CE**。

### 阈值 / 档位类断言：把被测量直接设到档界两侧，别等自然累积

实测教训（2026-10-25，RHAH 0002）：靠「推到第 18 游戏小时」等营养不良自然长过 0.40 去触发第 2 档，结果 5 人停在 **0.2887–0.3999**（最高那个差 **0.000086** 没过线），整轮白跑；而过了那个时间点战斗已经开打，数据又被污染。

做法：先从源码/Def 里读出档界（例 0.40 / 0.75）→ 对**同一个 pawn** 分别把 severity 设到档界**下方与上方**（0.39 / 0.41、0.74 / 0.76）→ 每设一次就回读 buff 的 `severity` 与该挂的心情。比"自然累积到点"快两个数量级，也不受事件干扰。

## 2 UI 路线（`src\ce.js`）

```js
import * as ce from '../src/ce.js';
await ce.ensureOpen(client);                 // 打开 main-tab:HotkeyEditor
await ce.openTab(client, 'Bio');             // Bio/Inventory/Health/Needs/Social/Log/Info/Records
await ce.selectPawn(client, 'Alex');         // 左侧列表
await ce.bumpSkill(client, 'Shooting', +3);  // 该行右侧的 −/+ 按钮
await ce.getSkillLevel(client, 'Shooting');
```

- 内部等待是**固定值**（轮询 400 ms、开窗 +600 ms、切标签 700 ms、选中 900 ms、每次点击 250 ms，见 `src/ce.js`）——可以当调用演示，不能当"已经等够了"。
- 画面判据用 `ce.ceSurface()` 的元素特征：技能行必须**恰好 2 个 `icon_button`**，凑不齐说明排版变了。
- 三栏（殖民者 / 特质 / 技能）共享同一批 y ⇒ 取元素必须**同时按 x 限列 + y 容差 ±8 px**。

## 3 写完必回读

1. `ce/get_skills` 比对用 **技能名 + 等级 + 激情**（等级列能写，见 §1）；**不要逐字比整串 `raw`**——第 4/5 列是 xp，每 tick 都在漂（实测 `-0.6 → -2.1 → -21.1`）。写完的**硬判据**是 `readback == wrote` 且 `changed == false`；
2. `step_game_ticks` 推若干 tick 再读一次（CE 自己 patch 了 `RecalcIndex` / gene 增删）；
3. 外貌、位置这类只能人眼判断的，截图交给人，不写成断言。

## 4 故障与维护

| 现象 | 多半是 | 处置 |
| --- | --- | --- |
| 没有 `ce/*` 工具 | DLL 没部署 | 按 [环境自检](环境自检.md) §4 部署 |
| `ce/probe` 报类型/成员找不到 | CE 升级，反射字符串对不上 | 重编 `bridge\DSH.CEBridge`（源码同名 `.cs`） |
| 写完回读没变 | 先看 `readback` 与 `wrote` 差在哪：全表归零 ⇒ 串里段数不够，没列出的技能被 0 重建；某一段没变 ⇒ 那段**列数≠5** 或 `DefName` 拼错（坏段被静默丢弃）。CE 自己 patch 了 `RecalcIndex` 也可能冲掉，但【条件不明·本轮未复现】 | 从 `get_skills` 的 `raw` 整串出发、只改目标段第 2 列、12 段一段不少，再写一次 |
