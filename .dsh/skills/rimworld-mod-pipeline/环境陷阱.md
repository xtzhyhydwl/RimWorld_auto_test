# 环境陷阱

**按需读**：当工具给出可疑结果、或两个工具说法不一致时读。

**每条的结构**：现象 → 真相 → 对策。全部是**实际踩到并确认过的**。
通用规则在最后。

---

## 一、行号与读取

| 现象 | 真相 | 对策 |
| --- | --- | --- |
| **同一个文件，两个工具报出不同的行数** | **默认读取器的编码假设**。实测：某默认读取器读"UTF-8 无 BOM 的中文文件"会**静默少算约 30% 的行** | 文件真实行数**以换行字节数为准**；显式指定编码读，或用底层 API 读 |
| 两份报告对同一段日志给出行号差 1~3 | 日志文件里含**裸 `\r`**，不同读取器对它的处理不同 | 同上 |

> **结论：行号不是可靠坐标。跨文档引用用「文件名 §节号」。**
> 上述两种现象都**不报错**——它们只是安静地给出不同的数字。

## 二、写入会静默改写内容

- **竖线字符**可能被丢弃或改形 ⇒ **表格列数会变**
- **行尾**可能被整文件改成另一种（如全变 CRLF）

  ⚠️ **但先查 git，别先怪写入通道。** 本机实测：`core.autocrlf = true` 且仓库**长期没有 `.gitattributes`**
  ⇒ **每次全新 checkout 都会把工作区文件变成 CRLF。**
  这是"文件怎么是 CRLF"的**第一个该排除的嫌疑**；
  修法是**加 `.gitattributes`（`* text=auto eol=lf`）**——**只在文档里写"用 LF"是挡不住 git 的**。
  排除了 git 之后，才轮得到怀疑写入通道。

**对策**：

1. **落盘前断言一个与内容语义无关的不变量**：行数 / 列数 / 某字符的**精确计数** / 字节数 / 哈希；**落盘后立刻复读**
2. **表格列数自检必须逐字符遍历**（数目标字符的码位），**不要用"按分隔符切分"**——因为切分方法**本身**会被同一个缺陷破坏
3. **临时文件不要建在目标目录里**（会污染给读者看的目录）；放到专门的暂存目录

## 三、反编译 / 元数据工具

| 现象 | 真相 |
| --- | --- |
| 输出**空白** | 可能是**含有某类语言特性的类型被静默丢弃**，**不是"类型不存在"**。⚠️ **且不是固定名单**——同一个工具会在不同程序集上丢不同的类型 |
| 调用点扫描返回 **0** | 可能是**过滤器语义不对**：有的要求**全名精确相等**（传短名必得 0），有的支持子串。**"0 命中"不能当"没有读者"** |
| IL 输出看起来像**"直筒式"**（没有跳转） | 该打印器可能**把分支指令丢掉了** ⇒ 守卫、提前返回、else 分支全都看不见 |
| 输出成**空文件** | 可能是**过滤器写错**导致静默输出空文件 |
| 对 **mod 程序集整体失效** | 往往是**缺依赖程序集**（mod 引用了开发环境里没有的 DLL），不是 mod 坏了 |
| **特性/注解扫描 0 命中** | **可能是假阴性**——有的实现不用注解，运行时手工注册 |
| 用 `>` 重定向写文件 | 可能写出 **UTF-16** 而不是 UTF-8 |
| **把 `$env:TEMP` 当持久备份位置** | 受限环境里它常被重定向到**会话级临时目录**（本机实测：`...\Temp\dsh-<随机串>\`）。三个后果：① **会话结束可能被清掉**；② **目录名每个进程都不一样** ⇒ 你**事后无法重建那个路径**（只能按文件名在 Temp 树里搜）；③ 用户真正的 `Temp` 目录**往往不可写**。⇒ **"备份到 TEMP"是假保险**。**要留退路就放到工作区内已被 gitignore 的临时目录**，并在文档里写明这个退路的路径与"可随时删除" |

**最强的一条对策**：

> **凡是结论形如"没有别的路径 / 无条件 / 从不被调用 / 不存在"的，必须换一个保留分支和上下文的工具复算。**
> 只打印"打了哪些指令"的工具，**天然无法证明"没有别的路径"**。

## 四、注册式框架会静默不生效

**现象**：调用注册接口 → **返回、不抛异常** → 但**什么都没注册**（缺少注解/声明）。

**对策**：

1. **注册之后必须自检**：查框架自己暴露的"已注册列表"
2. **自检必须带阴性对照**：故意注册一个**不存在**的目标，确认自检会报错
   —— 否则你无法区分"自检通过"和"自检恒真"
3. **别把"接口没报错"当成"生效了"**

## 五、界面驱动

- **点击类调用单独使用可能静默无效**：返回 `成功`，界面**什么都没发生**。
  常见原因是**缺少前置步骤**（例如需要**先把虚拟光标移到目标上**再点）
- **判据不是返回值**，而是**回读界面状态**（窗口列表 / 布局快照里目标真的变了吗）

> **"没反应"优先怀疑缺少前置步骤，而不是"这个做不到"。**

## 六、交互式应用的前置条件清单

**漏掉任何一步，都会伪装成"功能不存在"：**

```
① 资源是否可用（很多开局默认处于"禁止/不可用"状态）
② 目标设施是否已放置
③ 目标设施是否通电（开发者选项里的"无限电力"未必真的供电）
④ 界面操作是否有前置步骤（如点击前需要悬停）
⑤ 相关工作类型 / 开关是否已开启
```

**排完这张表之前，不要下"做不到"的结论。**

## 七、本会话的 HTTPS 探测不可信（Schannel 安全包缺失）

**现象**：`curl.exe` 对**任何** https 都 `exit 35`（SSL connect error，3ms 返回）；`Invoke-WebRequest` 报
`基础连接已经关闭: 接收时发生错误`；`.NET SslStream` 原文 `No credentials are available in the security package`。
**看起来像"被墙 / 服务端拒绝 / DNS 坏了"。**

**真相**：DNS 正常、`http://`（80 端口）返回 200、裸 TCP 443 能连。
**受限进程里 Schannel/CAPI 安全包不可用**，与目标服务器无关。代理绕过（`ProxyHandler({})`）也一样失败。

**对策**：

- 需要 HTTPS 的一次性探测，**走 OpenSSL 栈**：内置 Python 3 的 `urllib/requests`、或 node 的 `https`。
- **不要因为 curl 失败就下"服务不可达"的结论**——会白查一小时。
- 同理：`ping` / DNS / TCP 通，**不能证明 TLS 可用**；三者要分开验。

## 八、通用规则

1. **"不报错" ≠ "发生了"**
2. **"返回成功" ≠ "状态变了"** ⇒ 回读
3. **零结果先怀疑输入**（过滤器、编码、路径），不要先改自己的判定逻辑
4. **两个工具说法不一致 ⇒ 用第三个读数裁定**，不要猜、不要挑一个顺眼的
5. **"它工作了" ≠ "它因为 X 才工作"** ⇒ 需要**阴性对照**
6. **能力盘点先于结论**：说"做不到"之前，先把可用的能力列一遍
