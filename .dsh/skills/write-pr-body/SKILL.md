# 写 PR 正文（v0 占位）

> **v0 占位**：格式规范待用户后续补充；本版只固化已验证有效的写法（PR #9 得到用户认可的那一版）。

## 分工

- `github-pr-by-api` 管**机制**：fork、push、调 GitHub API、自检。
- 本 skill 管**正文怎么写**：写什么、不写什么、写多长。

## 已验证有效的写法

正文 **≤22 行**，四节按顺序：

| 节 | 写什么 |
|---|---|
| `## 问题` | 第一人称、玩家视角，**只讲现象**：我遇到什么、为什么觉得不合理 |
| `## 我认为合理的做法` | 为什么这样改才合理（讲道理，不讲实现） |
| `## 改动` | 3–5 条 bullet，人话，一条一件事 |
| `## 说明` | AI 起草 + 人工审核 + AI 复审；命名/分层按仓库约定；改动思路见 commit message；实现看代码 |

**禁止**：类名 / 方法名 / 变量名 / 框架名 / 文件名 / 坐标 / 性能数字表 / `tick` / HP 数值；emoji；本机绝对路径；「我作为 AI」这类元话。

**允许**：版本号（1.6 / 1.7）；「实跑验证过」这类结论。

判定标准的用户原话：

> 要说清楚问题是什么、为什么觉得不合理、改了什么；技术细节让作者的 agent 自己看代码。

## 待用户补充（用户填，填完升 v1）

- [ ] 是否附 commit 链接
