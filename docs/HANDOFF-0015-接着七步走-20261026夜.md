## 4 这次踩到 / 记下的坑（省的下一会话再撞）

1. **`git commit -- <路径>` 不是「只提交这些路径的改动」**：它取的是**工作区**内容，会把别人的在飞改动一起提交（本次子代理就这样误提交了 `交接-写新mod.md` / `新会话开场白.txt`，靠 `reset --soft` + mixed `reset` 才收拾干净，没 push）。正确姿势：`git add <显式路径>` 然后 `git commit`（**不带路径**），提交后 `git show --stat HEAD` 核一遍。
2. **`.gitignore` 的 `/docs/` 那条曾经让 `git add docs\…` 静默失败**（跟踪 70 份却还忽略新文件）。分离时已删；以后 docs 里的新文件能正常 add 了。
3. **4 个核心文件曾长期不在 git 里**：`src/advance.js` / `gamelink.js` / `save-parse.js` / `text-check.js`（`advance`、`text-check` 是 AGENTS 硬约束 6/7 的唯一入口）。已在 `595a320` 补进跟踪。
4. **HANDOFF-0014 §3 第 2 步的命令是笔误**：`git -C RimworldMods switch -c fix/0009-doc-rot origin/main` 会在**模组仓**开分支，而 0009 的改动全在**工作仓**。正确做法见 §3A-4。
5. **票 0009 的核心症状改不进任何仓库**：`C:\Users\MikanseiP\.dsh\skills\rimworld-auto-test\SKILL.md`（**用户级、无仓库**）有 9 处死引用，`:40`/`:239` 把已删的 `scripts/diag.mjs` 写成「卡住了的第一诊断」；用户级 `rimworld-mod-compat\SKILL.md` 另有 3 处。项目级没有 `rimworld-auto-test\`（只有 `rimworld-auto-test-closed-loop\`）⇒ 旧版删还是改**等人类定**（清单在 `docs\RHAH-0009-实施单-20261026.md` 末节）。
6. **`profiles\` 不入库、内容取决于本机**：激活 mod 数只问 `node src/cli.js env-check --profile <p>`（本机 `vanilla` 2026-10-26 是 568 条 activeMods，别当常量）。
