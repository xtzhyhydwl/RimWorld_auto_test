## 1. 现在是什么状态

等待从「每个子代理现场发明 `Start-Sleep`」变成**一条命令 + 写进协议**：

- [`src/wait.js`](../src/wait.js)：**唯一的**等待判定实现（15 个条件算子 + `all/any/not`）；超时**返回** `ok:false`
  并带回最后一次采样；**字段路径取不到 = 条件未成立、继续轮询**，只有算子写错/类型不符才立刻失败。
- `node src/cli.js wait --profile <p> --probe <只读工具> --condition-file cond.json [--args-file a.json] [--timeout 60000] [--interval 200]`
  → exit `0` 命中（stdout JSON：`ok/elapsedMs/attempts/probe/condition/sample/sampleTruncated`）、`2` 超时、`1` 其它。
  打印层把 `sample` 截到 2000 字符（完整载荷用 `cli call` 取）。
- `src/ui.js` 里那套 0 使用者的第二套 `waitUntil` 循环**已删**；`assertToolNameExists` 迁进 [`src/toolname.js`](../src/toolname.js) 复用。
- 协议已进上下文常驻文件：[skill「等游戏状态」](../.dsh/skills/rimworld-auto-test/SKILL.md) 有「要等什么→哪条命令」表；[AGENTS.md](../AGENTS.md) 硬约束 5 承认两种形式。

## 2. 真机实测（9 个用例，`voiced` 轻档 / 1.7.4985 / 桥接 2.1.1 / 184 工具）

| 场景 | 结果 |
| --- | --- |
| 已进图命中 `result.state.playable` | exit 0，**5 ms / 1 次采样** |
| **动作→闭环**：`open_main_tab` → 等 `get_ui_state.openMainTabId` | exit 0，**5 ms / 1 次**（随后 `close_main_tab` 也 exit 0） |
| 不可能条件，`--timeout 1500` | exit 2，attempts=7，stderr 有条件+最后采样 |
| 有图但字段名写错（`list_colonists` 等 `result.state.playable`） | exit 2，点名「断在 state 这一段，可用 success/count/colonists/operation」 |

| 算子写错 / 未知工具名 / `--source event` | 均 exit 1，1 秒内（含命名空间提示） |
| 开销 | `cli call` 71 ms vs `cli wait`（一次命中）69 ms（墙钟含 node 启动） |

## 3. 别踩（本次新增的坑，都是实测）

1. **起游戏的命令一退出，游戏就被连进程树杀掉。** `node src/cli.js start` 单独跑：桥接 7 s 就绪、命令返回，游戏随即消失（pid 立即 `ESRCH`，日志一个字节没写）。
   ⇒ 要**多步驱动**就得把启动命令挂成**保活 job**（`start` 后面接一个 `node -e "setInterval(()=>{}, 900000)"`），跑完先 `stop --profile <p>` 再杀保活 job。
   这也是以前只能靠单进程 `cli smoke` 的原因【实测】。
2. **`src/proc.js:125 isAlive` 把 `EPERM` 当活着**：PID 被别的（受保护）进程复用后，`start` 会被「profile 已有实例在运行」挡住。绕过：确认无 RimWorld 进程后删 `runs\game-process.<profile>.json`。**未修**。
3. **多实例会串台**：1.7 的 `Player.log` 全机共用、后启动者整份重写，`readBridgeInfo` 的「按最新记录」兜底会把别人的实例当成自己 ⇒ `call`/`wait` 可能打进别人的局，而返回看着"正常"。
   **每批动作前**跑 [`docs\多实例并发安全-给运行中会话的补充说明-20261024.md`](多实例并发安全-给运行中会话的补充说明-20261024.md) §0 的三段校验（记录 pid ↔ 监听该端口的 PID ↔ 该 PID 命令行含 `-savedatafolder=…\profiles\<profile>`）。**不要**用 `status`/`logs` 判断"我连的是谁"。
4. **别写假记录**：本会话一个子代理为离线测 `wait` 造过 `runs\game-process.dshwait-check.json`（pid=0、port=5288、token=`fake-token-…`），另一路会话的 `readBridgeInfo` 兜底把它当成了当前实例，4 次调用打进了假桥【对方实测】。文件已删，但**任何人都不该再往 `runs\game-process.*.json` 写测试记录**——离线测用假 `client` 对象，不要造记录文件。
5. **PowerShell 吞引号**：条件/参数一律走 `--condition-file` / `--args-file`；`@文件` 简写**必须带引号**（`'@cond.json'`，裸写是 splatting 解析错）【实测】。
