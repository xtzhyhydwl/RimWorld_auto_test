## 1. 现在是什么状态

等待从「每个子代理现场发明 `Start-Sleep`」变成**一条命令 + 写进协议**，并且**四类来源共用一个循环**：

- [`src/condition.js`](../src/condition.js)：**只有原子判定**（16 叶子算子 + `all/any/not` + `allItems/anyItem`）。
  `contains` 是 2026-10-24 新增（承载 `live --until` 的 `~`）；`contains`/`not` 是 Node 侧扩展，`rb.poll` 没有、不能下发游戏内。
  边界：算子只做「一个值 vs 一个期望值」；窗口/计数/派生量进采样层（设计稿 §2.4）。
- [`src/wait.js`](../src/wait.js)：只剩**循环**（间隔 + 超时 + 探针故障三分）。超时**返回** `ok:false` 并带回最后一次采样；
  **字段路径取不到 = 条件未成立、继续轮询**，只有算子写错/类型不符才立刻失败。
- [`src/wait-sources.js`](../src/wait-sources.js)：四类取样器（bridge / event / process / bridge-ready）+ `SOURCE_SPECS`（给 `cli atoms` 用）。
  聚合在这里：`--window-ms`（按事件自身 `ts` 裁剪）、`result.counts.<kind>`、`result.eventTexts[i]`。
- [`src/live.js`](../src/live.js)：**不再有自己的循环**。`--until` 只做「谓词 → 条件 JSON」的纯翻译，循环用 `waitFor`；
  输出格式与 `0/2/1` 退出码不变。
- 条件登记表 [`src/conditions.json`](../src/conditions.json)：16 个场景 + `wait --scenario / --list / --arg`（`$占位` 由 `--arg k=v` 填）。
  证据分级 `verifiedLevel` 四档（`wait-verified` / `field-verified` / `doc-example` / `inferred`），**不作准入门槛**，只用来排"还差哪几步没验"。
- **原子可检索**：`node src/cli.js atoms`（算子 + 四类来源快照字段 + 登记表统计，全部由代码导出，不会与实现漂移）。
- 命令形态：
  - `wait --scenario <场景名> [--arg k=v …]`（首选）
  - `wait --probe <只读工具> --condition-file cond.json [--args-file a.json]`
  - `wait --source process --pid <pid> [--verify]` / `--source event --file f [--event-format log] [--new-only] [--window-ms N]` / `--source bridge-ready`
  - 退出码一律 `0` 命中 / `2` 超时 / `1` 其它；打印层把 `sample` 截到 2000 字符（完整载荷用 `cli call` 取）。

## 2. 真机实测（9 个用例，`voiced` 轻档 / 1.7.4985 / 桥接 2.1.1 / 184 工具）

| 场景 | 结果 |
| --- | --- |
| 已进图命中 `result.state.playable` | exit 0，**5 ms / 1 次采样** |
| **动作→闭环**：`open_main_tab` → 等 `get_ui_state.openMainTabId` | exit 0，**5 ms / 1 次**（随后 `close_main_tab` 也 exit 0） |
| 不可能条件，`--timeout 1500` | exit 2，attempts=7，stderr 有条件+最后采样 |
| 有图但字段名写错（`list_colonists` 等 `result.state.playable`） | exit 2，点名「断在 state 这一段，可用 success/count/colonists/operation」 |
| 没进图就等 `result.colonists` | exit 2，点名「从头到尾没取到」+ 提示先等 `playable` |
| 算子写错 / 未知工具名 / `--source event` | 均 exit 1，1 秒内（含命名空间提示） |
| 开销 | `cli call` 71 ms vs `cli wait`（一次命中）69 ms（墙钟含 node 启动） |

细节与未验证清单见 [`docs\cli-wait-实测-20261024.md`](cli-wait-实测-20261024.md)、语法见 [`docs\cli-wait-用法-20261024.md`](cli-wait-用法-20261024.md)。

## 3. 别踩（本次新增的坑，都是实测）

1. **起游戏的命令一退出，游戏就被连进程树杀掉。** `node src/cli.js start` 单独跑：桥接 7 s 就绪、命令返回，游戏随即消失（pid 立即 `ESRCH`，日志一个字节没写）。
   ⇒ 要**多步驱动**就得把启动命令挂成**保活 job**（`start` 后面接一个 `node -e "setInterval(()=>{}, 900000)"`），跑完先 `stop --profile <p>` 再杀保活 job。
   这也是以前只能靠单进程 `cli smoke` 的原因【实测】。
2. ~~**`src/proc.js:125 isAlive` 把 `EPERM` 当活着**~~ **已修（2026-10-24 晚）**：`isAlive` 现在只认 `alive`；
   `EPERM` 单列成 `probePid().state === 'foreign'`，判「是不是我的实例」改用
   `verifyInstance(pid, {processesDir, expectedProfile})`（命令行里必须有本 profile 的 `-savedatafolder`）。
   `status` 的 `recordedAlive`、`stop` 的两处 `taskkill`、`--force` 收集 PID 都已换成身份校验。
   见 [`docs\多实例并发安全-修复记录-20261024.md`](多实例并发安全-修复记录-20261024.md) §5。
3. **多实例会串台** —— 机制仍在（1.7 的 `Player.log` 全机共用、后启动者整份重写），但**工具链已经不再会**把命令打到别人局里：
   有 profile 时记录即权威（不再去共用日志里刮），`call`/`wait`/`status` 先过 `resolveBridge()` 四道校验，
   不过就拒发并打印判据；启动时记 `logAnchor`，日志被重写就放弃日志解析。
   看 `status` 的 `bridgeResolution` 就够；老的三段校验脚本只在怀疑工具链本身出错时才手跑
   （[`docs\多实例并发安全-给运行中会话的补充说明-20261024.md`](多实例并发安全-给运行中会话的补充说明-20261024.md) §0）。
4. **别写假记录**：本会话一个子代理为离线测 `wait` 造过 `runs\game-process.dshwait-check.json`（pid=0、port=5288、token=`fake-token-…`），另一路会话的 `readBridgeInfo` 兜底把它当成了当前实例，4 次调用打进了假桥【对方实测】。文件已删，但**任何人都不该再往 `runs\game-process.*.json` 写测试记录**——离线测用假 `client` 对象，不要造记录文件。
5. **PowerShell 吞引号**：条件/参数一律走 `--condition-file` / `--args-file`；`@文件` 简写**必须带引号**（`'@cond.json'`，裸写是 splatting 解析错）【实测】。
