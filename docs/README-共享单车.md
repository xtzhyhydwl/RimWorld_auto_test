## ③ 最短施工路径（从「现在」到「能跑」）

来源：开发流程 §2 的六步流程与验收门。**步骤顺序按下面修正过的版本走：**

| 步 | 做什么 | 退出门（不过不进下一步） |
| --- | --- | --- |
| （前置） | 环境已就绪：干净测试实例、桥接操作、工具坑、编译现状 | 见开发流程 §1 |
| **Step 0** | 侦察（**不写一行产品代码**）：环境/工具坑/寻路路径是否走得通 | 能明确回答「哪些路径已验证走不通、别再试」 |
| **Step 0.5** | **地基探针**（见下） | 三个未知量各自有实测数字 |
| **Step 1** | 冻结 Def 规格（XML + 依赖 + LoadFolders） | 游戏里 `Hot reload Defs` 后能生成出这个物体 |
| **Step 2** | 逻辑骨架五件套 | 一个小人无人指令也能骑车到目的地并还车 |
| **Step 3** | 人车解绑总线逐条走完 | 每条之后「人恢复原速 + 车停在合法格且未被占用」 |
| **Step 4** | 存档往返 | 读档后状态与存档前一致 |
| **Step 5** | 贴图替换（并行线） | **占位 texPath 清单归零** |
| **Step 6** | 发布准备 | license / 双 TFM 留位 / AI 美术披露 |

> **流程修正 —— Step 0 的第 2.5 步「地基探针」**
> Step 0 原文是「不写一行产品代码」，但设计-v2 §9.4 列了三件**必须先做小样实测**的事：
> ① `MinifiedBike.PostMake` 装内层后物品是否正常工作（§2.3 设计 + §2.4 未实测标注 / §9.1-12）；② 骑行 Job 的上下车开销 `O`（§7.2 的阈值全靠它）；
> ③ 整理工是否真能一次背 5 辆车（§6.4）。
> **这三件都需要产品代码存在才能测** → 它们**不属于 Step 0**（Step 0 不许写代码），应作为**独立的「Step 0.5 · 地基探针」**执行。
> **产出物 = 用完即弃的探针代码**（不是产品代码，不进正式 `Source/`，不许被后续模块 import）。
> **Gate**：三个未知量各自有一个实测数字/结论；探针代码标记为一次性并可删。

## ⑤ 已知的文档健康问题

1. **交叉引用一律用「文件名 §节号」，不要用行号。** 设计-v2 曾出现「同一事实两处不同说法」，已由重排修复；
   而行号引用**已实际失效 4 次**。
2. **本工程的写入通道曾静默改写竖线字符与行尾**（已登记的失效类型 **S8b** / 规程 **R9**）
   → **改文档后必须跑结构自检**：逐字符遍历 `[char]124` 数表格列（**不要用 `split('|')`**）、核对行数、确认行尾仍是 **LF-only**。
3. 含**转义竖线 `\|`** 的表格（如 [自动化测试-变化驱动设计.md](自动化测试-变化驱动设计.md) §4.3）是**合法 markdown**，
   但任何「按管道符计列」的自检会**误报**，请用字符遍历计数。
4. **结构改动必须回核入口。** 本文件是"引用的集合"，**对其它文档的结构改动最敏感**——它建成后几分钟内就过期过一次：
   设计-v2 重排把 §2.4「14 处实测更正总账」整节剥走（移交真值表 §8），**本文件 3 处引用（② 人车解绑、④ ExitMap、④ 骑行形态）同时失效**。
   所以：**任何移动 / 删除 / 重命名章节的改动，都必须同步回核本文件**；只写"别用行号"（第 1 条）挡不住这一类。
