# RHAH 票 0001 结论（2026-10-25）：不是源码缺陷，是 1.6 发布包落后

> 证据来源：`docs\RHAH-0001-验证-1.7-20261025.md` + `docs\RHAH-0001-验证-1.6-20261025.md`，原始产物 `runs\2026-10-25-0001-rerun\`（182 件）与 `runs\2026-10-25-0001-16\`（142 件）。
> 标注：【实测】= 本轮真机回读；【读码】= 源码；【文档】= 旧报告。

## 一句话

同一个 `Source\`：**编出来的 1.6 收口，玩家手上那份 10-16 的 1.6 二进制不收口**。⇒ 这是发版问题，不是代码缺陷；票 0001 的 Q1 应定案为 (a)，本票不再需要源码改动。

## 机制对账

- 旧 1.6 包缺 `Owner` / `Refresh` / `Finish` / `Tick`（0006 二进制取证【文档】）⇒ 没人写 `Settled`、也没有「批次没人了」的兜底 ⇒ 记录恒 `Open` ⇒ 信恒 `Pending`。
- HEAD 里有这套兜底；重建后「最后一个围攻者死的同一 tick」就 `Finish(Ignore)` 并删信。【实测】
- 1.7 的 A/B 与 1.6 的 GREEN 三份都在 0 tick 收口 ⇒ **行为一致，跨版本没有分叉**。

## 对票 0001 的处置建议

1. **Q1 定案 (a)**：零源码改动。交付物 = 给作者的 **issue**：
   - 症状（玩家原话两层）：点「拒绝」对话框关不掉；杀光围攻者后信与警报一直在。
   - 根因：玩家加载的 `1.6/Assemblies/HungerAndHavoc.dll` 是 2026-10-16 的构建，缺 `Owner/Refresh/Finish/Tick`。
   - 修法：**用当前源码重编 1.6 并重新发布**；不需要改代码。
   - 证据：四行实测矩阵 + 两份日志 + 截图（旧包 +5000 tick 信仍在；重建版同 tick 消失）。
2. **不要走治本**（选敌对即 `Settled`）：会反 `docs/references/incidents.md:18/:20/:60` 的契约（拒绝只关窗、信留在栈、可随时补交粮止战），且要改 3 条既有断言。
3. **本票不必再开 `fix/0001-*` 分支**——没有代码要改。

## 仍未验证（留给下一步）

- **记录未清理**：GREEN 与 1.7 两版的 `settled=Ignore` 已写，但 `openChoices` 里那条记录仍是 5 个已死 pawn 的 id、`expireTick` = 到达 +1 天。【实测】到期那一刻会不会**重新冒出一封信**、或让警报条复活、或引发空指针——**没验**。这是「剩下的未知」，也是唯一还值得跑一次的东西。
- **旧包「点拒绝不关窗」的具体代码原因**：目前只归因为「整份二进制落后」，没有逐行对账。

## 复现步骤（给作者 / 复跑用）

1. 1.6 装到 `D:\RimWorld-1.6`，ModsConfig 14 项（清单见 skill `rimworld-switch-test-version`），`-savedatafolder` 与 `-logFile` 分离。
2. 起动后走桥接（`127.0.0.1:5174`，token 在 `Player.log` 的 `Bridge token:` 行）。
3. `execute_debug_action` → `Actions\Do incident\RHAH_BeggarSiege`。
4. `list_letters` 记下信；打开并点「拒绝」；再用 kill 动作杀光该批 5 人。
5. 杀光后**同 tick**回读 `list_letters`，再推 2500 / 5000 tick 各回读一次；`save_game` 后读 `.rws` 的 `openChoices`。
6. 对照：把 `1.6\Assemblies\HungerAndHavoc.dll` 换成 HEAD 重建版（`B3F0F895`）重跑同一流程。
