## 3. 闭环可行性（R2）

- **触发**：`execute_debug_action{Actions\Do incident\RHAH_BeggarSiege}`——有真机成功证据 + 5 个 `lookTarget`。【实测】
- **原子齐**：开信 / 读信 / 点选项 / 推 tick / `save_game` 后读 `.rws` 都已具备。
- **`list_letters` 直接给判据**：返回里有 `choiceCount`、`choices[].closesDialog`、`canDismissWithRightClick` ⇒「点敌对后对话框关没关」不用靠截图猜。【实测·schema】
- **真缺两件小活**：① `openChoices` 无在线探针（只能存档回读，反而是强证据）；② 信件类 `wait` 场景 0 条（补 `wait` 数据即可，不写脚本）。
- **半有两条**：`close_window` 对该 `closeOnCancel:false` 对话框是否生效**未验**（这是「推 1 小时」的前提，失败则停手）；杀 pawn 只有一次一个的 `Actions\T: Kill` 与粗粒度 `Destroy non-colonists`。

## 4. 一条必须先钉的冲突

R1 读码：点敌对后信仍 `Pending`（记录没结算）。
R2 现场：**对话框在点完之后还开着**（`runs\20261024-RHAH-E12\S04-after-refuse.png`；`ui-state` 里 tick 冻结 3181）。
二者不矛盾（信 Pending ≠ 窗已关），但**「点击后对话框状态」必须当第一条断言**，否则后面「信消失」的判据会被带偏。⇒ 用 `list_letters` 的 `closesDialog` / `canDismissWithRightClick` 判，不靠肉眼。
