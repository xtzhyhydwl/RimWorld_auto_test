01

改动落在哪一层

改动全部落在既有分层里：Defs 只放数据，Core 只放设置与 Def 引用，Generation 管到场，Pawn 管状态，最外一圈只做接线、文案与登记。点开任一个文件看它改了什么、为什么改。

L1 Defs 数据 只描述 buff 与心情，不含任何逻辑

新增 · 1.6 与 1.7 逐字节相同

initialSeverity 0.10、isBad false；comps 里挂两个组件：本票的档位组件，以及原版的 HediffCompProperties_Disappears（disappearsAfterTicks 120000、showRemainingTime true）。

  • 三个 stage 的 minSeverity 是 0 / 0.40 / 0.80，对应代码写入的 0.10 / 0.50 / 0.90——两者必须同时对，否则档位会串。
  • 每档给 painFactor、近战命中 / 伤害 / 出手间隔、闪避、承伤、移速、意识；逐档递增。

为什么：把"越饿越凶"做成一个可挂载、可显示剩余时间、到点自己消失的伤病载体，而不是另写一套计时器。

修改 · 追加三条 ThoughtDef

RHAH_Thought_SiegeFuryFoodInSight / …MealSoon / …Starving，thoughtClass 指向新的"不过期"记忆类，baseMoodEffect 40 / 50 / 60。

为什么：三档各配一条心情，用心情抵消围攻期间的崩溃风险；文案已由用户改定，本次不动。

L2 Core 设置 设置数据留 Core，Def 一律走 DefOf

修改 · 字段与存档

siegeFuryEnabled = true，紧跟在 armedWeaponsEnabled 之后；ExposeData 里一行 Scribe_Values.Look，key 与字段同名、默认值与字段一致。

为什么：开关属于设置数据，按分层规则留在 Core。顺带确认过 ResetToDefaults 是反射遍历字段，新字段自动被重置，不需要改。

修改 · Def 引用

新增 RHAH_SiegeFury（HediffDef）与三条 RHAH_Thought_SiegeFury*（ThoughtDef）。

为什么：本仓既有写法是 Def 全走 DefOf，业务代码里不拼字符串；新代码也就没再用 GetNamedSilentFail。

L3 Generation 到场 谁该拿到这份增益，只在这里判一次

新增 · 闸门 + 挂增益

GrantingEnabled = 索粮总开关 && 本票开关（注释写明"两个开关都要开"）；CanApply 是纯函数：开 / 有来客快照 / 非玩家派系 / 事件属于三种索粮围攻之一；AppliesTo(pawn) 只取一次快照再调 CanApply；Apply 先撤掉携带的营养不良，再 AddHediff（有 HasHediff 幂等保护）。

评审前这个类叫 RHAH_SiegeFury，与 HediffDef 同名、读不出"这是挂增益的入口"，B-4 改名 …Grant，文件同步。

修改 · 生成流水线

在 Initialize → FamineWeapons.Apply 之后加一行 RHAH_SiegeFuryGrant.Apply(pawn)，位置在关系绑定之前。

为什么：新角色登记来源后立刻挂增益，不加入场钩子、也不加读档钩子。

修改 · 形参改名（评审后缩减）

marked → hasVisitorSnapshot、player → isPlayerFaction。评审前这里还有一段"围攻者不给入场营养不良"的分支——B-2 指出那是拿 A 特性的闸门决定 B 特性的事，已整段删掉，挪回 SiegeFuryGrant.Apply。

为什么：入场营养不良是"所有饥荒来客"的共同行为，围攻者的特殊处理应当属于围攻特性本身。

修改 · 形参改名

marked → hasVisitorSnapshot、player → isPlayerFaction、source → incidentDisplayId。

为什么：旧名读不出到底标记的是什么、source 指的是事件编号还是别的东西；逻辑一字未动。

L4 Pawn 状态 档位跟着真实营养不良走，心情跟着档位走

新增 · 档位组件

SeverityPerStage {0.10, 0.50, 0.90}（注释写明每个值必须落在 XML 第 n 档区间）；StageOf 按营养不良 0.25 / 0.50 分档；CompPostPostAdd 初设档位并挂心情；CompPostTick 每游戏内小时对齐一次；CompPostPostRemoved 清心情。

为什么：慢状态按游戏内小时检查，不新增 tick 扫描器；每处只查一次营养不良（B-7 整改），档位没变就直接返回。

修改 · 心情收口

SetSiegeFuryMood(pawn, stage) 先清三档旧心情再挂当前档（三档互斥）；ClearSiegeFuryMood(pawn) 到期时清空；私有的 RemoveThought 统一做"取不到 Def 就跳过"。

为什么：心情的期限不另存，交给 hediff 的生命周期；原方法名 Notify… 读起来像"发通知"，实际是在改写心情，B 段把它改成 Set / Clear。

修改 · 记忆类

Thought_Memory_RHAH_NoExpiry 是唯一实现（ShouldDiscard => false，读档后不按 age 过期）；旧的 Thought_Memory_RHAH_EnslavedServing 改成它的空子类，只作读档兼容。

为什么：实测存档里是 Class="Thought_Memory…" 这种按类名重建的写法，直接删旧类会让旧存档里的记忆加载失败，所以保留旧名做别名（B-3 的安全变体）。

L5 外围接线与登记 UI 适配、三份文案、存档归属清单、测试

为什么：新增开关必须有显示文本；文案由用户改定，本次不动措辞。

登记新 HediffDef、两个新组件类型、新的不过期记忆类与三条 ThoughtDef 的卸载行为；SiegeFuryGrant 是静态类，不入档，不登记。

为什么：这一页是本仓"什么会进存档、卸载时怎么处理"的唯一清单，新增可序列化类型必须同步。

02

一次围攻来客的生命周期

从生成到消失只有一条主路径。分支（开关关掉、不是索粮事件、是玩家派系）都收在第一步的闸门里，不在这条线上分叉。

  1. 01

    这一步发生什么

    建角色后先跑两项初始化，再绑定关系。闸门只看两件事：这个角色有没有来客快照、来源事件是不是三种索粮围攻之一——不看身份标签，也不看阵营字符串。

  2. 02

    这一步发生什么

    这是"所有饥荒来客"的共同行为，不是围攻专属。围攻者的那份营养不良紧接着在下一步被撤掉，所以最终状态与他们"从零开始饿"一致。

  3. 03

    这一步发生什么

    闸门通过才动手：先撤掉身上携带的营养不良，再 AddHediff；已有同类 Hediff 时直接返回（幂等）。初始档位按当下营养不良算，通常就是第 1 档 0.10。

    真机实测（1.7）：新生成的 5 个载体全部 sev = 0.10、剩余时间 120000、营养不良 none，全场营养不良 Hediff 数为 0。

  4. 04

    这一步发生什么

    按整点散列触发，只读一次营养不良；档位没变就直接返回，变了才写回 severity。这样既不会漏掉缓慢变化，也不会每 tick 扫一遍。

  5. 05

    这一步发生什么

    先把三档旧心情都清掉，再挂当前档那一条；心情本身不设期限，只由 Hediff 的生命周期负责收尾。设计目的是让围攻期间别先精神崩溃。

  6. 06

    这一步发生什么

    到期由原版 Disappears 组件负责（第 120000 tick），移除时回调清掉三条心情。真机实测：读档后剩余时间不重置——74859 → 74819，对应 tick 45172 → 45212。

03

数据怎么变形

整条链只有一个输入：营养不良的 severity。它决定档位，档位决定 Hediff 的 severity、心情与全部 stat 修正。

输入
营养不良 severity（原版 Hediff）。低于 0.25 算第 1 档；0.25–0.50 第 2 档；0.50 以上第 3 档。不压上限：原版 0.8 / 1.0 的后果照常，实测见过 0.9014。
判定
两个纯函数：StageOf 分档，SeverityPerStage 给对应的 0.10 / 0.50 / 0.90。这两个值必须落进 XML 三档的 minSeverity（0 / 0.40 / 0.80）区间，否则档位会串——这条约定写在注释里。
输出
三档逐级增强：耐痛（painFactor 0.70 / 0.40 / 0.10）、近战命中与伤害、出手间隔、闪避、承伤、移速、意识；外加 40 / 50 / 60 的心情。两日后一起消失。
04

评审结论与逐条处置

评审按"命名不能有歧义、不许破分层与模块接口、能最小改动就最小改动"三条尺子过了一遍。结论：3 条必修、6 条建议、1 条可不改；下面每一条都能点开看位置、现状与最终处置。

结论：可以提 PR。 必修全部处置：2 条按原方案改（B-2、B-3 的核心），1 条不采纳且有实测依据（B-1），1 条走安全变体（B-3 改为保留旧类名做读档别名）；建议 6 条里 5 条已改、1 条按评审建议不动。整改后 1.6 / 1.7 双版本构建 0 警告 0 错误，并重跑了一遍真机（含读档）。

B-1 · 必修 · 不采纳

位置：RHAH_IrisMenusCompat.cs:237-238（唯一绘制点）；对照 ModEntry.cs:150-153 里两个同级开关。

评审担心：没装 IrisMenus 的玩家没有地方关这个功能。

处置：不采纳。实测 About/About.xml 的 modDependencies 里就列着 Nanaloveyuki.IrisMenus——它是硬依赖，缺了模组根本启用不了；而且"开关只放事件页、不放核心设置窗口与访客页"是已经定稿的设计口径。这一条不改代码。

状态：不改。若以后 IrisMenus 降级为软依赖，这条要重新拿回来做。

B-2 · 必修 · 已改（按评审推荐方案）

位置：RHAH_FamineArrival.cs:21-28 与紧接其后的 RHAH_PawnFactory.cs:57-59。

现状：到场初始化里拿"能不能挂这份增益"的闸门，去决定另一件事（要不要给入场营养不良），同一个闸门在生成流水线里连判两次——命名与语义错位，且让入场类知道了另一特性的开关。

改法：整段删掉；改成在 SiegeFuryGrant.Apply 里、AddHediff 之前撤掉携带的营养不良。闸门只判一次，入场类回到单一职责。

验证：真机新生成 5 个载体，营养不良 none、全场营养不良 Hediff 数为 0——"先加后撤"没有留下痕迹。

B-3 · 必修 · 安全变体

位置：RHAH_VisitorMood.cs:86-96：新旧两个"永不过期"记忆类实现一字不差，旧名 EnslavedServing 说的是另一件具体的事。

评审改法：以新名作唯一实现，把 XML 的 thoughtClass 指过去，删旧类。

为什么没照做：存档里记忆是按类名重建的（.rws 里可见 Class="Thought_Memory…"），删掉旧类会让旧存档里的这类记忆加载失败。

实际做法：NoExpiry 成为唯一实现（去掉 sealed），旧名改成它的空子类，注释写明"只留作读档兼容，新代码不要再引用"；XML 与登记表不动。

验证：用修复后的构建加载"修复前构建写出的"存档，加载成功、日志里没有类名解析错误，心情与剩余时间都在。

B-4 · 建议 · 已改

静态类原来叫 RHAH_SiegeFury，与 HediffDef 的 defName 一字不差，看到 RHAH_SiegeFury.Apply(pawn) 分不清说的是那个 Def 还是挂增益的入口。

改法：类与文件都改成 RHAH_SiegeFuryGrant；Def 与 DefOf 不动。调用点两处、测试一处同步。

纯改名，不动行为、不动存档。

B-5 · 建议 · 已改

Enabled 实际是"两个开关都开"，读起来却像"本特性总开关"。

改法：改名 GrantingEnabled，保留"关掉整个索粮事件就不该还挂这份增益"的注释。

不动行为。

B-6 · 建议 · 已改（不加断言）

代码写入的 0.10 / 0.50 / 0.90 必须落在 XML 三档 0 / 0.40 / 0.80 的区间里，这条契约只存在于两个文件之间；字段名 StageSeverities 又读起来像"档位门槛"。

改法：字段改名 SeverityPerStage，上方加一行契约注释。

没做：评审还建议在测试里抄一份阈值做断言——数值已经由用户冻结，再抄一份等于制造第二个来源，按 YAGNI 跳过。

档位同步时同一份营养不良查了两遍、分档也算了两次（加档与改档两处都是）。

改法：每处只查一次，档位与 severity 复用同一个局部值。

等价改写，不动行为。

B-8 · 建议 · 已改

B-9 · 建议 · 已改（加注释）

三条新心情继承自饥荒心情的记忆基类，于是"关掉饥荒心情"会连它们一起变成 0 并隐藏——同一个特性被两个设置交叉控制，第二个判断藏在继承里。

改法：在记忆类上方补一行说明，把这条关系写到明面上。

没做：真要分开就得改继承并显式读新开关，那是会改行为的设计决定，留给用户拍板。

同一份文件里，旧方法用字符串取 Def，新代码用 DefOf。新的更合规范，但把旧的改过来要在 DefOf 里补字段，反而变大。

按评审建议保持现状。

05

边界与术语

读完前面容易产生的四个误解，以及这份报告里反复出现的四个名字。

容易误读的地方

  • 饥饿上限没被压住。这是刻意的：围攻者照样会在原版的 0.8 / 1.0 后果里倒下，增益只是让他们在那之前更凶。
  • 三条心情同时受"饥荒心情"开关管。因为继承关系，关掉那个开关它们也会归零并隐藏；本次只加了注释，没有改行为。
  • 旧记忆类不是死代码。留着它是为了让旧存档按类名重建记忆时不报错，新代码不该再引用。
  • 单测没跑成。xunit 在本机 testhost 起不来（进程句柄被拒），这两个用例绿不绿未知；数值结论来自真机取证与用户目视复核。

术语

档位（stage）
按营养不良 0.25 / 0.50 切出来的三档，不是原版 Hediff 的 stage 概念，但写入的 severity 正好落进 XML 三档区间。
Hediff severity
buff 自身的强度值，0.10 / 0.50 / 0.90，决定原版按哪一段 stat 修正生效。
Disappears
原版组件：到期自动移除 Hediff，并保存剩余时间；两日消退就靠它。
来客快照
每个访客身上记录的来源事件等字段；闸门判断"是不是索粮围攻的来客"靠它，不靠身份标签。
