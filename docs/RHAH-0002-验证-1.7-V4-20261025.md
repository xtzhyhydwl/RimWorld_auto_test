## 3. 与任务书不一致、必须记下来的两点

1. **只覆盖 dll+api 不够。** 工坊 1.7 的 Defs 是作者 1.1.4 旧 XML：缺 `Defs\HediffDefs\RHAH_ArmedDemandEndurance.xml`，`ThoughtDefs\RHAH_Famine.xml` 里没有 3 条 `RHAH_Thought_SiegeFury*`。只换 dll+api 时 buff 根本不会出现（第一次 t0 存档 0 个 buff）。
   处置：把仓库 `1.7\` 整棵树同步到工坊（40 个 xml / 46 文件），并把整个 `3807233439` 目录 409 个文件完整备份到 `runs\2026-10-25-0002-v4\workshop-backup\3807233439-full\`。
2. **kill 掉「正持有桥接连接」的后台 job 会让游戏崩溃。** 15:22:48 出现 `CRASH … System.InvalidOperationException: Connection is not active（Lib.GAB.Server）`，存档丢失，只能重开一轮殖民地。以后推时间不要用后台 job，或只在两次调用之间停。

## 4. 时间推进为什么没踩准

- `play_for` **不传 `speed` 就按当前档跑**（实测 60 tick/s = 1×）。前半段因此在 1× 里白跑，`push24.log` 记到每段 40 s 只走 ~2400 tick。
- 改 `speed:"Ultrafast"` 后速度仍不稳定：`push-ultra3.log` 里同一批 30 s 段实测 891–903 tick（1×），而个别段一次冲出 38,327 / 59,715 tick（≈600–6000 tick/s 的补帧爆发）。结果 +86400 与 +129600 两个检查点都被一次性冲过，只能在 +119,700 与 +360,000 取到样。
- 结论（实测）：**这个 profile 上 Ultrafast 不可用于「定点采样」**；要用 `speed:"Fast"` + 每段回读 `ticksGame`、接近目标就换小段。
