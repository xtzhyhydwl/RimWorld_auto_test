## 2. 三条必须记住的实测

1. **「+22h = 开打之前」不成立。** 两个死者的死亡时刻可反推（ttd 冻结值），分别是 **+18.8h / +19.2h**；倒地者（#5，mal 0.580）的倒地时刻**没取到**（没有中间存档，属未测）。要在**无战斗污染**下取 B，检查点必须 **≤ +18h（tick ≤ 68363）**。本轮 +22h 的数据本身没问题（buff/心情/mal 都对），只是"无人死亡"这条被战斗搅了。
2. **`play_for` 请求的档位不等于实际档位。** 本轮 `--speed Superfast` 的 seg 6–34 连续 29 段只有 **59 tick/s**（= 1×），引擎自己把速度拉回去了；seg 1–5、35–52 是 320–650 tick/s。所以"推时间"只能按**回读的 tick 增量**判进度，不能按档位算。
3. **`Ultrafast` 依旧不能用于定点**：V4 实测单段 12 s 冲出 120000 tick，冲过即不可逆。本轮的 `advance` 默认改 `Fast`，见 §3。

## 3. 本轮新增的 CLI 能力：`advance --to-tick`

```
node src/cli.js advance --profile rhah --to-tick 79970 [--speed Fast] [--chunk-ms 5000] [--landing 3000] [--max-ms 1200000]
```
- 实现：新增 `src/advance.js`；`src/cli.js` 只加一个 `case`、一条 `COMMAND_HELP`、一条总表行、一条 `PROFILE_REQUIRED`。
- 对外**只有目标 tick** 一个参数。内部：`play_for` 大段巡航 → **每段回读 `ticksGame`** → 用「tick 增量 / 墙钟」抬高速率上界（**只升不降**）→ 下一段时长 = `min(chunk, 预算/上界 × 0.6)`，**保证跑满上界也不越过目标** → 剩余 ≤ `landing` 改 `step_game_ticks` 精确补齐 → 收尾 `pause_game` → 回读。
- 失败必先暂停再抛（`play_for` 调用异常 / `success:false` / 连续两段 0 增量 / 冲过目标 / 超墙钟预算），逐段数据全进 stderr（`--out` 一并落盘）。
- **自测（本轮真机）**：+3000（纯 step 路径，30.1 s）→ +30000（`play_for` 路径，39 段，184.2 s）→ +46200（`Superfast`，54 段，254.7 s）；三次 `reached` 与存档 `<ticksGame>` **逐次一致**（3770 / 33770 / 79970）。
- **口径已落进 skill**：`.dsh\skills\rimworld-auto-test-closed-loop\docs\测试SOP\推时间.md` §0（怎么用）与 §2.3（实测速率表 / 预算公式 / 时间↔tick 换算）；`atoms` 的 `docs.advance` 也指向它。

## 4. 偏差与没做的

1. **第一版解析差点判错。** 我先用整份存档的 `Dead=8 / Down=2` 当结论，那里面多数是**我方**（`Colonist`）和动物；按 buff 载体重新分组后才是 §1 那张表。教训：**断言必须先分组再计数**，"死了几个人"是全存档口径，不是 buff 口径。
2. **`--speed` 默认值是 `Fast`，没照 HANDOFF-0002 §0 写 `Ultrafast`。** 理由：§0 的默认值与 §3「Ultrafast 不能当精确落点用、本轮别用」自相矛盾，而冲过检查点**不可逆**；`Fast` 只是慢（22h 那程 7–8 分钟）。要更快可显式 `--speed Ultrafast`，落点仍由 step 负责。
3. **重编产物 SHA `773F2037…`** 与 V4 记录的 `CC282D88…` 不同（大小同为 871,424 B，命令是 `-t:Rebuild`）。二进制里 `RHAH_ArmedDemandEndurance` / `RHAH_Thought_SiegeFury*` / `famineSiegeFury` 都检出。**差异来源未深究**。
4. **mal 增速 2.39%/h**（实测），HANDOFF §7 的 2.08%/h 是 V4 在 33h 上的反推；按 2.08 预期 0.45，实测 0.527（高 0.07）。原因未查（可能与 Ratkin 的饥饿速率/事件当刻的初始值有关）。
5. **没做**：到期（两日）后的消退验证（C 只验到递减）；无战斗污染的 B（需重跑一局到 ≤+18h，本轮没跑）。
