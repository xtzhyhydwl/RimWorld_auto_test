```markdown
## 问题

本模组没有声明 RimTalk - Expand Toddlers（`cj.rimtalk.toddlers`）为前置。来客不会把不能行走的婴儿抱走，队伍会直接把婴儿丢在路边——Steam 上已有玩家反馈这一条。

## 我认为合理的做法

婴儿在访客体系里必须有行动能力且能被带走，否则就不该生成。所以在**生成年龄**这一步检查两件事：

1. Toddlers 可用（`cyanobot.toddlers` 启用，且 `LearningToWalk` / `LearningManipulation` 两个 HediffDef 真的加载）；
2. 抱婴能力可用（`JobDef RimTalk_PickUpToddler` 存在）。

缺任一条，就把本该刷成婴儿的年龄 **+3 岁并抬到 4 岁**（鼠族 3 岁以上是儿童，而生成阶段的分档线是 4 岁，两者都要过），并打一条 `[RHAH]` 日志说明原因。设置里的「允许不能走路的婴幼到来」仍然可以保留婴儿。

## 改动

- 新增 `RHAH_ToddlerPresence`：`Active`（Toddlers + 两个成长 HediffDef）、`BabiesCarriable`（再加抱婴 JobDef）。原先 4 处裸读 `ModsConfig.IsActive("cyanobot.toddlers")` 收敛到这一处。
- `RHAH_GenerationOptimizer`：抬龄抽成纯函数 `RHAH_VisitorRules.LiftBabyToChildAge`，对**所有角色**生效（原来只对 4 个幼年角色）；没有写年龄的请求不再自己造年龄（交回原版随机）。
- 设置页文案按真实闸门分三态（有抱婴扩展 / 只有 Toddlers / 都没有），三语同步，并新增 `RHAH_Settings_ImmobileBabies_NoCarry`。

## 说明

- **行为变化**：只装 Toddlers、不装抱婴扩展的玩家会**看不到婴儿访客**（此前是"看得到但被丢在路边"）。这是有意的取舍，可能需要一句 README 说明。
- 存档：**没有新增或修改任何存档键**；老档里已经存在的婴儿不回收，本改动只影响新生。
- 已验证：1.7 / 1.6 构建各 0 警告 0 错误、Tests 编译 0 错误、`python scripts/rhah_pipeline.py check` = PASS structure；**1.7 实机由用户本人验过：不满足条件时刷新的婴儿会自动抬成儿童**。1.6 只有构建证据。
```
