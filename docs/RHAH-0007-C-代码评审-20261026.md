## A 结论（≤3 行）

1. **方向对，落地有两处会比原 bug 更糟**：交易伏击者被整批钉成 4–7 岁儿童；抬龄只 +3，落到 3.x 岁仍是 `Baby`，原 Steam 反馈对 <1 岁婴儿没修好。
2. **分层没破**（`Generation → Pawn.Compat` 有先例），但"婴儿→儿童"这条规则在两层各写了一遍，且 Generation 里直接调 `Rand`，破掉本仓"规则函数注入 roll"的既有约定。
3. **命名普遍停在旧语义**（`Floor`/`WalkingAge`/`WalkingAgeRise` 都不再是名字说的东西），一个概念出现三个名字。必修 6 条。

## B 必修·分层

### B1 `Source/Generation/RHAH_GenerationOptimizer.cs:70-77` — 交易伏击全员变 4–7 岁儿童【必修】

- **现状**：`if (!request.BiologicalAge.HasValue && !carriable && !immobileAllowed)` → `Rand.Range(WalkingAge, WalkingAge + WalkingAgeRise)` 即 4.0–7.0，直接当作 `FixedBiologicalAge` 返回。
- **为什么错**：
  - 唯一不设 `BiologicalAge` 的生产调用点是 `Source/Trade/TradeEventRouter.cs:69`（`TrySpawnCaravanAmbush`，`Role = Thief`）。
  - `allowImmobileBabies` 默认 `false`（`Source/Core/RHAH_Settings.cs:345`），Toddlers 又不是声明前置 ⇒ **默认配置下整批伏击者都是 4–7 岁儿童**。原意是"别刷出婴儿"，实际做成了"把没有年龄的请求一律改成儿童"。
  - 同一个"婴儿→儿童"规则写了两遍：一遍是 `ChildAgeFloor` 的 `+3`，一遍是这里的 `Rand.Range`。这违反根 `AGENTS.md` 的 DRY / Easy to Change（改一处必须记得改两处），也违反本仓规则函数的既有形态——`RHAH_VisitorRules` 里 `GenerationAge/YoungAge/AirdropAge` 全部是"注入 roll 的纯函数"，只有新代码在 Generation 里直接 `Rand`，因此这条分支无法被单测覆盖（`Source/Tests` 里对 `WalkingAge` 0 命中）。
- **建议**：删掉这个分支（无年龄就交回原版随机），或把两种情形都收进一个纯函数 `ResolveVisitorAge(float? age, float roll)`（在 `RHAH_VisitorRules`，roll 由调用方给），Generation 只负责取 flag 和打日志。

### B2 `Source/Pawn/RHAH_VisitorRules.cs:265-279` + `Source/Generation/RHAH_GenerationOptimizer.cs:57` — "儿童起点"两处定义（3 vs 4）【必修】

- **现状**：抬龄阈值用 `ChildMinAge = 3f`（`RHAH_VisitorRules.cs:501`），抬完 = `age + 3`；但同一个类的 `StageFor` 用 `age < 4f → Baby`（`RHAH_GenerationOptimizer.cs:57`），单测把这个边界钉死为 `StageFor(3.9f) == Baby`（`Source/Tests/RHAH_GenerationOptimizerTests.cs:22`）。而 `BuildRequest` 用 `developmentalStages: StageFor(age)`（`RHAH_GenerationOptimizer.cs:32`）决定刷出来的生命阶段。
- **为什么错**：新增单测 `ChildAgeFloor(0.1f) == 3.1f`（`Source/Tests/RHAH_VisitorRulesTests.cs:84`）宣称"抬进儿童"，但 3.1 岁的请求仍以 `Baby` 阶段生成 ⇒ 原年龄 <1 的婴儿（普通来客抽 0–50 岁时的下段、鼠蛋 `RatEggMinAge=1/60 … RatEggMaxAge=2.9` 的下半段）抬完还是婴儿，Steam 那条"婴儿被丢在路边"原样存在。同一个概念（婴儿/儿童分界）两个常量、两个文件，改一处必忘另一处。
- **建议**：把分界提成一个常量（或让抬龄直接问 `StageFor`）两处共用，并加一条断言"抬龄后的年龄 `StageFor` 必须是 `Child`"。

## C 必修·命名

### C1 `Source/Pawn/RHAH_VisitorRules.cs:265` — `ChildAgeFloor` / 参数 `babySupport` 名实不符【必修】

- **现状**：函数名叫 "Floor"（下限），实现是"加 3 岁"：`2.9 → 5.9`，`3.5 → 3.5`。参数叫 `babySupport`，实参是 `carriable`（`RHAH_GenerationOptimizer.cs:80`）。
- **为什么错**：
  - 名字承诺的是"把值夹到某个下限"，实际输出不是任何下限（`2.9` 的下限是 `3`，返回 `5.9`），而且映射非单调：`2.99 → 5.99` 比 `3.00 → 3.00` 还大。名字错到会让人误判调用方语义。
  - `babySupport` 是迭代中间态的残留词：语义已从"Toddlers 可用"漂到"婴儿可被抱走"，名字停在两者之间，于是同一件事在调用方叫 `carriable`、在签名里叫 `babySupport`、在探针里叫 `BabiesCarriable`——一个概念三个词。
- **建议**：改名 `LiftBabyToChildAge(float? age, bool babiesCarriable, bool allowImmobileBabies)`，参数与 `RHAH_ToddlerPresence.BabiesCarriable` 同名。

### C2 `Source/Pawn/RHAH_VisitorRules.cs:496-498` + `Source/Generation/RHAH_GenerationOptimizer.cs:65` — `WalkingAgeRise` 一名两义、`WalkingAge(...)` 丢掉原义【必修】

- **现状**：`WalkingAge = 4f` 本义是"能走路的年龄"（仍被 `BegAgeFloor` 在 `RHAH_VisitorRules.cs:559` 这样用）；新常量 `WalkingAgeRise = 3f` 既当"抬进儿童档的偏移"（`:278`），又被 Generation 当作"随机区间的宽度"（`RHAH_GenerationOptimizer.cs:73-74`）。方法 `WalkingAge(RHAH_PawnRequest)`（`:65`）现在返回"生成用年龄"，还负责"没有年龄就造一个"，与 walking 已无关。
- **为什么错**：一是名字里的 `Walking` 已不描述返回值（B1 的 bug 正长在这层错名上：把一个"取行走年龄"的函数改成"发明年龄"）；二是一个常量承担两个无关语义（偏移量 / 区间宽度），改一个必然连带另一个；三是 `WalkingAgeRise` 的值恰好等于 `ChildMinAge`，看起来像"儿童线"，实际不是。
- **建议**：常量改 `BabyAgeLift`；"无年龄时的区间宽度"另给常量（或由 B1 的 `ResolveVisitorAge` 收走）；方法改 `ResolveGenerationAge`。

### C3 一个概念三个名字：`RHAH_ToddlerPresence.Usable` / `ToddlersActive()` ×2【必修】

- **现状**：`Source/Pawn/Compat/RHAH_ToddlerPresence.cs:14` 的 `Usable`；`Source/Pawn/RHAH_Begging.cs:183` 与 `Source/Pawn/Compat/RHAH_IrisMenusCompat.cs:2651` 各有一个纯一行转发 `ToddlersActive() => RHAH_ToddlerPresence.Usable`，各只有 1 个调用点（`RHAH_Begging.cs:227`、`RHAH_IrisMenusCompat.cs:2483`）。
- **为什么错**：同一个概念两个名字（`Usable` / `ToddlersActive`），且这对转发没有任何附加价值（不缓存、不加判据、不改语义），违反 `Source/AGENTS.md` 的"一个文件一个主概念"与根 `AGENTS.md` 的"DRY 包括命名"。另外 `Usable` 本身不说明主体（"什么可用"），而仓内同类第三方存在探针既有名式是 `RHAH_SkylandCompat.Active`（`Source/Pawn/Compat/RHAH_SkylandCompat.cs:14`）。
- **建议**：删掉两个 `ToddlersActive()`，全仓统一 `RHAH_ToddlerPresence.Active`（沿用 `Active` 名式）。

### C4 设置界面按错的概念选文案 + 三语文案与代码矛盾【必修】

- **现状**：
  - `Source/Pawn/Compat/RHAH_IrisMenusCompat.cs:2483`：`ToddlersActive() ? "RHAH_Settings_ImmobileBabies_Toddlers" : "RHAH_Settings_ImmobileBabies_Tooltip"`，即按"Toddlers 本体可用"选择"此开关对幼年鼠族最低年龄的限制已解除"。

- **为什么错**：生成侧的真实闸门是 `BabiesCarriable`（还要求 `RimTalk_PickUpToddler`，`RHAH_ToddlerPresence.cs:20`），界面用的却是 `Usable` ⇒ "装了 Toddlers、没装抱婴扩展"的玩家被告知限制已解除，关掉开关后照样被抬龄。同时 `:13` 承诺 ≥4 岁，代码给 3.x 岁（见 B2）。这两条都是玩家可见的错误承诺，且是三语文案，属于"名字/文案与判据漂移"最贵的一种。
