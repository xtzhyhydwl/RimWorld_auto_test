## 2 票 A：投喂重构（定案）

1. **计量单位 = 营养值**（不是"份"）。每件食物的营养实时取 `thing.GetStatValue(StatDefOf.Nutrition)`（按该 def 的实际值，**不写死 0.9**；`RHAH_FoodTransaction.cs:48` 已有同款用法）。
2. **一次给足**：菜单里每种食物**一个**选项，显示「给 N 件（约 X 营养 / 还差 Y）」，N = `ceil((目标 - 已交付) / 单件营养)`，允许溢出（0.9 的餐给 3 件补 2.0 的缺口 = 2.7，接受）。
3. **可重复给**：没到目标就能一直点，菜单实时显示剩余；不做"只给一次"。
4. **数值默认**：成年**鼠族 2.4 营养**、儿童**同成人 2.4**、婴儿 **0.48**（= 成人 × 0.2）。成人一个滑块（建议 0.8–4.0），儿童与婴儿由倍数算出，不做独立滑块。
5. **件数上限语义改写**：`maxFoodRequest` 从「份」改成「营养」，默认 `每人目标 × 人数`（即 2.4 × 人数）。理由：1.6 营养的干肉饼要 32 件，旧上限 12 会截断"一次给足"。
6. **食物范围 = 仓储区 + 点击者背包**，**不含地上散落**（用户明确：远处/危险处的散落食物不该出现在选项里）。仓储判据 = `IsInValidStorage()` 且存储归属玩家派系。背包另列（那就是"这个小人手上的"）。
7. **去掉单一食物类型锁**：`NoteFood` 从"钉死一种"改成按 def 记账；`RequestedFood` 不再参与菜单过滤。**按 def 记账而非营养累计**已被**营养计量**整体取代——`已交付` 直接存一个营养总量 + 一个 per-def 件数明细（明细只为存档迁移与显示）。
8. **老档迁移必做**（作者规范 `docs/adr/0003-engineering-standards.md:20/30/41`：正式发布后必须兼容读取或显式迁移）：`LoadingVars` 里读旧 `foodDef` + `foodCount` → `已交付营养 = 件数 × 该 def 营养`（def 取不到按 0.9/件折）；新键优先。
9. **等待与行走解耦**：点投喂**不再立刻切 toil**；来客照旧走 `TravelOrWait → WaitSpot`，到位后再进 `WaitFood`。等待点优先级沿用 `JobGiver_RHAH_WaitFood.WaitSpot`（赈灾区最近可达格 → 退 `Lord.WaitSpot`）。`RHAH_FoodHandoff.Start` 的成功判据随之改成「`BeginFoodWait` 成功」，不再要求"memo 之后 toil 已是 WaitFood"（否则玩家会看到"现在不能接受投喂"）。
10. **`preferability >= MealAwful` 从过滤降级为排序**（否则婴儿食物与生食材永远进不来）。
11. **接受者可食性进硬判据**：`receiver.RaceProps.CanEverEat(def)`，与 `RHAH_ReliefFood.Reject`、`JobGiver_RHAH_Family` 的既有做法对齐。
12. 菜单排序：仓储内 & 玩家派系 → 食物偏好 → 距离 → `defName`（保持确定性）。

## 3 票 B：保育（定案）

**B1 原语**：用原版 `JobDef BottleFeedBaby`（`JobDriver_BottleFeedBaby`）。**必须自己发 job**——原版 giver 全在殖民者/囚犯分支，来客永远等不到。构造入口 `ChildcareUtility.MakeBottlefeedJob(baby, food)`，`targetA = 婴儿`、`targetB = 食物`。
- 硬前提（已核实）：driver **零派系判断**；`CanSuckle` 要求婴儿 `DevelopmentalStage.Baby()`；食物必须**最终进喂食者背包**；食物筛选走**婴儿的** `WillEat`。
- 鼠族婴儿满足：`NewRatkinPlus` 的 `Ratkin` ThingDef `ParentName="Human"` ⇒ 继承原版 `HumanlikeBaby`（`<developmentalStage>Baby</developmentalStage>`）。

**B2 谁能保育**：**所有来客，含儿童**（不设 Manipulation 门槛、不设亲属门槛、不做"婴儿保育婴儿"的限制——那是玩家装 mod 的自由）。出生队列里没有真实亲属关系，所以不按亲子关系选人。

**B3 优先级**：保育在访客工作队列里**排最前**，但**让位给战斗与离场**（落点 = 现在 `JobGiver_RHAH_MotherFeed` 的位置，`JobGiver_RHAH_Visitor.cs:92`）。
（用户纠正：吃饭是需求层本能，不在工作队列里，所以"保育最高"不会把人饿死。）

**B4 触发条件**：存在**本批**的、正在饿的婴儿 + 保育者**身上有婴儿食物**。不主动去找婴儿食物以外的来源去"备货"。

**B5 保育者禁止误食婴儿食物**：在"自己吃"的候选里排除婴儿专属食物（动态判据：`ingestible.babiesCanIngest == true`）。
**唯一例外**：`Malnutrition.Severity >= 0.7`（原版档位 trivial 0 / minor 0.2 / moderate 0.4 / severe 0.6 / extreme 0.8 / lethal 1.0；`Hediffs_Global_Needs.xml`）。**不能用饥饿值百分比做判据**——来客刷出来就是饥饿 0 + 营养不良，那样等于人人放行。

**B6 婴儿食物从哪来**：
- 玩家投喂婴儿 → 食物**交给离点击殖民者最近的可行动来客**（儿童也可）；**这批没有可行动成员时，直接塞给婴儿本人**（他能吃就吃，不能吃也到此为止，不做别的分支）。
- 保育者也可以**去赈灾区**取婴儿食物（复用 `Area_RHAH_Relief` + 现成的搜索逻辑）。
- **不改赈灾区本身的语义、设置与判定**（用户：赈灾区是好设计，别改坏）。

**B7 记账口径**：**交付即记账**（塞给保育者就算），不做"实际喂进嘴才算"。用户明确：先做简单版，出问题再干预。

**B8 婴儿的"够不够"**：目标营养 **0.48**（成人 2.4 × 0.2）。交付的是散件（`BabyFood` 0.05/件 ⇒ 约 10 件 ≈ 两天），婴儿槽上限 0.125 由他自己按件吃，**不存在一次性灌爆**（用户纠正过我那版"溢出"论）。

**B9 食物筛选必须动态**：按 `ingestible.babiesCanIngest` + 婴儿的 `CanEverEat`/`WillEat` 筛，**不写死原版三件**（原版带该字段的只有 `BabyFood` / `Milk` / `InsectJelly`）。这样"用肉做婴儿食物"之类的 mod 自动兼容。

## 4 票 C：无合法 Toddlers 时不刷婴儿（定案）

1. **判据**：`ModsConfig.IsActive("cyanobot.toddlers")` **且** `LearningToWalk` / `LearningManipulation` 两个 `HediffDef` 实际存在（防"启用了但没加载成功"）。
2. **拦法**：抽到含婴儿的事件时**把年龄上调到儿童档**（婴儿 0–3 岁区间 + 随机偏移，落到儿童），**不整条删事件**（那等于砍内容）、**也不少生成一个人**。
3. 技术面：年龄是生成请求的输入，`RHAH_GenerationOptimizer.StageFor(age)` 已分好 Baby/Child/Adult ⇒ 改参数，不改结构；事件正文本来就按年龄分支，需同步。
4. **单独一票**（生成面 vs 交互面零重叠）。
