## 7 【未验证】/【缺原子】

### 7.1 【缺原子】精确的「殖民地食物总量」探针

- **想要**：`殖民地库存食物`（营养物质总量或逐堆叠单位数）在 `Leaving` 窗口前后各一次可比较读数。
- **现在做不到的原因**：`foodprobe/food_summary` 把**地图上所有**食物算进去（含 `Plant_Grass`/`Plant_TreeOak` 等野生植物），植物会自然生长 ⇒ 对「少吃一口」不敏感（实测 13785.7 → 13864.1，**升**）；`foodprobe/read_state` 依赖 `FoodControl` mod，本 profile 未加载（`success:false：FoodControl 未加载`）。
- **我试过**：`foodprobe/food_summary`（有数、但含植物）、`foodprobe/read_state`（成功=false，缺 FoodControl）。`foodprobe/forbidden_stats`、`foodprobe/storage_groups` 等其余 48 个 `foodprobe/*` **未逐个试**（它们面向建造/存储规则，`tools foodprobe` 描述里没有「营养合计」这一项）。
- **字段有没有据**：`food_summary` 的 `totalNutrition`/`foodStacks`/`topFoods` 有实测载荷；「仅库存/仅殖民地派系」这个**过滤维度在载荷里不存在**。
- **需要补**：一个只读探针（或 `food_summary` 的一个 `scope: stockpile|colony` 参数），返回「仅库存区/仅玩家派系」的逐 def 单位数与营养合计。
- **替代方案（本轮采用）**：**存档 XML 逐 def 统计**（`MealSurvivalPack/MealSimple/MealFine/Pemmican` 的叠数与单位数）——能覆盖已知 def 名单，但**不保证覆盖全部食物 def**（本轮先用 `food_summary.topFoods` 定位了实际存在的食物 def，再逐个统计）。
- **阻塞等级**：只卡这一条判据的精度，不卡整条需求（主判据 `curJob` 已测）。
- **可信度**：存档 XML 统计属**强判据**（同一名单前后逐单位比对）；`food_summary` 属**弱判据**（成立不等于「没吃」）。
- **补上之后能登记成**：`殖民地库存食物不变` = `foodprobe/food_summary(scope:stockpile)` + `{"path":"result.totalUnits","equals":<N>}`（现在只能登记成「存档 XML 文本前后一致」，属补数据而非补算子）。

### 7.2 【缺原子】受测体饥饿度

- **想要**：`该 pawn 的 Food need 当前值`（用于确认「他真的饿到会去触发原版求食」）。
- **做不到**：`rimworld/get_map_target_info` 不带 needs；`ce/*` 面向殖民者；存档 XML 里 `Need_Food` **没写 `<curLevel>`**（等于默认值被 Scribe 省略）⇒ 读不出数值。
- **需要补**：一个只读探针 `rimworld/get_pawn_needs{pawnId}`（或 `get_map_target_info` 增加 `needs` 字段）。
- **替代方案**：本轮用「他是 `RHAH_FamineRefugees` 事件刷出的 `Refugee`，且存档里有 `RHAH_HungerMark`」作为**间接**背景，不当作饥饿度证据。
- **阻塞等级**：只卡「S1 失效路径是否被真正触发」这一层；不卡「有没有拿食物」本身。

### 7.3 明确未验证的项

1. **离场瞬间的视觉证据（截图）没拿到**：`take_screenshot` 与 `screenshot_cell_rect` 在离场阶段连续 **3 次** `success:false：Timed out waiting for RimWorld to finish writing the screenshot file.`（`97-shot95.json`、`99-shot96.json`、`99-shot-rect.json`；另有一次是我漏写 `--args-file` 导致的 ENOENT，记在 `95-screenshot.json`）。唯一截图是 `Refuse` 之前那张（`play_for{600,Fast}` 后）。**位置结论不依赖截图**。
2. **暂停态 `step_game_ticks` 期间的画面不具证据力**：逻辑走、引擎不出帧（人类 2026-10-25 现场确认；本轮也只把 `play_for` 之后的画面当证据）。
3. **S2 的「凿墙」那半未构造**：本轮旧档轮是**走门**离图；没有造「无门」或「门被锁」的存档去验证 `canDig=true` 真能凿墙出去。
4. **S1 的触发条件未强制**：未确认受测体处于 `UrgentlyHungry`，因此「冷却窗口 → 原版 `JobGiver_GetFood` 回退」这条路径没有被正面跑出来（只证明「157 次采样里没有取食/进食 job」）。
5. **job 观测是采样而非全量**：60/30 tick 采样可能漏掉 <30 tick 的 job；「没有 `Mine`/`Ingest`」的强支撑来自「门/墙 HP 全程不变」与「食物物品数不变」，不是全量 job 日志。
6. **`TendPatient` 语义没深究**：`Refuse` 后前 ~1080 tick 他挂 `TendPatient`（存档显示 `targetA` 是他自己），与历史报告一致，属自愈/自我包扎一类的原版行为，本轮不追。
7. **只测 1 个事件、1 名受测体**：多来客同时抢一扇门、幼童/被抱持者、`HostileThreat` 分支、其它派系**全部未测**。
8. **只覆盖 1.7**：1.6 构建/运行未验证。
9. **`step_game_ticks` 有 3 次 `success:false`（unpaused）**：已在 §5.5 披露，tick 按 `advancedTicks` 计。
