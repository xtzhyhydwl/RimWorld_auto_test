## 结论（3 行）

1. **基线复现成功（红）**：来客 `Peanut` 在 tick 5000 因「短期收留到期」进入 `lifecycle=Leaving` + `duty=RHAH_VisitorLeave`，

2. **造场景法：真实事件 + 存档加速**。开发者动作 `Actions\Do incident\RHAH_FamineRefugees` 造真来客 →
   信件选项 `Take in short-term (leave after 5 days)` 走真「短期收留」→ `spawn_thing` 砌 7×7 房（含一扇 `Door`）→
   **只改测试存档的到期 tick**（`leaveAfterGameTick` 303778→1000）再读档，让 mod 自己走「收留到期」分支（不是自己写 Leaving 状态）。

## 六、过程中的坑（影响手法，不影响结论）

1. **已有实例进了图时，`start_debug_game_ready` 会白等满 300 s**：返回
   `success:false`、`blockingReason: "A game is already loaded"`、`targetReadiness: entryScene`（证据 `03-debug-game.json`，这次调用在遗留实例上跑的）。
   正确顺序：先 `stop` 再 `start`，然后新开局。
2. **读档后暂停会被自动解除**：`load_game_ready{pauseIfNeeded:true}` 之后 `wait_for_long_event_idle` 回读 `paused=false`，
   有几秒真实流逝（3778 → 4245 = 467 tick）。要严格控场，读档后**立刻补一次 `pause_game`**。
3. **`get_map_target_info` 用 `pawnId` 只解析得到玩家派系的 pawn**：pawn 一旦回到来客派系，
   `Could not find current-map pawn id 'Thing_Ratkin38483'`；换 `pawnName:"Peanut"` 就能读到（位置/job/派系/spawned 全有）。
4. **`get_selection_semantics` 点门后抛异常**：`ArgumentNullException: source`（`GetInspectTabTypes`），拿不到门的 inspectString（证据 `57-door-semantics.json`）。
5. **`run_lua` 读不到 `PawnCanOpen`**：其语言参考的 `unsupported` 列表明确含 `direct CLR access`（证据 `55-lua-reference.json` 原文：
   `"unsupported":["break","require","metatables","coroutines","module loading","direct CLR access",…]`），
   所以「用 run_lua 直接读门的开合判定」这条路走不通，只能走行为旁证。
6. **收留到期是 2 游戏小时一次的检查**（见上），所以「把到期 tick 改到过去」之后仍要 step 过下一个 5000 倍数才会翻转。
7. 本轮为了少写重复的 CLI 参数，在 `runs\20261024-RHAH-0008-trapped-baseline\` 下写了 5 个一次性脚本
   （`toolcall.mjs` / `build-room.mjs` / `observe.mjs` / `summarize.cjs` / `shorten-shelter.cjs` + 3 个只读探针 `.cjs`）。
   它们**只留在 runs 证据目录**，没有进 `scripts\`，没有污染仓库能力库。
