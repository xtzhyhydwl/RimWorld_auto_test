## 一、改动清单（为什么这么改）

行号为改后文件的实际行号。

### 1. 新增 `Source/Pawn/JobGiver_RHAH_Departure.cs:1-32`

| 行 | 内容 | 为什么 |
|-|-|-|
| `:8-14` | `public sealed class JobGiver_RHAH_Departure : JobGiver_ExitMapBest`；构造里 `defaultLocomotion = LocomotionUrgency.Jog` | 原版 `JobGiver_ExitMap.TryGiveJob` 是**所有**出图 Job 的唯一装配点，砸门/砸墙分支就在它里面（调研报告 §1.2）。继承 `JobGiver_ExitMapBest` 即「切到原版那条路」，不另写一套；`Jog` 对齐原版 `LordToil_ExitMap(Jog, canDig:true)` 的步态 |
| `:16-19` | `if (!RHAH_BatchAttitude.CanOrderLeave(pawn)) return null;` | `RHAH_VisitorLeave` 这个 duty 会被 `LordToil_*UpdateAllDuties` 发给**全部** `ownedPawns`；没有这道闸门时，一旦前一个子节点返回 null，原版 giver 会把**殖民者**也送去出图。同时顺带覆盖「囚犯/奴隶/收留期内」三类不该走的人 |
| `:21-24` | `if (!RHAH_Api.Allows(pawn, RHAH_BehaviorGate.ExitMap)) return null;` | 「该走」的权威判据是 `State.lifecycle == RHAH_Lifecycle.Leaving`（`Source/Identity/RHAH_PawnDefaults.cs:62-63` 只读这一个字段）；`ReadyToLeave` 未成立的来客不会到这里，因此**不误伤「还不想走」的人** |
| `:30` | `return base.TryGiveJob(pawn);` | 基类内部已经处理「倒地且不能爬 → null」「`canDig = duty.canDig && !pawn.CanReachMapEdge()`」「走不通才换 `PassAllDestroyableThings` 并拆第一个挡路建筑」，RHAH 不重复实现 |

### 2. `Source/Pawn/RHAH_VisitorRules.cs:5` 与 `:898-904`

- `:5` 加 `using HungerAndHavoc.Core;`（`RHAH_DefOf` 在 Core）。
- `:898-904` 新增 `internal static PawnDuty DepartureDuty()`：`new PawnDuty(RHAH_DefOf.RHAH_VisitorLeave)` 后 `duty.canDig = true`。
  **为什么集中一处**：票内 grep 复核实为 **7 处**构造点（报告只列了 4 处），漏掉任何一处就留下一条 `canDig = false` 的离场 duty，那条路径上的人仍然走不掉；工厂让「离场 duty 带 canDig」只有一处定义。

### 4. Def（双写）：`1.6/Defs/DutyDefs/RHAH_Duties.xml:20`、`1.7/Defs/DutyDefs/RHAH_Duties.xml:20`
