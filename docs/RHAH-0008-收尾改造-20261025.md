**为什么敌情排在离场放行之前**（这也是 `:35` 那行注释的内容）：离场分支是「返回、保留原版 true」，只要它先于敌情判定执行就会直接绕过禁止，于是围城时离场的客人会给敌人开门——正是审计 A1 认定的最重问题。任务书给的语义是「先判该不该管，再判离场放行，再判敌情禁止」，但「离场放行不得绕过敌情禁止」是硬保证；两条同时满足的唯一顺序就是**敌情先于离场放行**。等价地也可以写成「离场 && !敌情 → 放行」，这里选了提前 return 的写法以便每条分支只判一次。

- 原 `settings == null` 分支随设置一起删除：设置没了就没有「未初始化」这一说。
- 模块注释 `:10` 由「默认不让饥民开门 地图上有敌人时即使允许也不开」改为「来客只在离场时开门 地图上有敌人时离场也不开」——原文指向已删除的开关，不改就是错的注释（这是唯一一处改动既有原生注释的地方，理由记录在此）。
