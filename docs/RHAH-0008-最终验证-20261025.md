## 5 场景 C：有敌情时离场不开门 —— **【未做】**

判定**不做**，理由（按「低成本才做」的门槛）：

1. 要构造 `HostileThreat` 需要「门旁有一个敌对派系 pawn」，而现有原子**没有**能指定派系的 spawn：`rimworld/spawn_thing{defName,x,z}` 只给 ThingDef，无法指定 `Faction`/敌对状态；`rimworld/execute_debug_action` 里能刷袭击，但那会把整局变成战斗状态、且来访者会先跑/被抓，测不到「离场选路」这一层。
2. 也**没有只读探针**能读到「离场者此刻的 `HostileThreat` 判定 / `RHAH_BehaviorGate.ExitMap` 的值」——要断言「因为敌情所以不走门」，得先能读到这个判定。
3. 因此这一条属【未验证】，且**不是「不够便宜」而是「缺原子」**（见 §7.4）。

**本轮没有做任何与敌情相关的改动或推测**；「门/墙零损伤」这一条在 A 里成立，但「有敌情时改走凿墙」这条分支**没有被正面跑出来**。

## 7 【缺原子】

### 7.1 【缺原子】访客的「年龄 / 是否孕妇 / 能不能自己走」结构化探针

- **想要**：一条只读字段能给出 `ageBiologicalTicks`、`hasHediff(Pregnant)`、`canWalk`（受测体入选条件就是这三项）。
- **现在做不到的原因**：`rimworld/get_map_target_info` 的载荷里只有 `downed`/`dead`/`spawned`/`job`/`faction*`/`position`，**没有年龄、没有 hediff、没有「能否行走」**；`ce/*` 面向殖民者。
- **我试过**：`get_map_target_info{thingId}`（字段清单见 `32-subject-probe.json`、`120-pos-b2.json`）；最后靠**存档 XML**（`ageBiologicalTicks`、`Pregnant` 计数）+ **检视面板截图**（`Female, age 26`）补上。
- **字段有没有据**：`downed/dead/spawned/job` 有实测载荷；`age*`/`Pregnant`/`canWalk` **载荷里不存在**。
- **需要补**：`get_map_target_info` 增 `ageBiologicalTicks`、`hediffs[]`（或 `pregnant` 布尔）、`canWalk`。
- **不补也能测的替代**：存档 XML（强但贵，一次 7 MB 全档 grep）。
- **阻塞等级**：只卡「受测体入选条件」的取证成本，不卡整条需求。
- **可信度**：存档 XML = **强判据**；检视面板截图 = 弱（人能读，脚本不能断言）。
- **补上之后能登记成**：`受测体合格` = `bridge:rimworld/get_map_target_info` + `{all:[{path:"result.target.downed",equals:false},{path:"result.target.canWalk",equals:true},{path:"result.target.ageBiologicalTicks",greaterThan:64800000}]}`

### 7.2 【缺原子】访客的「全量 job 日志」

- **想要**：受测体从 `Leaving` 到离图的**每一次 job 切换**（用来把「没有 `Mine`/`AttackMelee` 打门打墙」从采样升级为全量）。
- **现在做不到的原因**：`rimworld/set_colonist_job_logging` 只对**殖民者**生效；受测体是访客（`RHAH_Faction_LeaningFriendly`）。
- **我试过**：只用 `get_map_target_info.job` 做 60/300/600 tick 采样（A 14 次、B 19 次）。
- **字段有没有据**：`job` 有实测载荷；「job 历史」这个维度没有。
- **需要补**：`set_pawn_job_logging{thingId}`（任意 pawn，不只殖民者），或 `get_pawn_job_history{thingId, fromTick, toTick}`。
- **不补也能测的替代（本轮采用）**：加密采样 + 「门/墙 HP 不变」这条**结构性判据**（要打就一定会掉 HP）。
- **阻塞等级**：只卡 A③ 的精度；不影响结论方向。
- **可信度**：采样 = **弱判据**（<60 tick 的 job 可能漏）；HP 不变 = 强判据。
- **补上之后能登记成**：`无挖墙job` = `bridge:rimworld/get_pawn_job_history` + `{not: {anyItem: {in: ["Mine","AttackMelee"]}}}`（配合 `countEquals` 断言非空）。

### 7.3 【缺原子】`<lifecycle>` / `duty.canDig` 的只读探针

- **想要**：不读 7 MB 存档就能读到「该 pawn 的 `lifecycle` 与 `mindState.duty.canDig`」。
- **现在做不到的原因**：桥接没有任何探针暴露这两个值（`get_map_target_info` 没有；`ce/*` 面向殖民者）。
- **我试过**：只能 `save_game` + `Select-String` 读 XML（本轮 A/B 各做一次，`E1`/`E2`）。
- **字段有没有据**：存档里 `<canDig>True</canDig>`、`<lifecycle>Leaving</lifecycle>` 都是**实测载荷**（有据），缺的是**在线探针**。
- **需要补**：`get_pawn_mod_state{thingId}`（返回 lifecycle + duty def + duty.canDig）。
- **阻塞等级**：只卡「存档/回读」这条链的成本（每次要落盘 7 MB）。
- **可信度**：存档 XML = **强判据**。

### 7.4 【缺原子】敌情（`HostileThreat`）的构造与读取（卡住场景 C）

- **想要**：① 在指定格子放一个**敌对派系**pawn；② 只读读到受测体此刻的威胁判定（`HostileThreat` / `BehaviorGate.ExitMap`）。
- **现在做不到的原因**：`spawn_thing` 只能给 ThingDef、不能设 faction/敌对；`execute_debug_action` 刷袭击不可控且会把整局拖进战斗；没有任何探针读闸门值。
- **我试过**：`describe spawn_thing`（只有 `defName/x/z/stackCount`）、`tools` 全表搜 `hostile|threat|gate`（无结果）。
- **字段有没有据**：`get_map_target_info` 只有 `factionHostileToPlayer`（那是**派系关系**，不是「附近有敌」的判定）⇒ 语义不等价。
- **需要补**：`spawn_pawn{kindDef, factionDef, x, z}` + `get_pawn_mod_state` 里带 `hostileThreat`。
- **阻塞等级**：**卡住整条场景 C**（不是「不够便宜」）。
- **可信度**：若补上，`{path:"result.target.hostileThreat",equals:true}` + 「门 HP 不变 & 墙 HP 下降」= 强判据组合。
- **补上之后能登记成**：`敌情下凿墙` = `bridge:rimworld/get_pawn_mod_state` + `{all:[{path:"result.hostileThreat",equals:true},{path:"result.duty.canDig",equals:true}]}`。
