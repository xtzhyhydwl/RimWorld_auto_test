## 结论（5 行）

1. **断言①（门 HP 下降 或 出现打门行为）：臂 A 红 / 臂 B 绿。** 臂 A 门 HP 全程 `104`（11 段、6600 tick），`curJob` 只在 `RHAH_Gnaw / Wait_Wander / GotoWander / Wait_MaintainPosture` 之间；臂 B 门 HP `104 → 64 → 24 → 被打烂`，`curJob = Mine` 连续出现（原版 `DigUtility.PassBlockerJob` 的凿 Job）。
2. **断言②（≤2.5 游戏小时内 `spawned=false`）：臂 A 红 / 臂 B 绿。** 臂 A 到 tick 7504 仍 `spawned=true`；臂 B 在 **tick 2031** 已 `spawned=false`（该 pawn 从地图上消失），距「Leaving 起点 tick 904」约 **1127 tick ≈ 0.45 游戏小时**。
3. **断言③（0 Exception，无 `Exception in … TryIssueJobPackage`）：两臂都绿。** 臂 A `Player.log` 全文 `Exception` 命中 **0**；臂 B 同样 **0**，`TryIssueJobPackage` 命中 **0**。
4. **门 HP：臂 A `104→104`（恒定）；臂 B `104→64→24→打烂`（门格变成 `Filth_RubbleBuilding`）。**
5. **pawn 是否离图：臂 A 否（始终在封闭房间内游荡）；臂 B 是（tick 2031 离图）。工坊文件已还原，3 个文件 SHA256 与备份逐一 `MATCH`。**

⇒ **一句话：同一场景下，作者原始 1.7 DLL 里来客被困且永远凿不开；换上我们的修复构建后，他凿门、出门、离图。修复在游戏内生效。**

## 二、场景（两臂步骤完全相同）

### 2.1 步骤

1. `node src/cli.js start --profile rhah --width 1600 --height 900` → 桥接就绪（事件/桥接就绪信号，非固定延时）。
2. `start_debug_game_ready{readiness: currentMap}` → `wait_for_game_loaded{currentMap}`。
3. **关 Storyteller**（`execute_debug_action "Settings\Enable Storyteller"` → 回读 `on:false`），减少随机事件干扰。
4. **真实事件刷来客**：`execute_debug_action "Actions\Do incident\RHAH_FamineRefugees"`。**不选「收留」**，只让来客自然进图。
5. 让来客**自己走到殖民地附近**（`step_game_ticks` 600–900，从地图边缘走到离四边 ≥4 格处）。
6. 暂停 → 用 `spawn_thing` 在他周围砌 **7×7 封闭房间**（23 面 `Wall` + 1 扇 `Door`，门是唯一出口），回读 49 格确认。
7. 打开那封信件 → 点 **`Refuse (may leave or turn hostile)`**（玩家的自然选择，让来客进入「该离场」）。**不碰 lifecycle / duty / stayKind。**
8. `save_game` 后读存档 XML，确认 `lifecycle=Leaving` 且 `mindstate.duty=RHAH_VisitorLeave`。
9. `step_game_ticks{600, pauseFirst:true}` 分段推进并逐段回读（臂 B 另加 100 tick 细采样），直到 `spawned=false` 或满 2.5 游戏小时。

### 2.2 与建议方案的偏离（如实记录）

- **没有用「麻醉 + 搬运」把 pawn 弄进房间**，改为**让来客自然走进殖民地附近后，就地砌墙把他围住**。
  理由：搬运必须动 pawn（存档改坐标 / 或救援指令），而「就地围住」在**完全不碰 pawn 任何状态**（含 health、lifecycle、duty、lord）的前提下达到了同样的物理围困；麻醉本身还会压制离场计时（`FedLeaveDue` 要求 `!downed`），把观测窗口吃掉。代价：没有「麻醉醒来」这一段。
  证据表明这一步不是必需的：两臂的来客都是**自己走进房间位置**的（臂 A 从 `132,249` 走到 `142,234`；臂 B 从 `164,0` 走到 `153,16`），`Moving` 能力由「确实走了 20+ 格」直接旁证。
- 臂 A 的「Refuse」结果：派系仍是 `RHAH_Faction_LeaningFriendly`（**没变敌对**），`hostile=False`。
- 两臂**未做任何健康干预**（没治疗、没清 hediff、没上麻醉）。

## 七、未验证 / 边界（如实）

1. **`Moving` / `Consciousness` 的数值**没读到（无 capacity 读取工具，`run_lua` 不支持 CLR）。只用「实际行走 + `downed=false` + 无妊娠/无失能 hediff」旁证健康。
2. **年龄**只到「成年背景」这一档（`Deserter` / `Tanner`），没有 `ageBiologicalTicks` 的具体值。
3. **两臂不是同一个 pawn**（事件随机刷人，`Royalheart` vs `Kali-Ridel`）；两臂保证的是「同族、同性、同年龄档、同 `downed=false`、同 `lifecycle/duty` 路径」。健康基线唯一的差异是臂 B 受测体带 `Malnutrition`（饥荒来客本来就饿），臂 A 受测体的 hediffSet 里当时只有 RHAH 标记。
4. **没有用麻醉/搬运**（见 §2.2），因此「麻醉代谢后自己站起来」这一环没有观测。
5. **截图有瑕疵**：臂 A 的两张被游戏自带的 Debug log 窗口遮住中央（该窗口在启动时自动弹出）。画面里能看到地图和 `Royalheart` 的名字，但房间细节被挡。臂 B 的三张是干净的。桥接的「按格子裁剪」在窗口被最大化后坐标失配，裁剪图全是桌面内容，已弃用。
6. `famineVisitorsOpenDoors` 仍是默认 `false`（两臂都没改设置），所以臂 B 的出门**不是**「开门放行」，而是**砸门**（`Mine` job + 门 HP 掉到 0 + 门格变 rubble）——这一点正是候选 A 的语义。
7. 只测了 `RHAH_FamineRefugees` 一个事件、单个来客；多来客抢门、幼童、被抱孩子、其它态度派系**未测**。
8. `armA_state1.rws` / `armB_state1.rws` 等测试存档留在 `profiles\rhah\Saves\`，未清理；**玩家 190 个 1.6 存档未被读或写**。

## 附录 A：旧场景（「收留 → 5 天到期」）数据 —— **已废弃，不作为结论**

第一版照抄基线报告的做法：`RHAH_FamineRefugees` → 信件选「Take in short-term (leave after 5 days)」→ 砌房 → 改存档 `leaveAfterGameTick` 到过去 → 读档让 mod 自己到期。

- 事实：**这条路径会把 pawn 从 `Visiting` 推过 `Staying` 再回到 `Leaving`，改变了状态机**，不是玩家真实遇到的路径（人类指出）。因此**不能**用来证明修复。
- 已产生的数据（保留备查，`runs\20261024-RHAH-0008-verify\50-timeline.jsonl`、`57-timeline.jsonl`、`rhah0008v-*`）：一名短期收留的来客在 `Leaving` 后被砌进封闭房间，**自己把门推开走出去了**（收留期间他属 `PlayerColony`，门对殖民者可开），随后在房外拿到 `Goto` 并走向边缘。这条数据说明「路通时行为不变」，但**它不是红侧也不是绿侧**，只作历史记录。
- 旧场景还暴露了一个有意义的坑：**在 `PlayerColony` 阶段砌房是关不住人的**（殖民者能开门），必须等他已经是来客派系、或者把门堵死。新场景用「来客自己走到殖民地附近再砌墙 + Refuse」绕开了这个坑。
