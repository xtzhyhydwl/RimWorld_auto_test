## 问题

乞食围攻时，同行的儿童(如果有可能的话, 婴儿)不参战，也不会去吃地上的食物：成人冲进去打、打完去捡地上的东西吃，儿童却一直站在远处原地转圈，最后活活饿倒。同一个事件里两拨人表现完全不一样, 并不合理

顺带把同一处判据旁边一处名不副实的临时变量改成达意的名字（行为不变），并给"武器只发成人"补了一行注释说明这是刻意的——儿童徒手。

## 为什么拆成两个 PR 而不是一个（2026-10-25 定，22:0x 修正）

**结论：两个 commit、两个 PR，两个都直接以 `main` 为 base（不是 stacked）。**

依据【实测】：

- 0002 = 19 files / +458 −7（新增玩法：围攻来客越饿越凶），commit `d699404`。
- 0010 = 4 files / +32 −15（行为修复：去掉年龄判据），commit `fc9b1c7`。
- **两者没有代码耦合**：把 0010 `git rebase --onto origin/main d699404` 直接落到 `main`（`2799c57`）上 **零冲突**；rebase 后单独编 1.7 仍 **0 警告 0 错误**。若它依赖 0002 的代码，这一步必撞。

> **上一轮的判断错了一处**：原本打算把 0010 做成 stacked PR（base = `feat/0002-siege-fury`）。
> 但 **GitHub 不允许 base 指向只存在于 fork 的分支**（base 分支必须在作者仓库里），上游没有这条分支 ⇒ stacked 提不上去。
> 改成两个互相独立的 PR，base 都是 `main`。

拆开的理由（针对"提给第三方作者"这个场景）：

1. **可批准性不同**：0002 是新增玩法（收不收、怎么平衡需要讨论），0010 是纯 bug 修复（好过）。合成一个 PR，0002 被讨论或搁置会把 0010 一起卡住。
2. **审阅粒度**：一个 PR 里同时有"加 buff"和"删闸门"，作者很难判断风险与回滚范围。
3. **合并顺序自由**：两个 PR 都基于 `main` 且零交叉，谁先合都行。
