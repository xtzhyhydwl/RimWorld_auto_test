## C 必修：命名与语义

### C-1【必修】`AbleToFight` 与 `CanFight` 是同义词，"能不能打由谁决定"读不出来

- 位置：`Source/Pawn/JobGiver_RHAH_Visitor.cs:43`（`CanFight`）对 `:60`（`AbleToFight`）
- 现状（实测）：`CanFight` = 外层判据（含 Lord/在编食物名单/倒地/昏迷/态度/派系/闸门/Violent 工作标签），`:52` 内部又调 `AbleToFight`（身体条件）。两个名字只差 `Can` / `Able`，英文里都是"能"，代码里没有任何线索告诉读者哪个是"最终能不能打"。
- 同一件事现在有**三个带 fight 的名字**：`RHAH_BehaviorGate.Fight`（闸门，`RHAH_PawnDefaults.cs:34-36`）、`RHAH_Api.Allows(pawn, Fight)`（查闸门，`JobGiver:55`）、`CanFight`（合成判据）、`AbleToFight`（子条件）。前三个名字各自名副其实（闸门/查询/合成），只有第四个是纯同义重复。
- 为什么错：`AGENTS.md` 顶层"DRY —— 包括命名""同一个概念在代码里只有一个名字"；`RimworldMods/AGENTS.md` 的 Code as Documentation。名字还**隐去了真正的判据**（年龄 + 动手阶段），所以下一次 `RHAH_FamineWeapons` 想知道"这个人算不算能打"时无名字可复用，只能再写一遍 `Adult()`——见 D-1。
- 建议改法（一句）：按 B-1 把这条政策搬成 `RHAH_VisitorRules.AllowsCombat(...)`，`CanFight` 保持唯一"能不能打"入口名；若坚持留 Pawn 层，改名 `CombatCapable`（`Can*` = 判据，`Capable` = 身体条件，与 Compat 家族 `CanWalkOut` / `CanFeedSelf` 不撞）。
- 影响面：纯改名 2 行（含 `:52` 调用点），零行为变化。

### C-2【必修】`ManipulationStage > 0` 在 vanilla 恒真，只在装 Toddlers 时生效，而那时它把"能走还不能动手"的儿童继续挡在战斗外——与本票口径冲突，且零测试覆盖

- 位置：`Source/Pawn/JobGiver_RHAH_Visitor.cs:62-63`，对应注释 `:59`"不是婴儿且能动手就算能打"
- 现状（实测，读 `RHAH_ChildMovement.cs` 推出）：
  - `ManipulationStage` 返回 0 只有两种可能：`IsVanillaImmobileBaby(pawn)`（`:13-27`，第一行就要求 `DevelopmentalStage == Baby`）或身上有 `LearningManipulation` 且 `CurStageIndex == 0`（`:64-70`）；没有该 hediff 一律返回 2。
  - 原版来客身上不会有 `LearningManipulation` ⇒ **vanilla 下 `ManipulationStage > 0` 与 `!= Baby` 完全等价**，第二个条件是死条件。
  - 只有装 Toddlers（`cyanobot.toddlers`，本仓支持：`RHAH_ChildMovement.cs:31`、`JobGiver_RHAH_Feed.cs:37`）时它才有内容。
- 为什么错：
  1. 死条件 + 只在第三方模组下活的分支，没有任何注释说明为什么要有它，也没有测试覆盖（新用例只测 `Child` + 无 hediff，即 stage 2，见 `RHAH_AttackChoiceTests.cs:561-571`）。
  2. 它生效的方向正好与本票口径相反：Toddlers 下"能走、但动手阶段还是 0"的儿童会被判成不能打 ⇒ 继续落到 `LordToil_RHAH_ArmedAssault.cs:20-21` 的 `RHAH_VisitorSeek` ⇒ 还是原地闲逛、还是不吃（`JobGiver_RHAH_Visitor.cs:88` 在 ArmedAssault 期间直接 `return null`，取食分支到不了）——就是本票要修的那个症状。而用户口径是"围攻里成人和儿童表现必须一样；儿童参战与否无所谓"，这类儿童恰好不满足。
  3. 注释说的"能动手"也不准：stage 0 的另一半含义是"原版不能动的婴儿"（`RHAH_ChildMovement.cs:56-62` 先把 immobility 和 manipulation 揉进同一个序号），"动手"与"能动"不是同一个轴。
- 建议改法（一句）：判据只留 `pawn.DevelopmentalStage != DevelopmentalStage.Baby`（倒地/昏迷 `CanFight` 已判），删掉 `> 0`；若确实要"不能动手就不许打"，则改用与"能动"同源的 `RHAH_ChildMovement.CanWalkOut` 家族命名判据，并补一条 stage 0 的用例把意图钉住。
- 影响面：判据 1 行 + 1 条测试；行为变化**只在 Toddlers 场景**（推测，未在游戏内验证）。
