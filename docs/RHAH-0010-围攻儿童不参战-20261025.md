# 票 0010：围攻的儿童不参战、有食物也不吃（2026-10-25）

> 来源：用户在 1.7 上目视实测票 0002 的构建时发现（2026-10-25 晚）。
> **本票不在 0002 里修**（用户口径：0002 只收尾、不扩范围），单独做。本文只记录现象与排查线索，**未改代码、未开分支**。

## 0 一句话

乞食围攻的**成年**来客会正常进攻、打完去吃地上的食物；同行的**儿童**不参与进攻（敌对状态下在闲逛），而且放着地上的食物不吃，最后饿死。

## 1 现象【实测 · 用户目视】

- 发起进攻后只有成年来客有进攻动作，儿童在原地闲逛。
- 殖民者被打死、食物落在地上之后，成年来客去吃；儿童仍然闲逛，不吃，最终饿死。
- 婴儿不在此列：婴儿本来就没有战斗能力，这里说的是**儿童（Child）**。

## 2 期望

1. 围攻的儿童在进攻阶段与成人一样参战（徒手也算）。
2. 地上有食物时儿童会去吃——至少不该出现"有食物还饿死"。

## 7 风险（要先跟用户确认的点）

- `Fight` 闸门是**全局默认**（`RHAH_PawnDefaults`）：放宽它会让**所有**访客类型的儿童都开始打架（乞讨、偷窃、野生、劳动）。要么按事件类型细化（只对索粮围攻放开），要么给角色加显式标记——后者更符合"闸门而不是角色"的约定。
- 儿童参战会显著提高围攻里儿童被打死的概率，属于叙事与手感层面的决定，需要拍板"要不要让儿童真的会死"。

## 9 首轮静态结论（2026-10-25 20:3x，只读代码，未跑游戏）

> 用户当时的猜测是"儿童没被派 job giver，所以一直闲逛"。**代码层面基本对上**，但不是"没派"，而是"唯一的 job giver 主动拒了儿童"，而且**拒的理由不止闸门一个**。

### 9.1 只读链路【实测】

1. 访客的 think tree 只有**一个**节点：`1.7/Defs/ThinkTreeDefs/RHAH_ThinkTrees.xml` 的 `RHAH_VisitorFallback` —— 插在 `Humanlike_PostDuty`、priority 100，根是 `ThinkNode_ConditionalRHAH_Visitor`（条件 = `RHAH_BatchAttitude.CanOrderLeave(pawn)`），子节点只有 `JobGiver_RHAH_Visitor`。
   ⇒ 来客的**全部**行为都从这一个 giver 出；它返回 null，pawn 就掉回原版 post-duty 节点 ⇒ **正好是"原地闲逛"**。
2. `Source/Pawn/JobGiver_RHAH_Visitor.cs:43-57` 的 `CanFight` 是参战闸门，它一次要求 **5 个条件**：
   - `pawn.DevelopmentalStage.Adult()`（**第 52 行，硬性的成人过滤**）
   - `RHAH_Api.Get(pawn).Attitude == RHAH_Attitude.Hostile`
   - `pawn.Faction != null && pawn.Faction.HostileTo(Faction.OfPlayer)`
   - `RHAH_Api.Allows(pawn, RHAH_BehaviorGate.Fight)`
   - `!pawn.WorkTagIsDisabled(WorkTags.Violent)`
   ⇒ **儿童在第一条就出局**，后面四条根本没机会生效。所以这不是"闸门写错"，是**代码里明确只让成人打**。
3. `RHAH_BehaviorGate.Fight` 的默认规则（`Source/Identity/RHAH_PawnDefaults.cs:34-36`）= `role == Siege || attitude == Hostile`；儿童角色（`BeggarChild`/`ThiefChild`/`WildChild`/`RatkinYoung`）永远不是 `Siege` ⇒ 即便去掉成人过滤，还得靠 attitude 兜底。
4. 批量层面也排儿童：`Source/Pawn/RHAH_BatchAttitude.cs:107,135` 在"下令开打/离场"时按成员逐个查 `Allows(Fight)`。
5. 发武器同样排儿童：`Source/Generation/RHAH_FamineWeapons.cs:29,38` 要求 `Adult()`（这条是合理的）。

### 9.2 所以"很好改"要打折扣

- **参战那一半确实小**：把 `CanFight` 的 `Adult()` 放宽成"非婴儿 + 能动"（例如 `DevelopmentalStage != Baby` 且 `ManipulationStage > 0`），再决定 attitude / 闸门怎么放行儿童（给角色加"可战"标记比改全局默认更合约定）。
- **但不只是一行**：还有 4 道条件在儿童身上要继续判；而且这条 giver 是**所有访客共用**的，放宽会波及乞讨/偷窃/野生来客的儿童。
- **"不吃食物"那一半另说**：吃这条路是 `JobGiver_RHAH_Feed`（`Source/Pawn/JobGiver_RHAH_Feed.cs:19-96`），里面有 `RHAH_ReliefFood.MayEatOutside(pawn)` 决定能不能吃"救济区外"的食物；儿童还有专门的"趴地上吃"分支（`RHAH_ReliefFood.cs:173` → `RHAH_ChildMovement.EatsOnFloor`，即 manipulation stage 1）。**所以儿童吃饭是有实现的，不吃更像"救济区/态度规则挡住了"或"没走到这个 giver"**——这一半必须实测，静态推不出来。
