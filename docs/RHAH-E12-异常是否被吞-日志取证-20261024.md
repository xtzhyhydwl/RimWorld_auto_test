# RHAH E12「异常被静默吞掉 → 兜底全死」假设：日志 + 代码取证

> 对象：`Ratkin: Hunger and Havoc`（RHAH），事件 `I-014` 乞食围攻选「敌对」后信件永久挂屏。
> 待验假设：`FindMap(record.MapId)` 返回 null → `Owner` 未判空解引用 → 每轮轮询抛 NRE → 被吞 → `Refresh/Finish/删信` 永不执行。
> 本文只做取证与判定，**未修改任何文件**（模组源码、日志、存档均只读）。全部数据采集于 2026-10-24 16:28–16:45。

---

## 结论

1. **假设不成立。** 决定性证据有两条，且互相独立：①`Owner` 在 `Source/Pawn/RHAH_ArmedDemand.cs:69-70` 已经用 `record == null ? null : FindMap(...)` + `map?.lordManager?.lords` 判空，`FindMap` 返回 null 时**不会**解引用，只会得到一个空循环并 `return null`；②即使 map 真的消失，`Refresh`（`:86-92`）会拿到 `Owner == null` 并立刻 `Finish(record, Ignore)`（`:94-101`）**把信删掉**——即"地图没了"导致的后果与现象**方向相反**，它会让信收口，而不是把信焊死。
2. **替代解释（推测，未验证）**：信留着是因为 `record.Settled` 从未被写（已知事实），而唯一能补写它的每小时 `Refresh` 依赖 `Owner()` 返回 null；既然 `Owner` 不会崩，那就只剩"`Owner` 每小时仍返回非 null"或"每小时那一轮循环没跑到这条记录"两种可能，**下一步该看 `Owner` 的返回值本身，而不是异常**。
3. **最小修法**：`Source/Incidents/RHAH_ChoiceRuntime.cs:122-132` —— 让 `I-014` 这类 armed request 不再用 `continue` 跳过通用"无人在场 → `CloseUnavailable`"兜底（语义不变：没人在场，请求作废）；另加 `:117-143` 的 per-record `try/catch` + `Log.Error` 防止一条坏记录毒死整轮。

## 二、tick 链异常隔离分析（代码实测）

调用链与隔离情况：

| 层 | 位置 | try/catch | 说明 |
|---|---|---|---|
| `GameComponentTick` | `Source/Core/GameComponent_RHAH_Game.cs:59-77` | **无** | 顺序执行 `TickPlague()` → `RHAH_ChoiceRuntime.Tick(this, tick)` → `TrySpawnPending` → `TickStays` → 六个 `Storyteller` runtime Tick。**任一环节抛出，后面全部不执行。** |
| `TickPlague` | `:398-428` | 无 | 先于 ChoiceRuntime 执行 |
| `RHAH_ChoiceRuntime.Tick` | `Source/Incidents/RHAH_ChoiceRuntime.cs:108-146` | **无**（循环内外都没有） | 对每条记录依次调 `RHAH_AllyTransfer.Tick`（`:120`）→ `RHAH_ArmedDemand.Tick`（`:124`）→ 通用兜底（`:127-132`）→ 超时结算（`:133-142`） |

| 循环后的批量清信 | `RHAH_ChoiceRuntime.cs:144` `RemoveSettledArmedLetters(records)` | 无 | **在 for 循环之后**，循环一旦抛出，这一步整轮不执行 |

结论（实测）：

- **完全没有任何 per-record 隔离。** 一条坏记录（无论抛在 `AllyTransfer.Tick` 还是某条 armed record 的 `ArmedDemand.Tick`）会中断当轮 for 循环，导致：①同 tick 内后续记录不再处理；②`:144` 的 `RemoveSettledArmedLetters` 不执行；③`:65-77` 里 `ChoiceRuntime.Tick` 之后的所有 Tick 与 `:66-69` 的整点逻辑也不执行。
- 但**这不是静默**：异常会一路上抛（见 1.4）。假设里"被 RimWorld 或某层 try/catch 吞掉"这一环，在代码里**找不到吞它的地方**，日志里**也没出现**它。
- 补充实测：`RHAH_AllyTransfer.Tick`（`Source/Incidents/RHAH_AllyTransfer.cs:162-179`）首行就 `record == null || AllyGiftDueTick < 0` 早返回，`FindMap` 的返回值在 `:172`/`:176` 都有判空——它是安全的，不会每小时炸。
- `RHAH_ChoiceRuntime.Tick` 是**每个游戏 tick** 都跑（`GameComponent_RHAH_Game.cs:63` 无条件调用），所以如果循环体真会抛，那不是"一小时一条错误"，而是**每 tick 一条**，日志会被刷爆。实测两份日志都没有这种洪泛。

## 三、Owner / Refresh 判空分析（代码实测）

### 3.1 `Owner`（`Source/Pawn/RHAH_ArmedDemand.cs:67-84`）

```csharp
67: internal static Lord Owner(RHAH_ChoiceRecord record)
68: {
69:     Map map = record == null ? null : RHAH_ChoiceRuntime.FindMap(record.MapId);
70:     List<Lord> lords = map?.lordManager?.lords;
71:     for (int i = 0; lords != null && i < lords.Count; i++)
```

- `:69` 对 `record` 判空；`:70` 用 `?.` 对 `map` 判空；`:71` 再对 `lords` 判空。
- **`FindMap` 返回 null 时，任何一行都不会崩**：`lords` 得到 null，循环条件立刻为假，函数走到 `:83 return null`。
- `RHAH_ChoiceRuntime.FindMap`（`Source/Incidents/RHAH_ChoiceRuntime.cs:181-187`）自身也做了 `Find.Maps == null` 判空，找不到就 `return null`，从不抛。
- 假设里"`Owner` 未判空就解引用、在 `FindMap` 那一步崩"**在现有代码里不存在**。这是本次判定最硬的一条。

### 3.2 `Refresh`（`Source/Pawn/RHAH_ArmedDemand.cs:86-92`）

```csharp
88:     if (record == null || !record.Open) return false;
89:     if (Owner(record) != null) return true;
90:     Finish(record, RHAH_ChoiceAction.Ignore);
91:     return false;
```

- 没有"因为上一步崩了所以走不到 Finish"的可能——`Owner` 不会崩。
- 反过来：**map 消失 → `Owner` 返回 null → `:90 Finish` → `:96 record.Settled = Ignore` + `:97-100` 从 `LetterStack` 移除该 `choiceId` 的信。** 也就是说"地图指向不存在的地图"这个前提如果成立，信应该在一小时内自己消失，**与现象完全相反**。

### 3.3 `Tick`（`Source/Pawn/RHAH_ArmedDemand.cs:103-112`）全文

```csharp
103: internal static void Tick(RHAH_ChoiceRecord record, int tick)
104: {
105:     if (!record.Open) return;
106:     if (!Enabled) { Resolve(record, RHAH_ChoiceAction.Ignore); return; }
107:     if (tick % GenDate.TicksPerHour != 0 && tick != record.ExpireTick) return;
108:     if (!Refresh(record)) return;
109:     LordJob_RHAH_Visitor job = (LordJob_RHAH_Visitor)Owner(record).LordJob;
110:     if (!job.ArmedAssault && record.ExpireTick >= 0 && tick >= record.ExpireTick)
111:         Resolve(record, RHAH_ChoiceAction.Timeout);
112: }
```

- 单条记录内部**没有** try/catch（见第二节）。
- `:109` 是这条链上**唯一一处**对 `Owner()` 返回值直接解引用、且 `Owner()` 被**第二次求值**的地方：`:108` 的 `Refresh` 里调过一次，`:109` 又调一次。当前是单线程、同一 tick 内状态不变，所以 `Refresh` 返回 true 时 `:109` 必然非 null——**实际打不到**；但它确实是"未判空解引用"的唯一残余形态，改起来只要一行（见第六节修法 3）。
- 同样的二次求值还出现在 `PlanPayment`（`:184-185`，`Refresh(record)` 之后 `Owner(record).ownedPawns`），风险同理。

### 3.4 与假设方向对不上的另一处

`ChoiceLetter_RHAH_Request.Pending`（`Source/Incidents/ChoiceLetter_RHAH_Request.cs:140-144`）：

```csharp
141: return record != null && record.Open && (Pawn.RHAH_ArmedDemand.IsRequest(record) ||
142:     record.ExpireTick < 0 || Find.TickManager == null || Find.TickManager.TicksGame < record.ExpireTick);
```

`Pending` 只看 `record.Open`，**完全不看地图是否存在**。所以"右键禁掉 / 没有关闭按钮"这两条症状只说明 `record.Open == true`（`RHAH_ChoiceRecord.Open => Settled == RHAH_ChoiceAction.None`，`Source/Incidents/RHAH_RequestRules.cs:574`），与 map/异常无关。同时它证明记录**仍在** `game.OpenChoices` 里（`FindRecord` 取不到会返回 null → `Pending(null)` 为 false → 反而不该禁右键）。

## 五、最小修法（语义不变，让信能收口）

按"改一处就够"的顺序排：

**修法 1（收口，首选）—— `Source/Incidents/RHAH_ChoiceRuntime.cs:122-132`**
现在 armed request 在 `:124` 处理完就 `continue`（`:125`），**永远走不到 `:127-132` 的通用兜底**（`FindMap(record.MapId) == null || Present(record).Count == 0 → CloseUnavailable`）。把 `:125` 的 `continue` 去掉（或把 `:127-132` 的判定提到 `IsRequest` 分支之前），让"围攻者一个都不在场（含地图已失效）"这件事对 armed request 同样生效。语义不变：没人在场 ⇒ 请求作废、信关闭——这正是玩家杀光围攻者后期望的结果，且不依赖 `Owner()`、也不依赖 `Refresh()` 是否被调用。

**修法 2（隔离，防"一条坏记录毒死整轮"）—— `Source/Incidents/RHAH_ChoiceRuntime.cs:117-143`**
把 for 循环体包进 `try { ... } catch (Exception exception) { Log.Error("[RHAH] Choice tick failed id=" + record.Id + "\n" + exception); }`，保证 `:144` 的 `RemoveSettledArmedLetters` 与同轮其它记录照常处理。这是本假设担心的问题的真实版本（隔离缺失确实存在），且顺手把"静默"变成"可见"。

**修法 3（消除唯一一处未判空解引用）—— `Source/Pawn/RHAH_ArmedDemand.cs:108-109`**
把 `if (!Refresh(record)) return;` 改为复用同一个结果，例如 `Lord lord = Owner(record); if (lord == null) { Finish(record, RHAH_ChoiceAction.Ignore); return; } LordJob_RHAH_Visitor job = (LordJob_RHAH_Visitor)lord.LordJob;`。语义不变，但把 `Owner()` 的二次求值去掉（`Refresh` 已含 Finish 逻辑，可写成 `if (!Refresh(record)) return; Lord lord = Owner(record); if (lord == null) return;` 更小改动）。

> 三条都不改 `ArmedAssault` 语义、不改"交付仍可平息"的设计意图（`Resolve` 的 Deliver 分支 `:153-162` 不动）。
