# RHAH E12「乞食围攻」收尾机制与「敌对后关不掉」死锁追踪

- 审查对象：`RimworldMods\ratkin_hunger_and_havoc`（源码 `Source\`，1.6/1.7 共用，宏见 `#if RIMWORLD_1_7`）
- 方式：**只读静态阅读**（未编译、未运行游戏、未改任何文件）。除注明「推测」外，所有结论都有代码行号支撑。
- 事件范围：`I-014`（乞食围攻 / `RHAH_BeggarSiege`）、`I-030`（强势围攻 / `RHAH_StrongSiege`）、`I-045`（鼠疫强势围攻 / `RHAH_PlagueStrongSiege`），同属 `Source\Incidents\RHAH_IncidentGroups.cs:21` 定义的事件类。
- 三个变体的入口不同、收尾完全相同：`I-014` 走 `IncidentWorker_BeggarSiege`（`Source\Incidents\IncidentWorker_RHAH_Group.cs:176-181`，Def 见 `1.6\Defs\IncidentDefs\RHAH_M1.xml:19`）；`I-030`/`I-045` 走 `IncidentWorker_Sequel`（`1.6\Defs\IncidentDefs\RHAH_M2.xml:18`、`:33`），最终都调用 `RHAH_IncidentFacts.Submit`（`Source\Incidents\IncidentWorker_RHAH_Group.cs:86`、`Source\Incidents\IncidentWorker_Sequel.cs:92-105`）。

## 0. 结论（先给三行）

1. **「是否已解决」只有一个权威载体**：`GameComponent_RHAH_Game.openChoices` 里的 `RHAH_ChoiceRecord.Settled`（`Open => Settled == RHAH_ChoiceAction.None`，`Source\Incidents\RHAH_RequestRules.cs:555`、`:574`；列表见 `Source\Core\GameComponent_RHAH_Game.cs:22`/`:37`）。选择信只是视图；`I-014/I-030/I-045` 共用同一条收尾链路。
2. **默认设置（`armedDemandEnabled = true`）下这个事件走「武装索粮」分支**：选「拒绝」只把 `LordJob_RHAH_Visitor.ArmedAssault` 置真并把整批转敌对，**不改 `Settled`**；此后 `ExpireTick` 超时结算被跳过（`Source\Pawn\RHAH_ArmedDemand.cs:110`），右键 dismiss 被禁、也没有「关闭」按钮 → 用户「选敌对后窗口关不掉」的观察在代码里成立。
3. **但「永远关不掉」不成立**：存在兜底 `RHAH_ArmedDemand.Refresh → Owner()==null → Finish(Ignore) → 移除信件`（`Source\Pawn\RHAH_ArmedDemand.cs:86-101`）；只要最后一名「可用」围攻者不再可用（死亡/倒地/被俘/加入/离图/Lord 消失）信件就会自动消失，另外手工交足食物也仍能在同一封信里结算。真正做到死锁的面是：**还剩一名站着的、玩家打不到也交不了粮的围攻者**。

`Pending` 的判定尤其关键（`Source\Incidents\ChoiceLetter_RHAH_Request.cs:140-144`）：

```
record != null && record.Open && (IsRequest(record) || record.ExpireTick < 0 || TickManager.TicksGame < record.ExpireTick)
```

只要 `IsRequest(record)` 为真（`DisplayId ∈ {I-014,I-030,I-045}` 且 `Kind == SimpleMeal`，`Source\Pawn\RHAH_ArmedDemand.cs:22-25`），**即使已经过了 ExpireTick，Pending 仍为真** → 右键不可 dismiss、无 Close 按钮。

信头与正文（武装索粮分支覆盖了普通请求的 `RHAH_Choice_Siege_*`）：

- 标题/正文：`Source\Incidents\RHAH_IncidentFacts.cs:334-335` 使用 `RHAH_ArmedDemand_LetterTitle` / `RHAH_ArmedDemand_LetterText`（`Languages\ChineseSimplified\Keyed\Incidents\RHAH_Famine.xml:3-4`）。正文原文已写明设计意图：**「拒绝会让他们立即进攻，未按期限交付也会引发进攻…即使进攻已经开始，仍可在信中交足食物」**。
- `RHAH_Choice_Siege_Label/_Text`（`RHAH_Choices.xml:44-45`）只在**关闭武装索粮**时经 `ChoiceKey`（`Source\Incidents\RHAH_IncidentFacts.cs:526-528`）使用。

### 1.3 「拒绝」为什么等于「立刻敌对进攻」

`Wrapped` → `Settle` → `RHAH_ChoiceRuntime.TrySettleRequest` → 武装分支 → `RHAH_ArmedDemand.Resolve(record, Reject)`：

- `Source\Incidents\ChoiceLetter_RHAH_Request.cs:104-110`（`Wrapped`，结算成功才 `option.dialog?.Close()`）
- `Source\Incidents\ChoiceLetter_RHAH_Request.cs:112-138`（`Settle`；`:136` 才在 `!record.Open` 时移除信件）
- `Source\Incidents\RHAH_ChoiceRuntime.cs:202-213`（武装分支：`Refresh` → `Resolve(requested)`，**不经过**通用 `Settled` 写入）
- `Source\Pawn\RHAH_ArmedDemand.cs:36-40`：`StartsAssault(...) = action == Reject || action == Timeout`
- `Source\Pawn\RHAH_ArmedDemand.cs:164-168`：`job.ArmedAssault = true` + `StartArmedAssault(members)` + `ReceiveMemo("RHAH_ArmedAssault")` + 威胁消息 `RHAH_ArmedDemand_Attack`
- `Source\Pawn\RHAH_BatchAttitude.cs:121-147`：`SetHostile` 改身份态度为 `Hostile`、锁好感、切敌对派系、刷新攻击目标缓存

**同一状态还能被「非选择」触发**：玩家对这名围攻者造成任何外部伤害时，`Source\Pawn\RHAH_AttitudeHarmPatch.cs:17-39`（`:37`）会调用 `RHAH_ArmedDemand.NotifyPlayerHarm` → `Resolve(Reject)`（`Source\Pawn\RHAH_ArmedDemand.cs:114-120`）。也就是说「先开枪再想选给食物」的人，会发现自己已经进入敌对分支。

### 3.4 逐条回答题面四问

1. **「交付食物」成功后怎么结束 / 是否唯一路径**：A1/A2 写 `Settled = Deliver` 并由 `Finish`（`Source\Pawn\RHAH_ArmedDemand.cs:94-101`）同步删信 —— 是**唯一的「玩家主动且立即生效」**路径，但不是唯一结束路径（A3/A4/A6 也能结束）。
2. **「敌对」后有没有终结路径**：有，但都**不取决于玩家选择**：A3/A4（最后一名可用成员消失）、A6（改设置）、A1/A2（若玩家之后仍能交足食物）。
3. **「拖延」超时后做什么**：`Timeout` 与 `Reject` 在代码里完全同路（`Source\Pawn\RHAH_ArmedDemand.cs:36-40`），**转敌对立即进攻**，`Settled` 保持 `None`，信件保留 → **不会转交付、不会关信**。
4. **有没有「进攻期间还能再次给食物」的第二次入口**：
   - **有，且就是同一封信**：记录仍 Open，点开信依旧有「交付」（`Source\Incidents\ChoiceLetter_RHAH_Request.cs:60-77`，`CanPay` 每次重算）。
   - **没有，右键「给食物」**：`RHAH_FoodHandoff.Refusal` 要求当前 toil 是 Seek/Travel/WaitFood（`Source\Pawn\RHAH_FoodHandoff.cs:78-84`、`:69-72`），进攻 toil（`Source\Pawn\LordToil_RHAH_ArmedAssault.cs:10-24`）不满足 → 右键菜单项被禁用（`Source\Pawn\RHAH_VisitorExpelMenu.cs:74-82`）；同时 `FoodRequest()` 在 `ArmedAssault` 时直接返回 null（`Source\Pawn\RHAH_ArmedDemand.cs:53-59`）。
   - 因此「二次入口」**只在信里**；习惯右键投喂的玩家会认为入口消失。

## 4. 死锁判定与证据链

### 4.1 判定：**部分成立**

| 用户断言 | 判定 | 依据 |
| --- | --- | --- |
| 选择只改变 pawn 行为，没改事件状态 | **成立** | 拒绝/超时只写 `LordJob_RHAH_Visitor.ArmedAssault` + 派系/态度（`Source\Pawn\RHAH_ArmedDemand.cs:164-168`、`Source\Pawn\RHAH_BatchAttitude.cs:121-147`），`Settled` 不变（`Source\Incidents\RHAH_ChoiceRuntime.cs:202-213`） |
| 事件真正关闭唯一绑在「交付食物」上 | **部分成立** | 交付是唯一「玩家可主动触发」的关闭；但 `Owner()==null` 的兜底（A3/A4）和设置开关（A6）也能关，且都不经交付 |
| 选敌对后永远关不掉 | **部分成立** | 只要有 ≥1 名「站着/在图/非囚/可下令」的围攻者，就既不会超时关闭也不会被手动关闭；但当他们全部死亡/倒地/被俘/加入/离图/Lord 消失时会自动关闭（A3/A4） |
| 「进攻期间还能给食物」的二次入口不存在或失效 | **部分成立** | 信里的「交付」仍可用（若 `CanPay`）；右键投喂入口确实失效（见 §3.4.4） |

### 4.2 决定性证据链（「A 调用 B，B 只在 C 下结束，C 在敌对后永假」）

**链一：超时关闭被永久跳过**
`RHAH_ChoiceRuntime.Tick`（`Source\Incidents\RHAH_ChoiceRuntime.cs:122-126`）把武装记录整个交给 `RHAH_ArmedDemand.Tick`
→ `Tick` 唯一能结算的自动路径是 `if (!job.ArmedAssault && tick >= record.ExpireTick) Resolve(Timeout)`（`Source\Pawn\RHAH_ArmedDemand.cs:110-111`）
→ `Resolve(Timeout)` 走的是 `StartsAssault`（`:164`），只置 `ArmedAssault = true`，**不调用 `Finish`**
→ 所以 `ArmedAssault == true` 后，「到期自动结束」这个条件**永假**。

**链二：手动关闭被禁用**
`CanDismissWithRightClick => !Pending(...)`（`Source\Incidents\ChoiceLetter_RHAH_Request.cs:17`）
→ `Pending` 对武装记录只要 `record.Open` 就为真，**不看 `ExpireTick`**（`:140-144`）
→ `Choices` 首行 `if (ArchivedOnly || !Pending(record)) { yield Option_Close; }`（`:24-28`）
→ 所以「右键关 / 点关闭」在 Open 期间**永假**。

**链三：敌对后唯一的自动关闭条件是「最后一名可用成员消失」**
`Refresh(record)`（`Source\Pawn\RHAH_ArmedDemand.cs:86-92`）→ 只有 `Owner(record) == null` 时才 `Finish(Ignore)`
→ `Owner()` 要求至少一名成员 `Spawned && !Downed && CanOrderLeave(...) && ArmedChoiceId == record.Id`（`:67-84`）
→ 敌对后这些成员仍在图上、仍站得住、Lord 仍是 `LordJob_RHAH_Visitor`（`SetHostile` 只换派系不拆 Lord，`Source\Pawn\RHAH_BatchAttitude.cs:126-147`，`:179-204` 特意 `PreserveForAttitudeChange`）
→ 所以「敌对但还活着站着」期间该条件为假 → 信不关、也不能手动关。

**链四：唯一的玩家出口要求在战斗中仍能交付**
交付按钮 `enough` 取 `RHAH_ArmedDemand.CanPay(record)`（`Source\Incidents\ChoiceLetter_RHAH_Request.cs:65-70`）
→ `CanPay` → `PlanPayment`（`Source\Pawn\RHAH_ArmedDemand.cs:179-214`）要求：允许的索粮食物（`Source\Pawn\RHAH_DemandFood.cs:31-35`）、**一名未倒地的殖民者能同时走到食物和这名成员**（`Source\Incidents\RHAH_FoodTransaction.cs:175-185`，`Danger.Deadly`）、且成员背包能收（`Source\Pawn\RHAH_ArmedDemand.cs:192-210`）
→ 交战中殖民者被打倒 / 成员在墙外或不可达 / 食物被禁或不在有效库存时 `CanPay == false`，按钮灰、提示「还需交付相当于 {0} 份简单餐的食物…」（`Languages\ChineseSimplified\Keyed\Incidents\RHAH_Famine.xml:7`）
→ 于是玩家既关不掉又交不了 → **这就是用户看到的「关不掉」**。

### 4.3 那条「没预料到的兜底」及玩家为什么看不到它

兜底 = A3/A4（`Refresh/Owner`）+ A7（`RemoveSettledArmedLetters`）。玩家感知不到的原因：

1. **它是静默的**：`Finish` 只写 `Settled` 并 `RemoveLetter`，没有任何 `Messages.Message`（`Source\Pawn\RHAH_ArmedDemand.cs:94-101`）。
2. **它要「最后一个」都不可用**：5 人只死 4 人、剩 1 人站着就永远不触发（`:67-84`）。
3. **它按小时节奏跑**（`GenDate.TicksPerHour`，`:107`）+ 无 tick 的暂停期不推进（`GameComponentTick` 只在游戏推进时调用，`Source\Core\GameComponent_RHAH_Game.cs:59-63`）。
4. **敌对者不会自己走**：`ExitMap` 闸门只对 `Lifecycle == Leaving` 放行（`Source\Identity\RHAH_PawnDefaults.cs:62-63`），而进攻期间没人会给他们写 Leaving；`ReadyToLeave` 又对持信者直接 false（`Source\Pawn\LordJob_RHAH_Visitor.cs:571`）。所以「把人打跑」在这个事件里几乎不会发生，玩家等不到兜底。
5. **倒地也算「不可用」**：全员倒地会立刻 `Ignore` 关信（可能让玩家以为「打赢了但什么都没结算」）。

## 附：一句话修复方向（仅供参考，未实施）
