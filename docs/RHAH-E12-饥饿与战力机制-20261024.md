# RHAH · E12 乞食围攻：饥饿 → 营养不良 → 能否等一天并进攻

对象：`RimworldMods/ratkin_hunger_and_havoc`（只读核查，未改动任何文件）。事件 = `Source/Incidents/RHAH_IncidentGroups.cs:21` 的 `I-014 / I-030 / I-045`。

证据分级（全文严格区分）：

- **【仓库】**：本 mod 仓库里读到的文件与行号。
- **【原版 Def】**：本机 RimWorld 1.6.4871 安装目录 `D:\SteamLibrary\steamapps\common\RimWorld\Data\Core\...` 的原版 Def 原文（**不是本仓库**，但可复现、可复核）。
- **【原版常识】**：RimWorld 机制知识，**未在本仓库、也未在原版 Def 文件中验证**。
- **【外部 wiki】**：rimworldwiki（引 URL），仅用于营养不良的自然演进速率。

---

## 结论（三行）

1. **(a) 部分成立**：来客确实「出生即带营养不良且饥饿条清零」——但默认严重度是 **0.25 = 原版 `minor` 档（中文「较轻」）**，不是「中度/中等」；要到 0.4 才是「中等」，按原版速率大约在到场后 **6.6–9.9 小时**才跨过去。【仓库 `Source/Generation/RHAH_FamineArrival.cs:20-29` + `Source/Core/RHAH_Settings.cs:57`】
2. **(b) 不成立（默认设置下）**：等一天 = 60000 tick（`requestDays=1`），期间营养不良只涨 0.36–0.54，落点 **0.61–0.79 = 「严重」档，意识 −30%（≈70%），不会倒地，仍能进攻**；按最快速率也要 **24.2 小时**才摸到 0.8「极重（意识上限 10%）」这条倒地线。默认 0.25 恰好压在 0.8 下方 0.005，属于临界调值。【仓库 `Source/Incidents/RHAH_IncidentFacts.cs:278` + `Source/Incidents/RHAH_RequestRules.cs:82-83` + 原版 Def 阶段表】
3. **(c) 改动最小入口**：`RHAH_Settings.famineArrivalMalnutrition` 的默认值与上限（`Source/Core/RHAH_Settings.cs:57`、`:349`、`:1673`）＋ 落值处 `Source/Generation/RHAH_FamineArrival.cs:28-29`；只要把它压到 ≤0.25（保险起见 ≤0.18），「等一天 → 进攻」就在机制上恒成立。「越饿越强」**没有任何现成机制**，可复用的只有 `StatPart_RHAH_ParentalInstinct`（StatPart 模式）、营养不良阶段表（Def 级插入点）、`RHAH_Trait_HungerRage` 的 `RHAH_Hunger` 特质标签。

## 3. 一天后会发生什么

### 3.1 仓库内证据（可复核）

1. **入场点已被钉死**：`CurLevel=0`（`RHAH_FamineArrival.cs:20`）+ `Malnutrition.Severity=0.25`（`:28-29`），且只在 `Lifecycle==Arriving` 时执行一次（`:10-13`、`RHAH_PawnFactory.cs:56-57`）——**等待期间不会二次加码**（全仓 `famineArrivalMalnutrition` 只出现在设置、设置界面、这一处与相应单测，无第二处写入）。
2. **仓库里没有任何代码直接改来客的 Consciousness / Moving / Manipulation**。全仓 `capacity` 命中都是**读**（`Source/Identity/RHAH_PlagueRuntime.cs:76` 读 BloodPumping；`Source/Pawn/Compat/RHAH_ChildMovement.cs:95-96` 读 Moving；另有 `Talking` 读于 `Source/Pawn/JobDriver_RHAH_BroadcastHope.cs:23`、`Source/Pawn/RHAH_BroadcastMenu.cs:41`，`Manipulation` 读于 `Source/Pawn/RHAH_MouseSwarm.cs:158`），没有写。→ 能力变化只能来自 **hediff 阶段**。
3. **倒地会被各闸门挡住**：`CanFight` 要求 `!pawn.Downed`（`Source/Pawn/JobGiver_RHAH_Visitor.cs:51`）；`LordToil_RHAH_ArmedAssault` 对不能战的人只发「就地寻食」duty（`Source/Pawn/LordToil_RHAH_ArmedAssault.cs:18-21`）。
4. **全批倒地会更糟**：`Owner(record)` 要求至少一名 `Spawned && !Downed && CanOrderLeave`（`RHAH_ArmedDemand.cs:79-81`）；若一个都不剩，`Refresh` 返回 false → `Finish(record, Ignore)`（`:86-101`）——**事件被静默结掉、不上敌人、信被撤掉**，`Resolve(Timeout)` 根本走不到 `:164`。
5. **倒地者仍留在 Lord 里**（`Source/Pawn/LordJob_RHAH_Visitor.cs:160-164`，`ShouldRemovePawn` 对 `Incapped` 返回 false），所以「几个倒地、剩下的照打」是可能的；只有全倒才没戏。
6. **另外两条能压意识的仓库资产**（不是营养不良，但同样能让人躺下）：
   - `RHAH_OvergnawedWall`：`Consciousness −0.6`、`painOffset 0.8`、`MaxNutrition ×0.1`（`1.6/Defs/HediffDefs/RHAH_Gnaw.xml:44-65`），由「啃第 5 口墙」触发（`Source/Pawn/JobDriver_RHAH_Gnaw.cs:52-54`，阈值 `RHAH_GnawHealth.cs:33-34` `OverSeverity=0.3`/`OverCount=5`）。触发前提是 `PrefersGnaw`（被乞讨对象扇过 2 次，`Source/Identity/RHAH_PawnState.cs:22`）→ `Source/Pawn/JobGiver_RHAH_Visitor.cs:107-114`。
   - `RHAH_RefeedingSyndrome`：`Consciousness −0.25`（`1.6/Defs/HediffDefs/RHAH_Refeeding.xml:16-33`），在「吃饱且 malnutrition ≥ 0.4」时加（`Source/Pawn/RHAH_Feeding.cs:76-97`，阈值 `RHAH_ReliefFood.cs:31`）——**这是给食成功后的代价，不是等待期的**。

### 3.2 原版机制（本节是常识/外部资料，非本仓库）

- **【外部 wiki】** 饥饿条见底后，营养不良严重度每小时上升 **1.51%–2.27%（0.0151–0.0227）**，每个 pawn 速率固定随机；吃饱后以同一速率回落：<https://rimworldwiki.com/wiki/Malnutrition>（1.5.4062 起）。→ 一天 = **+0.36 ~ +0.54**。
- **【原版常识，未验证】** 意识 < 30% 即 `Downed`（昏迷/倒地）；痛觉 ≥ 80% 触发 pain shock（默认 `PainShockThreshold` 0.8）；营养不良在饥饿条为 0 时才会上涨。

### 3.3 推演表（0.25 起，按 0.0151–0.0227/h）

| 经过 | severity | 档（原版 Def） | Consciousness | 能否进攻 |
| --- | --- | --- | --- | --- |
| 0 h（到场） | 0.25 | minor / 较轻 | 90% | 不能，此时还没敌对 |
| ~6.6–9.9 h | 0.40 | **moderate / 中等** | 80% | 不能 |
| **24 h（60000 tick，开打点）** | **0.61–0.79** | **severe / 严重** | **70%** | **能，且不会倒地** |
| ~24.2–36.4 h | 0.80 | extreme / 极重 | ≤10% | 倒地 |
| ~33–46 h | 1.00 | 死亡 | — | — |

灵敏度（同一速率区间）：

| `famineArrivalMalnutrition` | 一天后 | 结果 |
| --- | --- | --- |
| 0.01 | 0.37–0.55 | 较轻/中等，满状态进攻 |
| **0.25（默认）** | **0.61–0.79** | 严重，**不倒地**，能进攻 |
| 0.40 | 0.76–0.94 | 严重→极重，**部分倒地** |
| 0.50（上限） | 0.86–1.04 | 极重→死亡，**基本打不起来** |

**判定**：默认 0.25 + 24 h 的落点上限 0.795 恰好没到 0.8 ——「等一天后必然饿倒」在默认参数下**不成立**；但只需把入场值抬到 0.40 以上、把 `requestDays` 调到 2、或叠加一条压意识的 hediff（`RHAH_OvergnawedWall` / `RHAH_RefeedingSyndrome` / 鼠疫），就会真的躺倒。用户观察到的现象**可能真实，但归因不是「0.25 的中度营养不良」**：要么当时看到的是等待中途（≥0.4 的中等），要么设置被调高，要么是别的 hediff。

补充一个方向相反的影响：等待期间饥饿条为 0 的来客会**自己找吃的**（`Source/Pawn/JobGiver_RHAH_Visitor.cs:73-143`，尤其 `:98-105` 的救济取食、`:116-123` 乞讨），一旦吃上，malnutrition 以同速率回落——所以「饿不饿倒」还取决于场上有没有可及食物。
