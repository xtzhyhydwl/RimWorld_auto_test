## 5 发版机制（实测）

- `deploy:` = 发版提交，内容以编译产物为主：`fb03c08 deploy: v1.1.0` 只 1 个 dll；`33e8b1a v1.0.2` 2 个；`ce58a2a v1.0.1` 3 个；`607b605 v1.0.3` 只改 `About/About.xml`；`b2af586 beta 0.1.0` 连 `Preview.png`。
- `build:` = 只刷新 `1.6/Assemblies/*.dll`，不动版本号（7 条全部如此）。
- 版本号与 `deploy` **不同步**：`deploy: v1.0.1`/`v1.0.2` 时 `modVersion` 仍是 1.0.0；1.0.5 升版是单独 `chore: bump version to 1.0.5`；`deploy: v1.1.0` 只含 dll，版本号在更早的 `feat: v1.1.0 pre update` 里改。现状 `About.xml` = **1.1.4**，与最后一条 `deploy: v1.1.4` 一致（实测 `git show <h>:About/About.xml`）。
- **没有 git tag**（`git tag -l` 为空），但 `docs/agents/automation.md:34` 要求「`modVersion` 与主体项目 `Version` 一致，tag 必须是对应的 `v<版本>`；不一致报告失败，不自动修改版本号」——规则写了，tag 侧未落地或未随导入带过来。
- 变更说明写在 `README.md`（233 行）：`## 1.1.4 · 索粮食物与请求修复` 倒序排列、中英双语分节——README 就是事实上的 CHANGELOG。
