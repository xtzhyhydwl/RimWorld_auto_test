## 同层不同维度（Def 子节点粒度）

1. **DutyDefs 层**：`RHAH_VisitorSeek`/`RHAH_VisitorLeave` 是两个**平行** duty，唯一差异是兜底子节点（`JobGiver_WanderNearDutyLocation`:8 vs `JobGiver_RHAH_DigOut`:20），首个子节点**完全相同**（`JobGiver_RHAH_Visitor`，Duties:7 / :19）。→ 名字暗示「状态」，实际是「同一 duty 的两种兜底」；真名应是 `..._Wander` / `..._ExitMap`（🔴 defName 不动）。
2. **JobGiver 层一个目录混三种维度**：身份/派发（`JobGiver_RHAH_Visitor`）、单动作（`JobGiver_RHAH_Beg/Feed/Steal/Gnaw`）、离场两义（`JobGiver_RHAH_Leave` 决策 / `JobGiver_RHAH_DigOut` 手段）。同层节点命名维度不一致正是提问里指的那类。
3. **ThinkTreeDef 层**：`RHAH_VisitorFallback`（按职责）vs `RHAH_PrisonerNeeds`（按人群）。
4. **IncidentWorker 层四种维度且前缀不统一**：抽象按结构（`IncidentWorker_RHAH_Group`/`_OriginalGroup`，Group.cs:8/84）、按来源（`IncidentWorker_Sequel`）、按机制＋前缀（`IncidentWorker_RHAH_MouseSwarm`/`_PleadingJoin`/`_BanditAttack`）、14 个具体事件**无 RHAH_ 前缀**（`IncidentWorker_LargeRefugeeWave` 等，Group.cs:89-178）。
