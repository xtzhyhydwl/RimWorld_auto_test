# RHAH「来客能否开门」设置语义考证

只读核查，对象为 `RimworldMods\ratkin_hunger_and_havoc`（RHAH）当前工作区。行号以本次读取为准。

## 结论

1. **设置语义**：`RHAH_Settings.famineVisitorsOpenDoors`（`Source\Core\RHAH_Settings.cs:72`，默认 `false`，`Scribe` 默认 `false` @`:364`），界面名「允许饥民开门」。该 Postfix **只会把结果改成 `false`，从不改成 `true`**（`Source\Pawn\RHAH_DoorPatch.cs:37-40`），所以它是「解禁开关」，不是「授权开关」。
2. **是否全有或全无**：对 `Arriving`/`SeekingFood`/`Fed` 这三种活跃未离场状态是**全有或全无**（同一条判定，`RHAH_DoorPatch.cs:37`）；但 `Leaving` 在 `RHAH_DoorPatch.cs:25` 有硬编码提前返回——**离场客人任何时候都能开门，不受开关和敌情约束**。即：离场与求食其实已经分开，只是离场那半边写死了、没有开关。
3. **1.6/1.7**：Def XML 除 `1.7\Defs\WorldObjectDefs\RHAH_KingdomSite.xml` 的两行原版贴图路径外逐文件一致；`1.7\` 另有 `Guard\`（含三语 Guard.xml），1.6 用根 `Guard\`。语言文案只有根 `Languages\` 一份，两版本共用，不存在版本差异。源码单份，`RHAH_DoorPatch.cs` **没有** `#if RIMWORLD_1_7` 分支（全文件无 `#if`）。
4. **最小改法一句话**：新增 `famineVisitorsLeavingOpenDoors = true`，用它去包住 `RHAH_DoorPatch.cs:25` 那个提前返回（默认 `true` 保住现状），再补一条 Scribe、两个设置界面、三份语言文案。

## 新增「离场时允许开门」开关的最小改法（只给方案）

1. 字段：`Source\Core\RHAH_Settings.cs:72` 之后加 `public bool famineVisitorsLeavingOpenDoors = true;`
2. 存档：`Source\Core\RHAH_Settings.cs:364` 之后加 `Scribe_Values.Look(ref famineVisitorsLeavingOpenDoors, "famineVisitorsLeavingOpenDoors", true);`（初值与 Scribe 默认必须一致，`Source\AGENTS.md` 有硬要求）
3. 判定：`Source\Pawn\RHAH_DoorPatch.cs:25`——保留 `comp == null` 返回；`lifecycle == Leaving` 改为「仅当新开关为真才返回」，否则落到第 8 步统一按开关/敌情处理
4. 界面：`Source\Core\ModEntry.cs:172` 之后加一条 `listing.CheckboxLabeled(...)`；`Source\Pawn\Compat\RHAH_IrisMenusCompat.cs:1525` 之后加一条 `RHAH_IrisMenusWidgets.Checkbox(...)`
5. 文案：三份 `Languages\{ChineseSimplified,English,Japanese}\Keyed\Settings\RHAH_Visitors.xml:55` 之后各加 `RHAH_Settings_FamineDoors_Leaving` 与 `_Leaving_Tooltip`
6. 文档：`docs\references\save-ownership.md:719` 之后补一行说明新键

**旧档兼容**：`Scribe_Values.Look` 在旧档缺键时取第三个参数（本仓库 50+ 字段依赖同一行为，如 `tailBiteEnabled` 默认 `false`）。因此新字段默认值必须是 `true`——缺键 = 现状「离场永远可开门」，旧档行为不变；若默认 `false`，旧档会静默失去现行能力，且离场者被门挡住后只能去凿墙（`RHAH_DoorPatch.cs:23` 注释所述次级 giver 兜底）。
**风险（推断，未实测）**：`RHAH_ApiHost.cs:108-113` 只在**进入** `Leaving` 时清该 pawn 的可达性缓存；运行中切换新开关不会触发清理，已在离场的 pawn 可能不立即生效，需要额外 `map.reachability.ClearCacheFor(pawn)` 或等门状态变化。
