## 1. 这个 mod 到底想做什么

### 1.1 一句话
给鼠族加一整套「饥荒来客」事件系统（23 类 / 54 个编号来源），加一个新叙事者穗音，再用王国篇 K1–K5 给穗音铺人物背景与初步合作。**【实测】**`README.md:7-11`

前置：NewRatkinPlus、Harmony、Biotech、Oxygen DSL Framework（必须排在本模组前面），IrisMenus 用于分页设置。Def 前缀 `RHAH_`，事件显示 ID 用 `I-`，剧情用 `N-`/`J-`/`R-`。**【实测】**`README.md:9-11`

明确「独立作品，不是鼠灾-大荒年的 Continued」，不导入旧鼠灾存档，不能与旧鼠灾同时启用。**【实测】**`README.md:11`、`README.md:74`

### 1.2 事件系统（想做的规模）
- 自然事件与广播按 **23 类**选择，再决定人数、年龄、染疫等具体场景；共 **56 个活动来源场景**；`I-001`..`I-054` 加 3 个原版野人子事件 = 57 个 Def。**【实测】**`docs/references/incidents.md:3`、`incidents.md:76-98`、`incidents.md:110-166`
- 抽取不是原版 `baseChance`，而是自建 `RHAH_IncidentSchedule` + `RHAH_IncidentWeight`：每天先算正负两池平均间隔，`MTBEventOccurs` 决定是否抽池，再抽类、再抽场景；权重公式 `family × season × plague × trust × target × 玩家权重 / 100`。**【实测】**`incidents.md:7`、`incidents.md:17`
- 地图事件不直接生成 Pawn，而是先在目标家园外 4–6 格放一个没有 Pawn 的世界物体 `RHAH_Approach`，1 倍速平地每天 3 格走过去（默认 ×2 速度）。**【实测】**`incidents.md:7`、`README.md:45`
- **8 条长后续**：鼠妈回访、旧窝记物、换子追问、空投认领、认亲依恋、孤儿自称身份等；用 Oxygen DSL Framework 的 stage 机制，每批有真实人物、选择和后果。**【实测】**`README.md:103`、`README.md:86`、`incidents.md:56-58`
- 短后续：按 `followPredatorPercent`（默认 10%）掷一次野生捕食者，延迟 120 tick 到达，不重复掷。**【实测】**`docs/references/events/I-001.md:25`、`I-015.md:24`、`I-020.md:37`
- 年度荒年 + 3 个新事件（I-052 鼠潮 / I-053 祈求加入 / I-054 盗匪袭击）+ 通讯台「广播希望」。**【实测】**`README.md:113-123`、`incidents.md:30-34`

### 1.3 叙事者穗音
- Def `RHAH_Suiyin`，label 穗音，`listOrder 55`；描述是她翻墙看见平民区、被父母禁闭、被红发男人（兰迪）伸手；机制上「安排事件的节奏接近兰迪」，整体更难；**信任高时大型威胁间隔拉长，信任低时间隔缩短**。**【实测】**`1.7/Defs/StorytellerDefs/RHAH_Storytellers.xml:5-8`、同文件 `comps/RandomMain`
- 穗音信任（GLOSSARY「穗音信任」）只作**事件干涉因素**：负信任让负池更频繁（`1 - clamp(trust,-100,100)/400`），并让来客到达态度降一档。**【实测】**`incidents.md:17`、`incidents.md:28`、`docs/adr/0005-kingdom-facts-and-trust.md:8`
- 人物设定：受宫廷教育的王国二公主，20 岁，善良但软弱、依恋父母与宫廷；参考《红与黑》（音乐剧）与《是，首相》。**【实测】**`docs/references/backstory/suiyin.md:3-31`、`kingdom-arc/README.md:15-17`

### 1.4 王国篇 K1–K5 想做什么
**只铺陈背景与初步合作，不承担全篇终局。**【实测】**`kingdom-arc/README.md:3`、`kingdom-arc/README.md:19`、`README.md:168`

| 幕 | 想讲的事 | 幕间出口 |
| --- | --- | --- |
| 一 墙与那只手 | 童年御花园捧蝶、翻墙见平民区、父母禁闭、兰迪伸手 | 穗音寄出第一封私人来信 |
| 二 沿着粮食的痕迹 | 两份矛盾回执、被撤职的书记、配给厅闭门核验 | 取得证据或确认调查受阻 |
| 三 王国的回应 | 运输署正式使者、王室施舍日、护粮队 | 明确证据去向与王国态度 |
| 四 穗音的选择 | 补发配给 / 分别公开 / 转移书记 / 暂缓（一次只做一件） | 行动真实结果，**不锁定政治路线** |
| 五 墙还在 | 回顾初次合作，呈现善意与迟疑 | 阶段收束，**不是全篇结局** |

（表据 `kingdom-arc/README.md:33-39`、`05-after-the-wall/README.md:5-7`、`04-the-choice/README.md:7`）

远期规划有 **5 个政治结局**：温和的改良 / 激进的斗争 / 失败的反抗 / 永久的沉睡 / 癫狂的世界；作者明确写「均不在 K1–K5 触发，选择链、条件、优先级与演出尚未设计，不新增 Def、翻译键或存档字段」。**【实测】**`kingdom-arc/README.md:43-55`

## 6. 读这份稿子之后，评估「实现 vs 设计」的建议切口

1. **事件内容**：优先看 23 类的「短后续」只有一次捕食者投掷、长后续只有 8 条——设计上「后续反应」的重量几乎全压在 8 条长后续，其余 15 类事件的结果是「心情 + 态度 + 一次捕食者」。这解释了「后续做得糙」的体感，且是**设计层面**的取舍，不只是实现偷工。**【实测】**`incidents.md:56`、`README.md:103`
2. **事件流程**：访客 Lord 的「到达→停留→索粮→答复→离场」是原版访客机制的拼装（`incidents.md:24-27`、`RHAH_Visit*`/`RHAH_Relief*` 系列文件），与原版 `IncidentWorker` 的差异集中在自建抽取/队列/Approach。评估「拼装感」应从这里入手。
3. **王国篇**：真正的落差不在「有没有做」（Stage 全链路都在），而在「呈现密度」——设计稿 107 张分支图 vs 实现 54 张、一个阶段一段总结文本；以及 K5 五份终局稿被压成一封 `Response` 信。
