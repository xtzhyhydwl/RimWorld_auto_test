## 结论（3 行）

1. **原版靠什么走掉**：先由 `ThinkNode_ConditionalCannotReachMapEdge`（即 `!ReachabilityUtility.CanReachMapEdge`）或 lord 的 `Trigger_PawnCannotReachMapEdge` 判定「被困」，然后进入一个 **`canDig = true` 的离场状态**——`LordToil_ExitMap(locomotion, canDig:true, …)` 把 `PawnDuty(ExitMapBest){canDig=true}` 发给小人，`JobGiver_ExitMap.TryGiveJob` 据此把寻路模式切成 `TraverseMode.PassAllDestroyableThings`，再用 `DigUtility.PassBlockerJob` 生成**砸门/砸墙/开枪拆墙**的 Job；走通了才 `Goto` + `exitMapOnArrival` 出图。
2. **RHAH 差在哪**：`JobGiver_RHAH_Leave.TryCreate` 用的是**默认参数**的 `RCellFinder.TryFindBestExitSpot(pawn, out spot)`（`Source/Pawn/JobGiver_RHAH_Leave.cs:60`）= `TraverseMode.ByPawn`；而 `Verse.Region.Allows` 的 ByPawn 分支对**非敌对**小人只认 `door.CanPhysicallyPass(p) && !门被禁止通过`，**完全无视 `canBashDoors`** ⇒ 门一锁，可达性就断，找出口必然失败 ⇒ `:62 return null` ⇒ 小人没有 Job（`JobGiver_RHAH_Visitor.cs:83-87` 在 `Leaving` 时直接返回 null）⇒ 表现为原地游荡。RHAH 里**没有任何** `canDig` / `DigUtility` / `LordToil_ExitMap` / `Trigger_PawnCannotReachMapEdge` 的痕迹。
3. **推荐接法**：**候选 A**——离场 duty 设 `canDig = true`，并在 `RHAH_VisitorLeave` 这个 DutyDef 里把原版 `JobGiver_ExitMapBest` 挂成**次级节点**（薄包装一个带闸门检查的子类）。它复刻的正是原版商队/访客被围时那条路（`LordJob_VisitColony` / `LordJob_TradeWithColony` 的 `LordToil_ExitMap(Jog, canDig:true)`），**不改 `RHAH_DoorPatch`、不动「默认禁门」、不动 Lord 图、不加存档键**。代价：真被困住时会砸玩家的门/墙（这正是玩家要的）。

## 一、原版「被困 → 强行离开」机制清单

### 1.1 决定「走不走得掉」的三层判定

| 层 | 类 / 方法 | 位置 | 它做什么 | 关键参数 |
|-|-|-|-|-|
| 区域可达性（决定「算不算被困」） | `Verse.ReachabilityUtility.CanReachMapEdge(Pawn)` | 【IL】 | `map.reachability.CanReachMapEdge(p.Position, TraverseParms.For(p, Danger.Deadly, TraverseMode.ByPawn, canBashDoors:false, alwaysUseAvoidGrid:false, canBashFences:false, avoidPersistentDanger:true))`。**注意它是唯一一个 `canBashDoors=false` 硬编码的判定**，所以它回答的是「不开门、不砸门，走得到地图边缘吗」 | 无参数；`!Spawned` 直接 false |
| 区域链接放行（决定性） | `Verse.Region.Allows(TraverseParms tp, bool isDestination)` | 【IL】 | 对 `Region.type == door` 的链接：`mode` 为 `PassAllDestroyableThings`(3) → **无条件 true**；`PassAllDestroyablePlayerOwnedThings`(4) → 门不属于玩家时才 true；`PassAllDestroyableThingsNotWater`(6) → true；**`ByPawn`(0) + `pawn.HostileTo(door)`** → `door.CanPhysicallyPass(p) ? true : canBashDoors`；**`ByPawn`(0) + 非敌对** → `door.CanPhysicallyPass(p) && !ForbidUtility.IsForbiddenToPass(door,p)`（**`canBashDoors` 在这条分支里不起任何作用**） | `TraverseMode`：ByPawn=0, PassDoors=1, NoPassClosedDoors=2, PassAllDestroyableThings=3, PassAllDestroyablePlayerOwnedThings=4, NoPassClosedDoorsOrWater=5, PassAllDestroyableThingsNotWater=6 |

`RCellFinder.TryFindBestExitSpot` 签名【IL】：

## 二、「凿墙」的真实实现与触发条件

**一句话：凿墙不是某个 `WorkGiver`，是 `JobGiver_ExitMap.TryGiveJob` 里的 `canDig` 分支 + `DigUtility.PassBlockerJob` 合成的 Job。**

拆解：

1. **谁来判定要凿**：`canDig` 的四个来源（见 1.2 第 4 条）。最常用的是 **`duty.canDig && !pawn.CanReachMapEdge()`**——注意这个写法本身就把「路是通的就不凿」编码进去了。`LordToil_ExitMap(canDig:true)` 只是把 `Data.canDig` 抄进 `PawnDuty.canDig`（`Verse.AI.PawnDuty` 的 `public bool canDig` 字段，【IL】）。
2. **谁来让寻路穿过墙**：`canDig == true` 时 `JobGiver_ExitMap.TryGiveJob` 用 `TraverseParms.For(pawn, Danger.Deadly, TraverseMode.PassAllDestroyableThings, …)` 找路；`Region.Allows` 在 mode 3 直接返回 true，`PathUtility.GetDoorCost` 在 mode 3/4/6 返回「`costBlockedDoor + HP × costBlockedWallExtraPerHitPoint`」——**按血量计价**，所以离得近的门/薄墙优先。
3. **谁真正生成拆解 Job**：`RimWorld.DigUtility.PassBlockerJob(pawn, blocker, cellBeforeBlocker, canMineMineables, canMineNonMineables)`【IL】：
   - `StatDefOf.MiningSpeed.Worker.IsDisabledFor(pawn)` → 两个 canMine 都置 false（**不能挖矿的人只能近战**）；
   - `blocker.def.mineable` → `MineOrWaitJob` / `MeleeOrWaitJob`；
   - 否则若有装备且 `PrimaryVerb.verbProps.ai_IsBuildingDestroyer` → **`JobDefOf.UseVerbOnThing`**（ incendiary 还要 `FlammableNow`）；
   - 再否则 `canMineNonMineables ? MineOrWaitJob : MeleeOrWaitJob`。
   - `MeleeOrWaitJob`【IL】：`ReservationUtility.CanReserve(pawn, blocker)` 不通过 → **`WaitNearJob`（在墙角干等）**；通过 → **`JobDefOf.AttackMelee`**（`ignoreDesignations=true`、`checkOverrideOnExpire=true`、`expiryInterval = JobGiver_AIFightEnemy.ExpiryInterval_ShooterSucceeded.RandomInRange`）。
4. **触发条件（时间尺度）**：
   - lord 路径：`Trigger_PawnCannotReachMapEdge` 每 **197 tick** 检查一次；任一 ownedPawn（未死、未倒地、已 spawn）`!CanReachMapEdge()` 就切到 canDig 的 ExitMap toil，并打 `MessageVisitorsTrappedLeaving`；
   - 非 lord 路径：只有当 duty/XML 里带了 `canDig` / `forceCanDig*` 才会凿（动物/昆虫走 `DigOutIfCannotReachMapEdge` 子树，人形没有）；
   - **不是**「被敌对围住就凿」——`forceCanDigIfAnyHostileActiveThreat` 用的 `GenHostility.AnyHostileActiveThreatTo(map, faction, …)` 只在少数 duty 上开着（`TakeWoundedGuest`）。
5. **能力的天然上限**（对 RHAH 很关键）：
   - `StatDefOf.MiningSpeed` 被禁用（不能挖矿）→ 只能 `AttackMelee`；
   - 完全不能近战（`WorkTags.Violent` 被禁，如幼童/和平主义者）→ `AttackMelee` 的 Job 能生成，但执行时会因无法近战而失败（【推测】，未跑游戏；`AttackMelee` 的 Toil 里会对 `WorkTagIsDisabled(Violent)` 做检查，本轮未逐行核对）；
   - 抢不到预留 → `WaitNearJob`，表现为「站在墙边不动」。

## 四、候选接法

> 三条路都不改 `Source/Pawn/RHAH_DoorPatch.cs`，都不改 `famineVisitorsOpenDoors` 的默认值，因此「默认禁门」这个设计意图**原样保留**（差别只在候选 B 是否给「正在离场的人」开一扇门）。

### 候选 A（推荐）：`duty.canDig = true` + 原版 `JobGiver_ExitMapBest` 作次级节点

**改哪里**

1. 新增 `Source/Pawn/JobGiver_RHAH_Departure.cs`（薄包装，约 20 行）：
   `internal sealed class JobGiver_RHAH_Departure : JobGiver_ExitMapBest`，构造里 `defaultLocomotion = LocomotionUrgency.Jog`；`protected override Job TryGiveJob(Verse.Pawn pawn)` 先过 `RHAH_BatchAttitude.CanOrderLeave(pawn) && RHAH_Api.Allows(pawn, RHAH_BehaviorGate.ExitMap)`，再 `return base.TryGiveJob(pawn)`（基类即 `JobGiver_ExitMap.TryGiveJob`，`Downed && !Crawling → null` 已经在里面）。
   - 为什么必须包一层：`RHAH_VisitorLeave` duty 也会被 `LordToil_RHAH_VisitorLeave.UpdateAllDuties` 发给**所有** ownedPawns（`LordJob_RHAH_Visitor.cs:744-756` 会先 `CanOrderLeave` 过滤，但 `RHAH_VisitorStay.cs:134` 与 `:644`/`:728` 不保证）；纯 XML 挂原版 giver 时，一旦 `JobGiver_RHAH_Visitor` 因为别的原因返回 null（例如 `CanOrderLeave == false`），原版 giver 会把**殖民者**也送去出图。包一层闸门是必须的。
2. 新增一个 duty 工厂（DRY，一处定义）：`RHAH_VisitorRules.DepartureDuty()` → `new PawnDuty(RHAH_DefOf.RHAH_VisitorLeave) { canDig = true }`，替换 4 处 `new PawnDuty(RHAH_DefOf.RHAH_VisitorLeave)`：
   - `Source/Pawn/RHAH_VisitorStay.cs:134`
   - `Source/Pawn/LordJob_RHAH_Visitor.cs:644`（`LordToil_RHAH_VisitorTravel.UpdateAllDuties`）
   - `Source/Pawn/LordJob_RHAH_Visitor.cs:728`（`LordToil_RHAH_VisitorSeek.UpdateAllDuties`）
   - `Source/Pawn/LordJob_RHAH_Visitor.cs:754`（`LordToil_RHAH_VisitorLeave.UpdateAllDuties`）
3. `1.6/Defs/DutyDefs/RHAH_Duties.xml:16-22` 的 `RHAH_VisitorLeave.subNodes` 追加一行：
   `<li Class="HungerAndHavoc.Pawn.JobGiver_RHAH_Departure" />`（放在 `JobGiver_RHAH_Visitor` **之后**——`ThinkNode_Priority.TryIssueJobPackage`【IL】逐个子节点尝试，第一个产出有效 Job 的就返回，所以顺序就是「先按 RHAH 自己的 Goto 正常走，走不掉才让原版凿」）。

**语义**：完全等于原版访客/商队被围——`duty.canDig && !CanReachMapEdge()` 成立才切 `PassAllDestroyableThings`，路通的时候一点行为都不变。

**与 `RHAH_DoorPatch` 打架吗**：不打架。门禁在 `PawnCanOpen`，砸门走的是 `TraverseMode.PassAllDestroyableThings` + `DigUtility`，**不经过 `PawnCanOpen`**。副作用是：真被困住时他会把玩家的门（或墙）打烂——这正是玩家要的「直接凿墙走」。

**是否改变「禁门」设计**：不改。收留/投喂期照样开不了门，只有 `Leaving` 且**已经走不掉**时才砸。

**工作量**：小。1 个新文件（~20 行）+ 1 个 helper + 4 处替换 + 1 行 XML + 2～3 个单测（现有 `Source/Tests/RHAH_DoorPatchTests.cs:59-103` 不用改，因为门禁没动）。

**风险**
- 会破坏玩家的门/墙（可用候选 B 消掉，或让候选人先试「开门放行」再砸）；
- 不能自走/被抱的幼年来客：`RejectsSelfExit`（`RHAH_VisitorRules.cs:937-941`）只拦 `exitMapOnArrival` 的 Goto，**不拦 `AttackMelee`**，所以砸墙 Job 会照发；但幼童多半 `WorkTagIsDisabled(Violent)`，砸不动（见 2.5）；
- 抢不到门（多人同时抢一扇门）→ `WaitNearJob` 干等；
- 需要确认 `JobGiver_RHAH_Departure` 在 `ThinkNode_Priority` 里抛异常会被吞成一条 `Log.Error`（`"Exception in " + … + " TryIssueJobPackage: "`，【IL】`ThinkNode_Priority.TryIssueJobPackage` 的 catch 分支）——这条正好可以当验证断言。

### 候选 B（最便宜、不砸东西）：只对「正在离场」的来客放开 `PawnCanOpen`

**改哪里**：`Source/Pawn/RHAH_DoorPatch.cs:16-20` 的早退条件里加一条：`RHAH_Api.Get(p)?.Lifecycle == RHAH_Lifecycle.Leaving` 时 `return`（不动原版结果）。可选再加 `RHAH_VisitorStay.Kind(p) == (int)RHAH_StayKind.None` 收紧到「已不在收留中」。

**语义**：现有 `JobGiver_RHAH_Leave` 的 Goto 立刻就能寻路出门，一行代码解决「到点被困」。不砸任何东西，观感最好。

**与 `RHAH_DoorPatch` 打架吗**：就是改它，是本方案里**唯一**碰门禁的一条。

**是否改变「禁门」设计**：**会**（只在 `Leaving` 阶段）。严格说这是「禁门照旧、给正在离开的人放行」，但它确实扩大了能开门的人群，按玩家「保留默认禁门」的要求**必须先问**。

**工作量**：最小（1 行 + 改/加 `RHAH_DoorPatchTests` 用例）。风险：`Leaving` 的来客理论上可以顺路去仓库拿吃的（但 `RHAH_VisitorLeave` duty 只发离场 Job，`RHAH_ReliefFood` 仍拦），以及「被驱逐的敌对来客」也会获得开门权（如票 0008 修法③所述）。

### 候选 C（最 vanilla、最重）：把 RHAH 的离场 toil 换成原版 `LordToil_ExitMap(Jog, canDig:true)`

**改哪里**：`Source/Pawn/LordJob_RHAH_Visitor.cs:229` 的 `LordToil_RHAH_VisitorLeave` 换成 `new Verse.AI.Group.LordToil_ExitMap(LocomotionUrgency.Jog, canDig: true, interruptCurrentJob: false)`；并在 `CreateGraph` 里追加一条 `Transition(…, target=该 toil)` + `new Trigger_PawnCannotReachMapEdge()`（仿 `LordJob_VisitColony.CreateGraph`）。

**语义**：\(100\%\) 复刻原版，连 `MessageVisitorsTrappedLeaving` 提示都会有。

**与 `RHAH_DoorPatch` 打架吗**：不打架（同上，砸门不过 `PawnCanOpen`）。

**是否改变「禁门」设计**：不改，但**会绕开 RHAH 的行为闸门与携带逻辑**：`LordToil_ExitMap.UpdateAllDuties` 会把 duty 覆盖成 `DutyDefOf.ExitMapBest`，`RHAH_Api.Allows(ExitMap)` 不再被查询；`LordToil_ExitMap` 对**所有** ownedPawns 生效，倒地/囚犯/收留中的也会被推去出图；`CarryDependent`（`JobGiver_RHAH_Leave.cs:89-152`）与 `RHAH_CarryYoung` 的抱孩子流程整段失效。

**工作量**：中-大。风险最高（改 lord 图影响存档里的 toil 索引；`LordJob_RHAH_Visitor.cs:291` 那句「追加 toil 保持已发布访客图的旧索引不变」就是上一次踩坑的注释）。**不建议**。

### 优先级

A ≻ B ≻ C。A 是「用原版机制、不改设计、代价是砸门」；B 是「不砸门、但要玩家点头改门禁」；C 只在「必须连提示文案都一致」时才值得。

## 五、「该走」的判定条件（RHAH 内）

### 5.1 权威字段

`CompRHAH_Pawn.State.lifecycle`（`RHAH_Lifecycle`）——**`== RHAH_Lifecycle.Leaving` 就是「该走」**。

- `RHAH_Api.IsVisitor(p)` = `lifecycle != Released && lifecycle != Dead`（`Source/Identity/RHAH_PawnState.cs:42-43`，经 `Source/Api/RHAH_Api.cs:36-40`）。
- 行为闸门 `ExitMap` 只看这一个字段：`return lifecycle == RHAH_Lifecycle.Leaving;`（`Source/Identity/RHAH_PawnDefaults.cs:62-63`）。

### 5.2 `Leaving` 是谁写的

| 位置 | 触发场景 |
|-|-|
| `Source/Pawn/RHAH_VisitorStay.cs:131`（`RestoreDeparture`） | ① 收留/雇佣/招募**到期**（`:83` → `:102`）；② 半截状态修复（`:71-75` + `RHAH_VisitorRules.RestoresStuckDeparture:831-835`：玩家派系 + 已 `Leaving` + 不在收留中）；③ 玩家驱逐/到期信 |
| `Source/Pawn/LordJob_RHAH_Visitor.cs:254` | 路人（`IsPasserby`）到达后 |
| `Source/Pawn/LordJob_RHAH_Visitor.cs:687` | `LordToil_RHAH_VisitorTravel` 里路人到点 |
| `Source/Pawn/LordJob_RHAH_Visitor.cs:753` | `LordToil_RHAH_VisitorLeave.UpdateAllDuties` |
| `Source/Pawn/LordJob_RHAH_Visitor.cs:797`、`Source/Pawn/RHAH_BatchAttitude.cs:262`、`Source/Pawn/JobGiver_RHAH_Leave.cs:33` | 驱逐 / 批次反应 / 离场 Job 下发时兜底写入 |

### 5.3 「还不想走」怎么区分

`LordJob_RHAH_Visitor.ReadyToLeave(pawn, snapshot)`（`Source/Pawn/LordJob_RHAH_Visitor.cs:561-589`）：

```
Leaving                                  → true（已判过，不重复判）
MouseSwarm 来源 / ArmedDemand.Holds      → false
WaitFood toil 且在食物名单里              → 等 FoodWaitDeadline 到点
否则 = Allows(LeaveAfterFed) && FedLeaveDue(settings.leaveAfterFed, HasBeenFed, now, LeaveAfterGameTick, Downed)
        || FoodWaitExpired(pawn, snapshot)
```

`FedLeaveDue` 规则体在 `Source/Pawn/RHAH_VisitorRules.cs:754-757`：`leaveEnabled && hasBeenFed && !downed && leaveTick >= 0 && now >= leaveTick`；`NoFoodWaitExpired` 在 `:749-752`。

⇒ **一句话判别式**：`Lifecycle == Leaving` ⇒ 该走；否则 `ReadyToLeave` 决定；`stayKind ∈ {Shelter, Hire, Recruit}` 期间（`RHAH_VisitorRules.IsColonyStay:873-878`）**不该走**。

### 5.4 「不该走的人」原版已经挡住

- 倒地且不能爬：`JobGiver_ExitMap.TryGiveJob` IL_0000 直接 null；
- 不能自走的来客被人塞出图 Goto：`RHAH_VisitorRules.RejectsSelfExit`（`:937-941`）否掉 `Pawn_JobTracker.StartJob`；
- 囚犯/奴隶/玩家派系：`RHAH_BatchAttitude.CanOrderLeave`（`Source/Pawn/RHAH_BatchAttitude.cs:207-218`）；
- 收留计时期暂停：`RHAH_VisitorStay.PausesStay`（`:105-118`）+ `RHAH_VisitorRules.StayExpired`（`:821-824`，「倒地不计时」）；
- 死了：`Tick` 里 `pawn.Dead` 直接 return（`RHAH_VisitorStay.cs:63`）。

⇒ 「不替玩家做决定、倒地不硬走、囚犯/招募走不了、死了就死了」这四条**已经由现有代码 + 候选 A 的原版语义同时满足**，不需要额外写逻辑。

## 六、游戏内复现与验证方案

> 环境约定（沿用 `docs\RimWorld-隔离测试环境-已创建rhah-profile-20261024.md`）：独立 profile `rhah`（14 个 mod，含 RHAH + RimBridgeServer + DSH_GameLink），**不碰玩家那一局**，速度上限 `Fast`，禁 `Superfast/Ultrafast`。

### 6.1 复现「治好后被关在房里出不去」（修复前必须能稳定复现，否则修复无法证伪）

前置：
1. `node src\cli.js start --profile rhah`（后台 job）→ `node src\cli.js status --profile rhah` 需同时看到 `runningState: running` **和** `bridge.reachable: true`。
2. `dump-tools` 落 `runs\tools.json`（确认 `step_game_ticks` / `take_screenshot` / `run_lua` / `execute_debug_action` / `get_cell_info` / `get_ui_state` 都在）。
3. `load_game_ready` 或 `start_debug_game_ready`，等 `wait_for_game_loaded{readiness:'currentMap'}` 满足 + `get_bridge_status.state.programState == 'Playing'` + `ticksGame > 0`。
4. `get_ui_state.windowsForcePause` 必须为 `false`（否则 `step_game_ticks` 静默 0 tick —— 本工程已实测踩过）。

摆场景（两条路，选一条）：
- **A. 纯 run_lua 摆**（推荐，确定性最高）：`run_lua` 建一个 5×5 房间（玩家派系墙 + 一扇 `Door`），把一个已存在的来客 `Pawn` 传送到房间里中心，然后：
  - `RHAH_Api.SetLifecycle(pawn, RHAH_Lifecycle.Leaving)`；
  - `pawn.mindState.duty = new PawnDuty(DefDatabase<DutyDef>.GetNamed("RHAH_VisitorLeave"))`；
  - `pawn.jobs.StopAll()`；
  等价于 `RestoreDeparture`（`Source/Pawn/RHAH_VisitorStay.cs:120-138`）的后半段，但不依赖"等 5 天到期"。
- **B. 走真实收留到期**：用调试动作/信件选项让来客进入短期收留，再把 `shelterDays` 调到 1（设置项 `RHAH_Settings.shelterDays:114`），`step_game_ticks` 推 ~60 000 tick 等 `RestoreDeparture`。慢、但端到端。

**修复前的可观测断言（应当全部成立）**：
1. `mindState.duty.def.defName == "RHAH_VisitorLeave"` 且 `RHAH` 生命周期为 `Leaving`；
2. 连续两次 `step_game_ticks{ticks: 600, pauseFirst: true}`（判据只看返回的 `advancedTicks == 600`，不看 `success`），pawn 的 `position` 仍在房间矩形内；
3. `pawn.jobs.curJob` **始终为 null**（`JobGiver_RHAH_Leave.cs:60-63` 返回 null → `JobGiver_RHAH_Visitor.cs:83-87` 直接返回 null），或偶尔出现 `Goto` 但立刻被 `EndCurrentJob`（若走候选 B 时会看到 Goto 正常执行）；
4. 那扇门的 `HitPoints == MaxHitPoints`（**没有凿的痕迹**）；
5. `map.mapPawns.AllPawns` 里该 pawn 仍在；
6. 截图（`take_screenshot`）入 `runs\<runId>\`：人在房间里，门完好。

### 6.2 修复后怎么验证「他会自己凿墙/走到边缘离场」

按候选 A 落地后：

**主断言（决定性）**：
1. `pawn.jobs.curJob.def == JobDefOf.AttackMelee` 且 `curJob.targetA.Thing.def.defName` 是那扇 `Door`（或某段 `Wall`）——**这是「凿」的直接证据**；
2. 该门的 `HitPoints` **下降**（`get_cell_info` 独立回读，不信 job 字段）；
