## 4. 承重数字：骑车到底值不值（**写代码前必须知道**）

全部由已确证的常量推出【IL + 原版XML】：

- `MoveSpeed` 的 `defaultBaseValue = 3.0`，且 `ticks = Clamp(1/(v/60), 1, 450)`
  → **`MoveSpeed` 的单位就是「格/秒」**，`v=3.0` → 20 tick/格
- 另有修正：restraints ×0.35、搬人 ×0.6、对角 ×1.41421、天气

设：行程 `D` 格、绕路取车 `d` 格、车载速度 `v_b` 格/秒、上下车开销 `O` 秒。

```
直接走：      T_walk = D / 3
骑车：        T_bike = d / 3 + D / v_b + O

骑车更快的条件：   d < D · (1 − 3/v_b) − 3O
```

| 车速 | 加速比 | 可接受的绕路 |
| --- | --- | --- |
| 4.5 | 1.5× | `d < D/3 − 3O` |
| **6.0** | **2×** | **`d < D/2 − 3O`** |
| 9.0 | 3× | `d < 2D/3 − 3O` |

**代入一个真实场景**：若车平均散布在 ~10 格内（期望绕路 `d ≈ 5`），2× 车、
`O=2` 秒上下车，则需 `D > 2×(5 + 6) = 22` 格才划算。
**殖民地跨度不到 ~22 格时，共享单车是负收益。**

> ⚠ **「人口越多越划算」这条需求本身是坑。**
> 车数固定 + 人口上升 → 争用上升 → 等待上升 → **收益反而下降**。
> 要真的随人口产生正收益，需要：① 车数随人口增长；② **目的地分散**
> （如果所有人都挤向同一个仓库，该建的其实是**公交线**而不是共享单车）；
> ③ 轻量调度（按最近 / 最久未用选车）。

**这就是 Step 0 的产出**：先把这个数字算出来，再决定做不做、以及车速该定多少。

## 5. 难点分级（回答「哪些专注、哪些随意」）

### 决定 80% 成败的那 20%（全部不是"加速"）

| 难点 | 占比 |
| --- | --- |
| **人车解绑总线无死角**（Step 3） | **~40%** |
| **「车停在哪」的规则**：还车要搜索合法格（不能生成在门洞/墙上/别人身上/不可通行格）；目的地会形成**车的堆积**；车是可通行 Thing → 挡路 / 被绕行 / 被 Haul 搬走 | **~25%** |
| **存档格式**（Step 4） | **~15%** |

### 看起来难、其实简单（**别过度设计**）

| 看起来难 | 实际 |
| --- | --- |
| 插思考树要 patch 一堆原版树 | **一行 XML**：`<insertTag>Humanlike_PostMain</insertTag>` + `<insertPriority>` |
| 加速要改 StatDef / PawnCapacity 一堆系统 | **一个 Postfix 打在 `Pawn.TicksPerMove(bool)`** |
| 共享要自己写占用管理 | **`Reserve(maxPawns:1)` + Job 生命周期自动释放** |
| 骑乘要把小人 despawn、冻结需求 | **不需要**（那是 Vehicles Framework 路线；小人始终是正常 spawned Pawn） |
| 要做 A/B 路径代价比较 | **不要**，直线距离估算就够（原版 AI 本身也是这个精度） |

### 看起来简单、其实很坑

| 看起来简单 | 实际 |
| --- | --- |
| Hediff 加速 | 进健康面板、可被治疗移除；`statOffsets` 在 `HediffStage` 上不在 `HediffDef` 上 |
| Apparel 加速 | 倒地/剥光/囚犯化会脱落 → 车消失 |
| 每 tick 找最近的车 | `O(小人×车)`；必须 MapComponent + 空间分桶 + 脏标记 |
| 车位置每 tick 跟随小人 | 会让"车跟着一个已放弃骑行的小人跑"。**只在上下车两个瞬时点写入** |

### 可以随意的地方

- `Defs` 下的**子目录名和文件名随便起**
- PNG 在 `Textures` 下的**子目录层数任意深**，只要 texPath 对应
- `drawSize == size` 直接用 1:1（原版 371 个里 222 个如此）
- 占位 texPath 用哪个原版物件都行（5 个候选见 Step 1）

## 6. 双 TFM 结构（**发布前必须补**）

```xml
<TargetFrameworks>net472;net10.0</TargetFrameworks>
```

| | `Source/1.6` | `Source/1.7` |
| --- | --- | --- |
| TargetFramework | `net472` | `net10.0` |
| 引用 | `Managed\mscorlib.dll` 等 / `Krafs.Rimworld.Ref 1.6.4871` | 游戏根 `Assembly-CSharp.dll` + `UnityStubs.dll` + `Waylith.dll` |
| LangVersion | `7.3` | `latest`（保守可用 `12.0`） |
| Harmony | 2.4.x | **3.0** |
| 输出 | `../1.6/Assemblies/` | `../1.7/Assemblies/` |

```
你的Mod/
├── About/About.xml
├── LoadFolders.xml          <v1.6>…<v1.7>…
├── 1.6/Assemblies/  1.7/Assemblies/
├── Defs/ Patches/ Textures/ Languages/     ← 版本无关，放根目录
└── Source/1.6/  Source/1.7/
```

**你现在做不到的事**：本机**没有 .NET SDK**（只有 5.0/6.0 运行时），所以 **`net10.0` 那一支现在编不出来**——
不是架构问题，是缺工具链。**主开发锁 1.6**（唯一可编译可测试），`Source/1.7` 先留空。

**但你的架构已经帮了你**：`Core`（纯逻辑，不引用任何游戏类型）/ `Game`（引用 `Assembly-CSharp`）的分层，
意味着 **Core 可以 `net472` 和 `net10.0` 各编一遍、一行不改**，1.7 真正要动的只有 `Game` 层。

## 7. 发布渠道与 AI 美术（针对「明确打算发布」）

### 7.1 规则侧（有实际效力）

| 问题 | 结论 |
| --- | --- |
| Valve 的 AI 披露义务 | **不适用于创意工坊**（Content Survey 是开发者发布 App 的流程；工坊上传者没有这个表单）。**此为推断，官方正反两面都无明文** |
| 「Tynan 禁 AI」 | **不实**。Ludeon 置顶发布规则全文**无 AI 条款**；那条规则出自**社区自建、非 Ludeon 运营**的 Discord |
| Tynan 真实立场 | AI 生成代码"不推荐"，但理由是**质量问题**；对"AI 生成 pawn 台词"**举例认可** |
| 唯一真会导致下架的路径 | **版权投诉（DMCA）**。工坊**不存在**"举报 AI"这个类别 |
| Steam SSA 6.D | 要求你保证 *"you have sufficient rights in all User Generated Content"*，且工坊物品**另有"originally created by you"的独立保证** |

### 7.2 版权：修图是**取得权利**的路径，不是洗白

- 美国版权局默认纯 AI 输出**不可版权**（*Zarya of the Dawn*、*Théâtre D'opéra Spatial* 均被驳回）
- **但** 2025 年 *A Single Piece of American Cheese* **获准登记**：作者做了 **35 轮迭代修改**并提交
  **过程文档（含延时录像）**，版权局认定"具备充分的人类原创作者身份"
- 中国北京互联网法院李某案：**"设计提示词、设置参数、进行个性化选择与安排"被写进判决理由**

→ **保全过程记录（提示词、参数、被否决的迭代、分层源文件、修图截图/延时录像）同时解决两件事**：
版权归属 + SSA 6.D 的权利保证。

### 7.3 声誉侧（软性，但成本真实）

工坊社区对 AI 美术的敌意是**有记录、可引用**的：高赞回复如
「*我宁愿看一个画得很烂、没用任何技法的手绘 sprite，也不想看一个根本没有作者的东西*」、
「*所有 mod 都该加 AI 标签，让我能过滤、能给标错的人举报*」。
（**未查证到**任何点名具体 mod 的抵制案例。）

**六条实操**：

1. 逐张**版权尽调**：不含可识别的版权角色 / logo / 真人肖像
2. **保全过程记录**（见 7.2）
3. **不要写虚假声明**（写"美术为原创/手绘"而实际以 AI 为主 = 投诉把柄）
4. **主动如实披露，写进 mod 描述正文**（不是评论区回复）；措辞可借 Nexus Mods 三分类，
   把"宣传图是 AI"和"游戏内素材是 AI"**分开说**
5. **把缩略图 / 宣传图手工化**——那是玩家最先看到、也最先吐槽的
6. **渠道分开规划**：Ludeon 官方论坛**不禁止** AI 美术，但**那个社区 Discord 不接受** AI 内容

> 反直觉但重要：被举出的反面典型恰恰是「**曾经披露、后来停止披露**」的作者。
> **被发现隐瞒的代价远高于主动说明。**
