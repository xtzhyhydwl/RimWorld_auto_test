# `cli wait` 用法（2026-10-24）

等一个**可观测条件**成立，替代「睡固定时长再赌一把」。判定在 Node 侧做一套（`src/wait.js`），
探针就是一次普通工具调用，条件 JSON 的算子与游戏内 `rb.poll` 的 15 个条件算子同构
（唯一的例外是 `not`，见算子表）。

```powershell
node src/cli.js wait --profile <p> [--source bridge] --probe <工具名> `
  (--condition '<JSON>' | --condition-file <文件> | --condition '@<文件>') `
  [--args '<JSON>' | --args-file <文件> | --args '@<文件>'] [--timeout 60000] [--interval 200]
```

| 退出码 | 含义 | 输出 |
| --- | --- | --- |
| `0` | 条件命中 | stdout 一个 JSON：`{ok, elapsedMs, attempts, probe, condition, sample, sampleTruncated}` |
| `2` | 超时（到 `--timeout` 仍不成立） | stderr：`condition` + 最后一次 `sample` + `attempts` + `elapsedMs` |
| `1` | 参数错 / 工具名不存在 / 桥接未就绪 / **条件本身写错** / 探针故障 | stderr 说明原因，绝不只印「超时」 |

默认 `--timeout 60000`、`--interval 200`；`--source` 只认 `bridge`（`event`/`process` 属 P1，未实现，传了直接 exit 1）。
命中立刻返回，不额外等一个间隔。
采样序列化后超过 **2000 字符**时只印前 2000 字符并标 `"sampleTruncated": true`（同时给一句
`要看完整载荷：node src/cli.js call <probe> …`）；完整载荷随时能用 `call` 重取，`src/wait.js` 里的 `sample` 始终是完整的。

## 多实例时先校验「连的是自己那一局」

`wait` 和 `call` 一样靠 `readBridgeInfo()` 找端口/令牌；1.7 的 `Player.log` 全机共用、后启动者整份重写，
`readBridgeInfo` 的「按最新记录」兜底可能把**别人的实例**当成你的 ⇒ 探针会打进别人的局，
而条件看起来"正常不成立/正常成立"。并发/多会话时，发 `wait` 前先跑
[`多实例并发安全-给运行中会话的补充说明-20261024.md`](多实例并发安全-给运行中会话的补充说明-20261024.md) §0 的三段校验
（记录里的 `pid` ↔ 监听该端口的 PID ↔ 那个 PID 的命令行含 `-savedatafolder=…\profiles\<profile>`），任一不符就别发命令。

## 路径取不到 ≠ 参数错（默认语义）

- **字段这一次不存在 ⇒ 这次采样算「未成立」，继续按 `--interval` 轮询。**
  `rimworld/list_colonists` 在没进图时载荷里根本没有 `colonists`，这正是为它设计的：
  调用方不该再自己套一层重试循环（那就是「动作后睡固定时长」又回来了）。
- **条件本身写错 ⇒ 立刻 exit 1**：不认识的算子、`countEquals` 给了字符串、组合子写法错、
  `path` 不以 `result.` 开头 —— 这些再等一万年也不会变。
- 超时且最后一次采样仍是「路径缺失」时，除了常规证据再打印两行：

```
路径 result.colonists 从头到尾都没取到；断在 colonists 这一段，那一层的可用字段：success, message
通常是还没进图（先等 {"path":"result.state.playable","equals":true}），或字段名写错；这条不是参数错误，是条件一直没成立。
```

（`exists` 不参与这套：它本来就是问「有没有」。）

## `result.` 是什么

`result` 指**这次探针调用返回的载荷根对象**。桥接的 `callTool` 原样返回载荷，不再套一层：

- `rimbridge/get_bridge_status` → `{success, state:{hasCurrentGame,…}, version, …}` ⇒ `result.state.hasCurrentGame`
- `rimworld/list_colonists` → `{success, count, colonists:[{job,…}, …]}` ⇒ `result.colonists`

根条件的路径**必须以 `result.` 开头**，写成 `state.hasCurrentGame` 会报错（不会替你猜）。
`allItems`/`anyItem` 内部的子条件，`path` 相对**列表元素**，此时**不要**带 `result.`
（例 `{"path":"result.colonists","allItems":{"path":"job","in":["Wait_Combat"]}}`）。
数组元素用数字段取：`result.colonists.0.job`。

## 15 个算子（每个一条最小例子）

组合子（节点里只放一个键）：`all` / `any` / `not`

| 算子 | 例（都可直接当 `--condition`） |
| --- | --- |
| `all` | `{"all":[{"path":"result.count","greaterThan":0},{"path":"result.success","equals":true}]}` |
| `any` | `{"any":[{"path":"result.state.inEntryScene","equals":true},{"path":"result.state.hasCurrentGame","equals":false}]}` |
| `not` ⚠ | `{"not":{"path":"result.state.longEventPending","equals":true}}`（**本仓库扩展，`rb.poll` 没有这个算子**） |
| `path` | 不是独立算子：每个叶子都靠它指定读哪里，例见下 |
| `exists` | `{"path":"result.state.hasCurrentGame","exists":true}`（`false` = 要求这个字段不存在） |
| `allItems` | `{"path":"result.colonists","allItems":{"path":"job","in":["Wait_Combat","Wait_MaintainPosture"]}}` |
| `anyItem` | `{"path":"result.colonists","anyItem":{"path":"drafted","equals":true}}` |
| `countEquals` | `{"path":"result.colonists","countEquals":3}` |
| `equals` | `{"path":"result.state.programState","equals":"Playing"}` |
| `notEquals` | `{"path":"result.state.programState","notEquals":"Entry"}` |
| `in` | `{"path":"result.state.programState","in":["Playing","Paused"]}` |
| `notIn` | `{"path":"result.state.programState","notIn":["Entry","Loading"]}` |
| `greaterThan` | `{"path":"result.count","greaterThan":0}` |
| `greaterThanOrEqual` | `{"path":"result.state.mapCount","greaterThanOrEqual":1}` |
| `lessThan` | `{"path":"result.state.fadeOverlayAlpha","lessThan":0.01}` |
| `lessThanOrEqual` | `{"path":"result.state.mapCount","lessThanOrEqual":2}` |

补充：`countEquals` 要求采样值是数组、四个比较算子要求采样值与该值都是数字，不符即 exit 1；
`allItems`/`anyItem` 的值是一个子条件节点；`all:[]` 恒真、`any:[]` 恒假。

## 文件传参（PowerShell 必看）

PowerShell 会把行内 JSON 的双引号吃掉（`'{"path":"result.x"}'` 到 node 手里变成 `{path:result.x}`）。
所以给文件是**主用法**，带 BOM 的 UTF-8 也能读：

```powershell
Set-Content cond.json '{"path":"result.state.hasCurrentGame","equals":true}'
node src/cli.js wait --profile voiced --probe rimbridge/get_bridge_status --condition-file cond.json
node src/cli.js wait --profile voiced --probe rimbridge/get_bridge_status --condition '@cond.json'   # 同一件事
```

`@` 写法**必须带引号**：不带引号的 `--condition @cond.json` 会被 PowerShell 当成 splatting，直接报参数错。
`--condition-file` / `--args-file` 不受影响。

## 三个例子

**1. 等殖民地人数到 3**（`args.json` = `{"currentMapOnly":true}`，`cond.json` = `{"path":"result.colonists","countEquals":3}`）

```powershell
# ① 先等图载入完成（这些字段任何时候都在）
node src/cli.js wait --profile voiced --probe rimbridge/get_bridge_status --condition-file ready.json
# ② 再等人数到 3
node src/cli.js wait --profile voiced --probe rimworld/list_colonists --args-file args.json --condition-file cond.json --timeout 60000
# exit 0 → {"ok":true,"attempts":N,"elapsedMs":…,"sample":{"success":true,"count":3,"colonists":[…]}}
```

也可以只跑 ②：未进图时 `colonists` 不存在，会被当成「还没成立」继续等下去，进图后条件成立即返回。
先等 ① 只是让「到底卡在哪」更早、更清楚（超时信息会直接指到 `playable`）。

**2. 等图载入完成**

```powershell
node src/cli.js wait --profile voiced --probe rimbridge/get_bridge_status --condition-file ready.json
# ready.json = {"all":[{"path":"result.state.hasCurrentGame","equals":true},{"path":"result.state.playable","equals":true}]}
```

**3. 等 UI 窗口全部关掉**（`get_screen_targets` 的 `targets.uiState.windowCount`）

```powershell
node src/cli.js wait --profile voiced --probe rimworld/get_screen_targets --condition-file win.json
# win.json = {"path":"result.targets.uiState.windowCount","equals":0}
```

## 本文件已实测 / 未实测

**实测（2026-10-24）**：
- 真机（voiced 在线）：`{"path":"result.state.hasCurrentGame","exists":true}` → exit 0、`attempts=1`、`elapsedMs=12`；
  `{"path":"result.state.mapCount","equals":12345}` + `--timeout 1200` → exit 2、`attempts=7`、`elapsedMs=1211`，带条件 + 最后采样。
- 假桥接离线（`timeoutMs=300`、探针恒返回 `{success:false,message:'No current map'}`，与未进图的 `list_colonists` 同形）：
  字段缺失**不再 exit 1**，而是继续轮询到超时。`waitFor` 返回 `ok:false`（**不抛**）、`attempts=3`、
  `missingPath={path:'result.colonists', brokenAt:'colonists', available:['success','message']}`；
  CLI 层 exit 2，stderr 含「从头到尾都没取到 / 断在 colonists」两行 + 完整 JSON 证据。
- 打印截断：同一条件、采样 2625 字符 ⇒ 只印 2001 字符并标 `"sampleTruncated": true`（`call` 完整打印 126 行 / 3691 字符，
  `wait` 的 stderr 28 行 / 3232 字符，其中 JSON 块 23 行 / 2737 字符）。
- `'@文件'` 带引号可用（exit 2 而非参数错）；行内 JSON 不带引号会被 PowerShell 吞引号（实测直接报 JSON 解析失败）。
- 求值器离线：16 例算子矩阵 0 mismatch；未知算子 / `countEquals` 给字符串 / 缺 `result.` 前缀 → 抛；
  路径缺失 → `false`（`allItems`/`anyItem`/四个比较算子/`not` 等 15 个算子 + 数组下标都覆盖）。
- 参数错、`--source event|process`、工具名不存在、桥接不可达 → 均 exit 1，最快的桥接不可达 51ms 返回。

**未实测**：
- 例子 3（`windowCount` 归零）没在真游戏里跑过；字段路径取自 `runs/voiced-targets.json` 的真实载荷。
- `--source event` / `--source process`（P1 未实现，故意不做空壳）。
- 探针故障分支只在离线注入里出现过；真机上没人为制造过一次。
- 真机上的长等待（`--timeout 60000` 量级）没跑过，实测都是 0.3–1.2s 的短跑。
- `not` 下发 `rb.poll` 的同构性：`rb.poll` 的 15 个算子**不含** `not`，含 `not` 的条件不能原样下发。
