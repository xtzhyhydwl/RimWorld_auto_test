## 5. 附带源码的 mod：源码完整度如何

先看整体口径（`Source\` 与 `*.csproj` 并存与否）：

| 情况 | 数量 |
|---|---|
| 有 `Source\` 且有 `*.csproj` | 141 |
| 有 `Source\` 但**没有** csproj | 18 |
| 有 `*.csproj` 但**没有** `Source\` 目录 | 4 |

"有 Source 但没 csproj"的 18 个里，多数只是丢了一堆 `.cs` 源文件（缺工程文件，无法直接编译）。抽查明细见下。**结论：附带的源码普遍不完整**——要么缺工程文件，要么工程文件里的 `HintPath` 指向**本机不存在的绝对路径**。

### 例 1：`WS\1578693166` NewRatkinPlus（鼠族本体）— 源码基本齐全但引用路径失效

- 有 `1.6\Source\NewRatkin.csproj`（5,512 B）+ `NewRatkin.sln`，非 SDK 风格，`TargetFrameworkVersion = v4.7.2`
- `<Compile Include=>` **4** 条（用通配 `**\*.cs` + 3 个显式）→ 源码目录下实际有 **147** 个 `.cs`
- `<Reference Include=>` **11** 条，`<HintPath>` **8** 条
- **`HintPath` 全部指向本机不存在的路径**（实测 `Test-Path` = False）：
  - `C:\Program Files (x86)\Steam\steamapps\workshop\content\294100\2009463077\Current\Assemblies\0Harmony.dll` → **不存在**（本机 Harmony 在 D 库且实际布局是 `2009463077\1.6\Assemblies\0Harmony.dll`，没有 `Current\` 目录）
  - `C:\Program Files (x86)\Steam\steamapps\common\RimWorld\...` → **不存在**（本机游戏在 `D:\SteamLibrary`）
- 源码里有 `AlienRaceCompat\`、`AutoTests\`、`TestCode\` 等目录，以及 `Patch_InfoCard_HotSwap.cs`、`DamageWorker_ChainSword.cs` 等 147 个 `.cs`；`bin\`、`obj\`、`.vs\` 也在包里
- 判定：**源码内容看起来是完整的（有 sln/csproj/全部 cs），但工程不可直接还原编译**——所有外部引用指向别的 Steam 库盘符与一个不存在的 `Current\` 子目录；同时 `lib\`/`packages\` 目录数为 0，没有随包携带被引用 dll。

### 例 2：`WS\3613814532` RKU.RatkinUnderground — 有 csproj + 157 个 cs，但依赖一批本机没有的 dll

- `1.6\Sources\RatkinUnderground\RatkinUnderground.csproj`（29,188 B），非 SDK 风格，`TargetFrameworkVersion = v4.8`
- `<Compile Include=>` **155** 条，目录下 `.cs` = 157
- `<Reference Include=>` **84** 条，`<HintPath>` **81** 条
- `HintPath` 用相对路径回退到 Steam 库，例如 `..\..\..\..\..\..\..\workshop\content\294100\839005762\1.6\Assemblies\0Harmony.dll`——实测**该文件存在**（True），说明作者按自己的库结构写相对路径，在本机恰好能解析
- 但 `..\..\..\..\..\RimWorldWin64_Data\Managed\Unity.*.dll` 这类相对路径与本机实际盘符布局不同（本机游戏在 D 盘、工坊在 D 盘，相对关系需实际验证；`lib\`/`packages\` 目录数 = 0）
- 判定：**源码相对完整**（155/157 编译项 + 81 条 dll 引用），但 `<ProjectReference>` = 0，全部走 `HintPath` 硬绑定某些工坊 mod 的 dll 版本；未随包携带任何被引用 dll。

### 例 3：`WS\3761197692` dtrndg.rkbodypartanimate（[DG] Ratkin BodyPart Animation）— 有 Source、**完全没有 csproj**

- mod 根下有 `Source\`（含 5 个 `.cs`：`RKBodyPartAnimateSettings.cs`、`RKEarBreathingAnimator.cs`、`RKEarFlickAnimator.cs`、`RKTailBreathingAnimator.cs`、`RKTailFlickAnimator.cs`），`*.csproj` 数 = **0**
- 同时有 `Assemblies\` 里编译好的 dll（见 4.3），即"给了源码但不给工程文件"
- 判定：**源码不完整**——只能读代码，无法直接编译还原 dll。

### 例 4（反例，说明确实存在完好的）：`Mods\PetDoor` — 小而全

- `Source\PetDoor.csproj`（2,386 B），非 SDK 风格，`TargetFrameworkVersion = v4.7.2`
- `<Compile Include=>` 2 条，目录下 `.cs` = 2（一一对应）
