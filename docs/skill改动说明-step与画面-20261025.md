## 3 新增的 §4（推时间.md）写了什么

1. **机理一句话**：暂停态硬推 tick，逻辑照跑、坐标是对的，但引擎不连续出帧、pawn 绘制位置不刷新。
2. **实测证据**（可直接引用）：`Avila (104,110)→(110,111)`、`Ren (110,115)→(114,113)` 而名字标签像素位移 = 0；
   按格裁剪仍在旧格；雪牛同样冻结；`play_for` 400 ms（≈74 tick）后立刻追平，之后再 `step` 又冻。
   **人现场验证**：同一实例手动放开时间画面完全连续正常 ⇒ 游戏与引擎没问题。
   环境侧不背锅：1.7 = Waylith + Vulkan，Unity 图形参数无解析者；`-monitor` 被忽略、`-screen-width` 生效；813×486 是 DPI=192 虚拟化值。
3. **选型表**（纯 step / 纯 `play_for` / 混合 × 适用场景 / 速度量级 / 画面是否会动 / 风险）：
   纯 step ≈100 tick/s、画面冻结、期间截图不可用；纯 `play_for` ≈真实时间（600 tick ≈3.3 s，**按实测 182 tick/s 折算的量级估计**）、画面连续；
   **混合 = 推荐默认**（速度接近纯 step，画面基本连续，像快进）。
4. **可复现判据**：推进前记旧格 → `step` 后回读得新格 → `screenshot_cell_rect` 裁旧格与新格 → 旧格还有人 = 冻结帧作废，先 `play_for` 再来。
5. **不擅自提速**：不要为画面启用 `Superfast` / `Ultrafast`（需用户当次同意），要快就用混合加段。
