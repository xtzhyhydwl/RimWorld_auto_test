## 3. 后续每局的固定流程（人做，agent 只看）

> **目标**：把"可变因素"压到最小，让**流程结构**（而不是某次事件）成为可比较的对象。

### 3.1 硬性规则

| # | 规则 | 说明 |
| --- | --- | --- |
| 1 | **游戏保持用户手动控制** | 全程由用户操作；**不使用自动化桥接干预**——不下达 `rimworld/start_debug_game_ready`、不 `step_game_ticks`、不 `apply_architect_designator`、不遥控 UI |
| 2 | **每局新建全新殖民地/存档** | 每局从"新建殖民地"开始；**不覆盖**上局存档，**不复用**上局文件名 |
| 3 | **尽量同一规则、同一难度/人数/落点选择原则** | 剧本、叙事者、难度、人数、开始区域（温带/山地等）**在同一套原则下选择**；确有必要的改变要**写进 §3.3 备注** |
| 4 | **不使用自动化桥接干预** | 见第 1 条；桥接即使可用也不接进来 |
| 5 | **正常游玩到约 20 游戏日** | 目标 ≈ **1,200,000 tick**（1 游戏日 = 60,000 tick；`day = tick/60000` 是**殖民地建立以来**的天数，**不是游戏内日期**） |
| 6 | **完成后记录三件事** | ① 实验编号 ② 存档名 ③ 结束时间（墙钟 + 游戏内 tick） |

### 3.2 时间基准与"计数从哪开始"

- **tick 基准**：`tick` = **本殖民地建立以来**的 tick（新局从 1 开始）；`absTick` = 游戏进程绝对 tick。**两局之间的"同一天数"要用 `tick` 比，不要用 `absTick` 比**。
- **20 日的判定**：以**该局 `tick` 的推进量**为准（≥ 1,200,000 即达标），而不是墙钟时长。
- **慢速/暂停**：允许暂停与变速；只要**最终 tick 推进量**达标即可。但**不要在记录中途改 `intervalTicks`**（默认快照 6,000 / 操作 30）。

### 3.3 每局必记（贴到 §6 的记录表里）

- **实验编号**（建议 `EXP-03`、`EXP-04`；基线的 A/B 记为 `EXP-01` / `EXP-02`）
- **runId**（ColonyRecorder 在 `Player.log` 里打印，形如 `20261004-115726-0-ce9c`）
- **存档名**（`Saves\*.rws`）
- **开始时间 / 结束时间**（墙钟，`HH:mm:ss`）
- **结束时的 `tick`**（≈ 1,200,000 附近）
- **殖民地正式命名时间**（第 1 次把默认名改掉的那一刻）
- **关键建造 / 指定 / 区域 / bill / 事件**（见 §5.4 表格）

## 4. 分析分组规则（**先 runId，再 logical game**）

```
第 1 步  按 runId 分桶            ← 同一次游戏进程启动 = 一个 runId
第 2 步  在 run 内按 logical game 分段   ← 拆局只看两个信号：
                                       (a) tick 回到 1（新殖民地建立）
                                       (b) 出现新的 baseline 行
第 3 步  sessionSeq 只在"局内部"编号      ← 段内顺序，不跨局比较
```

### 4.1 三条"不许用"的判据

| 不许用 | 为什么 |
| --- | --- |
| ❌ **文件名** `colony-<名>-<mapId>.jsonl` | 它是**命名那一刻新开一份文件的副作用**；同一局会在命名前后分成两个文件 |
| ❌ **`mapId`** | 本 run 五段全是 `mapId=0`【已证实】⇒ 用它拆局会把 A 和 B 合并，把同一局的命名前后误拆 |
| ❌ **`colonyName`** | 它恰是"未命名→命名"的变量本身（§1.2 第 1 条） |

### 4.2 判定表

| 观察 | 结论 |
| --- | --- |
| 同一 runId、`tick` 继续往上走、只有 `colonyName` 变了 | **同一局**（A 的 s0001→s0002 就是这个形态） |
| 同一 runId、`tick` **回到 1**、`actions` 出现新 `baseline` | **拆局**（A→B 就是这个形态；14:04:50 的第 5 段也满足） |
| 出现**新 runId** | **另起一桶**（新进程会话），桶内再按上面两条分段 |
| 目录空 / 只有零星几行 | **不是样本**，不进分析（§1.4） |

### 4.3 旧数据隔离

- 主分析样本集合 = **基线（A、B）+ 后续手动新录的局**。
- **旧根目录旧 schema、`profiles\vanilla\…` 老格式文件**：只作辅助对照，**不与新样本混合**；若必须引用，在报告里**单独列一节并标明格式不同**。

## 6. 随机性控制原则

| 原则 | 具体做法 |
| --- | --- |
| **不追求完全相同的地图/事件** | 随机地图、随机殖民者、随机事件本身就是游戏的一部分；强行复现会失真 |
| **固定可控条件** | 剧本、叙事者、难度、开局人数、是否允许重掷（roll）——**同一套设定**并写进 §5.4 表 A 备注 |
| **记录不可控随机项** | 地形/生物群系细节、殖民者特质、事件序列、袭击规模 ⇒ 在表 B "备注"里写清，作为**解释差异**的候选，而不是**结论** |
| **跨样本只比稳定结构** | 比较对象：**建造/指定/区域的先后顺序、前置依赖、重复动作的模式**；不是"第 3 天该不该来袭击" |
| **不把单次事件当通用规律** | 一次袭击/一次疾病 ⇏ "这局必然如此"；**至少 3 样本重复出现才算模式** |
| **先 3 样本做重复模式，再扩到 5 样本** | 3 样本：找**重复出现的结构**；5 样本：检验这些结构是否稳定、并剔除偶然 |

### 7.1 允许做（只读）

6. 结论必须区分 **已证实 / 推断 / 未验证**。
