## 八、已实测的坑（**务必抄进脑子，这些是花代价换来的**）

| 坑 | 说明 |
| --- | --- |
| **反射：元数据里"有这个成员" ≠ 默认绑定拿得到** | `RimWorld.ResearchManager.currentProj` 在 1.6 是 **private 字段**，公有侧**没有** getter ⇒ `GetProperty` 和默认 `GetField`（只找 public）**都返回 null**（同一个地方踩了两次）。正解：公有 API `IsCurrentProject(def)` 遍历，再退化到带 `NonPublic` 的反射。反射必须**显式写 `BindingFlags`**，并**在运行时**验证（磁盘元数据会骗人）。 |
| **命名空间直觉会错** | `Blueprint` / `Frame` 在 **global 命名空间**（写 `Verse.Blueprint` 编译不过）；`Thing` 上**没有** `IsBlueprint/IsFrame`，要用 `ThingDef.IsBlueprint/IsFrame`；`Pawn_ApparelTracker/Pawn_SkillTracker/Pawn_StoryTracker/Pawn_WorkSettings` 在 **RimWorld**，而 `Pawn_HealthTracker/Pawn_AgeTracker` 在 **Verse**；`Map.Tile` 是 `PlanetTile` 不是 int；`BuildingProperties` **没有 `isDoor`**（只有 `isWall`，门要用 `Building_Door` 类型判）；`PawnCapacityDefOf` 是**静态 Def 字段**（不能 `DefDatabase<...>.GetNamed`）。 |
| **部署** | 游戏在跑时 Mono 把 DLL 映射住，覆盖会报 `ERROR_USER_MAPPED_FILE`/`UNKNOWN: copyfile` ⇒ `scripts/build-recorder.mjs --deploy` 已有"先删后拷"回退；还失败就手动先删后拷。**新 DLL 必须重启游戏才生效**（不会热加载）。 |
| **进程/启动** | `node src/cli.js stop` 可能误报 `stillAlive`（沙箱下进程枚举被拒）；`runs/game-process.json` 里的**陈旧记录**会让 `cli.js start` 拒绝启动（删掉那个文件即可）。（实测：该文件当前存在 —— 本线不用 `cli.js start`，但别被它绊住。） |
| **PowerShell** | `.ps1` 里有中文会解析失败（PS 5.1 按 ANSI 读）⇒ 临时脚本**只用 ASCII**；`Get-Content` 读中文日志会乱码 ⇒ 用 `read` 工具。 |
| **git** | `git commit -m "多行中文"` 会被引号拆坏 ⇒ 写进文件用 `git commit -F`。 |
| **别用 JS 正则改 C# 文件** | 引号打架、会替换错位置 ⇒ 用 `edit` 工具。 |
| **分析端也会"说假话"** | 报告里曾**无条件**印一句"research.current 全程空 → 读法失效"，在数据健康的文件里就是假话（已修成看数据才印）。**凡结论必须由数据决定**。 |
| **静默 `catch {}` 会把"读不到"伪装成"没有"** | `designations` 一度是 `catch (Exception) { }`，标记读失败时看起来就像"这一局没有标记"。已改成记 `warnings`（本项目纪律：**失败必须带原因**）。 |
| **换局/读档会让 tick 倒退** | 新地图 tick 从 ~0 开始，而采样状态是静态的 → `sincePrevTick` 算成负数、序号接着上一局走。已加"tick 倒退 = 新的一局，清采样状态"。 |
