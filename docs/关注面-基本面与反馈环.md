# 关注面（Concerns）：玩家真正在意的那几个**基本面**

> 来源：用户 2026-10-03。这一条把整件事**提升了一个层次**。
>
> 用户原话：
> 「就我刚才说的那些东西，它只是**一个侧面**，其实我还有很多**别的需要关注的面**。
>  比如说**科技的发展**，比如说**生产队列**，比如说**小人的心情**怎么变化。
>  然后可能玩家他做了某些好像**无法解释的行为**，但实际上是关照了小人心情的情况
>  —— 就是地图中的某些变化，其实他对小人的心情有**正向影响**，而这个是玩家**故意而为之**。
>  如果能分析到这一点，那么就说明可能 AI 也能够理解这个环世界当中
>  **殖民者心情**这么一个比较重要的要素是如何去考虑的。
>
>  我想说的就是，我作为玩家，我肯定不会具体地关心到**某个资源的数值**是多少，
>  而是我是**总体的**去观察所有资源，以及我会总体的观察整个建筑
>  ——有没有**缺的建筑**，或者说**生产队列**里边有没有说"我们需要、但是没有在生产"的东西。
>
>  很多东西它都是**关注一次之后、设置好一次之后就长期可使用**的那种情况。比如说食物对吧？
>  比如说厨房里面有烹饪食物，我就是挂一个那种**生产队列**，然后生产队列的满足条件是
>  **把这个食物维持到某个量**，然后挂住之后我就基本不会改了。
>  然后我**只有在某些情况下才会去变更**那个食物的生产：
>  比如说有**新的成员加入**，就是食物、烹饪食物马上要不够吃了，所以我要去增加；
>  或者说**殖民地越来越富有了**，然后小人他有一个**心情期望的基础值**，他会增高，
>  他心情会往下掉，这个时候我可能需要去生产**更好的食物**来满足小人的心情需求。
>  **他其实是连环的。**
>
>  但是只要我们能够把这些**基本面**都考虑到，我们能够**综合分析出为什么玩家要做出这样的操作**，
>  那他就更加接近真实的 —— 就是说一个比如说一个**新手环世界玩家**，
>  他怎么一步一步地去学习这个游戏、该怎么把它持续地玩下去，他就更接近这种模式了。」

## 一、要关注的"面"（不只是"存储区"这一个侧面）

| # | 面 | 玩家怎么看 | 游戏里的结构化对象（**已确证**） |
| --- | --- | --- | --- |
| 1 | **生产队列** | **"有没有我们需要的、但没在生产的东西"** | `RimWorld.Bill` / `BillStack` / `BillRepeatModeDefOf` |
| 2 | **科技** | 在研究生么、下一步研究什么 | `ResearchUtility` / `Alert_NeedResearchProject` / `Building_ResearchBench` |
| 3 | **心情** | 为什么掉、怎么补 | `ExpectationsUtility.CurrentExpectationFor(pawn)` / `ExpectationDefOf` |
| 3b | **★ 期望↔心情的环** | **"变富 → 期望↑ → 心情↓ → 要更好的食物"** | `RimWorld.PawnExpectationsQualityOffset` |
| 4 | 资源 | **总体的**，不是单个数值 | `listerThings` 聚合 |
| 5 | 建筑 | **有没有缺的建筑** | `listerThings` + 需求推导 |
| 6 | 功能分区 | 存储组/种植区/储藏区 | `StorageGroupManager` / `ZoneManager`（已做） |

## 二、★ 核心洞察：**反馈环**（玩家懂，AI 不懂）

用户点出的那个环：

```
殖民地变富（财富↑）
   ↓
小人期望基础值↑            ← ExpectationsUtility.CurrentExpectationFor(pawn)
   ↓
心情↓（同样的食物/房间不再满足他）
   ↓
玩家去生产**更好的食物**     ← 这个动作单独看"莫名其妙"：食物明明够吃！
   ↓
心情回升
```

★★ **为什么这条特别重要**：

如果一个 AI 只看"**食物够不够**"，它**永远看不懂"为什么要产精致食物"** ——
因为普通的饭**数量上完全够**。

→ 所以"**为什么玩家做了这个动作**"必须从**几个基本面联合**推出来，
  而不能从单一指标推。**这正是用户说"它是连环的"的意思。**

### 类似的环还有（值得一起建模）

| 环 | 链条 |
| --- | --- |
| **人口↑** | 新人加入 → 食物消耗↑ → 需要扩产 / 加床 |
| **财富↑** | 见上（期望→心情→食物品质） |
| **心情↓（别的原因）** | 环境丑/房间小 → 铺地板/加装饰 → 心情↑ |
| **科技↑** | 解锁新建筑 → 有更好的选择 → 改建/替换旧的 |

## 三、★ 另一条重要的**性质**：设定一次，长期不变

用户：
> 「很多东西它都是**关注一次之后、设置好一次之后就长期可使用**的那种情况。
>  挂住之后我就基本不会改了。然后我**只有在某些情况下才会去变更**。」

例：厨房挂一个 "维持米饭到 20" 的生产队列 → **就不动了**。

### 这个性质对"记录什么"有决定性影响

| 记录方式 | 能回答什么 |
| --- | --- |
| 只记"当前状态" | 知道现在挂着什么，但**不知道什么时候变的** |
| **状态 + 变更点** | 能回答"**他为什么在那一刻改了**" ← ★ 这才是金子 |

★ 关键：**变更点比变更内容更有信息量。**
  一个生产队列的**配置**是静态的；而"**第 12 天把目标从 20 改成 40**"
  这个**变更点**，配上那天的**人口/财富/期望**，才能推出规则。

→ 所以正确做法是**两者都要**：
  - **面向对象**：每次快照读全量对象（用户上一轮的要求）
  - **变更点**：对**同一对象**的历次快照做对比，**变更点**单独标出来（**注意：这不是"面向过程"，而是"对象的时序"**）

⚠ **重要区分**（免得我又走回头路）：
  - ❌ 面向过程 = 我**推断事件**（"用户点了按钮"），事件是我的**唯一数据源**
  - ✅ 对象时序 = 我**读对象**，然后**比较同一对象在不同时刻的值**
    → 数据源是**对象**，时序只是**同一对象的历史**。**这仍然是面向对象。**

## 四、★ 记录 vs 解释：这一层的目标

用户说得非常明确：
> 「只要我们能够把这些基本面都考虑到，我们能够**综合分析出为什么玩家要做出这样的操作**，
>  那他就更加接近真实的……一个新手环世界玩家，他怎么一步一步地去学习这个游戏。」

所以这一层的**目标不是"记录动作"，而是"还原动机"**：

```
输入：对象快照序列 + 每个变更点 + 那一刻的基本面（人口/财富/期望/食物/科技）
输出：**"他为什么这么做"** —— 例如
      "第 12 天把米饭目标 20→40，因为第 11 天新生儿加入，人口 3→4，
       日耗 4.8→6.4，按当前存量只够 6 天，低于他的 10 天舒适线"
```

★ 而"**AI 能不能理解殖民者心情**"是这个目标里最重要的一环 ——
  因为**心情是最多"看似无法解释的行为"的来源**（用户原话）。

## 六、和前面几条原则的关系

| 原则 | 内容 |
| --- | --- |
| **套公式 > 局部最优** | 能用公式/样板的，不要用算法 |
| **面向对象 > 面向过程** | 读游戏已存好的对象，不要推断事件 |
| **关注面 + 反馈环**（本文件） | 不要只看一个指标；**基本面是连环的** |

第三条是对前两条的**必要补充**：
- 前两条讲"**怎么拿数据**"（对象、公式）
- 这一条讲"**该看哪些数据、它们怎么互相影响**"

而用户那句「我作为玩家，**肯定不会具体关心某个资源的数值**，
而是**总体的**去观察」是这个文件的核心：
> **AI 要学的是"看基本面"，而不是"看每一个数值"。**
