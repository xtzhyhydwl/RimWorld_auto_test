## 0. 一句话架构

**钩子只负责"看见"，Announcer 负责"要不要说"，VoicePlayer 负责"说出来"。**

```text
游戏事件
  │
  ├─ NotifyHooks      ┐
  ├─ LetterHooks      │  每个钩子只做一件事：
  ├─ IncidentHooks    ├─► 把一个 Notice{Category, Text} 交给 Announcer
  ├─ PawnHooks        │
  └─ BlueprintHooks   ┘
                            │
                    ┌───────▼────────┐
                    │   Announcer    │  ← **唯一**查开关的地方
                    │ Switchboard    │     + 去重 + 合并窗口 + 定优先级
                    └───────┬────────┘
                            │ Utterance{ 片段序列 }
                    ┌───────▼────────┐
                    │  SpeechQueue   │  FIFO + 威胁插队
                    └───────┬────────┘
                    ┌───────▼────────┐   ┌──────────┐
                    │   VoicePlayer  │◄──│ TtsCache │
                    │ dspTime 游标   │   └──────────┘
                    └────────────────┘         ▲
                            │                  │ 后台线程
                        AudioSource ◄────── TtsClient (HTTP)
```

## 2. 唯一检查点（回应"是不是每个出发点都要查一遍开关"）

**不是。** 所有钩子调的都是同一个函数：

```csharp
Announcer.Receive(SpokenCategory.IncidentRaid, "侦测到袭击，机械族，从东边来");
```

`Announcer.Receive` 第一行：

```csharp
if (!Switchboard.Enabled(category)) return;   // 全 mod 唯一一处开关判断
```

加一个新的播报类型 = 三处各加一行（enum + 目录表 + UI 表），**没有任何一处 if 需要改**。
这就是 Easy to Change 的验收标准：新需求**加数据**，不改流程。

## 3. 播报类型（`SpokenCategory`，开发期全开）

开发阶段：**全部默认开**，不做三档，不做"空闲才播"（用户已定）。
每类一个 enum 值 + UI 一行开关。

`ThreatRaid`（袭击）· `ThreatSiege`（围攻/空投/集群）· `ThreatAnimalInsanity`（动物发狂）·
`PawnDowned`（倒地）· `PawnDied`（死亡）· `MentalBreak`（精神崩溃）· `Birth`（分娩/出生）·
`DiseaseOutbreak`（疾病爆发）· `DiseaseSpread`（感染/瘟疫）· `Addiction`（成瘾戒断）·
`TraderArrival`（商队）· `Visitors`（访客/难民）· `Quests`（任务/委托）·
`WeatherExtreme`（热浪/寒潮/火山冬天）· `EnvHazard`（耀斑/日食/毒尘/辐射）· `Rotten`（腐烂）·
`BuildMissingMaterials`（缺料，派生）· `BuildPlaceFailed`（落点失败）· `BillSuspended`（工作台缺料）·
`OtherIncident`（兜底）· `OtherLetter`（兜底）· `OtherMessage`（兜底）

## 4. 线程与生命周期

| 阶段 | 线程 | 约束 |
|---|---|---|
| 钩子读取游戏状态 | **主线程** | 只在钩子体内读 `Pawn`/`Map`/`Letter`，转成纯字符串 |
| `Notice` 生成 | 主线程 | `Notice` 里**不允许**带 `Thing`/`Pawn` 引用（只带 `LookTargets` 可选） |
| HTTP 合成 | 后台 `Task` | 绝不碰 Verse 对象；只传字符串 |
| WAV → `AudioClip` | **主线程** | 旧 mod 在后台建 `AudioClip`，是未定义行为（复盘 §8.2） |
| 播放 | 主线程 `Update` | `PlayScheduled(dspTime)` 游标 |

回主线程的通道：`GameComponent.Update` 里轮询一个 `ConcurrentQueue<合成结果>`（不依赖 `LongEventHandler`，避免加载期阻塞）。

## 5. 文本与音频的来源

一条 `Utterance` = 有序片段列表，每个片段是：

- `PreRecorded(defName)` —— 121 条旧 ogg 之一（若继承；未定）
- `Synthesize(text)` —— 走 TTS，键 = 原文，命中缓存则零延迟

**分工原则**：固定话术走预录（若没有则 TTS），动态内容（人名/派系名/商人类型/病名）走 TTS。
开发期第一版可以**全走 TTS**，把"预录"当成后续优化 —— 这样先打通链路，不被资产问题卡住。

## 6. UI 结构

- `Dialog_VoiceSettings`：`DoWindowContents` 里画左侧 4 个页签按钮 + 右侧内容区 + 底部 `恢复默认/关闭`。
- 每个 Tab 是一个类，实现同一个 `void Draw(Rect inRect)`。
- **开关表用一个公共绘制器** `DrawToggleList(entries)`，22 条和 4 条走同一段代码（DRY）。
- 改动即时写盘（不做"应用"按钮）。

## 7. 日志埋点（D11）

`Trace.Step("1")`、`Trace.Step("5.1")` … 只在 `Settings.traceEnabled` 时输出，前缀 `[VD]`。
固定埋 6 个主环节：
`1` 钩子被调用 → `2` 进入 Announcer（含分类与开关结果）→ `3` 进入队列（含队列长度）→
`4` 开始播放 → `5` TTS 请求（`5.1` 发 / `5.2` 回 / `5.3` 失败）→ `6` 播放完成。

## 8. 编码顺序（每步都能单独验收）

| 步 | 做什么 | 验收 |
|---|---|---|
| 1 | `About` + `VoiceDeputyMod` + 空 `Settings` | 游戏里 mod 列表可见、无红字、无报错 |
| 2 | 设置窗口 4 页签 + 存盘读回 | 改开关 → 重启游戏 → 状态还在 |
| 3 | 5 个钩子 + `Trace`，**不发声** | 日志里看到 `[VD] 1` / `[VD] 2`，分类正确 |
| 4 | `VoicePlayer` + 一条测试音（先用 TTS 或本地文件） | 按键能出声 |
| 5 | `TtsClient` + `TtsCache` + 试听按钮 | 试听成功、断网有明确失败提示 |
| 6 | `SpeechQueue` + 合并窗口 + 威胁插队 | 连发 3 个事件，不叠音、不丢失 |
| 7 | 蓝图缺料派生信号 | 放一个缺料蓝图，播「缺 35 钢铁」 |

**第 3 步就是自动化测试的第一个验收点**：不需要听觉，只要日志。

## 9. 明确不做

- 不做本地 TTS 模型（SiliconFlow 一个通道 + 可换 BaseUrl 就够）
- 不做多语言（文案全中文，但集中在 `SpeechCatalog` 一个文件）
- 不做音量混音组（自带滑条，D9）
- 不做"逐个 defName 勾选"（22 类封顶）
- 不做 pilot / 自主决策（与本文无关）
