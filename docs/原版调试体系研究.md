# RimWorld 原版调试体系研究

在 RimWorld 1.6.4871（原版 + 全 6 DLC + Harmony + RimBridgeServer）上实测。
目标是**把原版自带的调试能力摸清并形成规律**，作为 mod 自动化测试的地基。

数据源：通过桥接完整爬取了 debug action 树 —— 本次抓到 **40,021 个节点**（仍被上限截断，
真实规模更大）。原始数据在 `runs/debug-tree-*.json`，索引在 `runs/debug-tree-index.json`，
顶层动作清单在 `runs/debug-actions-top.md`，Settings/Outputs 详见 `runs/debug-settings-outputs.md`。

---

## 一、体系总览：只有 3 个根

| 根 | 规模 | 用途 |
| --- | --- | --- |
| **`Actions`** | **341 个顶层动作**（展开后 4 万+ 叶子） | 所有**动作**：生成、事件、改属性、播特效、地图操作 |
| **`Outputs`** | **247 项** | 纯**读取/诊断**：把游戏内部数值以文本吐出来 |
| **`Settings`** | **181 个开关** | 全局**开关**：确定性、加速、可视化叠加、日志、作弊 |

这三者分工非常清晰，正好对应测试的三个需求：**做事（Actions）/ 看数（Outputs）/ 调环境（Settings）**。

---

## 二、结构规律（5 条，全部实测得出）

### 1. 带 `...` 的是参数化动作，会按 Def 展开成海量叶子

这是树膨胀到几万节点的原因，也是**最有价值的一条**：

| 动作 | 展开出的叶子 |
| --- | --- |
| `Actions\Spawn thing...` | 1,387 |
| `Actions\Spawn fill area (rect)...` | 3,415 |
| `Actions\Add Hediff...` | 324 |
| `Actions\Spawn Pawn...` | 282 |
| `Actions\Give Trait...` | 73 |
| `Actions\Add Gene...` | 3 |

**含义**：你可以**直接按 Def 名寻址任意一个**，不必在游戏里翻几十层菜单。
例如 `Actions\Spawn Pawn...\Thrumbo`、`Actions\Add Hediff...\Acid burn`。

### 2. 父节点通常是 `BrowseOnly`，真正能执行的是叶子

父节点只是菜单容器。用 `execution.kind` 判断：
`BrowseOnly` = 只是个目录；`Direct` / `PawnTarget` / `MapTarget` / `WorldTarget` = 可执行。

### 3. `execution.requiredTargetKind` 决定调用时要传什么

| requiredTargetKind | 数量（本次） | 调用时传 |
| --- | --- | --- |
| （空） | 14,994 | 直接调 |
| `world` | 13,111 | 世界地图坐标 |
| `map` | 9,310 | `x`, `z` |
| `pawn` | 2,606 | `pawnId` 或 `pawnName` |

### 4. 标签以 `T:` 开头 = 工具型动作（需要在地图上画/点）

如 `Actions\T: Abandon Thing...`、`Actions\T: Set Stuff...`。

### 5. 标签以 `...` 结尾 = 执行后可能弹二级对话框

实测「Drop pod raid at location...」是 **4 步**：势力 → 点数 → 点地图 → 投放半径。
**不要硬编码层数**，用循环处理（见 `scripts/raid-full.mjs`）。

## 三、Actions：实测验证过的用法

### 3.1 生成 pawn（★ 替代会崩的 `spawn_thing`）

`rimworld/spawn_thing` 生成 pawn **必崩**（`Verse.Pawn.SpawnSetup` NullReferenceException）。
正确姿势：

```js
await call('rimworld/execute_debug_action', {
  path: 'Actions\\Spawn Pawn...\\Thrumbo',   // PawnKindDef 名
  x, z,                                      // requiredTargetKind = map
});
```

**实测验证**：执行 `Actions\Spawn Pawn...\AlphaThrumbo` → 回读落点区域出现 `Alpha thrumbo`。

`Spawn Pawn...` 下 282 个 pawn 里包括 `Thrumbo` / `Muffalo` / `Elephant` / `Megasloth` /
`Bear_Grizzly` / `Wolf_Timber` / `Cougar` / `Boomalope` 等，执行类型统一是 `MapTarget/map`。
同类还有 `Spawn Pawn With Lifestage...` / `Spawn Child...` / `Spawn Newborn...`（各 282-290）。

### 3.2 改人物属性（与你写人物 mod 直接相关）

**实测验证**：

```js
// 技能拉满 —— 两级结构，PawnTarget
await call('rimworld/execute_debug_action', {
  path: 'Actions\\Max Skill...\\Shooting',
  pawnId: 'Thing_Human409',
});
// → success=true

// 给特质 —— 两级结构，PawnTarget（注意标签带等级后缀）
await call('rimworld/execute_debug_action', {
  path: 'Actions\\Give Trait...\\nudist (0)',
  pawnId: 'Thing_Human409',
});
// → success=true
```

结构一览：

| 动作 | 叶子数 | 层级 | 叶子示例 |
| --- | --- | --- | --- |
| `Max Skill...` | 12 | 两级（技能名） | Shooting / Melee / Construction / Mining / Cooking / Plants / Animals / Crafting / Artistic / Medicine / Social / Intellectual |
| `Set Skill...` | 12 | 两级 | 同上 |
| `Set Passion...` / `Max Passion...` | 12 | 两级 | 同上 |
| `Give Trait...` | 73 | 两级 | nudist (0) / bloodlust (0) / kind (0) / psychopath (0) |
| `Add Hediff...` | 324 | 两级 | Acid burn / Adrenal heart / Aesthetic nose |
| `Set Backstory...` | 2 | 三级（Adulthood / Childhood） | — |
| `Add Gene...` | 3 | 三级（Xenogene / Endogene / Heritable） | — |

其他同类（未逐个验证但结构一致）：`Set Xenotype...`、`Change Age`、`Mental state...`（47）、
`Mental break...`（36）、`Apply damage...`（104）、`Give Ability...`（98）、
`Wear apparel (selected)...`（113）、`Equip primary (selected)...`（95）。

## 四、Settings：181 个开关（测试环境的控制面板）

这是**做确定性测试最关键的一块**。按用途分：

### 4.1 确定性控制（写回归测试必开）

| 开关 | 默认 | 作用 |
| --- | --- | --- |
| `Settings\Enable Storyteller` | on | **关掉 = 不再随机刷事件**，测试可复现 |
| `Settings\Enable Random Mental States` | on | 关掉 = 不随机精神崩溃 |
| `Settings\Enable Random Diseases` | on | 关掉 = 不随机生病 |
| `Settings\Enable Damage` | on | 关掉 = 不结算伤害 |
| `Settings\Enable Player Damage` | on | 关掉 = 玩家方不受伤害 |
| `Settings\Pause On Error` | **off** | 保持 off，出错不弹窗卡住自动化 |

> 注意：默认值里有好几个是 `on`。做「固定输入 → 固定输出」的测试时，
> 应当先把这些随机源关掉，否则同一份测试每次结果都不同。

### 4.2 加速（缩短测试时间）

## 六、读状态的正确姿势（纠正一个我先前的错误）

`rimworld/get_selection_semantics` 的 inspect 文本**不在** `inspectStrings`（那是空的），
而在 **`selectedObjects[].inspectString`**：

```js
const sem = await call('rimworld/get_selection_semantics');
// 顶层键: success, hasSelection, selectionFingerprint, selectedCount,
//         detailedObjectCount, selectionDetailsTruncated, selectedKinds,
//         selectedObjects, visibleGizmoCount, uiState
sem.selectedObjects[0].inspectString
// → "Female, age 17 (1942) of New Arrivals\r\nGoing sw..."
```

这是**验证 pawn 状态最直接的文本通道**，做人物 mod 断言时应该用它。

## 七、对 mod 自动化测试的意义

把上面三块拼起来，一个确定性的人物相关测试场景可以这样搭：

```
1. 开调试殖民地（start_debug_game_ready）
2. 【确定性】关掉随机源
   set_debug_setting('Settings\\Enable Storyteller', false)
   set_debug_setting('Settings\\Enable Random Mental States', false)
   set_debug_setting('Settings\\Enable Random Diseases', false)
3. 【加速】打开 Fast Research / Fast Learning / Fast Crafting
4. 【摆场景】用 Actions 精确造出需要的人
   Actions\Spawn Pawn...\<kind>          → 生成指定种族
   Actions\Max Skill...\Shooting          → 技能拉满
   Actions\Give Trait...\<trait>          → 给特质
   Actions\Add Hediff...\<hediff>         → 加健康状态
5. 【做事】对被试小人执行你要测的操作（gizmo / debug action / 地图点击）
6. 【读回】get_selection_semantics → selectedObjects[].inspectString
           list_colonists / get_cells_info / rimbridge/list_logs
           Outputs\* 取内部数值
7. 【断言 + 截图】step_game_ticks 推进固定 tick，比对结果
```

关键在于**第 2、4 步**：把随机源关掉、把初始条件用 Actions 精确摆好，
才能得到可复现的测试。
