# 双实例与资源约束 —— 机制事实（2026-10-17，只读核查）

> 场景：用户自己开一局（满配 mod）+ 自动化另开一局轻量实例，推时间要 ~2 倍速。
> 全部只读：未起游戏、未改代码、未写脚本。「实测」只指本轮跑过的只读命令 `node src/cli.js status|bridge`（输出见下）。

## 1. `start` 的「已有实例」守卫：**两条都查，第二条会挡住用户那一局**

- **结论**：`start` 先查**记录里的 PID**（`runs/game-process.json`），再**枚举全机 RimWorldWin64**；任一命中就 throw。报「已有 RimWorld 测试实例在运行（PID …）」的是**记录分支**，枚举分支是另一句文案。
- **证据**：`src/cli.js:132`（start→startGame）；`src/launcher.js:275-280`（recordedAlive→「已有 RimWorld 测试实例在运行」，PID 来自 `launcher.js:48-50` 的 `runs/game-process.json`，存活判定 `launcher.js:148` `isAlive`）；`src/launcher.js:281-286`（枚举到任何 RimWorldWin64→「检测到已在运行的 RimWorld 进程…请先关闭它」）；`launcher.js:115-129` →`proc.js:162`（tasklist）`proc.js:213`（Get-Process 兜底）。
- **读代码 / 实测**：读代码确认；**实测**（`status --profile voiced`）本机 tasklist 可用（`via:"tasklist",known:true`）⇒ **枚举这条路是通的，用户自己开一局会让我们的 start 直接失败**。附注：陈旧记录同样会挡（`isAlive` 只看 PID，PID 复用会误判）。
- **理想形态要改**：守卫得能判断「这个进程是不是我们的实例」（按 `-savedatafolder` 归属或加 `--attach/--allow-existing`），别按映像名一刀切。

## 2. `stop` 杀谁：**不是只杀记录的 PID，等价于按映像名批量杀（安全红线）**

- **结论**：pids = 记录 PID ∪ 全机 RimWorldWin64 枚举；先温和 `taskkill /PID`（发 WM_CLOSE），20s 没退再 `killForce` + `taskkill /PID /T /F`。**用户那一局会被一起关掉**，且无法区分。
- **证据**：`src/launcher.js:454-458`（pids 收集，含 `status.enumeration.processes`）；`launcher.js:464`（温和）；`launcher.js:473-478`（强杀兜底）。cli 的 stop 分支**不读 `--profile`**（`src/cli.js:333-334` → `stopGame()` 无参）；`src/smoke.js:303-305`、`plugin/dsh-rimworld/lib/index.js:187-189` 走同一个 `stopGame()`。代码里没有 `taskkill /IM` 或 `Get-Process|Stop-Process`，效果等价。
- **读代码**：确认。**未实测**（不杀进程）。
- **理想形态要改**：`stop` 只杀记录内的 PID（或记录里那个 profile 的 PID），枚举只用来**报**不**杀**。

## 3. 桥接端口：默认 5174，唯一可配途径是 DSH 进程的环境变量（不分 profile）

- **结论**：`GABP_SERVER_PORT` 有就用、没有就 5174，**所有 profile 共用一个值**；没有「每 profile 独立端口」的配置项。桥接侧确实读 `GABP_SERVER_PORT`/`GABP_TOKEN`/`GABS_GAME_ID`（`Lib.GAB.dll` 的 #US 字符串常量，二进制只读证据），并据此打**两种**日志之一（`RimBridgeServer.dll` 的两条格式串）：`[RimBridge] GABP server connected to GABS on port {0}` / `[RimBridge] GABP server running standalone on port {0}` + `Bridge token: `。
- **`readBridgeInfo` 只认 standalone 那条**：正则 `/GABP server running standalone on port (\d+)/g`（`src/launcher.js:76`），且**必须同时**匹配 `/Bridge token:\s*(\S+)/g`（`launcher.js:77`）才返回 `source:'log'`；否则回退到记录里的预定值（`launcher.js:89-98`，`source:'env'`，还要求 `rec.logFile === logFile`）。
- **实测**：`bridge --profile voiced` 输出 `source:"env"`，而 `profiles/voiced/Player.log:129` 是 `connected to GABS on port 5174` ⇒ **日志正则当前永远不命中**，端口/token 实际来自记录回退。在本机 GABS 模式下**没有** `Bridge token:` 行。
- **两实例同端口**：后启动的会 bind 失败（`RimBridgeServer.dll` 有 `[RimBridge] Failed to start server: {0}`），但具体表现（无桥接 / 换端口 / 卡启动）**未实测，未确定**；且换端口也接不上，因为记录是单实例的（见 4）。
- **理想形态要改**：端口按 profile 定（`profiles/<p>/prefs.json` 或 `profile.port`），并让 `readBridgeInfo` 同时认 GABS 那一行（否则永远读不到 `source:'log'`）。

## 4. 并发实例本身：靠 `-savedatafolder` 隔开，**但记录是单一定点**

- **结论**：不传 `-single-instance`（全仓库 grep 0 命中）⇒ 游戏侧不互斥，唯一互斥点是端口。隔离参数：`-savedatafolder=<profiles/p>`（`launcher.js:316`）、`-logFile <profiles/p/Player.log>`（`317-318`，旧日志归档 `303-307`）、`-screen-*`/`-monitor`（`319-327`）、关 doorstop 时 `--doorstop-enabled false`（`333`）+ `DOORSTOP_ENABLED=0`（`343`）。
- **按 profile 分开的**：`Config/Prefs.xml`（`src/prefs.js:99-101`）、`runs/live/<profile>.ndjson`（`src/live.js:50-57`）、`proc.js:23` 的临时目录（每次 mkdtemp）。**两实例共用同一份**（只读加载，非冲突）：游戏目录 `Mods\`（junction 回仓库 `mods\`）、`BridgeTools\` 伴生 DLL。
- **假设「全机一个 RimWorld」的地方**：`runs/game-process.json` 是**单一定点记录**（`launcher.js:48-50`），每次 start 覆盖写（`launcher.js:375`）⇒ 后启动的实例把前一个的 PID/端口/token 抹掉；`readBridgeInfo` 的 env 回退又要求 `rec.logFile === logFile`（`launcher.js:91`），前一实例此后无法被 CLI 定位。
- **注意**：题目说 RimBridgeServer 在 `mods\` 下 —— **不在**（仓库 `mods\` 只有 BikeProbe/ColonyRecorder/DSH_GameLink/FoodControl）。它是游戏目录里的**普通目录** `D:\SteamLibrary\steamapps\common\RimWorld\Mods\RimBridgeServer`（2.1.1）。
- **理想形态要改**：记录按 profile 落盘（`runs/game-process.<p>.json`）或存成数组，`start/stop/status/bridge` 全部按 profile 取。

## 5. 倍速：能设哪些、boost 是什么、各档倍率**仓库无实测**

- **结论/证据**：`rimworld/set_time_speed` 的 `speed` = Paused/Normal/Fast/Superfast/Ultrafast，另有 `ultraSpeedBoost`（直接改私有 `TickManager.UltraSpeedBoost`；工具描述称 RimBridgeServer 启动时默认已开）—— `runs/tools.json:2672,2680,2683-2686`。`rimworld/play_for` 的 `speed` = Normal/Fast/Superfast/Ultrafast（不可 Paused）+ `durationMs` + `forceRequestedSpeed`（跑期间压掉 RimWorld 的「强制 1 倍速」降速、确保 boost 打开，跑完还原）—— `runs/tools.json:915,927,935-939`。`play_until_letter` 同（`5555,5568`）。
- **实测数字（只有 Ultrafast+boost 的墙钟速度）**：7110.7 tick/s（`docs/时间推进实测.md:20`）、7755 tick/s（`:83`）、~4700 tick/s（`docs/RIMBRIDGE-技巧手册.md:151`）、`step_game_ticks` ≈ 541–591.8 tick/s（`docs/食物自动化-技术侦察.md:638`、`时间推进实测.md:19`）。**Normal/Fast/Superfast 的 tick 倍率：仓库无实测**（不从原版常识反推）。
- **现状**：`src/` 与 `scripts/*.mjs` 里都没有真正的 `play_for`/`set_time_speed` 调用（只出现在注释里，grep 0 处调用）⇒「~2 倍速」目前没有落点；按名字应设 `speed:'Fast'`，但「2 倍 = 多少 tick/s」**未实测**。
- **理想形态要改**：把「想要的速度」收敛成一处配置（profile 或 CLI 参数），别让每个脚本各写 speed 字面量。

## 给 AGENTS.md 的建议条目

1. 用户自己在玩时**不要**跑 `start`/`stop`：`start` 会因任何 RimWorldWin64 进程拒绝启动，`stop` 会把全机 RimWorld 一起关掉。
2. 端口只有一个来源：DSH 进程的 `GABP_SERVER_PORT`（默认 5174），**不分 profile**；两实例同端口会撞，第二个桥接的具体表现**待确认**。
3. 实例记录是单一定点 `runs/game-process.json`，后启动的会覆盖前一个；要并发多实例**必须先改成按 profile 记录**（待做）。
4. 桥接在 GABS 模式打的是 `connected to GABS on port`，而 `readBridgeInfo` 只认 `running standalone on port`；端口/token 现在实际来自记录回退（`source:'env'`）。
5. 推时间默认 Ultrafast+boost；各档 tick 倍率**仓库无实测**，写「2 倍速」前先实测再落数字。
