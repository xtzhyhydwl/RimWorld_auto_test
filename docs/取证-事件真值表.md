## 1. 结论速览

- ✔ **实测**：Core 有 **57** 个具体 `IncidentDef`（含 3 个 Abstract 祖先共 60 个节点）；**全 DLC 合计 131**。分类不是语义标签，而是 13 个 `IncidentCategoryDef`（Misc 50 / ThreatBig 33 / GiveQuest 12 / DiseaseHuman 11 / Special 11）。
- ✔ **实测**：**所有 incident 执行必经 `RimWorld.IncidentWorker.TryExecute`**。`TryExecuteWorker` 全程序集只有 2 处引用，其中唯一的真实调用在 `TryExecute` 体内（`[IL_002D callvirt]`）。
- ✔ **实测**：`TryExecute` 自己**不发任何 Letter/Message**；发信的是各 `TryExecuteWorker`（→`SendStandardLetter`→`SendIncidentLetter`→`LetterMaker.MakeLetter`→`LetterStack.ReceiveLetter`）。中途有两个抑制开关：`IncidentParms.silent` / `IncidentParms.sendLetter`。
- ✔ **实测（反直觉①）**：`Pawn.Kill`/`Pawn.Notify_Downed` 都不是"唯一入口"的那种入口——**死亡真正的收口是 `Verse.Thing.Kill`（虚方法，61 处调用点）**，`Verse.Pawn` 覆写它；`Pawn.Notify_Downed` 全程序集**只有 1 个调用者**（`Pawn_HealthTracker.MakeDowned`）。
- ✔ **实测（反直觉②）**：只挂 `IncidentWorker.SendStandardLetter` **不够**——`ShortCircuitUtility.DoShortCircuit`、`IncidentWorker_MeteoriteImpact.MakeLetter`、`IncidentWorker_RansomDemand.TryExecuteWorker` 都**绕过它**直接 `ReceiveLetter`。挂 `LetterStack.ReceiveLetter` 才全。
- ✔ **实测（反直觉③）**："缺 35 钢铁"**原版已经算过**：`Designator_Build.DrawPlaceMouseAttachments` 里 `CostListCalculator.CostListAdjusted` → 逐项 `map.resourceCounter.GetCount` → 不足就红字。mod 只需复刻这个比较（~12 行），**不用遍历地图、不用每帧**。
- ? **未确证**：`Messages.Message` 有 801 个调用点 / 441 个类型，无法逐一归类；"哪些是玩家真会注意到的提示"只能运行时观察。

### 2.2 执行入口证明（**实测**）

```powershell

RefDump.exe <asm> <managed> "=RimWorld.IncidentWorker" "TryExecute"         # → == HITS: 32
```

- `TryExecuteWorker` 的 2 处引用 = `IncidentDef::get_Worker [IL_0014 castclass]`（类型 token，非调用）+ `IncidentWorker::TryExecute [IL_002D callvirt]`。⇒ **没有第二条通往 worker 的路**。
- `TryExecute` 的 32 处调用（去掉 1 个 castclass 噪声 = 31 个真实调用点），**只有 1 个来自讲故事者**：`RimWorld.Storyteller::TryFire`。其余 15 类是玩法/任务/仪式/剧本驱动的：`QuestPart_Incident`(×2)/`QuestPart_RandomRaid`/`QuestPart_SurpriseReinforcement`、`CompAbilityEffect_RaidEnemy|Infestation|RandomAlliedMilitaryAid`、`RitualAttachableOutcomeEffectWorker_*`(×4)、`RitualOutcomeEffectWorker_Skylantern`、`SitePartWorker_RaidSource`、`ScenPart_CreateIncident|PursuingMechanoids`、`SignalAction_Incident`、`Instruction_DownRaider`、`Planet.TimedDetectionRaids`、`GameCondition_DroughtInitial`、`FactionDialogMaker.CallForAid`、`RoyalTitlePermitWorker_CallAid`、`IncidentWorker_CaravanMeeting`；剩下 9 个是 `DebugActions*`。
- **结论**：想要"所有 incident 级事件"，钩 `IncidentWorker.TryExecute` 的 Prefix/Postfix 一个点就够（含任务、仪式、技能、剧本触发的袭击）。

## 3. B 节 · Letter / Message 重叠

### 3.1 典型 IncidentDef 走哪条路（**实测**，RaidEnemy）
`Storyteller::TryFire → IncidentWorker_RaidEnemy.TryExecute → (base) IncidentWorker.TryExecute → TryExecuteWorker → IncidentWorker_Raid.TryExecuteWorker [IL_0144 SendStandardLetter] → SendStandardLetter(TaggedString×2,LetterDef,parms,lookTargets) [IL_000F SendIncidentLetter] → SendIncidentLetter → LetterMaker.MakeLetter [IL_00FE] → LetterStack.ReceiveLetter [IL_0159]`。
- **发 Letter：是。发 Messages：否**（`IncidentWorker_Raid*` 不在 `Messages.Message` 调用者名单里）。
- `IncidentWorker.TryExecute` 体内只有 tale 记录 + `Storyteller.RecordIncidentFired` + `EntityCodex.SetDiscovered`，**无任何 UI 输出**。

### 3.2 辅助方法签名与抑制开关（**实测**）
```csharp
protected void SendStandardLetter(IncidentParms parms, LookTargets lookTargets, params NamedArgument[] textArgs)                       // 56 处调用
protected void SendStandardLetter(TaggedString label, TaggedString text, LetterDef def, IncidentParms parms, LookTargets lt, params NamedArgument[]) 
public static void SendIncidentLetter(TaggedString label, TaggedString text, LetterDef def, IncidentParms parms, LookTargets lt, IncidentDef def, params NamedArgument[])  // 6 处调用
```
`SendIncidentLetter` 第一段：`if (parms.silent || !parms.sendLetter) return;`（`IL_0001/IL_0009/IL_0010 ret`），`IncidentParms.silent`/`sendLetter` 都是 public bool。⇒ **事件发生了但没信**是合法的（安抚/静默 raid、任务内触发）。

### 3.3 单挂 `ReceiveLetter` 能否覆盖？（**实测**）
能覆盖**所有信件**（`LetterStack.letters` 只在 `LetterStack` 内写；296 处调用点全部汇流）。但**不能覆盖角落小字**，且：
- **只发 Message 不发 Letter（2 例）**：`ShipChunkDrop`（`IncidentWorker_ShipChunkDrop::TryExecuteWorker [IL_0054]`，文本 key `MessageShipChunkDrop`）、`TravelerGroup`（`[IL_0113]`）。
- **只发 Letter 不发 Message（2 例）**：`RaidEnemy`（`IncidentWorker_Raid`）、`Disease_Flu`（`IncidentWorker_Disease [IL_0303 SendStandardLetter]`）。
- **绕过 `SendStandardLetter` 直接发信（挂 SendStandardLetter 会漏）**：`ShortCircuitUtility.DoShortCircuit [IL_01B6 ReceiveLetter]`（key `LetterLabelShortCircuit`）、`IncidentWorker_MeteoriteImpact::MakeLetter [IL_00A6 MakeLetter]`、`IncidentWorker_RansomDemand::TryExecuteWorker [IL_0086 MakeLetter][IL_010B ReceiveLetter]`、`QuestUtility.SendLetterQuestAvailable`。
- **两个通道都不发**：`IncidentWorker_ShortCircuit::TryExecuteWorker` 只调 `ShortCircuitUtility.DoShortCircuit`；短路若没触发信（小规模）则屏幕无文字（`推测`：只剩音效/火灾）。

### 4.4 可行性判断（**实测 + 推测**）
**原版已经算过这个差值**——`RimWorld.Designator_Build.DrawPlaceMouseAttachments`：
`IL_00E7 CostListCalculator.CostListAdjusted(entDef, StuffDef, true)` → 循环 → `IL_0159 needed = 拖拽格数 * count` → `IL_017F map.resourceCounter.GetCount(thingDef)` → `IL_0186 bge`（够则跳过）→ 否则红字 + `"NotEnoughStoredLower"`。这就是玩家看到的"not enough stored"。
- 代码量：**~12 行**（`CostListAdjusted` + `foreach` + `GetCount` 比较 + 拼串），**不需要遍历地图**（`ResourceCounter` 是维护好的字典），**不需要每帧**（在 `PlaceBlueprintForBuild` postfix 里算一次；原版每帧只是在 GUI 里重复查字典，开销可忽略——`推测`，未计时）。
- 语义细节（**推测**）：`GetCount` 是**全地图库存**，不含"正在搬/在途"，也不含已被其他蓝图预定的量；蓝图自身的 `TotalMaterialCost()` 不扣已送到框架的材料（送到后变 `Frame`）。要"缺 35"精确到框架层，需改钩 `Frame`/`ThingCountNeeded`。
