# 取证 · RimWorld 1.6 的「当前存档标识」（给语音缓存分区用）

> 对象：`D:\SteamLibrary\steamapps\common\RimWorld\RimWorldWin64_Data\Managed\Assembly-CSharp.dll`（**1.6.9676.17735**）。
> 手段：仓库现成只读工具 `tools/asmdump/{AsmDump,IlDump,RefDump}.exe`。**未写脚本、未启动游戏、未改任何文件**。
> 标注：**实测** = 元数据/IL 直接读到；**推测** = 由 IL 推出、无运行时观察；**未确证** = 没查到。

## 1. 结论速览

- ✔ **实测**：**原版没有任何"当前存档名/路径"的运行时缓存**。存档 XML 头只有 `gameVersion/modIds/modSteamIds/modNames`；`GameDataSaveLoader.SaveGame(fileName)` 收下文件名就转给 `GenFilePaths::FilePathForSavedGame`，无人保存。
- ✔ **推荐（唯一能区分"同种子重开"的方案）**：**mod 自铸 GUID**，写进自己的 `Verse.GameComponent.ExposeData`（`Scribe_Values.Look(ref id, "voiceCacheId")`），`LoadedGame()`/`StartedNewGame()` 时若为空就 `Guid.NewGuid().ToString("N")`。骨架**实测**（组件存盘时序、两个回调点都在），"GUID 本身"是常规做法（**推测**）。
- ✔ **次选（零自建状态，纯原版字段）**：`Find.World.info.seedString`。**实测**它随存档存盘、跨读档稳定。缺陷：**同种子重开的殖民地会撞**——因为 `name` 与 `persistentRandomValue` 也都是 seed 的确定性函数（见 §2），三者同源、叠加无增益。**推测**同种子时原版派系名本来也相同，故"派系名缓存"撞了不算错，但"殖民者名缓存"撞了会念错人。
- ✘ `WorldInfo.name` 单独用：**实测**原版无改名入口（全程序集只有 3 个写点：ctor / `WorldGenerator.GenerateWorld` / `ExposeData`），但词库有限、不同种子可能同名（**推测**），且与 seedString 同源。
- ✘ `WorldInfo.FileNameNoExtension` **别被名字骗了**：**实测** IL 是 `GenText.CapitalizedNoSpaces(name)` = 星球名去空格，**不是存档文件名**。
- ✘ `GameInfo` 无用：**实测**只有 `permadeathMode / permadeathModeUniqueName / startingTile / startingAndOptionalPawns / realPlayTimeInteracting`，与"存档身份"无关。
- ✔ **时机**：`Verse.GameComponentUtility.LoadedGame()`（读档完成）与 `StartedNewGame()`（新殖民地完成）**各只有 1 个调用点**（见 §4）。

## 2. `WorldInfo` 成员表（**实测**，`AsmDump "WorldInfo" "*" np`）

**注意命名空间**：1.6 是 `RimWorld.Planet.WorldInfo`（不是 `Verse.WorldInfo`）；实例从 `Verse.Game.World`(public 字段) → `RimWorld.Planet.World.info`(public 字段) 走，即 `Find.World.info`。

| 成员 | 类型 | 可见性 | 存盘 | 稳定性判断 |
| --- | --- | --- | --- | --- |
| `name` | string | public 字段 | ✔ `Scribe_Values "name"` | 世界生成时 `NameGenerator.GenerateName` 赋值；无原版改名；与 seed 同源（**推测**） |
| `seedString` | string | public 字段 | ✔ `"seedString"` | ★ 玩家建世界时**可自填**；同一存档跨读写恒定（**实测** 唯一外部写点是 `GenerateWorld`） |
| `persistentRandomValue` | int | public 字段 | ✔ `"persistentRandomValue"` | ctor 里 `Rand.Int` 一次；`GenerateWorld` 在 `Rand.Seed=GetSeedFromSeedString(seed)` **之后**才 `new World()` ⇒ 种子派生（**实测** IL 顺序：`IL_0017 set_Seed` → `IL_001C newobj World` → ctor `IL_0017 call Rand::get_Int`） |
| `planetCoverage` | float | public 字段 | ✔ | 建世界参数，同种子同值 |
| `overallRainfall` / `overallTemperature` / `overallPopulation` / `landmarkDensity` | 枚举 | public 字段 | ✔ | 同上（`landmarkDensity` 是 1.6 新增） |
| `pollution` | float | public 字段 | ✔ | 同上 |
| `initialMapSize` | IntVec3 | public 字段 | ✔ | 同上 |
| `factions` | List\<FactionDef\> | public 字段 | ✔（旧档走 `factionCounts` 兼容） | 同上；**这是"派系名单"层面的存档内固定数据** |
| `Seed` | int（get） | public 属性 | 派生 | `GenText.StableStringHash(seedString)`；**实测**是经典 `h*31+ch`，跨进程/平台稳定（不是 `String.GetHashCode`） |
| `FileNameNoExtension` | string（get） | public 属性 | 派生 | `CapitalizedNoSpaces(name)` —— **星球名，不是存档文件名** |
| `ExposeData()` | void | public | — | 上面 11 个字段全部 `Scribe_Values.Look` / `Scribe_Collections.Look` |

**"玩家可改吗"**：`name` 的原版写点只有 `WorldInfo::.ctor`（`"DefaultWorldName"`）、`WorldGenerator::GenerateWorld`（`IL_007B NameGenerator::GenerateName` → `IL_0080 stfld name`）、`ExposeData`；`WITab_Planet::FillTab` 只**读**它（星球信息页展示）。⇒ **原版无改名 UI**（**实测**，`IlDump --usages name RimWorld.Planet.WorldInfo` = 8 命中全部可解释）；**其他 mod 仍可写**（public 字段）→ 拿 name 当键会被第三方改名打断。

## 3. 备选方案与坑

| 方案 | 判定 | 坑 |
| --- | --- | --- |
| 自铸 GUID（存进自己的 GameComponent） | ✔ 首选 | 保存前必须已铸；老档（字段为空）在读档时补铸后要**立刻**参与 Scribe，否则下次存盘才落盘 |
| `seedString` | ✔ 次选 | 同种子重开 → 撞；玩家可自填（`"SeedError"` 是 ctor 占位） |
| `seedString + name + persistentRandomValue` | ✘ 不比单用强 | 三者同源（种子派生），**实测** `persistentRandomValue` 只有 ctor 一个写点、名字只在 GenerateWorld 一个写点 ⇒ 无独立熵 |
| `name` 单独 | ✘ | 重名（不同种子可能同名）+ 第三方改名 |
| `World.Seed`（hash） | ✘ | 就是 `seedString` 的哈希，额外信息为零 |
| 存档文件名/路径 | ✘ | 读档后**拿不到**（无人缓存）；即使挂钩 `GameDataSaveLoader.LoadGame(string)` 抓到，也**每次 autosave 都变** → 分区抖动（每次自动保存生成新缓存目录）。仅建议写日志 |
| `permadeathModeUniqueName` | ✘ | 只有永久死亡模式才非空（**推测**，字段名与 `Autosaver.MaxPermadeathModeAutosaveInterval` 配套） |
| DLC 地图 / 1.6 多层星球 | ✔ 不冲突 | **实测** `WorldInfo` 每 `World` 一份（`World::.ctor` 里 `new WorldInfo()`），`WorldGenerator` 遍历的 `PlanetLayer` 共享同一个 `World.info` ⇒ 同存档内所有地图/层自动同分区（正是想要的行为） |

## 4. "存档已加载"的可靠时机点（**实测**）

读档链（`IlDump "Verse.Game" "LoadGame"`，方法序由 IL 偏移给出）：

| 序 | 调用 | 备注 |
| --- | --- | --- |
| 1 | `Game.ExposeSmallComponents()`（`IL_0033`） | 内含 `"info" "rules" "scenario" "tickManager" ... "components"`（`IL_0297`）。**→ 我们的 GameComponent.ExposeData 在 world 之前跑，此时 `Find.World` 可能为 null，别在这里算指纹！** |
| 2 | `Scribe.EnterNode("world")` → `new World()` → `World.ExposeData()`（`IL_004C..0069`） | `World.info` 在此之后才有值 |
| 3 | `World.FinalizeInit`（`IL_00A7`） | |
| 4 | `Scribe.EnterNode("maps")` … `Map.FinalizeLoading` | |
| 5 | `Game.FinalizeInit()`（`IL_0279`）→ `GameComponentUtility.FinalizeInit()`、`Current.ProgramState=Playing` | |
| 6 | **`GameComponentUtility.LoadedGame()`（`IL_02AE`）** | ★ **唯一调用者就是 `Game.LoadGame`**（`RefDump` HITS: 1）。world/maps 全就绪 |
| 7 | `BackCompatibility.PostLoadSavegame` | |

新殖民地：**`GameComponentUtility.StartedNewGame()`**，唯一调用者 `Game.InitNewGame`（`IL_01FD`，方法体末尾，`history.FinalizeInit` 之后）⇒ 此时 world 已存在（**推测**：InitNewGame 更早处已建世界/地图，未逐行读）。

签名（**实测**）：
```csharp
public static void Verse.GameComponentUtility.LoadedGame();       // 遍历 Current.Game.components → callvirt GameComponent.LoadedGame()
public static void Verse.GameComponentUtility.StartedNewGame();   // 同上 → GameComponent.StartedNewGame()
// Verse.GameComponent 公开 void ExposeData()/LoadedGame()/StartedNewGame()/FinalizeInit()，callvirt ⇒ virtual，可直接继承
```
`Verse.Root` **没有** `OnLoad`（成员只有 `Start/Update/OnGUI/Shutdown`），`Verse.Game.LoadGame()` 太早（世界还没读），都不适合。

## 5. 具体建议

```csharp
// 有自铸 id 就用它（推荐；null 只可能出现在极老档或存档被手改）
Fingerprint = ownCacheId ?? $"w{Find.World.info.Seed:x8}_{Find.World.info.persistentRandomValue:x8}";
// ownCacheId 由 StartedNewGame()/LoadedGame() 里补铸：Guid.NewGuid().ToString("N")
```
落盘建议：`global` 之外再开一层 `save/<Fingerprint>/`；指纹变化时不要去删旧目录（换存档回来还要用）。

## 6. 未确证 / 需开游戏才能答

1. **未确证**：`NameGenerator.GenerateName` 是否完全由 `Rand`（种子）驱动 ⇒ "同名概率""同种子必同名"都只是**推测**。运行时抓两个不同种子世界的 `info.name` 即可定论。
2. **未确证**：两个**同种子**殖民地是否真的生成同名派系（决定"seed 撞车到底有多无害"）。需实测：同种子开两局，比对 `World.factionManager.AllFactions` 的名字。
3. **未确证**：`persistentRandomValue` 在 1.7 是否仍由 ctor 首个 `Rand.Int` 产生（若加了个 Rand 调用就会整体平移）⇒ 跨版本用它做键会集体失效（退化为重建缓存，不致命）。
4. **未确证**：`StartedNewGame()` 回调时 `Find.World.info` 是否一定有值（只证明 world 在此前被创建，未证明 info 已填充）。
5. **未实施**：运行时验证"读档 → LoadedGame → 指纹一致"需要开游戏打日志；本次按要求未启动游戏、未写探测脚本。
