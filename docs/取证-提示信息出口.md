# 取证 · RimWorld 1.6 屏幕提示信息的出口

> 取证对象：`D:\SteamLibrary\...\Managed\Assembly-CSharp.dll`（**Assembly-CSharp 1.6.9676.17735**，游戏 1.6.4871）+ `Data\**` 的 XML。
> 手段：仓库现成只读工具 `tools/asmdump/{AsmDump,IlDump,RefDump}.exe`（元数据反射 + IL 反汇编 + 引用扫描），**未写新脚本、未改任何文件**。
> 标注：**实测** = 本机 IL/元数据/XML 直接读到；**推测** = 由 IL 推出行为、无运行时观察；**未确证** = 没查到或查不下去。

---

## 1. 结论速览

- ✔ **实测**：角落里那串小字**只有一个出口**——`Verse.Messages.Message(...)`。IL 证明 `Messages.liveMessages` 这个列表在**全程序集里只被 `Verse.Messages` 自己读写**，外部代码无法绕过它往屏幕塞消息。
- ✔ **实测**：信件（右上角）**只有一个出口**——`Verse.LetterStack.ReceiveLetter(...)`，3 个重载；`LetterStack.letters` 列表同样**只在 `LetterStack` 内部被增删**。
- ✔ **实测**：`MessageTypeDefOf` 在 **`RimWorld`** 命名空间（不是 `Verse`），共 **12** 个成员，**没有 `Silent`，只有 `SilentInput`**。
- ✘ **实测（否定）**：**"建造材料不足"在原版里不是角落 `Messages`**。全程序集字符串池里与材料有关的 key 只有 `MissingMaterials`、`NotEnoughStoredLower`、`ShowMaterials`；前者走 `JobFailReason.Is("MissingMaterials")`（右键菜单灰条理由），后者走 `Designator_Build.DrawPlaceMouseAttachments`（造价读数旁）。用户记忆里的"角落小字"，**最可能是设计器落点失败的那条 `SilentInput` 消息**，或造价读数，而不是"材料不足"消息。
- ✔ **实测**：题目给的 7 个 patch 点在 1.6.4871 里**每个都只有 1 个重载**，按名 patch **不会**抛 `AmbiguousMatchException`；但 **3 个类型名写错了命名空间**（见 C 节）。

### 2.3 能否一个钩子拿全部？

- ✔ **实测（依据：字段写点唯一）**：`IlDump --usages liveMessages Verse.Messages` → 23 处命中**全部落在 `Verse.Messages` 内部**（`.cctor` 初始化 + 各方法读写）。没有任何外部类型能 append。
  ⇒ 挂 `Verse.Messages.Message(Verse.Message, bool)` 的 Postfix **能拿到全部角落小字**（4 个重载全部汇流到这里）。
- ✔ **实测**：`LetterStack.letters` 的 22 处命中全部在 `Verse.LetterStack` 内（ctor 初始化、`ReceiveLetter` 加、`RemoveLetter` 删、`LettersOnGUI`/`LetterStackUpdate` 读）。⇒ 挂 `ReceiveLetter(Letter, string, int, bool)` **能拿到全部信件**。
- ? **未确证**：mod 可以用反射直接 `liveMessages.Add(...)` / `letters.Add(...)` 绕过。原版没有；第三方 mod 理论上可以。
- **不属于这条通道的其它"屏幕反馈"**（别混）：`MoteText`/`TextMote_*`（世界内飘字）、`Alert`（右侧警报栏）、`Tutor`/`ConceptDef`（教学弹窗）、`FloatMenu` 灰条理由、设计器面板读数。

## 4. C 节 · 旧 mod 的 7 个 patch 点（**全部实测**：AsmDump 元数据，`DeclaredOnly`）

| 类型.方法（1.6 真实名字） | 重载数 | 签名 | 风险 |
| --- | --- | --- | --- |
| `Verse.Pawn.Kill`（**不是 `RimWorld.Pawn`**） | 1 | `public void Kill(Nullable<Verse.DamageInfo> dinfo, Verse.Hediff exactCulprit = null)` | 低。另有私有 `DoKillSideEffects`，名字不同不冲突 |
| `RimWorld.IncidentWorker.TryExecute` | 1 | `public bool TryExecute(RimWorld.IncidentParms parms)` | 低。`TryExecuteWorker` 是另一个名字 |
| `Verse.Hediff_Pregnant.StartLabor`（**`Verse`**） | 1 | `public void StartLabor()` | 低 |
| `Verse.Pawn.Notify_Downed`（**`Verse`**） | 1 | `public void Notify_Downed()` | 低 |
| `Verse.AI.MentalStateHandler.TryStartMentalState`（**`Verse.AI`**） | 1 | `public bool TryStartMentalState(Verse.MentalStateDef stateDef, string reason = null, bool forced = false, bool forceWake = false, bool causedByMood = false, Verse.Pawn otherPawn = null, bool transitionSilently = false, bool causedByDamage = false, bool causedByPsycast = false)` | 低。**9 个参数，增参风险高**（1.7 易变），建议 patch 时写死参数类型 |

> **但**：`LetterStack.ReceiveLetter`（3 个）和 `Messages.Message`（4 个）**会**——这两个如果只按名 patch 必炸，必须写参数类型。

## 5. 对"新 mod 该挂哪几个钩子"的建议（**建议，不是事实**）

建议只挂两个"总闸"，不追具体场景：①`[HarmonyPostfix] Verse.Messages.Message(Verse.Message msg, bool historical)` —— 读 `msg.text` / `msg.def`（用 `def.defName` 区分 `SilentInput`/`RejectInput`/`NegativeEvent`…）+ `msg.lookTargets`，这是**唯一能覆盖所有角落小字**的点（4 个重载都汇流于此，且 `AcceptsMessage` 去重会让"同文同目标"的重复消息不产生新对象——需要自己去重或读 `ResetTimer` 前后状态）；②`[HarmonyPostfix] Verse.LetterStack.ReceiveLetter(Verse.Letter let, string debugInfo, int delayTicks, bool playSound)` —— 读 `let.def`/`let.Label`/`let.lookTargets`，`ChoiceLetter` 额外读 `title`/`Text`。两个都必须**写全参数类型**否则抛 `AmbiguousMatchException`。**不建议**去 hook `JobFailReason` 或 `AcceptanceReport` 来"补全"——那两类是面板/灰条文本，语义上不是提示消息，接了只会让上层误判成"玩家收到了提示"。
