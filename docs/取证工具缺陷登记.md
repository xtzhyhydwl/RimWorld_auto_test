|---|---|---|---|
| R1 | **让"查不到 / 算不准"变成可区分的状态或直接失败** | 输出一个**看起来确定**的结论（`false` / `0` / 空行 / 乱码） | **三态（`true／false／null`、`known／unknown`）** 或 **`throw` / 非 0 退出**；`null` 必须在 stderr 显式警告"**不要把 null 当成 false**" |

| R5 | **判据不要绑在人类可读文本上** | 匹配 `Build succeeded` / 「成功」/ 英文关键字 | 用**退出码**或**结构化字段**（JSON 字段、元数据 flags 数值） |

### §4.1 L1 / L2 / L2b 三类根因层次

> **编号说明**：本节原为"**两类**根因层次"（L1 / L2）。本轮追加 **L2b（S8b，写方向）** 后改为**三层**；**原二分法的痕迹保留在"判据"列与下方理由里**（L2 与 L2b **同根因、反方向**，因此也可以读作"L2 的两个方向"；本表选择分列，因为二者的**可观测性与排查方向不同**）。

| # | 层次 | 归入实例 | 出错的环节 | 工具自身 | **是否有对照物** | 排查方向 + 判据 |
|---|---|---|---|---|---|---|
| L1 | **工具计算错误** | S1–S7 | **工具**（过滤/解码/异常/取值/判据/编码/schema） | **做错了事** | ✅ **有对照物**：可用独立手段**验算同一个问题**（CLR 互校 / 变异测试 / 规范原文） | 查工具：过滤器写法、行尺寸表、类型折叠、作用域、判据文本；对照"工具的已知缺陷清单" |
| L2 | **输入被静默改写**（读方向） | **S8** | **输入通道**（工具**之前**） | **没有做错任何事** | ⚠ **有对照物，但需要构造**：**跨通道对照**（同一字符串走两条通道，看结果是否一致） | 查输入通道：**我实际分析的是我以为的那些字节吗？** 并排看"证据计数"与"结论计数"，冲突即命中；工具自检**全过**是 L2 的旁证 |
| L2b | **输出被静默改写**（写方向） | **S8b** | **写入/落盘通道**（工具**之后**、落盘**之前**） | **没有做错任何事** | ❌ **没有天然对照物**：你**看不到**"文件里本来应该是什么" ⇒ 只能靠**事后结构自检**（列数 / 分隔行 / 配对符号 / 计数）**反向发现** | 查写入链路与**落盘前断言的不变量**（§4.4.3-R9）；判据 = 结构自检报出的**列数/计数不符** |

**为什么分列而不是把 S8b 并进 S8（理由，三条）**：

1. **出错环节不同**：S1–S7 都发生在**工具内部**（`Where(t => t != null)` 丢类型、行尺寸表算错、`obj.length` 恒假、函数作用域遮蔽 `$LASTEXITCODE`、拿英文文本当判据、按 ANSI 解码）——都是"**工具做错了事**"。S8 发生在**工具的输入侧**：那个竖线字符在**到达工具之前**就没了，工具对**它真正拿到的字节**给出的结论是**正确的**。**S8b 发生在工具的写入侧、落盘之前**：工具（写入通道）"以为自己写的是全角竖线"，**落盘的是别的字符**。
2. **可观测性不同**：L1 有"**输出可疑**"这个抓手（乱码、空行、0 命中本身就可疑，且 §4.4.3-R3/R4 的自检能抓）；**L2 连"可疑"都没有** —— 自检**全部通过**（它检查的是被改写后的输入，一切自洽），输出**看起来完全合法**；**L2b 更彻底**：连"跨通道对照"这条 L2 的退路都没有（**没有第二条通道去写同一个文件**能给你一个比对物），只能靠**事后结构自检**反向发现。
3. **排查方向相反**：L1 要**读工具源码 / 查已知缺陷**；L2 要**验证输入通道与字节**；**L2b 要在写入链路上"落盘前断言不变量"**。把 S8/S8b 塞进 S1–S7 会让人第一时间去查工具（本轮若照此排查，前一半会去改自检脚本的正则——真凶在通道上；后一半会去"目视检查文件内容"——而目视正是 S8b 唯一抓不到的手段）。

**计数同步（第二版，保留旧痕迹）**：§4.4 标题**原为"已发生 7 条 / 6 类机制"** → 上一轮改为"**8 条 / 7 类**" → **本轮改为"9 条 / 8 类机制"**（S1–S8b 共 **9 条**；L1 六类 ＋ L2 一类 ＋ L2b 一类 = **8 类**）。同时 §4.4.2 小节标题、§7 追加区块标题、文首索引行**同步更新**，R 系列新增 **R9**。

> **原始节标题**：`### §4.4.2-注 S8b：**S8 的第二例 —— 同一根因的"反向"复现（输出被改写在落盘之前）**`（真值表原位编号，保留作对照；标题文字一字未改）

> **登记理由**：它不是"同一个 bug 又出现一次"，而是**同一根因（字符在到达目的地之前被改写）在另一个方向上的复现**；而且**这一例提供了一个上一例没有的东西：一个可复用的规避手法**（已升级为 §4.4.3-R9）。

| 维度 | 内容 |
|---|---|
| 现象 | 用**写入/编辑通道**把一个**本应是全角竖线的字符**写进本文件时，**落盘的是 ASCII 竖线（U+007C）** ⇒ 那一行**多出一列**（列数自检立刻报 `cols=6 expected=5`）；而事后按**转义竖线**去匹配又**匹配不到**（因为实际落盘的是**全角**字，不是转义序列） |
| 与 S8 的关系 | **同一根因，方向相反**：S8 是"**输入**被改写在**工具之前**"（读方向）；S8b 是"**输出**被改写在**落盘之前**"（写方向）。两者都是"**我拿到的字节不是我以为的那批字节**" |
| 为什么比 S8 更隐蔽 | S8 还能靠**跨通道对照**发现（同一个字符串走两条通道，看结果是否一致）；**S8b 没有天然对照物** —— 你**无法直接看到**文件里应该是什么，只能靠**事后的结构自检**（列数 / 分隔行 / 计数）**反向发现**。本次就是被 §4.4.3 的结构自检抓出来的 |
| 通道身份（**诚实表述**） | **"某条具体通道会丢 / 改形竖线，通道身份待定"** —— ⚠ **不得**写成"pwsh 通道有 bug"：本轮实测 `pwsh` 执行通道对含裸竖线的单字符拼接**完好**（但也有一次异常丢过）。**归因未定，不要归因给某一个通道** |
| 触发条件（**如实写出，不要泛化**） | 本次观察到的触发场景：**用 `edit` 工具把含竖线的整行替换为新文本时**（本行就是在做这件事时被抓到的）。**不得**由此推广成"所有写入都不可靠" —— 证据只支持"**这条路径出现过一次**" |
| 规避手法（**可复用，已升级为 R9**） | **落盘前断言一个独立可验证的不变量**：本次用"该行 **ASCII 竖线恰为 6 个**"；实测做法是 **整行写进临时文件 → `ReadAllLines` 读回 → 逐行切片替换 → 断言计数通过才落盘**（临时文件随后删除，`docs\` 下 `_*` 文件数 = 0） |
