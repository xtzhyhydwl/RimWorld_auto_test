## 一句话风险

**不同 profile 并行也不安全**：1.7 的 `Player.log` 全机共用、后启动者整份重写；桥接解析还会串台 ⇒ 你可能**把命令打进别人的局**，或打进一个假桥，而断言看起来「正常返回」。

## 0. 先做三件事（每批动作前重跑，30 秒）

把 `<你的profile>` 换成你自己的，整段贴进 PowerShell（2026-10-24 18:56 实测跑过）：

```powershell
$p = '<你的profile>'
if (-not (Test-Path "runs\game-process.$p.json")) { throw "没有记录文件：不要发任何命令" }
$rec    = Get-Content "runs\game-process.$p.json" -Raw | ConvertFrom-Json      # ① 你自己的记录
$listen = (Get-NetTCPConnection -State Listen -LocalPort $rec.bridge.port -EA SilentlyContinue |
           Select-Object -First 1).OwningProcess            # ② 谁在监听（无匹配时它会抛错，被吞掉=空=无人监听）
$cmd    = (Get-CimInstance Win32_Process -Filter "ProcessId=$listen" -EA SilentlyContinue).CommandLine   # ③ 那个 PID 到底是谁
"record pid=$($rec.pid) port=$($rec.bridge.port) token=$($rec.bridge.token) shared=$($rec.logShared)"; "listener pid=$listen"; "cmdline $cmd"
if (-not $listen) { "无人监听 $($rec.bridge.port)：你自己的桥接还没起来 ⇒ 不要发命令（别当成串台）" }
elseif ($listen -ne $rec.pid) { "串台：端口 $($rec.bridge.port) 属于 PID $listen，记录里是 $($rec.pid) ⇒ 停手" }
elseif ($cmd -notmatch [regex]::Escape("profiles\$p")) { "命令行不含 -savedatafolder=…\profiles\$p ⇒ 停手" }
elseif ($rec.bridge.token -match 'fake|offline|test') { "哨兵 token ⇒ 这是假记录/假桥，停手" }
else { "OK：三处自洽，可以继续" }
```

判读：三条必须**同时**成立。**(a)** 监听 `$rec.bridge.port` 的 PID == 记录里的 `pid`；**(b)** 该 PID 命令行含 `-savedatafolder=…\profiles\<你的profile>`；**(c)** 记录里 pid / port / token 自洽且 token 不是哨兵值。
**任一条不成立 ⇒ 不发 `call`/`wait`/`stop`**（副作用会落在别人局里）；「无人监听」是第三种情况：你连不上，但**不能**据此断言自己被杀。
实例（18:56 实测）：5175 归 rhah 的 PID 23688，5174 **无人监听**，而 voiced 的 PID 26644 还活着 ⇒ 那时任何「voiced 在 5174 上」的假设都不成立。
另：记录里的 `profileDir` 可能带乱码（实测 rhah 记录是 `2026.7浠ュ悗鐨勬柊宸ョ▼`、voiced 正常）⇒ 校验只比 ASCII 的 `profiles\<profile>`，**别比整条路径**。

## 1. 根因（`src\launcher.js:185` 的兜底选错了记录）

- `readBridgeInfo()` 在本 profile 的记录/日志里刮不到 `GABP server … port` 行时，兜底调 `findRecordByLogFile(<1.7 共用日志路径>)`（`:226-249`），后者按 **`startedAt` 最新**挑 `runs\game-process.*.json`；
- 假记录 `runs\game-process.dshwait-check.json`（pid=0、port=**5288**、app=FakeBridge、token=`fake-token-for-offline-check`）的 `logFile` 与共用日志同路径、「启动」时间更晚 ⇒ 「取最新」把它当成了当前实例；
- **实测**：4 次桥接调用（incident / list_letters / list_messages / ping）全部打到 5288，返回 `success:false, message:"No current map"` —— 看着像业务失败，其实是**打错了对象**。该文件当前已被删除，但任何人（含别的会话）都能再写一条。
- 另一个方向：`status --profile voiced` 曾报到 **5175**（rhah 的实例）并握手成功 ⇒ `call --profile voiced` 会在 rhah 那一局里执行【推断，没有真的下发工具调用】。

## 2. 当时的规避手段（**2026-10-24 晚起不再必需**，留作故障时的诊断路径）

> 现在这六条里 1/2/4/5 已由代码保证（`resolveBridge` 拒发、`--force` 先验身份、`stop` 先验身份）；
> 3 与 6 仍然成立（同一时刻多起一局会互抢 CPU/窗口；日志仍共用、仍不可用于判死活）。

1. **不走** `status` / `logs` / `readBridgeInfo` 去问「我连的是谁」：直接读 `runs\game-process.<你的profile>.json` 的 `port` + `token` 连接；
2. 每批动作前重跑 §0 的三重校验；不一致就**不发命令**；
3. **同一时刻只让一个会话起游戏**：已有实例在跑（`Get-Process -Name RimWorld`）时不要 `start`；同一 profile 更绝对不要；
4. **`--force`/`--all` 禁用**：`launcher.js:713-723`、`:752-757` 按映像名枚举全机并 `/T /F`，会连用户自己那一局一起杀；
5. **`stop` 默认是安全的**【实测】：只杀本 profile 记录里的那个 PID、`taskkill /PID` 不带 `/F`（`:725`、`:741`）—— 但先确认记录里的 `pid` 确实是你自己的实例（§0 的 (a)）；
6. 等状态只用 `runs\live\<你的profile>.ndjson`（`live.js:50-58`，唯一真正按 profile 隔离的通道）+ 桥接探针；**别用** `logs`/`--source log` 判断自己死活（它读共享日志，会看到别人的行，`cli.js:392-398`）。

## 3. 日志不可靠（写断言前必须知道）

【实测】1.7 的 `%LocalLow%\Ludeon Studios\RimWorld by Ludeon Studios\Logs\Player.log` **全机一份**，每次启动**整份重写**（`-logFile` 被忽略）：

- 记录写着 `logStartOffset: 320607` / `logShared: true`，而同一时段文件实际只有 ~127 KB（另一路会话实测）；本文件作者 18:56 实测该文件 163,706 B、mtime 就在那一分钟 —— 正好等于那时另一条记录的新偏移 ⇒ **偏移随时失效**；
- ~~`readBridgeInfo` 的读法（`launcher.js:190-192`）：偏移 ≥ 文件长度时**回退读整份** ⇒ 会把别人实例的行当成自己的~~
  **已修（2026-10-24 晚）**：启动时记 `logAnchor`（大小 + 末尾 256B sha1），对不上就**放弃日志解析**并告警，
  不再回退读整份；有 profile 时更是直接用记录，压根不读日志。
- ⇒ 凡「按偏移读日志 / 按 ERROR 计数 / 日志里没有就算失败」的断言都要**标注口径限制**，或改成**按时间戳区间 + 只认自己关心的关键词**；能走桥接就不断言日志。

1. **截断**：后启动者启动的瞬间清掉先启动者已写的 **2,084 行 / 175,911 B**，文件里只剩它自己的启动头。
