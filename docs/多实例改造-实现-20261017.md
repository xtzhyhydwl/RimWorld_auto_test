## 2. 配套（同一条链路上必须跟着改，否则读不到自己）

- `readBridgeInfo`（`src/launcher.js:85`）：正则 `:94` 改为 `/GABP server (?:running standalone on|connected to GABS on) port (\d+)/`；回退改为按「日志路径的父目录名 = profile」（`:62 profileFromLogPath`）读该 profile 的记录，**回退保留**（GABS 日志没有 `Bridge token:` 行时仍走 `source:'env'`）。
- `readProcessRecord(profile)`（`:266`）改为同步读（`readBridgeInfo` 是同步函数）；所有旧 `await` 调用点不变仍可用。
- `status`（`src/cli.js:181`）、`bridge`、`logs`、`call`、`live` 全部按 `--profile` 取（`logs/call/live/tools` 本来就按 profile，现只改了取记录/桥接来源）；`status` 输出新增 `profile`、`otherGamePids`、`bridgeInLog.source`。
- 签名兼容：`startGame({profile,port,...})`、`stopGame({profile,force,timeoutMs})` 仍是对象参数；`src/smoke.js:305`、`plugin/dsh-rimworld/lib/index.js:92/189` 改为显式传 `profile`（否则 smoke --profile voiced / 插件会去动 vanilla 的实例）。默认 profile 仍 `vanilla`。
- 未引入依赖、未改 `package.json`、未改游戏侧 mod、未改 `语音副官/`。

## 4.5 实测：两个实例真并发（2026-10-17 18:05–18:12，全部亲手跑）

| 验的东西 | 结果 |
|-|-|
| 双实例并发 | **成立**。`voiced` PID 24564 → 端口 5174；`bike` PID 29520 → 端口 **5175**（auto 避让，没挤 5174） |
| 记录互不覆盖 | `runs/game-process.voiced.json` 与 `runs/game-process.bike.json` 同时存在 |
| 两个端口各自可达 | 两个 profile 的 `call rimworld/get_game_info` 都返回 `status:"no_game"`（= 各自的桥接活着、不串） |
| 守卫只拦同 profile | 并发期间 `start --profile voiced` 被拒，文案写明 profile 与该用哪条 stop；`bike` 的 start 只打「检测到其它 RimWorld 进程 PID 24564…并行启动」就继续 |
| `status` 归属正确 | 两边 `gameRunning=true`、`recordedPid` 各是自己的、`otherGamePids` 各是对方 |
| `stop --profile bike` 只杀自己 | bike 29520 退出、voiced 24564 仍在、voiced 桥接继续应答；再 `stop --profile voiced` 清干净，最终 0 个 RimWorld |
| 旧记录提示 | 每次 start 打「发现旧的单实例记录 … 已忽略」，随后删掉了那个死记录（它指向早已消失的 PID 14976） |
| 资源（主菜单、都没进图） | voiced 607 MB、bike 1159 MB working set；累计 CPU 秒 60.1 / 31.0 |
| **不需要长驻 job 托游戏** | `start` 命令退出后游戏仍在（detached 生效）。**推翻了旧 handoff 里「job 结束会带走游戏」的说法** |

仍未验：`--force` 全机强杀（破坏性，没跑）、两实例同时进图后的 CPU/内存、`Fast` 档的实际 tick 倍率。
