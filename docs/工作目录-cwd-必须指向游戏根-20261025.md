# 工作目录（cwd）必须指向游戏根

> 2026-10-25。结论先行：**launcher 早已正确**（`src\launcher.js:938` 的 `cwd: root`）；真正踩坑的是手工 `Start-Process` 起 1.6 那条路。

## 现象

1.6 起进程时不指定工作目录，日志里出现 `System.ExecutionEngineException: String conversion error: Illegal byte sequence encounted in the input`
（原文含拼写错误 `encounted`），位置在 `HarmonyLib.HarmonySharedState` 静态构造里做 `FieldRefAccess<StackFrame, long>` 时抛。
后果：Harmony 全部补丁失效，看起来像"一堆无关 mod 崩了"。

## 根因链

1. 不指定工作目录 ⇒ 子进程继承父进程 CWD = `E:\2026.7以后的新工程\...`（**含中文**）
2. Mono 在 Harmony 静态构造里反射取程序集路径（**由 CWD 派生**）并转字符串
3. 路径非 ASCII ⇒ `Illegal byte sequence` ⇒ `HarmonySharedState` 类型初始化异常
4. ⇒ Harmony 全废 ⇒ HAR 的 `AlienRace.CachedData` 初始化失败 ⇒ 鼠族 Ratkin def 解析失败 ⇒ 主界面每帧 NRE（本步为推理，依据日志时序）

## 证据（1.6 实测 A/B，同一份 12 项最小 ModsConfig）

| 轮次 | 进程 CWD | `-savedatafolder` | `Illegal byte sequence` | HarmonySharedState | Applied essential Harmony | Exception |
|---|---|---|---|---|---|---|
| A | 中文（继承工程目录） | 中文 | 7 | 8 | 0 | 1069 |
| B | 中文（继承工程目录） | `D:\rw16data`（ASCII） | 7 | 8 | 0 | 1069 |
| C | `D:\RimWorld-1.6`（ASCII） | `D:\rw16data4` | 0 | 2 | 1 | 1041 |

- A vs B 只换存档路径 → 数字逐项相同 ⇒ **存档路径不是原因**；A/B vs C 只换 CWD → `Illegal byte sequence` 7→0、`Applied essential Harmony` 0→1 ⇒ **CWD 是变量**。
- C 行剩下的 1041 Exception 是 IrisMenus 版本不匹配等独立问题，与 CWD 无关。原始记录：`docs\RimWorld-1.6补DLC与前置-20261025.md` 第 9 节、`docs\RimWorld-1.6-可运行化与验证-20261025.md`。

## 修法

- 代码：`spawnDetached(exe, args, { cwd: root })`，`root = gameRoot()` 即 exe 所在目录（不是 `Managed`、不是工程目录）。这行自初始提交 `e86e9e6` 起就在，本次只补了「为什么」的注释。
- 手工起 1.6 必须带 `-WorkingDirectory`：
  `Start-Process -FilePath 'D:\RimWorld-1.6\RimWorldWin64.exe' -WorkingDirectory 'D:\RimWorld-1.6' -ArgumentList ...`

## 如何自检（不启动游戏）

把 `child_process.spawn` 换成截获函数再调 `startGame()`，断言 `cwd === gameRoot() === path.dirname(exe)`；
脚本与实测输出见 `docs\launcher-cwd修复-20261025.md`。
