### 3.3 为什么没改（依据都是读码 + 实跑，不是推测）

1. **格式里没有"已停止"这个字段。** `src\launcher.js:917-952` 是这条记录**唯一**的写入口（`launcher.startGame`），它写死的字段是 `schema/source/writer/pid/startedAt/profile/profileDir/logFile/logStartOffset/logShared/logAnchor/gameVersion/gameMajorMinor/gameImage/waylith/modsConfigStamp/recordPath/exe/args/doorstop/bridge/portSource/prefsFile/window`，**没有任何 `stoppedAt` / `state` / `stopped` 字段**。
2. **`stopGame` 根本不写记录。** `src\launcher.js:1048-1127` 只 `readProcessRecord`，拿到 pid 就 `taskkill`，全程不落盘。也就是说工程里不存在"停止后把记录标记为已停止"的既有写法可以照抄。
3. **清空 pid 会让状态输出变成假话。** `recordTrust`（`src\launcher.js:280-295`）要求 `pid` 是正整数，`pid <= 0` 会被判为**不可信**（注释明说 `pid=0` 是"有人为了离线测 `wait` 手写记录"留下的，属于要拒绝的形态）。一旦 pid 被清空：`readProcessRecord` 返回 `null` → `gameStatus`（`:582-611`）的 evidence 会变成「没有 profile「rhah」的启动记录（…不存在）」，而文件**明明存在**；`cli.js stop`（`:688-694`）也会从「记录里的 PID 12612 已不在运行」退化成「没有 rhah 的运行记录」。两处都丢掉了"这一轮曾经跑过、现在死了"这个事实。
4. **这条陈旧记录当前并不造成误判。** 实跑 `node src/cli.js status --profile rhah` 得到 `gameRunning: false`、`runningState: "not-running"`、`recordedPid: 12612`、`recordedAlive: false`，evidence 第一行就是「profile「rhah」记录里的 PID 12612 不是本 profile 的运行实例（PID 12612 不存在）」。`startGame` 只在 `status.recordedAlive` 为真时拒启（`:787-795`），而 `recordedAlive` 现在走 `verifyInstance`（按命令行里的 `-savedatafolder=…\profiles\rhah` 认人），死 PID 不会挡 `start`。
5. **工程里有一条"不要手写这个文件"的既存约定**：`docs\RHAH-0008-走门验证-20261024.md:72` 记着上一轮会话「`runs\game-process.rhah.json` 仍是上一轮的死记录……我**没有改写**该文件（遵守「不写 `runs/game-process.*.json`」）」。
6. 另外，文件自述 `"writer": "src/launcher.js"`。手工改写会让这个 provenance 字段变成假的；即使只追加一个 `stoppedAt` 字段也不行——写它的就不是 launcher 了。

因此按任务给出的逃生口执行：「不确定就只备份、不改」。**建议**（留给下一轮决定，本次未做）：若要真正消除这条记录，正路是让 `stopGame` 在确认 pid 已死后自己写一个 `state:"stopped"` + `stoppedAt`（改 `src\launcher.js`，属于代码改动，本次硬性要求禁止改 `src\`），而不是手工编辑 JSON。
