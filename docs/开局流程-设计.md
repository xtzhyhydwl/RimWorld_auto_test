# 开局流程（Colony Bootstrap Routine）设计

> 来源：用户 2026-10-03。这是**比样板系统更基础**的一条线。
>
> 用户原话：
> 「随着我们这些流程越来越明确，**开局要做的事情越来越多**。
>  那么它大概就分为**开局要做的一批事情**，然后可能中期要注意的一些事情，
>  就至少**开局一定要做的事情是可以完全被完全规定出来的**。
>  那只要做到这些事情，基本上**开局就稳了**。」

---

## 一、核心思想：把"开局该做什么"固化成一个确定的清单

现在的做法是"各个域各自判断该不该动手"，这是**反应式**的。
用户提的是一条更简单也更可靠的路：

> **开局有一批固定要做的事，按固定顺序做完就行 —— 不需要判断。**

这跟样板系统是同一个哲学：**不靠智慧，靠抄已知正确的做法**。
而且它**更基础**：先把地基打好（允许物资、划好区），后面的域才有意义。

### 为什么这条重要

- **可完全规定 → 可完全测试**（不需要"看情况"，直接断言清单执行完了）
- **幂等**：做过就跳过，读档/重开都不会重复
- **顺序敏感**：有些事必须在前（比如"允许物资"必须在"划储藏区"之前，
  否则小人不会去搬）
- **失败可定位**：哪一步没做成，一眼能看出来

---

## 二、开局清单（当前已知的部分）

| # | 步骤 | 状态 | 备注 |
| --- | --- | --- | --- |
| 1 | **允许地图上所有物资被拾取** | ✅ 已实现（S1，14/14） | 玩家习惯的"全选→允许" |
| 2 | **划一片"丢弃区"储藏区在地图边缘** | ⬜ 要新增 | 专门放**人类尸体 / 有毒垃圾**这类脏东西 |
| 3 | **划一片"生活区"储藏区在基地附近** | 🟡 部分（S3 已有储藏区，但规则不对） | **必须排除**尸体与垃圾 |
| 4 | （待定）住处 / 食物 | 🟡 已有域 | 是否纳入"开局清单"待定 |

### ⚠ 步骤 2/3 是用户指出的一个**真缺陷**

用户原话：
> 「新放下来的存储器它会有一个缺点，就是**他什么都允许放置**，
>  结果就导致能够从事搬运的小人，他就会去把那种**尸体**给搬运到存储区，
>  也就是搬运到**生活区附近**，这就不太好了。」

**实测确认**：我的 `StockpileDomain` 确实调了 `filter.SetAllowAll(null, true)`
（"允许所有"）→ 会把 DLC 开局刷的**两具尸体**搬回生活区。

### 正确做法

```
① 边缘储藏区：只放"脏东西"
   → 默认禁止所有，然后只允许：尸体（人类/动物）、有毒垃圾

② 生活区储藏区：放正常物资
   → 默认允许所有，但**显式禁止**：尸体、有毒垃圾
```

**关键**：不是"允许什么"，而是**两片区的 filter 互为补集**。
这样无论 DLC 加了什么新垃圾，都不会漏到生活区（因为它不在"允许"列表里）。

## 三、开局清单应该长什么样（设计）

关键取舍：**清单放在哪**、**怎么表达**、**怎么保证幂等**。

### 方案：一个显式的、有顺序的 `OpeningChecklist`

```
BootstrapStep {
    string Id;            // 稳定标识（幂等用）
    string Description;   // 人话
    int    Order;         // 执行顺序（小的先）
    bool   IsDone(state); // 已经做过了吗
    StepResult Run(ctx);  // 真的做
}
```

好处：
- **顺序显式**：不用靠"域优先级"来暗示先后
- **幂等靠 `IsDone`**：每步自己判断（而不是靠一个全局"开局做过了"标记 ——
  那个坑我在 S1 踩过：一次性标记在地图还没就绪时就被置位了）
- **可测**：喂一个合成世界 → 断言每一步的结果

### 与现有"域框架"的关系

| | 域（INeedDomain） | 开局清单（BootstrapStep） |
| --- | --- | --- |
| 性质 | **持续**的、反应式 | **一次性**、规定式 |
| 触发 | 每天/每 N 天 | 只在前几天，或条件满足时 |
| 判断 | "现在该不该动手" | "这步做了没" |

→ 两者**并存**：清单负责"把地基打好"，域负责"之后持续维持"。
   清单跑完之后，域才开始有意义（比如没划储藏区，食物域种出来的东西没地方放）。

## 四、这条线怎么和样板系统配合

用户提的"中期要注意的事情"和"后期逐步扩张"其实都能落到同一套机制上：

```
开局清单（规定死）  →  样板库（抄已知设计）  →  域（持续维持）
   最可靠                    可靠                    灵活
```

- **开局清单**：完全规定，没有判断
- **样板库**：需要判断"盖哪个样板、盖在哪"，但**盖什么**是确定的
- **域**：持续反应（食物会不会不够、储藏区够不够）

越靠左越可靠、越容易测；越靠右越灵活、越难保证。
**所以正确策略是：能用左边解决的，就不要动右边。**

## 六、一个要小心的地方

清单是"规定死"的，但**世界是随机的**：地图上可能没有合适的地方放边缘储藏区，
或者基地位置特殊。所以每一步都要：
- **失败不阻塞后续**（这步没做成，继续做下一步，并把失败写进报告）
- **给出可诊断的原因**（不是静默跳过）

这和域框架的"不放弃"原则一致。
