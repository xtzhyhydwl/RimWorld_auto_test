# 样板拼接：共享墙复用（用户 2026-10-03 提出）

> 用户原话：
> 「13 乘 13 你能发现，如果你要把**两个房子连在一起**，那么他们**中间的墙是可以复用的**。
>  就这个逻辑我不知道应该是好不好写吧，能复用的话**少一面墙**，
>  然后它其实也**更像一个整体**。」

---

## 一、这条需求比"省一面墙"更重要

省一面墙（13 格木料）是**次要收益**。真正的收益是：

> **基地能长成一个整体，而不是一堆散落的方盒子。**

这一点直接决定"后期逐步扩张（空间/纵深/防御）"能不能做 ——
如果每间房都必须独占一块空地，那么基地永远是一盘散沙，
既不好防御，也不好看，更不可能做"扩建"。

所以这条需求的**本质**是：**样板要能拼接**。

---

## 二、⚠ 先暴露一个架构缺口：现在根本不会挨着

当前实现是 `TemplatePlacer.FindBestSite` —— 它**只找"整块空地上能塞下样板"的位置**，
`PlacementGrid.CanPlace` 里"已有建筑"的格子直接是 `false`。

**结果：两个房子永远不会贴在一起，也就永远谈不上复用墙。**

所以这条需求拆成**两个**，而且必须先做 A 才能做 B：

| # | 需求 | 现状 |
| --- | --- | --- |
| **A** | **贴靠选址**：选址能"贴着已有房子"放，而不是只找空地 | ⬜ 未实现（当前只找空地） |
| **B** | **共享墙去重**：重合的墙格不重复放蓝图 | ⬜ 未实现 |

---

## 三、设计

### A. 贴靠选址

在现有滑窗选址的基础上，加一个"贴靠模式"：

```
对每个候选位置：
  if 整块都空        → 可行（现状）
  else if 与已有建筑/蓝图相邻，且
          只有**边缘格**被占、内部格都是空的 → 也可行（贴靠）
  else               → 不可行
```

关键判据：**样板内部（非边缘）必须都是空的**。理由：
- 边缘格被占 = 那一格本来就是别人的墙 → 可以共用（见 B）
- 内部格被占 = 里面已经有东西了 → 放进去会打架

### B. 共享墙去重

放蓝图时，对每个模板格先查**那一格是不是已经有墙/门了**：

```
for 每个模板格 (x,z):
    sym = 样板里这一格的角色
    已有 = 地图上 (mx,mz) 是否已有同类的建筑/蓝图

    if 已有 且 角色匹配（都是墙类 / 都是门类）:
        跳过（★ 复用，不重复放）
    else if 已有 但角色不匹配:
        ★ 冲突 → 这一格不跳过，也不硬放；记进 Unresolved 并说明
    else:
        正常放
```

### ⚠ 必须防的一个错误：把**门**当成共享墙跳过

如果已有那一格是**门**，而样板里是**墙**（或反之），**绝不能当作可复用**。
后果是：
- 把门当墙跳过 → 门还在（还行）
- 把墙当门跳过 → **墙上多了个洞，房子不封闭，屋顶不会长**

所以角色匹配必须是**同类才算复用**：
`wall↔wall` 可以，`door↔door` 可以，`wall↔door` **不行**。

→ 这正好用得上现有的 `TemplateRole.IsWallLike` / `IsDoorLike`。

---

## 四、⚠ 一个必须说清的局限（不隐瞒）

**共用墙意味着"一损俱损"**：那面墙被拆/烧毁/被虫蛀，两间房同时漏。

但要注意：
- **这不是拼接引入的新问题** —— 玩家手连房也有同样的风险
- RimWorld 的墙是**独立物件**，本来就没有"共用墙体"的概念
- 所以"复用"在实现上就是**不重复放蓝图**，墙本身仍是一格一个

**真正需要防的是"以为能省结果造出危房"**：
如果那一格已有的是**框架/未建成的蓝图**，跳过之后那面墙可能永远没建成。
→ 所以共享墙必须**回读验证**：拼接完成后，共用的那几格**必须确实有墙**。

## 五、测试计划（纯逻辑，可离线）

`TemplatePlacer` 里加：
1. `FindAttachSite` —— 找贴靠位置（内部必须空、边缘可占）
2. `Plan` 增加"已有建筑"输入，重合的同类格跳过

断言：
- [ ] 两个 13×13 并排 → 共享的那一列墙**只放一次蓝图**
- [ ] 共享的是**门**时不会被墙覆盖（双向都测）
- [ ] 共享墙那一格**已有的是框架**时，**不跳过**（否则可能永远建不成）
- [ ] 样板内部被占 → 该位置不可用（不能"贴靠"进别人屋里）
- [ ] 拼接后总面积不是"两倍"（墙数少于 2×44）

## 六、优先级

放在 **S5（5 天生存验收）之后**。理由：

- S5 是当前阶段目标，且**不依赖**拼接（一间房就够撑 5 天）
- 拼接是"扩张期"的需求（用户说的"后期逐步扩张：空间/纵深/防御"）
- 但它**必须在收集第二批样板之前想清楚** —— 因为样板可能会因为
  "要不要预留共享边"而改变形状（比如两面开门的角房 vs 四面开门的独立房）

→ 所以现在的动作是：**记录 + 写测试基础设施**，实现放到 S5 之后。
