## 一、样板不只是"形状"，它有**语义**（本次扫描就暴露了）

### 扫出来的东西

`templates/bedroom-13x13.json`（用户在 (132,126) 造的 13×13）：

```
WWWWWWDWWWWWW
WBWBW...WBWBW
WBWBW...WBWBW
WDWDW...WDWDW
W.......W...W
W...TSS.....W
D...STTS....D
W...STTS....W
W...W.A.....W
WDWDW...WDWDW
WBWBW..EWBWBW
WBWBW..EWBWBW
WWWWWWDWWWWWW
```

结构：**四个 5×5 角房 + 中央十字走廊**，每间角房 2 床（共 8 床）。

### ⚠ 我的分类器把**娱乐设施**错认成**餐桌**

| 代号 | 我标的角色 | 实际扫到的 Def | 真相 |
| --- | --- | --- | --- |
| `T` | **table（餐桌）** | **`ChessTable`（国际象棋桌）** | ★ **是娱乐设施，不是餐桌** |
| `S` | seat（凳子） | `Stool` | 围着棋桌 → 也是娱乐 |
| `A` | furniture | `HorseshoesPin`（马蹄铁） | 也是娱乐 |

→ 这三个合起来是**一个娱乐区**。按我的错误分类盖出来，会**少一个娱乐设施、多一个假餐桌**。

**教训**：`accepts` 的语义分类不能只看 Def 名里有没有 "Table"。
  **`ChessTable` 的字面名字骗了我** —— 它的 `thingCategories` / `joyKind` 才是真相。
  （这正是"套公式"的反面：名字匹配是"猜"，查分类是"查"。）

### 由此得出：样板需要**两层语义**

```
① 形状层：rows（哪些格放什么）        ← 已有
② 语义层：每个槽位的角色 + 它属于哪一类  ← 需要补
    - 结构（墙/门）
    - 睡眠（床）
    - 进食（餐桌椅）
    - 娱乐（棋桌/马蹄铁/台球…）★ 本次漏掉的
    - 照明（灯/火把）
    - 储物（架子）
```

## 二、**数量是动态的**：有几个人放几张床

用户：
> 「一般来说，**有几个人造几个床就可以了**。」

所以样板里的 8 张床**不是"必须 8 张"，而是"最多 8 个位置"**。

→ 需要一个新的概念：**槽位的数量策略**

| 策略 | 含义 | 例子 |
| --- | --- | --- |
| `fixed` | 照样板放满 | 墙、门 |
| `perColonist` | **按殖民者数**放 | **床**（每人 1 张） |
| `perColonistRatio` | 按比例 | 餐桌椅（可能 2 人 1 桌） |
| `atLeastOne` | 至少 1 个 | 光源、娱乐设施 |

★ 这次的样板（8 床）如果按 `perColonist` 放，3 个殖民者只放 3 张床 ——
  正好符合用户说的"有几个人造几个床"。
  而**其余的床槽位留空**（变成空地），不是放个假的。

## 三、**分段材料决策**（推翻我上一轮的设计）

用户在上一轮让我做"建造前评估材料"，我做了**整栋一次性评估**。
**用户现在明确否定了这个粒度**：

> 「**不是说是在造整个样板之前就决定**，而是它可能有一个**分段的决策**。」
> 「先把外墙的命令下下去，也是用木头。然后发现木头不够了，然后再把那个床的命令
>  下下去，用的是铁。」

### 对比

| | 整栋一次评估（我上轮做的） | **分段决策（用户要的）** |
| --- | --- | --- |
| 粒度 | 整栋用同一种材料 | **每个阶段各选各的材料** |
| 木头不足时 | 整栋转钢（或整栋不造） | **外墙用木头（够的部分），床用铁** |
| 结果 | 均匀但不灵活 | **能用上的材料都用上** |

### 为什么分段更好

想清楚这一点很重要：**整栋一次评估会浪费已够用的部分**。

例：需 320，木头有 300、钢有 900。
- 整栋一次评估 → 全是钢（900 够）→ **木头 300 一点没用上**
- 分段 → 外墙用木头（比如只需 260，够）→ 剩 40 木头 → 床用铁
  → **木头用掉了，钢用得少**，总体更省

★ 这跟"建造顺序"是**同一个机制的两面**：既然建造是有顺序的，
  那材料也应该**跟着顺序分段决定**。

## 四、★ **建造顺序 = 放置顺序**？（关键假设，**必须实测**）

用户：
> 「如果我没记错的话，环世界小人执行这些命令的顺序，应该就是你**放置蓝图的顺序**。」

**这是整个设计的承重墙**：

- 如果**成立** → 我只要**按期望顺序放蓝图**，就能控制施工顺序
  → "分段材料决策"和"先墙后床"都自然成立
- 如果**不成立**（比如按距离/工作类型/随机排） → 整个设计要换

### 我目前知道的（不确定的部分要标出来）

我文档里记录了建造由三个 WorkGiver 承接（`生产自动化-设计.md` §7.15）：
```
WorkGiver_ConstructDeliverResourcesToBlueprints   送料到蓝图
WorkGiver_ConstructDeliverResourcesToFrames       送料到框架
WorkGiver_ConstructFinishFrames                   施工完成
```
但**排序规则我从没确证过**。

⚠ **不能猜**。需要一个**实测**：

```
实验设计：
  ① 在一个空区域，先放 A 蓝图、后放 B 蓝图（相距较远，排除"就近"干扰）
  ② 推几十 tick，观察**哪个先被送料/先变成框架/先建成**
  ③ 交换顺序再测一次（排除"位置偏好"）
判据：
  - 两次都是"先放的先建" → 放置顺序决定 ✓
  - 两次都是"某个位置的先建" → 由位置决定 ✗
  - 随机 → 需要别的控制手段（比如分阶段放，等上一段建完再放下一段）
```

★ 无论结果如何，**"分阶段放 + 等上一阶段完成再放下一阶段"**都能实现顺序控制 ——
  只是效率低一点（要等待）。所以**最坏情况也能做**，但要知道代价。

## 七、和"套公式优于局部最优"的关系

这一轮**完全印证**了那条原则：

- 用户给的**建造顺序**是一个**公式**（墙→门→床→桌→光→娱乐），不是我发明的启发式
- 用户给的**床数规则**（有几个人放几张）是一个**公式**，不是优化
- 用户给的**分段材料**是一个**规则**，不是全局最优求解

而我的"整栋一次评估材料"就是**又一次局部最优**：它在"整栋材料一致"这个子问题里最优，
却**浪费了已够用的木头**。
