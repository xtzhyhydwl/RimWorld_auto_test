## 用户给了第一份真样板(13x13 卧室)

坐标 (132,126)-(144,138), 扫描存为 templates/bedroom-13x13.json

结构与语义(我读出来的):
  - 四个 5x5 角房, 每间 2 张床 = 共 8 床
  - 中央十字走廊
  - 中央有 **娱乐区**: ChessTable(棋桌) + 4 Stool(凳) + HorseshoesPin(马蹄铁)
  - 左下有 2 个 Shelf(架子, 储物)
  - 四边中点各一扇门(外墙), 另有 8 扇内门连通角房与走廊

★★ 抓到我的分类器一个**语义错误**:
  T 我标成 `table`(餐桌), 但实际扫到的是 **`ChessTable`(国际象棋桌)** —— 那是**娱乐设施**。
  它 + 4 个 Stool + HorseshoesPin 合起来是**一个娱乐区**。
  按我的错误分类盖出来 -> **少一个娱乐设施、多一个假餐桌**。
  教训: `accepts` 的语义分类不能靠 Def 名里有没有 "Table" ——
  **`ChessTable` 的字面名字骗了我**。要看 `thingCategories` / `joyKind`。

## 用户提出的三条设计(都改变了下一步)

### ① 数量是动态的: 有几个人放几张床
  样板里 8 张床不是"必须 8 张", 而是"最多 8 个位置"。
  -> 需要"槽位数量策略": fixed / perColonist / atLeastOne

### ② 分段材料决策(推翻我上一轮的设计)
  用户: "**不是**在造整个样板之前就决定, 而是它可能有一个**分段的决策**"
        "先把外墙的命令下下去, 也是用木头。然后发现木头不够了,
         然后再把那个床的命令下下去, 用的是铁。"
  ★ 我上一轮做的"整栋一次评估"是**又一次局部最优**:
    需 320, 木头有 300, 钢有 900 -> 整栋一次评估会选钢 -> **木头 300 一点没用上**
    分段则: 外墙用木头(够) -> 剩 40 木头 -> 床用铁 -> **木头用掉了, 钢用得少**
  -> 跟"建造顺序"是同一个机制的两面

### ③ 建造顺序 = 放置顺序? (承重假设, 必须实测)
  用户: "环世界小人执行这些命令的顺序, 应该就是你**放置蓝图的顺序**"
  如果成立 -> 按期望顺序放蓝图就能控制施工顺序
  如果不成立 -> 需要"分阶段放 + 等上一阶段完成"
  ⚠ 我文档里**只记了谁去做建造, 从没确证排序规则**。不能猜。
