## 2. 两个症状的真因

### 2.1 「做一张票老发散到别处」

三层，按因果排：

1. **决策票 ≠ 实施票。** 决策票的产物是「决定」，实施票的产物是「一个可回滚的改动 + 一条断言」。你在决策票上直接开工，等于每轮都在**现场重新划定范围**——而范围一飘，顺手改和顺带发现就是必然。
2. **没有「一张票只准碰哪些文件」的硬边界。** 计划里其实有这条（「谁都不许同时改同一文件」`EXECUTION-PLAN.md` §4），但它是**排期规则**，不是**单票规则**：真正在写代码时没人拿着清单核。结果 0008 的 16 个未合并文件把 0007/0002/0003 全堵住（`RHAH-下一票选择` §1.1 已实测）。
3. **上下文从不换。** 0002 → 0010 → 0007 → 0008 在同一会话里连着做，上一票的细节全在窗口里，于是「顺手」总是有理由；为了让下一轮能接上，只能再写一份 HANDOFF——11 份 HANDOFF 就是「上下文没清」的物证。

### 2.2 「自动化不了」

不是票的问题，是**三处基础设施缺口**，每一处都在每张票上重新收一次费：

| 缺口 | 后果 | 现在谁在替它付账 |
|---|---|---|
| 单测跑不了（testhost 拒 `OpenProcess`） | 没有「一条先变红的命令」，红绿回路不存在 ⇒ 只能真机 + 人眼 | 每票一轮真机验证（0002 有 V4/V5/V8 三轮报告） |
| 缺原子：小人 stat、敌情场景、信件状态等 | 每票现造测试装置与判据 | `docs\条件登记表-候选数据-20261024.md`、`runs\...\C-缺原子\` |
| 1.6 不稳 / CLI 只包 1.7 | 「1.6 也要验」的票直接卡死或退化成构建证据 | 0001、0007、0010 都记着「1.6 只有构建证据」 |

再叠上闸门第 5 道是人工，**每张票的终点都停在你的眼睛上**。票一多，你不在时它们就只能挂着开分支——这就是「3 个 PR 同时开着」的来源。

## 3. 接下来七步（每步带判据）

### 第 0 步：先决定两张「地基票」的待决项（10 分钟，只有你能拍）
- **0010（流程与规则缺口）待决 1**：把「闸门 / 票号 / 一次只一票 / 票仓库指针」写进本仓库 `AGENTS.md`（三句摘要 + 指针，不复制正文）。
- **0010 待决 5**：插在 0009 之前还是之后。建议**之后**（先止血 0009，再立规则）。
- **0009（工具/文档腐化）待决 1**：选 **(a) `cli doccheck`**；**待决 2**：本 PR **不含** ③；**待决 3**（同族小修）**另开票**。
- 判据：`AGENTS.md` 里能用一句话答出「票在哪、一次做几张、闸门是什么」，且新会话不用看对话。

> 为什么先做这两张：它们是**唯一会降低后续每一张票成本**的票。跳过它们直接做行为票，就是这两天的循环。

### 第 1 步：把在飞的收掉，回到「零分支」
顺序按文件冲突来，不按票号：**#10（0002）→ #11（0010）→ #12（0007）**（三者互不重叠，可并行评审，但合并要串行）。
判据：本机只剩 `main`，`git branch -a` 无 feature 分支，工作区只剩构建产物。

### 第 2 步：把 map 收口成一页 spec，然后**重切实施票**
一页纸只写三件事：这批票要实现的行为、明确不做、先后顺序。
每张实施票 ≤ 1 页，五栏固定：**行为断言 / 文件白名单 / 明确不做 / 阻塞边 / 一条能机械跑的验收命令**。
老的 16–79 KB 决策票**降级为参考资料**（只在写票时查，不再逐票通读）。
判据：一张票交给新会话，它不需要读 `docs\` 里任何别的文件就能开工。

### 第 3 步：一次只开一票，新上下文，5 行派单
派单只写：票号、行为断言、文件白名单、验收命令、不许做的事。
判据：同时只有一个 feature 分支。

### 第 4 步：一张票只准产出 3 个文件
票面 `## 状态` 更新、1 份验证报告、PR 正文。其余内容写进票的对应小节——**不再新建文件**。
判据：`docs\` 下按票号的计数，一张票 ≤ 3。

### 第 5 步：三处自动化缺口各修一次（挂在 0009/0010 名下，不摊到每票）
- 单测：放进上游 CI（PR 的 check 已经会跑），或修 testhost 权限。二者选一，**这是「自动化」的唯一开关**。
- 原子：把票里反复要的三类（小人 stat / 敌情 / 信件状态）登记成 `wait --source bridge` 条件。
- 1.6：按 `rimworld-switch-test-version` 把「能切」做成命令，不要每票手工试。

### 第 6 步：人眼验收批处理
一个会话结束前，把所有「要你看一眼」的合成一张清单一次看完，不要让每张票各自堵在闸门 5。

### 第 7 步：收尾 retro 写进 `AGENTS.md` / skill，不写成第 12 份文档
`docs\2026-10-25-skill试跑缺陷.md`、`docs\组合skill-试跑-20261024.md` 已经是两份很好的 retro——但它们停在 docs 里，所以同样的坑还在（0010 就是为这件事开的票）。

### 8.2 它不是「过期」，是「当场就是错的」【实测 2026-10-26 20:0x】

- `STATUS.md:57` 写「`rhah`（19 mod…）**现在在跑**」；同一时刻 `env-check --profile rhah` 输出 `running=false pid=19048 不存在`、`桥接 reachable=false`、阻塞项 1 条。⇒ 读它的人会以为有个在跑的实例。
- 顶部写「现在（2026-10-25 18:2x 核）」，正文里已有 2026-10-26 00:1x / 01:16 的内容 ⇒「核对时间」没人维护，读者无法判断哪条还成立。
- 体量：HEAD 版 **36 行 / 3,560 字符**（`c57b2a6`「压缩成索引」的结果），工作区 **93 行 / 17,138 字节**，而 `c57b2a6` 之后 **0 次提交** ⇒ 13 KB 增长全在未提交状态，没人评审、没进任何闸门。`git log -- STATUS.md` 累计 **58 次**改动。

### 8.3 一条可复用的判据

> **30 秒内能自己重新算出来的事实，不要进状态文件；不会自己变的事实，才该进。**
> 端口 / mod 数 / DLL hash / 某进程在不在 → 现查；只有**不会自己变**的约定才写下来（例：游戏 / 工坊里的二进制属于玩家，替换后必须还原并比 hash）。
