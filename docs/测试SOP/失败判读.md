# 失败判读

> 先分清是**哪种**失败，处置完全不同。动作类命令（`call` / `start`）的失败也在这查。
> 本文件只写「怎么判 + 下一步做什么」，不重复 SOP 的步骤。

## 0 快速三分

| 现象 | 是什么 | 去哪 |
| --- | --- | --- |
| `wait` 退出码 `2`，stderr 有 `[wait] 超时：` | 条件一直没成立 | §1 |
| `wait` 退出码 `1`，stderr **含** `[错误]` / `条件写错了` | 命令、参数、环境或探针本身坏 | §2 |
| `call` 退出码 `1` | 命令级失败（参数/工具名/连不上桥接）**或**动作级失败（工具返回 `success:false`） | §2.1 |
| 探针故障 `GABP_TIMEOUT` | 取不到观测（桥接没回来） | §3 |
| 退出码 `0`，但断言不成立 | 判据选错，或前置动作没生效 | §4 |

`wait` 的 stderr 会先打一行 `[wait] profile=… source=… …` 横幅，所以别按"开头是什么"判，按**含**什么判。

退出码约定：`0` 命中 / `2` 超时没等到 / `1` 其它。出处只指符号不指行号（`src/cli.js` 里 `process.exitCode` 的赋值处：`1` 在参数/环境错、未知子命令与 `call` 的动作级失败分支，`2` 在 `wait` 超时分支，`0` 是正常返回）——**这个文件天天在改，写死的行号必漂**。

`call` 的 `1` 不是单一含义：同样是 `1`，可能什么都没执行（命令级），也可能工具真的跑了但失败了（动作级，stdout 有完整载荷）。分辨方法见 §2.1。

## 1 退出码 2：时间到了，条件没成立

stderr 会给三样东西：`attempts` 与 `elapsedMs`、最后一次采样（打印时截断到 2000 字符）、以及有没有 `missingPath`。

- **带 `missingPath`** ⇒ 这个路径**从头到尾都取不到**。三种来源：①字段名写错；②前置阶段没做（没进图时 `list_colonists` 里根本没有 `colonists`）；③**探针自己返回 `success:false`**。
  第三类的判据：`available` 的形状恰为 `success, message, exception, operation`（探针把错误当载荷返回，业务字段一个都没有）。
  正确处置：`node src/cli.js call <同一探针> --args-file <同一参数> --profile <p>` 读 `message`（里面写清了为什么），**不是**去改字段名，也不是等进图。
  提示里带 `brokenAt`（断在哪一段）和那一层的可用字段（最多 12 个）——照着它改路径。
- **不带 `missingPath`** ⇒ 路径取到了，是**值不匹配**或条件本身不成立。改算子/期望值，或者先把时间推够再等。
- 采样被截断时，用 `node src/cli.js call <工具名> --profile <p>` 取完整载荷。

处置顺序：先补前置（例如先等 `result.state.playable`），再改字段名，最后才考虑加预算。**加大超时换不来结论。**

## 2 退出码 1：命令或环境问题（改完再跑，不重试）

| 文案特征 | 成因 | 处置 |
| --- | --- | --- |
| `条件写错了：不认识的算子` / 类型不符 / 顶层不是对象 | 条件 JSON 或算子写错 | 照 `cli atoms` 的算子表改 |
| 路径没以 `result.` 开头 | 探针载荷都在 `result` 下 | 补上 `result.` |
| `未知工具` / `已阻止调用` | 工具名不存在 | `tools <关键词> --profile <p>` 查全名，再 `describe <工具名> --profile <p>` 看参数 |
| `拒绝连接 …`（记录可信 / PID / 端口 / token） | 多实例归属校验没过 | `status --profile <p>` 看 `bridgeResolution` 的判据 |
| 握手失败 / 连接超时 | 桥接没起来或端口不通 | 重启实例，重新等 `bridge-ready` |
| `ENOENT`（`--condition-file` / `--args-file`） | 文件路径错 | 换成正确路径；`@file` 要带引号。裸写 `@cond.json`（不带目录）在 PowerShell 里是**解析期**的 splatting 报错（`'@cond' 只能当命令参数用`），node 根本没启动；带路径分隔符的裸写反而能跑 |
| `--args` / `--condition` 报 `JSON 解析失败`，`收到：{readiness:playable}`（**双引号没了**） | Windows PowerShell 5.1 吞掉了双引号（不是 CLI 坏、也不是参数错） | **JSON 落文件**：用 `write` 工具写一个小 JSON 文件，改走 `--args-file <文件>` / `--condition-file <文件>`；或把内层引号写成 `\"`。**不要**用 `Set-Content` 写 JSON（PS 5.1 会把中文写成 GBK） |
| 用法提示（命令拼错） | 参数不对 | 照 `docs/cli-wait-用法-20261024.md` |

各来源的差异：

- `--source process` 既没有 `--pid` 也没有可用记录 ⇒ `1`。
- **两套 source 命名，别混**：
  - `live --source events|log`（跟读事件文件 / Player.log）；写成 `--source event` ⇒ usage 错 exit `1`。文件不存在不报错：读到空 ⇒ 轮询到超时 ⇒ `2`，先确认 `runs/live/<p>.ndjson` 在写。
  - `wait --source bridge|event|process|bridge-ready`（采样来源：`event` 是单数）；写成 `--source events` ⇒ 同样 exit `1`。
- `--source bridge-ready` 在没游戏时是**超时** ⇒ `2`，不是环境错。

### 2.1 `call` 的 `exit 1`：命令级 vs 动作级

`cli call` 命中工具、但**工具返回 `success:false`** 时退出码也是 `1`（stderr 一行说明，stdout 仍打完整载荷）。两种 `1` 的处置完全相反：

| | 命令级失败 | 动作级失败 |
| --- | --- | --- |
| 什么坏了 | 参数错 / 工具名不存在 / 连不上桥接 | 工具真的执行了，但结果是 `success:false` |
| stdout | **没有**载荷 | **有**完整载荷（`success:false` + `message` / `operation.Error`） |
| 下一步 | 按 §2 的表改命令 | 读 `message`，**不要**去改判据 |

**区分方法就一条：看 stdout 有没有完整载荷。** 所以脚本里不能把「`call` 退出码非 0」当成「命令没执行」——那会把「动作失败了」误读成「调用写错了」。

动作级失败的处置：先读 `message`（工具自己写清了为什么：前置没做、参数不被接受、目标不存在……）。**判据没错，是这次动作没成**；改判据/改字段名只会把一次真实的失败掩盖掉。
`wait` 的 `missingPath` 里若 `available` 恰好是 `success, message, exception, operation` 四个字段，那是**同一种**动作级失败（探针把错误当载荷返回了），判法见 §1 第一类。

## 3 探针故障：`GABP_TIMEOUT`

文案：`探针故障（第 N 次采样，Xms）：…` 加一句「再等也不会变好」。含义是这次桥接调用没在预算内回来，常见于游戏主线程被长任务占住。

处置：重启实例并重新等 `bridge-ready`；换一个探针不会让它变好。

例外：最后一轮探针正好把预算耗光，`wait` 会归成 `2`（这是时间到了，不是桥接坏了）。

**反过来的坑**：从第 2 轮起，挂住的探针会把剩余预算全耗光，`wait` 于是归成 `2`，带回的还是**上一轮**的采样。
所以看到 `2` 且 `attempts ≥ 2`、`elapsedMs` 贴着预算时，先用 `cli call` 打一次同一探针：能回 ⇒ 是判据问题；回不来 ⇒ 桥接挂了，按本节处置。

## 4 断言不成立，但状态"看起来对"

判据选错了。回 skill `rimworld-auto-test-closed-loop` §2 重答四问，另选一个可回读的字段。

位置类结论只用格子/坐标回读：2026-10-24 实测所有 pawn 的渲染位置可能不跟随实际位置，截图不作位置证据。

## 5 症状 → 处置

| 症状 | 多半是 | 处置 |
| --- | --- | --- |
| 动作返回 `success: true`，状态没变 | 调用成功 ≠ 状态变了 | 回读探针或截图 |
| 一直等 `result.colonists` 到超时 | 还没进图 | 先等 `result.state.playable` |
| `step_game_ticks` 返回 `advancedTicks: 0` | 被强制暂停或新窗口掐住 | 先等「无强制暂停窗口」，再分段推 |
| 桥接调用成功，但结果像别人的局 | 归属没校验 | 先 `status --profile <p>` |
| 按 `Player.log` 偏移 / ERROR 计数下结论 | 1.7 日志全机共用、被后启动者重写 | 桥接探针或 `runs/live/<p>.ndjson` |
| 想往回复里贴长 JSON | 吃上下文、无法复查 | 落 `runs/<日期>-<主题>/`，正文给路径 |
