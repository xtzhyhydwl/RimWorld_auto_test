# SOP：存档读档（存 → 读回 → 字段对账）

> 证据等级：**整份【未验证】**（没按本文件顺序真跑过）。本文件由 2026-10-24 已落盘的实测产物反推：`runs\20261024-RHAH-0008-trapped-baseline\` 的 35-save / 38-load / 40-wait-idle / 42-pause3 / 43-target-by-name。
> 标【实测】= 该字段或现象在那批产物里有原文；命令一律在 `$WS` 下执行，`<p>` = 本次 profile，`<主题>` = 本次 `runs/<日期>-<主题>/`。JSON 一律落文件走 `--args-file` / `--condition-file`，**不要内联** `--args '{…}'` / `--condition '{…}'`：PS 5.1 会吞掉双引号，node 收到的是 `{a:b}` ⇒ 直接解析失败。落文件用 `write` 工具，**别用 `Set-Content`**（PS 5.1 会把中文写成 GBK）。

## 0 什么时候用

**用**（三条任一）：
1. 需求里出现「存档 / 读档 / 读回来 / 跨存档 / Scribe / ExposeData / 改存档再读」。
2. 要证明**桥接读不到的字段**真的写进了存档：桥接没有 CLR 访问能力，组件字段只能 `save_game` + 读 `.rws` 原文（现成做法见 [RIMBRIDGE-技巧手册](../RIMBRIDGE-技巧手册.md) §9）。
3. 要反复回到同一个已知状态重跑同一段：存一次，之后每次读档回起点。

**不用**：一把跑完、不需要跨存档证明 ⇒ [标准-六阶段](标准-六阶段.md)；两个实例同时跑 ⇒ 回[目录](README.md)「特殊流程」按适用条件挑。
**六阶段为什么不顶用**（三条都是它的空档）：§2「进门」只有 `start` + `start_debug_game_ready` 一条路（开新局），没有"读档进门"；§6 取证只有截图 / 回读 JSON / 事件三类，没有"存档 XML"这条通道；§4 默认时间是受控的，而读档后时间会自己往前跑（见阶段 5）。

**开测前先过[环境自检](环境自检.md)的四项检查**（桥接归属 / 必备 mod / 加载顺序 / 摆小人的工具）。

## 1 起实例并进图（本 SOP 从"已进图"接手）

- 动作：`node src/cli.js start --profile <p> --width 1600 --height 900 --monitor <n>`；进图 `node src/cli.js call rimworld/start_debug_game_ready --profile <p>`。
- 判据：`node src/cli.js wait --profile <p> --scenario 已进图可玩` exit `0`（登记表 wait-verified 档）。
- 证据：`runs/<日期>-<主题>/01-ready.json`（`call` 全量载荷）。细节见 [标准-六阶段](标准-六阶段.md) §1–§2，不在此重复。

## 2 记存前基线（后面全靠它做对账）

- 动作：`node src/cli.js call rimworld/get_game_info --profile <p>`；`node src/cli.js call rimworld/list_colonists --args-file a-colonists.json --profile <p>`（`a-colonists.json` 内容：`{"currentMapOnly":true}`）。
- 判据：`result.ticksGame` `>= 1` 且 `result.mapCount` `>= 1`【实测 940 / 1】；`result.count` `>= 1`【实测 3】。
- 证据：`02-baseline-game-info.json`、`02-baseline-colonists.json`。把 `ticksGame`、`count`、每个 `colonists[].pawnId` 抄进报告 §0，作为阶段 6 的期望值。

## 3 存档

- 动作：`node src/cli.js call rimworld/save_game --args-file a-save.json --profile <p>`（`{"saveName":"<档名>"}`，不带扩展名）。
- 判据（三件，缺一不算过）：
  1. 返回 `result.exists = true` 且 `result.sizeBytes > 0`【实测 15,498,613 B，DurationMs 557】。
  2. 磁盘上 `result.path` 的实际长度 = `result.sizeBytes`：`Get-Item '<path>' | Select-Object Length`。
  3. 目标键在存档原文里的命中数 = 期望值：`(Select-String -Path '<path>' -Pattern '<目标键>' -AllMatches).Matches.Count`（例：`<lifecycle>Leaving</lifecycle>`）。这个数是阶段 6 的对账基准。
- 证据：`03-save.json`、`03-save-xml.txt`（`Select-String … | Set-Content`）。
- **`save_game` 是动作，不能当 `wait --probe`** —— `--probe` 会反复调用它，等于反复存档。判据一律"动作一次 + 只读探针/磁盘核对"。

## 4 读档

- 动作：`node src/cli.js call rimworld/load_game_ready --args-file a-load.json --profile <p>`，参数 `{"saveName":"<档名>","readiness":"mapData","pauseIfNeeded":true,"ignoreModCompatibility":true,"timeoutMs":180000}`。`readiness` 取值：`gameData` / `mapData` / `currentMap` / `playable` / `visual`。
- 判据：`result.wait.satisfied = true`【实测 attempts 1 / elapsedMs 196】**并且** `node src/cli.js wait --profile <p> --scenario 已进图可玩` exit `0`。
  **不许拿 `result.success` 当判据**：同一份返回里 `result.state.playable = false`【实测，见 38-load.json】。
- 证据：`04-load.json`、`04-playable.json`。
- `ignoreModCompatibility=true` 只在测试档上开；它跳过"存档记录的 mod 是否都启用"这道校验，也把结果写进 `result.compatibilityCheckIgnored`。

## 5 立刻重新钉住暂停

- 动作：`node src/cli.js call rimworld/pause_game --profile <p>`。
- 判据：`node src/cli.js wait --profile <p> --probe rimbridge/get_bridge_status --condition-file c-paused.json` exit `0`（`c-paused.json` 内容：`{"path":"result.state.paused","equals":true}`）。
- 为什么必须补：`pauseIfNeeded:true` 返回时 `paused = true`（09:42:19），9 秒后同一字段已 `paused=false`、`timeSpeed=Normal`【实测：38-load.json → 40-wait-idle.json】，这段里 tick 从 3778 漂到 4245【实测：19-letters.json 的 `currentGameTick` → summary.json 的 `tickFirst`】。不补这一下，阶段 6 的对账基准和第二段观测窗口全被漂移污染。
- 证据：`05-pause.json`、`05-paused.json`。

## 6 对账（这一步才是"读回来了"）

- 动作：`call rimworld/get_game_info`；`call rimworld/list_colonists --args-file a-colonists.json`（内容 `{"currentMapOnly":true}`）；`call rimworld/get_map_target_info --args-file a-target.json`（内容 `{"pawnName":"<小人名>"}`）。
- 判据（每条都是探针 + 一次单值比较，exit `0` 才算过）：
  - 时间没倒退：`node src/cli.js wait --profile <p> --probe rimworld/get_game_info --condition-file c-ticks.json`（`c-ticks.json` 内容：`{"path":"result.ticksGame","greaterThanOrEqual":<阶段2的 tick>}`）。把 `读回 tick − 存前 tick` 记为**漂移量**写进报告。
  - 人还在：`node src/cli.js wait --profile <p> --probe rimworld/list_colonists --args-file a-colonists.json --condition-file c-count.json`（`c-count.json` 内容：`{"path":"result.count","greaterThanOrEqual":<阶段2的 count>}`）。
  - 目标定位得到：`get_map_target_info` 的 `result.success = true`（按 `pawnName` 命中，返回 `result.thingId` 与 `result.position`）。
  - 存档字段没被改写：重跑阶段 3 判据 3 那条 `Select-String`，命中数与存档时**完全相同**。
- 证据：`06-*.json`、`06-xml-after.txt`。
- **不要用读档前的 `pawnId` 当判据**：实测读档完成约 2 s 后按旧 `pawnId` 查 → `success:false`「Could not find current-map pawn id」；9 s 后同一个 `pawnId`（`Thing_Ratkin38483`）又能查到。成因是"小人还没刷进当前图"，不是 ID 变了 ⇒ 判据写「查得到」，不写「ID 和上次一样」。

## 7 收工

- 停实例：`node src/cli.js stop --profile <p>`（不带 `--force`）；判据 `node src/cli.js wait --profile <p> --scenario 游戏进程已退出` exit `0`（登记表 inferred 档，未真机验过）。
- 清残留：删本次造的测试档 `profiles/<p>/Saves/<档名>.rws`，删前先 `Get-Item` 确认绝对路径。**实测反例**：RHAH 那几轮的 `rhah0008_*.rws`／`armA_/armB_state1.rws` 都留在 `profiles\rhah\Saves\` 没清。
- 不碰玩家存档：隔离 profile 的存档在 `profiles/<p>/Saves\`，玩家那局在 `%LocalLow%\Ludeon Studios\…\Saves\`，一个文件都不读不写。

## 失败怎么读

统一在[失败判读](失败判读.md)里找处置，本文件不重复正文。本 SOP 常撞的六种，按节号去查：

- 阶段 4/6 的 `wait` exit `2`，stderr 带 `missingPath` ⇒ [失败判读](失败判读.md) §1（先补前置：`result.state.currentMapReady`，再改字段名）。
- `get_map_target_info` 报 `Could not find current-map pawn id` ⇒ [失败判读](失败判读.md) §1，不是 §2 的工具名错。先用 `list_colonists` 确认人在当前图。
- exit `1` 且文案是 `拒绝连接 …`（另一个 profile 的记录 / token）⇒ [失败判读](失败判读.md) §2 表里那一行，先 `status --profile <p>`。
- 动作回 `success:true` 但字段没变 ⇒ [失败判读](失败判读.md) §5 第一行。
- 探针挂住 `GABP_TIMEOUT`（读大档时常见，主线程被存档/反序列化占住）⇒ [失败判读](失败判读.md) §3。
- 阶段 6 之后要推时间 ⇒ [推时间](推时间.md) §1 三个前置；要截图/判位置 ⇒ [截图取证](截图取证.md) §1 与 §3（位置只认坐标回读）。
