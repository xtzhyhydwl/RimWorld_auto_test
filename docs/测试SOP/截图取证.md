# 截图与位置证据

> 结论先行：**暂停态 `step_game_ticks` 之后，pawn 层的渲染不刷新**。画面里的 UI、静态物件可信；"小人现在在哪"不可信。

## 0 现象（2026-10-24 实测）

| 画面里看什么 | 是否跟随 |
| --- | --- |
| UI（温度 / 光照 / 新警报） | 正常 |
| 新建的墙、物件上屏 | 正常 |
| 相机平移 / 缩放 | 正常 |
| **pawn 的贴图 + 名字标签** | **冻在推进前的位置** |
| 动物 | 同样冻住 |
| 逻辑状态（坐标回读） | 正常推进 |

- 触发条件：**暂停态**下用 `step_game_ticks` 推进 tick —— 逻辑在走，`DrawPos` 不刷新。
- 追平：`play_for` 真跑 **400 ms（约 74 tick）**，pawn 立刻回到真实格子；之后再 `step_game_ticks` 又冻。两次独立验证。
- 与 mod、启动参数、窗口尺寸无关（6 项 mod 的最小 profile、原版 Human / Muffalo 同样复现），日志里没有任何渲染错误。

## 1 所以取证这样做

1. **截图 / 人眼看之前**：先 `play_for{ durationMs: 400–1000, speed: 'Fast' }`。
2. **位置、移动、在场/离场**只用坐标回读（`list_colonists`、`get_cell_info`、`get_map_target_info` 等），并附**新旧格裁剪对照**：同一块区域 step 前后各裁一张，标出旧格与新格。
3. **不用整图 diff**：整图里 UI 在变、pawn 不动，diff 会得出错误结论。
4. 2026-10-24 之前用"截图看起来对"下的结论，一律降级为【未验证】；靠回读的关键断言（门 HP / `curJob` / `spawned`）不受影响。

## 2 截图本身的坑

- 桥接报的窗口尺寸可能是 **DPI 虚拟化读数**：日志写 1600×900，读回 813×486 是 DPI=192 的虚拟化结果，不是窗口变小。
- 启动参数：`-monitor` 实测**被忽略**；`-screen-width` / `-screen-height` 生效。
- 日志没有渲染错误 ⇒ 不要从日志里找原因。

## 3 什么时候可以信截图

- 可以：UI 状态、窗口/按钮位置、静态建筑与地形、推进后新建的物件。
- 不可以：pawn 位置、动画、某 pawn 是否在场（除非先 `play_for` 刷新）。
- 只能主观判断的（"看起来对不对"）交给人，不写成断言。
