# 日志与事件取证（**主张据**）

> 2026-10-24 用户定：截图不可靠，**主张据 = 游戏内日志埋点 + 动作 + 推时间 + 回来看日志是否按预期输出**。
> 本文件讲"从哪读、怎么写判据、怎么算通过"。埋点什么算过由 [埋点协议.md](埋点协议.md) 约定；截图降级见 [截图取证.md](截图取证.md)。

## 0 三个通道

| 通道 | 在哪 | 谁写的 | 可靠性 |
| --- | --- | --- | --- |
| ① `Player.log` | 路径由 `detectGameLayout` 决定（1.6 在 `profiles/<p>/Player.log`，1.7 在默认日志目录） | 游戏 + 所有 mod | **共享**：1.7 下全机共用、**后启动者整份重写** ⇒ 多实例时不可靠 |
| ② GameLink 事件 `runs/live/<profile>.ndjson` | 每 profile 一个文件 | **游戏侧推送**（`mods/DSH_GameLink`） | **唯一真正按 profile 隔离**的通道；但只有经 `start`（launcher）启动的实例才写【实测：非 launcher 起的实例该文件不更新】 |
| ③ 桥接日志类工具 | `rimbridge/list_logs` 的内存 journal | 桥接（per-instance） | 按实例隔离、带 `afterSequence` 游标；**是否覆盖全部 `Log.Message` 通道未核**⇒【待核】 |

已核实的工具名（`runs/tools.json`）：

- `rimbridge/list_logs{limit, minimumLevel:'info'|'warning'|'error'|'fatal', afterSequence, operationId, rootOperationId, capabilityId}` → `logs[]`，元素含 `level` / `message`；
  游标基线取 `rimbridge/get_bridge_status` 的 `latestLogSequence`（`src/smoke.js` 就这么用）。
- `rimbridge/list_operations{limit, includeResults}`、`rimbridge/list_operation_events{limit, eventType, afterSequence, operationId, includeDiagnostics}`、`rimbridge/get_operation{operationId}`、`rimbridge/wait_for_operation{operationId, timeoutMs, pollIntervalMs}`。
- `foodprobe/telemetry_tail{lines}`：读该 mod 自写的 `telemetry.jsonl` 末尾（**只有自带 telemetry 的 mod 有这条路**，通用性【待核】）。
- `rimworld/set_colonist_job_logging{pawnName, pawnId, enabled}`：返回**日志游标 + 可直接用的 `list_logs` 参数**（工具自身描述原文），是把"某个 pawn 的 job 轨迹"变成可断言的现成入口。

## 1 判据怎么写

```powershell
node src/cli.js live --profile <p> --until 'kind=<事件>'                       # 等某类事件
node src/cli.js live --profile <p> --until 'kind=log text~[DSH-TEST] 点.动作'   # 等某条埋点日志
node src/cli.js live --profile <p> --until 'kind=colony_started' --timeout 120000
node src/cli.js live --profile <p> --new-only --until 'kind=<事件>'            # 只看从现在起新增（确定还没发生才用）
```

- 事件 `kind` 表（DSH_GameLink）：`game_loaded` / `colony_started` / `window` / `log` / `heartbeat` / `error`；
  `log` 行的字段是 `level` + `text`，所以判据写 `kind=log text~<子串>`；多个条件用空格或 `&&` 连接。
- `live` 默认从文件开头扫（历史里已有 ⇒ 立刻命中），`--last N` 只看末尾；退出码 `0` 命中 / `2` 超时 / `1` 参数错。
- **`wait --probe` 只能挂在"只读工具载荷"上**（`rimbridge/get_bridge_status`、`rimworld/list_colonists` 这类），`result.` 指该工具返回的载荷根。
  **不能拿日志当 probe**：要等日志就 `live --until`。（`wait --source event` 代码里已实现，但真机未实测【未实测】；`docs/cli-wait-用法-20261024.md` 的"P1 未实现"是旧说法，以代码为准。）
- 日志断言只在"事后回读"用也可以：`list_logs{minimumLevel:'info', afterSequence:<游标>}` 取本次新增，再用埋点里的 tick 对时间。

## 2 一条铁律：正负成对

**每条日志断言必须写两半**：

1. **预期出现的正面串**（埋点的 `做了` 一侧）——证明"发生过"；
2. **必须不出现的负面串**（埋点的 `做错了/该做没做` 一侧 + 该场景已知的报错模式）——证明"没出错"。

只有正面串 ⇒ 只能证明"发生过"，**不能证明"没出错"**：埋点打了正常行、随后抛异常，单看正面串仍是"通过"。
负面的机械兜底（不是替代埋点）：跑完后 `rimbridge/list_logs{minimumLevel:'warning', afterSequence:<游标>}` **无新增**（`src/smoke.js` 的现成写法）。
`kind=error` 事件（mod 自己捕获的异常）同样计入负面集合。

## 3 多实例：优先 ndjson，不要用共享 Player.log

- 1.7 的 `Player.log` 全机共用、后启动者整份重写 ⇒ 你和用户同时在跑时，读到的是别人的局；`readBridgeInfo` 的"按最新记录"兜底也会连错实例。
- 优先级：**`runs/live/<profile>.ndjson`（按 profile 隔离）> `rimbridge/list_logs`（按实例隔离）> `Player.log`**。
- 非 launcher 启动的实例**不写 ndjson** ⇒ 这时改用 `list_logs`；再不行才用 `Player.log`，且必须核首行 `Started:` 时间与自己的启动时刻一致。
- 用 `Player.log` 时永远走 `node src/cli.js logs --profile <p>`（或 `live --source log`），不要自己拼路径。

**实测**：`live --until 'kind=colony_started'` 214 ms 命中历史、`--new-only` 时 exit 2；`live --source log --until 'text~RimWorld'` 206 ms 命中 `Player.log`（`docs/等待机制-事件驱动-20261017.md`）；
`list_logs{minimumLevel:'warning', afterSequence}` 游标式取新增（`src/smoke.js`，本轮 `12-wait-无模态窗口.json` 同型）；
GameLink `log` 通道的过滤规则（只放含 `[VD]` 的 Message/Warning + 全部 Error，`mods/DSH_GameLink/Source/LogTap.cs`）。

**未实测 / 待核**：`wait --source event` 真机；`list_logs` 是否覆盖第三方 mod 的裸 `Log.Message`【待核】；
`foodprobe/telemetry_tail` 之外是否还有其它 mod 提供 telemetry 通道【待核】。
