## 1 起实例

| 项 | 内容 |
| --- | --- |
| 启动命令 | `node src/cli.js start --profile <p> --width 1600 --height 900 --monitor <n>` |
| 保活方式 | `<挂成 job / 单进程 smoke>` |
| 就绪判据 | 等桥接就绪——**推荐**反复 `call rimbridge/ping` 到 exit 0（三种方式按可靠性排序，见下方「等桥接就绪」） |
| 实测 | `<exit 码 / elapsedMs>` |

等桥接就绪（按可靠性排序）：
1. `node src/cli.js call rimbridge/ping --profile <p>` 反复采样到 exit 0 —— **推荐**。注意：桥接还没监听时 `wait` 会**立刻 exit 1**（`ECONNREFUSED`），不会按 `--interval` 轮询，所以"等桥接"不能用 `wait`，只能这样外层重试。
2. `node src/cli.js wait --profile <p> --scenario 桥接可连` —— **只在桥接已监听之后**当一次性校验用（场景 = `rimbridge/ping` 且 `message=="pong"`）。
3. `node src/cli.js wait --profile <p> --source bridge-ready --condition-file ready.json`（`ready.json` = `{"path":"result.ready","equals":true}`）—— 语义最强（四道校验"这个桥接是不是我的"），但 **`result.ready` 的真实字段形状本轮没在真机上核过**，属【推测】可跑。

## 2 进门

| 项 | 内容 |
| --- | --- |
| 动作 | `node src/cli.js call rimworld/start_debug_game_ready --args-file 2-entry.json --profile <p>`（`{"readiness":"playable","pauseIfNeeded":true}`） |
| 判据 | `wait --scenario 已进图可玩`（或 `<自定义条件>`） |
| 实测 | `<exit 码 / attempts>` |

> **参数 JSON 落文件，不要内联**（PS 5.1 会吞引号）：本机 `pwsh` 是 Windows PowerShell 5.1，`--args '{"readiness":"playable"}'` 到 node 手上已经是 `{readiness:playable}`（双引号被吃掉）⇒ `JSON 解析失败`。做法：用 `write` 工具把参数落成一个小文件（`runs/<日期>-<主题>/2-entry.json`），再 `--args-file <路径>`；条件同理走 `--condition-file`。**不要用 `Set-Content` 写 JSON**（PS 5.1 会把中文写成 GBK，`JSON.parse` 抛错）。

无参 `rimworld/start_debug_game` 只排队、**不保证就绪**；要判据稳定就用 `_ready`，判据只留 `wait.satisfied = true`。耗时/轮数：本机一次实测 6017 ms / 84 attempts（**会漂，只作量级参考**）。
`readiness` 取值：`gameData` / `mapData` / `currentMap` / `playable` / `visual` —— 配 `已进图可玩`（判 `result.state.playable`）就用 `playable` 这一档，`currentMap` 不保证可玩。
进图前若主菜单上挂着 Debug log 窗口，先 `node src/cli.js call rimworld/close_window --profile <p>`，判据 `result.changed = true`（或 `windowCount` 下降），再发进图动作。
