# 角色编辑器（Character Editor，`void.charactereditor`）

> **什么时候用**：要把小人摆成任意状态（技能 / 特质 / 健康 / 断肢 / 基因 / 外貌 / 名字 / 整只克隆），或要读一只 pawn 的全量状态。
> **什么时候不用**：只改技能、特质、hediff 时，原版 debug action 已经覆盖（`Actions\Max Skill…` / `Give Trait…` / `Add Hediff…` / `Set Backstory…` / `Add Gene…`），零依赖。
> 本体在工坊 `294100/1874644848`，依赖只有 `brrainz.harmony`（`modVersion 1.7.1`，支持 1.0–1.7）。

## 0 两条路线

| 路线 | 入口 | 能做什么 | 代价 |
| --- | --- | --- | --- |
| **反射（优先）** | `ce/*` 工具（`bridge\DSH.CEBridge` 伴生 DLL） | 精确、批量、文本化读写，不依赖 UI | 要先部署 DLL；CE 升级后反射字符串可能失效 |
| UI 驱动 | `src\ce.js` | "看着界面"操作、验证 UI 本身 | 慢、脆；改不了滑块和文字（桥接没有输入工具） |

## 1 反射路线：`ce/*` 工具

```powershell
node src/cli.js call ce/probe                            # 自检：CE 加载了？内部 API 还在？
node src/cli.js call ce/colonists                        # 列殖民者 + 稳定 pawnId
node src/cli.js call ce/get_skills  --args-file a.json   # {"pawnId":"Thing_115"}
node src/cli.js call ce/set_skills  --args-file b.json   # {"pawnId":"…","skills":"Shooting|5|1|0|0:Melee|6|2|0|0"}
node src/cli.js call ce/get_traits  --args-file a.json
node src/cli.js call ce/body        --args-file a.json   # 身体部位树 + 缺失状态
node src/cli.js call ce/amputate    --args-file b.json   # {"part":"left leg","pawnId":"…"}
node src/cli.js call ce/restore     --args-file b.json
node src/cli.js call ce/ce_api      --args-file c.json   # {"tool":"HealthTool"} dump CE 内部方法
```

技能是**自描述文本**，一次读全部、一次写全部：`技能|等级|激情|经验|…`，多个技能用 `:` 分段。
写工具的参数名以 `describe` 为准；参数里有反斜杠或中文就走 `--args-file`。

### 断肢实测语义（Human 共 64 个部位）

| 操作 | 结果 |
| --- | --- |
| `amputate "left leg"` | **9 个部位**变缺失：Leg + Femur + Tibia + Foot + 5 个 Toe |
| `amputate "left foot"` | **6 个部位**变缺失：Foot + 5 个 Toe |
| `restore` | 清掉**整棵子树**，回到 0 缺失 |

- `part` 是标签**子串**（大小写不敏感），多个匹配时用 `index`（0 起）。
- 父部位缺失时子部位通过 `PartIsMissing()` 也算缺失 ⇒ **读状态用 `ce/body`，不要只看有没有 `MissingBodyPart` 这个 hediff**。
- 实际截肢走原版健康 API（`HediffMaker.MakeHediff(HediffDefOf.MissingBodyPart, …)` + `health.AddHediff`），CE 的 UI 只是前端 ⇒ 测「断肢后逻辑」的 mod **不依赖 CE**。

## 2 UI 路线（`src\ce.js`）

```js
import * as ce from '../src/ce.js';
await ce.ensureOpen(client);                 // 打开 main-tab:HotkeyEditor
await ce.openTab(client, 'Bio');             // Bio/Inventory/Health/Needs/Social/Log/Info/Records
await ce.selectPawn(client, 'Alex');         // 左侧列表
await ce.bumpSkill(client, 'Shooting', +3);  // 该行右侧的 −/+ 按钮
await ce.getSkillLevel(client, 'Shooting');
```

- 内部等待是**固定值**（轮询 400 ms、开窗 +600 ms、切标签 700 ms、选中 900 ms、每次点击 250 ms，见 `src/ce.js`）——可以当调用演示，不能当"已经等够了"。
- 画面判据用 `ce.ceSurface()` 的元素特征：技能行必须**恰好 2 个 `icon_button`**，凑不齐说明排版变了。
- 三栏（殖民者 / 特质 / 技能）共享同一批 y ⇒ 取元素必须**同时按 x 限列 + y 容差 ±8 px**。

## 3 写完必回读

1. `ce/get_skills` 的 `raw` 串逐字比对刚写的文本；
2. `step_game_ticks` 推若干 tick 再读一次（CE 自己 patch 了 `RecalcIndex` / gene 增删，实测会冲掉直接改的值）；
3. 外貌、位置这类只能人眼判断的，截图交给人，不写成断言。

## 4 故障与维护

| 现象 | 多半是 | 处置 |
| --- | --- | --- |
| 没有 `ce/*` 工具 | DLL 没部署 | 按 [环境自检](环境自检.md) §4 部署 |
| `ce/probe` 报类型/成员找不到 | CE 升级，反射字符串对不上 | 重编 `bridge\DSH.CEBridge`（源码同名 `.cs`） |
| 写完回读没变 | 被 CE 的 RecalcIndex 冲掉 | 推 tick 后再写一次；或改走 UI 路线 |
