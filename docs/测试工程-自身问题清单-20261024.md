# 测试工程自身问题清单（2026-10-24）

> 面向：**维护本测试工程的人**（`src\` CLI、`runs\` 记录、profile/实例机制）。这不是 mod 侧问题清单。
> 口径：**【实测】**=报告里有命令或文件证据；**【文档称已修】**=只见到修复记录，本轮未复验。
> 严重度从高到低；行号指 `src\` 当前版本或 `docs\` 报告。素材＝2026-10-24 的 6 份报告（走门验证 / 优先走门 / 渲染诊断 / 多实例日志冲突 / 多实例补充说明 / 多会话抢进程）；第 7 条另引评审修复报告核 `dotnet test` 原文。

## P0：会让你「拿到看似正常的错误结果」

### 1. CLI 在受限沙箱下整体不可用（PID 存活探测假阴性）
- **现象**：`node src/cli.js call/wait/start/stop` 全部不可用。`process.kill(<活着的 RimWorld PID>, 0)` 返回 **`ESRCH`**（`src\proc.js:139-146` `probePid`），`resolveBridge` 据此判「PID 不存在」并**拒发命令**；同一 PID 用 `Get-CimInstance` / `tasklist` 明明在，端口也属于它。【实测】
- **触发**：受限沙箱（子代理会话）里对活进程做 PID 存活探测；与实例好坏无关。
- **证据**：`docs\RHAH-0008-走门验证-20261024.md:68`（§2.1a）。后果是该轮子代理**完全绕过 CLI**，改用直连 GABP（`src\gabp.js` `connectGabp`，port/token 取自记录）+ 每批动作前手工三重校验（同报告 `:74-79`、`§8.7`）。
- **影响**：`wait`/`live`/`status` 等原子全废，闭环退化成手搓；同一份命令在别的会话能跑，故障不可复现。
- **最小修法建议**：`resolveBridge`/`isAlive` 不要用 `process.kill(pid,0)` 判存活，改用 `Get-CimInstance Win32_Process -Filter "ProcessId="` 或「监听端口 PID ↔ 记录 pid」；`ESRCH` 在沙箱下不能当「进程不存在」，应至少降级为「未知」并打印判据。

### 2. 陈旧 `game-process.<profile>.json` 导致 stop/status 误判
- **现象**：记录里是**死 PID 12612**，`stop --profile rhah` 返回 `{"stopped":[],"alreadyStopped":true,…,"skipped":[{"pid":12612,"reason":"PID 12612 不存在"}]}` —— **实际实例（32424）没被停到**。【实测】
- **触发**：实例不是 launcher 起的（或上一轮异常结束），记录未改写；本轮受测实例即非 launcher 启动。
- **证据**：`docs\RHAH-0008-走门验证-20261024.md:72`（§2.1e）、`:213`（§7 停实例）。
- **影响**：「已停止」是假绿 ⇒ 可能叠第二个实例、锁/端口冲突、日志归属全错。
- **最小修法建议**：读记录时校验 `pid` 存活 + `startedAt`/进程启动时间一致；`recordedAlive=false` 时不要报 `alreadyStopped`，改报「记录陈旧（pid 不存在）」并回扫 5174–5183 端口找命令行含 `-savedatafolder=…\profiles\<p>` 的实例。

### 3. 假记录 / 串台：`--profile` 不是路由
- **现象**：曾出现 `runs\game-process.dshwait-check.json`（`pid 0`、port **5288**、`FakeBridge 0.0.0`、token `fake-token-for-offline-check`），`readBridgeInfo` 的「取最新启动」兜底（`launcher.js:226-249` `findRecordByLogFile` 按 `startedAt` 最新）把它当成共用日志的归属 ⇒ 4 次桥接调用全打到 5288、返回 `No current map`；另 `status --profile voiced` 报到 **5175**（rhah 的实例），`wait --profile voiced` 返回 `Playing`，而直连自己的 5174 是 `Entry`。【实测】
- **触发**：任何人手工/旁路写一条 `runs\game-process.*.json`；或两个 profile 同时在线（1.7 共用日志路径里没有 profile 名）。
- **证据**：`docs\多实例并发-日志与写入冲突实测-20261024.md:187-207`（§B.5）、`:259`（§C.3）；`docs\多会话抢进程-排查-20261024.md:111-129`（§A6）、`:200-205`（§B5）；`docs\多实例并发安全-给运行中会话的补充说明-20261024.md:46-48`（§1）。
- **影响**：命令打进别人的局 / 假桥，返回值「success:false 但正常返回」，断言看起来成立。
- **最小修法建议**：`readBridgeInfo` 显式收 `profile`、只读该 profile 的记录，取不到就返回 `null`（**删掉**「全机最新」兜底）；采集记录时过滤 `pid<=0`、端口不在 5174–5183、哨兵 token（`fake|offline|test`）。注：补充说明 `:3-6` 称已在 `a316f87`/`5f3e9ea` 修，但同日 19:44 的走门验证仍撞上 1/2/3 的后果 ⇒ 需按验收清单复核。

### 4. 挂死实例杀不掉，`stop` 的兜底不够
- **现象**：`taskkill /PID`（WM_CLOSE）、`taskkill /F /PID`（返回 "no running instance"）、`Stop-Process -Force` **全部无效**；最后 `Invoke-CimMethod Win32_Process.Terminate()` → `ReturnValue=0` 进程才消失。【实测】
- **触发**：实例主线程挂死（桥接 `session/hello` 60 s 无响应）但进程还在。
- **证据**：`docs\RHAH-0008-走门验证-20261024.md:69`（§2.1b）。
- **影响**：占着 profile 与端口，下一轮验证必须人工清场；`launcher.js:752-757` 的 `killForce + taskkill /T /F` 对这一类也不够。
- **最小修法建议**：`stop` 最后一档补 WMI Terminate；「挂死」判据用「端口仍监听 + 桥接 hello 超时」，不要只看进程是否存在。

## P1：会让你「取证/断言本身不可信」

### 5. `step_game_ticks` 冻结 pawn 绘制（截图不能判位置）
- **现象**：暂停态 step 后 pawn 的贴图与名字标签**停在旧格**（Avila 坐标 +6 格、标签 0 px 位移；两人坐标同为 (108,112) 却画在两处），坐标回读已变；相机移动/缩放、生成新物件都不恢复；`play_for{400, Fast}`＝**74 tick** 真实帧后立刻追上。【实测】
- **触发**：用 `step_game_ticks` 推进（暂停态推进 tick）；`voiced`（6 mod、无 Ratkin/HAR/RHAH）同样复现 ⇒ 与 mod、启动参数无关。
- **证据**：`docs\RimWorld-1.7渲染不更新-诊断-20261024.md:13-15`（§0）、`:52-64`（§1.3 活→冻→活）、`:168`（§6①）。
- **影响**：所有「截图看位置/行为」的结论在 1.7 下必然错（本轮已把判据改成坐标回读 + `screenshot_cell_rect`）。
- **最小修法建议**：任何渲染/截图断言前强制 `play_for{400~1000, Fast}`；位置只认 `position`/`get_cells_info` 回读；在 skill 里禁掉「整图 diff / pawn 在屏幕中心」这类判据。

### 6. 1.7 忽略 `-monitor`；813×486 是 DPI 虚拟化读数
- **现象**：命令行确实收到 `-monitor 2`（`launcher.js:879`），窗口仍落在 `\\.\DISPLAY1`；`-screen-width/height` 生效（内部 1600×900）；读数 813×486 是 **DPI=192** 下 2× 折算，**不是**被忽略的证据。【实测】
- **触发**：任何 `start --monitor N`；用 DPI-unaware 的 PowerShell 读窗口矩形。
- **证据**：`docs\RimWorld-1.7渲染不更新-诊断-20261024.md:113-124`（§4）。
- **影响**：「窗口放副屏」的约定在 1.7 下不成立（起游戏会抢主屏焦点）；把 813×486 当异常会浪费一轮排查。
- **最小修法建议**：起实例后用 `MoveWindow`/`SetWindowPos` 自行搬到目标显示器（或明确告知会占主屏），并把「`-monitor` 在 1.7 无效」写进 prefs/env 说明；窗口读数一律按 DPI 感知换算。

### 7. `dotnet test` 在沙箱被拒，单测只编译不执行
- **现象**：testhost 启动即 `System.ComponentModel.Win32Exception (5): 拒绝访问`（`TestHost.DefaultEngineInvoker.SetParentProcessExitCallback` → `ProcessManager.OpenProcess`），`EXIT=1`。【实测】
- **触发**：`dotnet test --filter FullyQualifiedName~RHAH_JobGiverTests`（受限/非交互宿主）。
- **证据**：`docs\RHAH-0008-评审修复-20261024.md:174`（§五.3）；`docs\RHAH-0008-优先走门-20261024.md:140`（本轮不做单测的理由）。
- **影响**：新增契约断言「编译通过但从未执行」，`Source\Tests` 形同虚设。
- **最小修法建议**：改用可执行的宿主（`xunit.runner.console` 或自建 console runner 直接加载测试程序集），或把测试放到能起 testhost 的终端跑；跑不了时报告里必须显式标「未执行」。

### 8. 共用 `Player.log`：并发时日志断言全部作废
- **现象**：1.7 `-logFile` 被忽略，全机一份 `%LocalLow%\…\Logs\Player.log`；后启动者把先启动者的 **2,084 行 / 175,911 B** 截断、连同 `Player-prev.log` 一起删；两进程各按自己偏移写 ⇒ **48,185 B NUL 空洞**；偏移落后的进程退出时把对方 **348 行覆盖（18 行 `[VD]`→0）**，最终日志「看起来只跑过一个实例」。【实测】
- **触发**：两个实例并发（**不同 profile 也一样**）。
- **证据**：`docs\多实例并发-日志与写入冲突实测-20261024.md:133-181`（§B.2–B.4）、`:263-300`（时间线/原文）、`:330-337`（影响清单）；`docs\多实例并发安全-给运行中会话的补充说明-20261024.md:103-110`。
- **影响**：按行数/偏移/ERROR 计数/启动头的断言一律不可信；`logStartOffset` 机制失效（记 280,608、实际 126,605）。
- **最小修法建议**：断言改走 `runs\live\<profile>.ndjson` + 桥接回读；只在「全机只有一个 RimWorld」时用日志（先 `tasklist` 三路验证）；`start` 成功后把 `Player.log` 快照到 `runs\<runId>\`，`stop` 前再快照一次。
