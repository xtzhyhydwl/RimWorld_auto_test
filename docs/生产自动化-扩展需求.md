# 需求：从「只种食物」扩展到「把前期殖民地运营起来」

> 来源：用户 2026-10-03 的反馈。这是**下一阶段的范围定义**，不是当前实现。
> 当前状态见 `STATUS.md`；架构见 [foodcontrol-架构与流程.md](foodcontrol-架构与流程.md)。

---

## 最终目标

**保证小人有吃、有穿、有住处、心情不崩** —— 最终是让 agent 接管殖民地的日常生产，
人只做规划。

但**分阶段**：先把一个**经典前期开局**运营起来，验收标准是
**撑过 5 天：所有小人有得吃 + 心情不崩溃**。

---

## 一、用户观察到的两个问题（已核实）

### 问题 1：debug 开局的物资被禁取，小人拿不到 ✅ 已核实

用户原话：

> 出生的时候带的物资，它是全部都是被设置为禁用的……一般来说习惯上开局就是把整个地图
> 禁止被拾取的那些东西全部允许使用。这样的话才能够在一开始就能够用上所有的资源。

**核实结果**：`foodprobe/forbidden_stats` 实测新开的 debug 殖民地有
**56 个被禁取的东西**（含木头/钢铁等建材），调 `foodprobe/unforbid_all` 后归零。

**含义**：
- 这是**测试场景的缺陷，不是 mod 的 bug**。之前"人饿死"的现象要先排除这个因素。
- 「开局允许所有物资」本身是玩家习惯的一次性操作，**值得做成 mod 的第一个功能**。

**注**：被禁取的**食物**营养量实测为 0（食物没被禁），所以饿死不能全归因于此 ——
还要看小人有没有能力去拿到食物、以及地图上到底有多少吃的。

### 问题 2：随机地形可能不适合（比如沙漠）

**核实结果**：`scripts/diagnose-plot.mjs` 对本轮地图做了 259 个 3×3 块的普查：

```
有可种格 111 个 / 全可种 13 个 / ≥75% 可种 68 个
地表: Soil 649, Sandstone_Rough 808, Granite_Rough 285, Gravel 125, SoilRich 29, ...
可用空地 1612 格
```

→ **这张地图不坏**，土地充足。所以之前 `FindBestPlot` 返回 null **不是地形问题**。
（真实原因见 `docs/生产自动化-设计.md` §七septies：算法/语义错误，已修。）

**但仍需处理**：开局地形是随机的，可能真落到沙漠/冰盖。测试框架应支持
**指定生物群系**，否则"能不能运营"的结论不可复现。

## 二、需求：前期运营需要的自动化能力

按用户描述，除了已做的"种食物"，还需要：

| # | 能力 | 用户原话要点 |
| --- | --- | --- |
| 1 | **开局允许所有物资** | "开局先允许所有的物资的这种小操作" |
| 2 | **划储藏区** | "至少首先他要能够划分一些区域，比如说你至少要把储藏区给划起来" |
| 3 | **盖房子（方块房）** | "可能会给一些木头，那么到时候就造一个方块房子呗，方块房子是最简单的" |
| 4 | **屋顶** | "屋顶是自动铺的"（→ 不用管） |
| 5 | **安排人从事建筑工作** | "主要就是要安排人去从事建筑的工作" |
| 6 | **决策在哪盖** | "一般来说就是在地图中心造" |
| 7 | **按现有资源选材质** | "结合现有的资源来决定……造铁的墙壁，还是木头的墙壁，还是石头的墙壁" |

**用户明确说可以推后的**：

> 我觉得收集资源这一部分可以先不用管，开局其实是有一些资源的。

→ **采集/采石/伐木不做**，先用开局物资。

## 三、直接复用现有架构的部分

这几个新能力和"种食物"**结构上同构**，可以直接套现成的五层：

| 新能力 | 复用 |
| --- | --- |
| 划储藏区 | `SiteSelection`（距离场/基地中心/评分）**完全适用** —— "离基地近"同样是要件 |
| 盖房子选址 | 同上；用户说"地图中心"，正好就是 `ResolveBaseCenter` 兜底链的最后一档 |
| 建材选择 | 和"选什么作物"同构：读现有库存 → 选可用材质 |
| 安排建筑工作 | 与种植工作同理（都属于工作派发，P2 的 `work/priorities` 范畴） |

**这就是 §2.4 说的 `INeedDomain` 重构的动机** ——
如果现在把"食物"从框架里摘出来，上面每一条都只是写一个新的 domain 实现。

## 四、建议的实现顺序

```
S1  开局允许所有物资（forbidden → allowed）
    小、独立、立刻可验证。也是后续一切的基础（不然小人拿不到木头就盖不了房）
       ↓
S2  抽象 INeedDomain 框架（只搬食物，不加功能）
    纯重构，零行为变化，靠现有 65 条 Core 测试 + 地基测试兜底
       ↓
S3  储藏区 domain
    复用 SiteSelection；验收「地图上出现 Zone_Stockpile 且格数>0」
       ↓
S4  住处 domain（方块房）
    选址 → 按库存选材质 → 放置蓝图 → 靠游戏自己的建造系统施工
    验收「房子盖起来了」
       ↓
S5  5 天生存验收
    「3 个殖民者撑过 5 游戏天，全部有饭吃、心情不崩」
```

### S4 的一个技术要点（已确证 API）

用户说"屋顶是自动铺的"，这在 RimWorld 里成立（房间自动加屋顶），
**前提是造出封闭的墙体**。所以 mod 只需要：
1. 选一块地
2. 按矩形放置墙的**蓝图**（`Blueprint_Build`）
3. 游戏自己的建造系统会让小人去盖（**不用自己派活** —— 放置蓝图就会自动生成建造工作）

#### ✅ 蓝图 API 已确证（`tools/asmdump` 元数据，2026-10-03）

```csharp
// 放蓝图（核心）
RimWorld.Blueprint_Build GenConstruct.PlaceBlueprintForBuild(
    BuildableDef sourceDef, IntVec3 center, Map map, Rot4 rotation,
    Faction faction, ThingDef stuff,
    Precept_ThingStyle styleSource = null, ThingStyleDef styleDef = null,
    bool sendBPSpawnedSignal = true);

// 放之前先检查合不合法（**必须先查，别硬放**）
AcceptanceReport GenConstruct.CanPlaceBlueprintAt(
    BuildableDef entDef, IntVec3 center, Rot4 rot, Map map, bool godMode = false,
    Thing thingToIgnore = null, Thing thing = null, ThingDef stuffDef = null, ...);

// 地表能不能承重（地板/地基相关）
bool GenConstruct.CanBuildOnTerrain(BuildableDef entDef, IntVec3 c, Map map, Rot4 rot,
    Thing thingToIgnore = null, ThingDef stuffDef = null);
bool GenConstruct.TerrainCanSupport(CellRect rect, Map map, ThingDef thing);
```

**`stuff` 参数就是"用什么材质"的入口** —— 正好接上 S1 里
`ColonySetup.CountBuildingMaterials()` 数出来的建材（木/石/钢）。所以
「**按现有资源选材质**」这条需求的实现路径已经清楚了。

⚠ 仍需注意的未确证点：
- `PlaceBlueprintForBuild` 的返回值是否可能为 null、以及失败时的行为
- **门**：完全封闭的墙小人进不去/出不来，必须留门（`ThingDefOf.Door`）
- 屋顶是否真的自动铺（需要建成**完整房间**，且房间判定有面积上限）
- 蓝图放下去之后，小人的建造工作由游戏自动生成 —— 这点要实测确认

---

⚠ 5 天验收**必须先把"食物量级"这条理清**。实测：

```
1 格水稻 ≈ 0.154 nutrition/天
每天消耗 = 1.6 nutrition/殖民者
⇒ 仅维持平衡就需 每殖民者约 10.4 格
```

3 个殖民者 + 储备目标 ≈ 上百格。小人翻地播种需要时间，
所以**5 天内能不能进入正循环**本身就是要验证的东西 ——
如果不行，结论应该是"前期需要靠采集/狩猎过渡"，而不是硬调参数掩盖。

---

## 五、这一阶段不做

- ❌ 采集资源（伐木/采矿）—— 用户明确说推后
- ❌ 狩猎（P1 就定了不进 MVP）
- ❌ 心情的**直接**干预（娱乐/装饰）—— 心情是**结果**，吃住稳了自然会好
- ❌ 多领域仲裁器 —— 等真的出现冲突再做（见架构文档 §2.6）
