## 4. 最小原子操作清单（建议执行顺序）

| 步 | 做什么 | 验收方式（怎么知道它成了） |
| --- | --- | --- |
| 1 | 起隔离实例：`node src\cli.js start`（**后台任务托管**） | `status` 输出 `runningState: running` **且** `bridge.reachable: true`（两条独立证据）；`bridge` 打印 host/port |
| 2 | 确证能力面：`cli.js dump-tools` → `runs\tools.json` | 打印「已导出 N 个工具的完整 schema」；N 与 `runs\tools.json` 里条数一致；**以在线 N 为准，不采信 134 的旧快照** |
| 3 | 进场景：`load_game_ready`（指定存档）或 `start_debug_game_ready`（新殖民地） | `wait_for_game_loaded{readiness:'currentMap'}` 返回 `satisfied:true` **且** `get_bridge_status.state.programState=='Playing'` **且** `ticksGame>0` |
| 4 | 读基线并清障碍：`list_colonists` + `get_ui_state` | 拿到人数/名字/`pawnId`；`windowsForcePause` 必须为 `false`（若 true 先 `close_main_tab`），否则第 6 步会静默跑 0 tick |
| 5 | 做一次确定性改动：`execute_debug_action`（或 `spawn_thing` 生成物品） | 返回的 `stateBefore ≠ stateAfter`（或 `effects.logs[]` 有内容）**并且**用 `get_cell_info.things[].defName` **独立回读**到目标 —— 两边对账，不看 `success` |
| 6 | 推进时间：`step_game_ticks{ticks, pauseFirst:true, timeoutMs:110000+}` | `advancedTicks == ticks` **且** `status == 'completed'`（`pauseFirst` 缺省 false 时实测三次全 failed、0 tick） |
| 7 | 截图取证：`take_screenshot`，拷进 `runs\<runId>\` | 文件存在、体积 > 0、尺寸 = 1600x900（与 `Prefs.xml` 一致） |
| 8 | 断言出报告：`node src\cli.js smoke`（或复用其 `report.json` 结构） | `runs\<runId>\report.md` 出现「通过 ✅」；断言条目含一条**新 mod 已加载**的独立判据（`list_mods.loadedInSession` 或调试树里出现它的 Def），不是只看"没报错" |

> 1～8 全部跑通 = 最小原子操作闭环成立。**3～8 里任何一步只拿到 `success:true` 而没有第 5 步那种独立回读，都不算通过。**
