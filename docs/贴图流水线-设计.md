# 贴图流水线 —— 生成 / 判定分离的设计

> 适用：RimWorld 1.6.4871 rev590（实测版本），mod 工程 `E:\2026.7以后的新工程\DSH\RimWorld_auto_test`
> 工具：`tools/gen-art-spec.py`（契约生成器）、`tools/validate-art-spec.py`（校验器）、
> `tools/make-broken-samples.py`（坏样本）、`tools/demo-iterate-loop.py`（迭代循环演示）
> 运行环境：**捆绑 Python**（Pillow + lxml），零第三方安装。

---

## 1. 核心原则：生成随机，判定确定

| | 生成侧 | 判定侧 |
|---|---|---|
| 谁做 | AI 模型 / 画师 | `tools/validate-art-spec.py` |
| 性质 | 随机、有创造性、不可复现 | 确定性、可复现、逐条给证据 |
| 输出 | PNG 文件 | `report.json` + `todo.json` + 退出码 |
| 权力 | **只能出图** | **唯一裁判** |

三条铁律：

1. **模型永远不当裁判。** 模型说"我画好了"不算数；只有校验器的 `error == 0` 才算数。
   这里没有任何"让模型自己评估一下"的环节 —— 那正是这类流水线最常见的失效点。
2. **判定必须可复现。** 同一份输入跑两次，报告**逐字节一致**（已实测，见 §7）。
   报告里不含时间戳、不含随机数、不含哈希字典序不稳定带来的抖动。
3. **契约不由人手写。** `art-spec.json` 从 Defs XML **机械导出**；手改它等于改契约，
   会在下一步被 XML 的真值打回来（生成器带 `inputDigestSha256` 记录输入指纹）。

## 2. `art-spec.json`：契约

由 `tools/gen-art-spec.py` 从 mod 的 Defs XML 导出，是"这个 mod 需要哪些贴图、每张的硬规格"的**唯一事实来源**。

### 2.1 抽取规则（严格、可复核）

只取每个 `<Def>` 根子树下的 `<graphicData>` / `<bodyGraphicData>`（含 `building/`、`weapon/`、
`renderTree/`、`doorTopGraphic` 等常见容器，最多下钻 3 层）：

| 字段 | 来源 | 说明 |
|---|---|---|
| `texPath` | `<texPath>` | **不带 `Textures/` 前缀、不带扩展名**（IL 已确证） |
| `graphicClass` | `<graphicClass>` | 决定方向需求，见 §2.2 |
| `drawSize` | `<graphicData><drawSize>` → 退 `<Def><size>` → 退父模板 → 退命名后缀推断 | 带 `drawSizeProvenance` 标明**每个值是怎么来的** |
| `defName` / `defType` | `<defName>` / Def 标签名 | 便于定位 |
| `sourceXml` / `elementPath` | 文件路径 / 元素路径 | 例如 `building/doorTopGraphic` |
| `requiredSuffixes` | 由 `graphicClass` 推出 | `[]` 或 `["_north","_east","_south","_west"]` |
| `targetPixels` | `round(drawSize × pxPerCell)` | 见 §2.3 |
| `coReferencedBy` | 去重后合并 | 同一 texPath 被多个 Def 引用时列出其它 defName |

**跳过规则**（不产出契约条目，但记进 `skipped[]` 供人核对）：

- Def 自身 `graphicData` 没写 `texPath`、而该 Def 带 `ParentName` → `inherited_from_parent`
  （继承父模板的 texPath = 复用已有贴图，不产生新需求）；
- **`Abstract="True"` 的模板 Def** → `abstract_template`（模板永不被实例化，它的 texPath 不是需求）。
  实测修正：最初版本会把 `Abstract` 模板的 texPath 也当成需求，导致契约里多出永远不会被渲染的条目，
  已在 `gen-art-spec.py` 中排除。

### 2.2 方向后缀

`requiredSuffixes` 由 `graphicClass` 决定：

- `Graphic_Single`（以及 `Graphic_Shadow`、`Graphic_Blend`）→ `[]`
- 其它 `Graphic_Multi*` → `["_north","_east","_south","_west"]`，**全小写**（IL 已确证）
- 未知 `graphicClass` → 按多方向处理并打 `graphicClassUnknown` 标记（宁可多查，不可漏查）

### 2.3 `targetPixels` 是**项目约定值，不是引擎要求**（本项目 = **128**，已冻结，见 §2.3.1）

`drawSize` 的单位是**格子**，与 PNG 像素**解耦**：引擎按 `drawSize` 缩放，
像素尺寸**不参与加载**。所以：

```json
"pxPerCell": 128,
"pxPerCellNote": "targetPixels = round(drawSize x pxPerCell)。pxPerCell 是**项目约定值**，
                  不是引擎要求：drawSize 的单位是格子，引擎按 drawSize 缩放，
                  像素尺寸不参与加载，因此尺寸不符只会糊/超框，不会加载失败。"
```

- 显式参数：`--px-per-cell 128`（默认 128）。
- 尺寸不符默认判 `warning`，因为引擎允许；要用它当硬门禁就加 `--strict-size`（升 `error`），
  或 `--allow-size-mismatch`（降成纯 `measure`）。**这个开关是刻意的**：像素尺寸是团队约定，
  不该由工具单方面当红线。

### 2.3.1 ★ 决定记录：本项目 `pxPerCell = 128`，**已冻结**

> **决定**：本项目（`RimWorld_auto_test` 仓库内开发的 mod，如 `mods/FoodControl`、
> `mods/ColonyRecorder`，以及后续新 mod）统一采用
> **`pxPerCell = 128`**。这是最终决定，**已冻结**，不再讨论。
> **依据**：与 DLC / 新 mod 保持像素密度一致。
> 工具三处默认值已对齐 128：`gen-art-spec.py` 的 `--px-per-cell` 默认值、
> `validate-art-spec.py` 的契约回退默认值、本文档的示例。

**重申：这是项目约定值，不是引擎要求。** 引擎按 `drawSize` 缩放，像素密度与占格**解耦** ——
这不是推理，是实测：把所有已装 mod 里 `drawSize = (1,1)` 的贴图按实际像素边长统计
（778 个样本），分布跨了三个数量级：

| 像素边长 | 张数 | 像素边长 | 张数 |
|---|---|---|---|
| 16 | 2 | 400 | 12 |
| 64 | 171 | 440 | 6 |
| **128（本项目）** | **182** | 512 | 80 |
| 256 | 215 | 540 | 2 |
| 280 | 9 | 640 | 12 |
| 300 | 39 | 1024 | 3 |
| 320 | 1 | 1280 | 4 |

同一个 `drawSize=(1,1)`，有人出 64、有人出 256、有人出 512 —— 游戏全都正常加载。
**所以 128 是我们选的，不是游戏规定的。**

**改这个值的代价与前提**：

1. 改 `pxPerCell` **必须重跑生成器**（契约不允许手写）：
   `gen-art-spec.py --mod <MOD> --px-per-cell <新值>` → 覆盖 `art-spec.json`；
2. 然后**重新导出所有贴图**到新的 `targetPixels`；
3. 旧图全部会变成 `size_mismatch`。

因此对美术侧有一条硬性要求：**始终保留高分辨率原图与分层源文件**（psd / kri / xcf / 分层输出）。
只要源文件在，改 `pxPerCell` 就只是**重新导出**（分钟级）；源文件丢了，就变成**重画**（周级）。

> **与版权主张的重合**：这条要求与"AI 美术需保留过程记录以主张版权"**是同一个动作** ——
> 保留分层源文件 + 保留生成过程记录，既让 `pxPerCell` 可改，又为版权主张留下证据链。
> 一次动作，两个目的。**别把它们当两件事做，会漏掉一个。**

**PetDoor 的 64 只是"别的项目可能选不同值"的例子**：原版 PetDoor 是 64×64 / 1 格 =
**64 px/格**，与本项目选定的 128 不同。这**不影响**本项目的决定 —— 它恰好证明了
"像素密度可以由项目各自约定"这件事本身。文档里保留它，是为了让未来的人看到
"同一个 `drawSize=(1,1)` 在不同项目里有不同像素实现"是有先例的，不要以为 128 是唯一解。

### 2.4 契约显式排除的东西（只记 `diagnostics`，不产出条目）

`<uiIconPath>`、`<texturePath>`（MainButtonDef 等）这类**非 graphicData 的贴图引用**，
不在契约内（契约只覆盖渲染入口）。生成器会把它们列进 `diagnostics[]` 并在 stdout 打出来，
**不假装覆盖了**。FoodControl 就是活例：它只用了 `MainButtonDef/texturePath = UI/Commands/OpenLog`。

## 3. 校验器：每条检查对应的真实故障

`tools/validate-art-spec.py` 读 `art-spec.json` + mod 目录，输出人类可读清单、
`report.json`（机器可读）、`todo.json`（生成循环待办），退出码 `0`（无 error）/`1`（有 error）/`2`（输入错）。

### 3.1 分级总表

| # | 检查 | 判级 | code | 真实故障 |
|---|---|---|---|---|
| A1 | 期望贴图（含方向变体）是否存在 | **error** | `missing_file` | 游戏画空白框/紫黑格 |
| A1b | `Graphic_Multi` 一个变体都没有 | **error** | `missing_file` | 同上 |
| A2 | `Textures/` 下多余文件 | warning | `orphan_texture` | 改名/删 Def 后的残留，白占体积、误导后人 |
| A3 | `texPath` 写法（不带 `Textures/`、不带扩展名、用 `/`） | **error** | `texpath_out_of_textures` | 映射失败 → 找不到贴图 |
| B4 | 真 PNG 魔数 | **error** | `masquerading_jpeg` / `masquerading_gif` / `masquerading_webp` / `masquerading_bmp` / `masquerading_zip` / `not_png_magic` | **JPG 改名成 .png** → 解码失败 → 紫黑格 |
| B4b | PNG 魔数对但解码失败 | **error** | `not_png_decode_fail` | 文件截断/损坏 |
| B4c | 扩展名不是 `.png`（在 spec 期望路径上） | warning | `extension_not_png` | 游戏只认 `.png` |
| A2b | `Textures/` 下的非 `.png` 残留 | warning | `orphan_non_png` | 废文件占体积，且容易被后人误当素材 |
| B5 | 是否有 alpha 通道 | warning | `no_alpha_channel` | 需要透明的地方一定错 |
| C6 | 实际尺寸 vs `targetPixels` | warning（`--strict-size` 时 error） | `size_mismatch` | 糊 / 超框（引擎不报错） |
| C7a | 边长是 2 的幂 | warning | `dim_not_power_of_two` | 老 GPU 强制缩放，模糊 |
| C7b | 边长是 4 的倍数 | warning | `dim_not_multiple_of_4` | DXT/压缩管线不友好 |
| D | 透明像素亮度占比 | warning（>阈值）/ measure（否则） | `white_fringe_background_carried` / `transparent_luminance_measured` | **白边根因**，见 §3.2 |
| E8 | 占位符残留 | error（原版 DLC 命中）/ warning（Core 辅证命中） | `placeholder_residue` | 发布红线：贴图没出，指着原版的图 |
| E8b | 白名单里的占位符 | info | `placeholder_allowlisted` | 有意为之，不计门禁 |
| F9 | 撞原版 DLC 资源 | **error** | `collision_vanilla` | **后加载者胜**，可能覆盖原版贴图 → 发布红线 |
| F10 | 撞其它已装 mod | info | `collision_mod` | 互相覆盖，需人确认谁是作者 |
| G11a | 缺 `_north` 且无任何回退候选 | **error** | `missing_north_no_fallback` | 回退链走到尽头 → 渲染不出来 |
| G11b | 缺 `_east`/`_south`/`_west`（有回退） | warning | `missing_direction_with_fallback` | 朝向错，但能显示 |
| — | PNG 元数据 | info | `png_metadata_present` | 体积/隐私，非必须 |
| — | 全图无透明像素 | measure | `no_transparent_pixels` | 数据，白边风险不适用 |

### 3.2 D：透明像素颜色 = 白边根因（重点）

**根因**：游戏里松散 PNG 会被**内存压缩**。如果画图软件把**完全透明（alpha=0）的像素**的
颜色数据丢成高亮值（常见的就是"原来的白背景残留"），压缩时邻接采样会把亮色渗进边缘 → **白边**。

**测量方式**（逐像素，只统计 `alpha == 0` 的像素）：

```
指标    : max(r,g,b)/255
阈值    : --transparent-lum-threshold（默认 0.8）
输出    : transparentHighLuminanceCount / transparentHighLuminanceRatio
          transparentMeanMaxChannel / transparentMeanLuminance
等级    : whiteFringeRisk ∈ none(<0.1) / low / medium / high(>0.5)
判级    : ratio > --white-fringe-error-threshold（默认 0.5）→ warning，否则只给 measure
```

工具**不硬失败**：这是启发式测量，最后是人拍板。真实数据两例：

- 干净样本 `tmp/holdout`：`alpha=0 像素 8559 个（占全图 52.24%），其中 max(r,g,b)>0.80 的有 0 个
  （占透明像素 0.00%），透明像素平均 max(r,g,b)=0.0000，风险=none`
- 坏样本 `WhiteFringe.png`：`alpha=0 像素 11371 个（占全图 69.40%），其中 max(r,g,b)>0.80 的有
  11371 个（占透明像素 100.00%），透明像素平均 max(r,g,b)=0.9840，风险=high` → warning

### 3.3 E：占位符残留（发布红线）

"占位符" = 开发期允许 `<texPath>` 指向原版已有贴图。检出方式：

1. **自动识别**：mod 自己 `Textures/` 下没有对应文件，但该 texPath 命中原版资源索引。
   - 命中 DLC manifest → `kind=vanilla_dlc` → **error**
   - 命中 Core/Defs 辅证索引 → `kind=vanilla_core_advisory` → warning
   - 也覆盖"manifest 里只有方向变体"的情况（`k`/`k+north` 两种查法，实测修正）
2. **显式清单**：`--placeholder-list <file>`（每行一个 texPath，`#` 注释），
   命中的降级为 `info`，**不计入发布门禁**（这是"已知有意"，不是残留）。

`report.gate.placeholderResidue` 必须为 0 才放行。

### 3.4 F：撞名（最严重）

- **权威依据 = 原版 DLC 的 `.manifest`**（纯文本，逐行列出包内真实资源路径）。
  还原方式：`Assets/Data/<DLC>/Textures/<相对路径>.png` → texPath =
  `<相对路径>`（去 `Textures/` 前缀、去扩展名）。**按行 split**，不做整读正则
  （manifest 末尾可能没有换行）。
- **比对单位是"实际文件相对路径"，不是 texPath** —— 这是实测修正：manifest 里
  `Graphic_Multi` 是**一个方向一个文件**（`BioferriteGenerator_north.png` 等），
  只比 texPath 会漏报。现在逐个变体文件比对。
- `.psd` 条目被排除（源文件占位，游戏不会把 .psd 当松散 PNG 加载）。
- 实测索引规模（本机 1.6.4871 rev590）：

  | DLC | PNG 条数 |
  |---|---|
  | Anomaly | 783 |
  | Biotech | 1012 |
  | Ideology | 887 |
  | Odyssey | 1479 |
  | Royalty | 63 |
  | **合计** | **4224** |

- **Core 没有 `.manifest`**（贴图在 Unity `resources.assets`/`.resS` 里，**无明文路径**；
  实测扫过 `resources.assets`(7.4MB)、`resources.resS`(254MB)、`globalgamemanagers.assets`
  都没有 `UI/Commands`、`Things/Building`、`Texture` 这类路径字符串）。
  因此 Core 只能提供**辅证**：扫 `Data/Core/Defs/**/*.xml` 的 `<texPath>`
  （实测 550 个 XML → **907 个** distinct texPath）。辅证索引命中判 warning 而非 error，
  并在报告里明确标注"非权威"。**这是本工具已知覆盖缺口，见 §8。**

- 撞其它 mod：扫 `--mods-dir`（本地 Mods）与 `--workshop-dir`（工坊 `294100/*/Textures/`）。
  按 texPath 精确比对（`Textures/` 之后、扩展名之前），判 `info`（需要人确认谁是"作者"，
  工具不能替你决定该不该覆盖）。

## 4. 迭代循环

```
                 ┌───────────────────────────────────────────────┐
                 │  1. 契约（一次性，之后冻结）                    │
                 │     python tools/gen-art-spec.py --mod <MOD>   │
                 │     → art-spec.json                            │
                 └───────────────────┬───────────────────────────┘
                                     ▼
        ┌────────────────────────────────────────────────────────────┐
        │  2. 模型出图（随机、有创造性）                              │
        │     输入：art-spec.json 的单个条目                          │
        │       texPath / graphicClass / requiredSuffixes             │
        │       targetPixels（项目约定尺寸）                          │
        └───────────────────┬────────────────────────────────────────┘
                            ▼
        ┌────────────────────────────────────────────────────────────┐
        │  3. 校验（确定性、唯一裁判）                                │
        │     python tools/validate-art-spec.py \                     │
        │         --spec art-spec.json --mod <MOD> \                  │
        │         --json-out report.json --todo-out todo.json         │
        │     退出码：0 = 无 error，1 = 有 error，2 = 输入错误         │
        └───────────────────┬────────────────────────────────────────┘
                            ▼
                  ┌──────────────────┐
                  │ error == 0 ?      │
                  └───┬──────────┬────┘
                  no  │          │ yes
                      ▼          ▼
   ┌──────────────────────────┐  ┌──────────────────────────────┐
   │  4. 按 todo.json 重生成   │  │  5. 发布门禁检查              │
   │     不是"重画一遍"！      │  │     gate.placeholderResidue=0 │
   │     每条 todo 带：        │  │     gate.collisionsVanilla=0  │
   │       code / severity     │  │     summary.errors = 0        │
   │       expected / actual   │  └──────────────┬───────────────┘
   │       evidence / fixHint  │                 ▼
   └──────────────┬───────────┘  ┌──────────────────────────────┐
                  │              │  6. 游戏内截图 + 人确认        │
                  └──回到 3 ─────┤     （艺术质量只有人能判）    │
                                 └──────────────────────────────┘
```

**收敛判据**：`gate.releaseBlocked == false` 且 `summary.errors == 0`。
`todo.json` 里 `done: true` 就是这个意思。warning 不阻塞收敛，但要人过一遍。

`todo.json` 的结构（供生成侧直接消费）：

```json
{
  "targets": [ { "texPathOrFile", "code", "severity",
                 "expected", "actual", "evidence", "fixHint" } ],
  "targetsByTexPath": { "<贴图>": [ { "code", "severity", "expected", "actual", "fixHint" } ] },
  "errorCount": 2, "warningCount": 4, "done": false,
  "convergenceRule": "gate.releaseBlocked == false 且 summary.errors == 0",
  "byCode": { "size_mismatch": 2, "white_fringe_background_carried": 1, ... }
}
```

**为什么要"带具体错误重生成"而不是简单重跑**：模型重画时必须知道
`expected`（要 256×256 还是 128×128）、`actual`（现在是 96×96）、
`fixHint`（"透明区 RGB 清零"），否则它只会再随机一次。
实测两轮收敛：`第1轮 exit=1（error=2 warning=4）→ 第2轮 exit=0（error=0 warning=0）`。

## 5. 这套工具判定不了什么（必须人来）

工具只判**可被文件系统与像素数据证实的事实**。以下**明确不在**判定范围内：

1. **艺术质量**：好不好看、精不精致、细节够不够。工具一个像素都不"理解"。
2. **是否符合游戏美术风格**：色彩、笔触、明暗、透视、RimWorld 特有的俯视 3/4 视角。
   `dim_*`、`size_*` 只说尺寸，不说风格。
3. **贴图内容对不对 / 朝向对不对**：`_north` 里画的究竟是北面还是南面，
   工具只能验证"文件在、尺寸对、名字对"。**这是最容易漏的一类错**。
4. **`drawSize` 的语义正确性**：契约是从 XML 机械导出的，XML 写错了契约就一起错
   （错进错出）。工具不判断"这个 Def 的 drawSize 应该是 2 还是 3"。
5. **`pxPerCell` 这个约定值本身**：是项目约定，工具只是执行它。
6. **alpha 通道是否"语义上必要"**：只看有没有通道，不看该不该有。
7. **白边最终会不会真的出现**：D 项量的是"根因指标"（透明像素残留亮度），
   不是"压缩后实际渲染出来的白边"。真实观感要在**游戏内截图**确认。
8. **Core 原版贴图的撞名**：Core 无 manifest 无明文路径（见 §3.4），只能辅证。
9. **程序化生成 / Shader 出图**：`Graphic_Multi` 之外的动态图形（比如
   `Graphic_Random`、材质色、剖面 shader）不走松散 PNG，本流水线不覆盖。
10. **`uiIconPath` / `texturePath` 等非 graphicData 引用**：只记录，不校验。
11. **`.psd` 源文件被误打进发布包**（manifest 里 DLC 自己就有 .psd 条目）：
    未检查，需要时可加"发布包内不得含 .psd"这条。
12. **跨 mod 的 Def 继承**：契约只看本 mod 的 XML；若本 mod 的 Def 继承**别的 mod** 的
    模板，texPath 不在本 mod XML 里，会被漏掉。

**结论**：`error == 0` 是**必要不充分**条件。发布前必须补一步
**游戏内截图 + 人确认**（艺术质量与内容正确性）。

## 6. 用法速查

```powershell
# 环境（捆绑 Python，零安装）
$py = 'C:\Users\MikanseiP\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe'
$WS = 'E:\2026.7以后的新工程\DSH\RimWorld_auto_test'

# 1) 生成契约
& $py "$WS\tools\gen-art-spec.py" --mod <MOD目录> --out <art-spec.json> `
       [--px-per-cell 128] [--game-version 1.6] [--defs-root <目录>] [--quiet]

# 2) 校验
& $py "$WS\tools\validate-art-spec.py" --spec <art-spec.json> --mod <MOD目录> `
       --json-out <report.json> --todo-out <todo.json> `
       [--strict-size | --allow-size-mismatch] `
       [--transparent-lum-threshold 0.8] [--white-fringe-error-threshold 0.5] `
       [--manifest-dir <RimWorld\Data>] [--advisory-core-dir auto] `
       [--mods-dir <RimWorld\Mods>] [--workshop-dir <workshop\content\294100>] `
       [--no-collision-scan] [--no-advisory-scan] [--no-workshop-scan] [--no-pixel-scan] `
       [--placeholder-list <清单文件>] [--px-per-cell N] [--quiet]

# 3) 坏样本 / 循环演示
& $py "$WS\tools\make-broken-samples.py"
& $py "$WS\tools\demo-iterate-loop.py"
```

`--advisory-core-dir auto` = 用 `--manifest-dir` 下的 `Core`。
`--no-pixel-scan` 跳过**逐像素**分析（白边测量），但**真伪/尺寸/alpha 仍会查**
（只读 64 字节文件头，几乎不花时间）—— 这是刻意的：不能让"快跑"把
JPG 改名成 .png 这类最严重的错漏掉。
