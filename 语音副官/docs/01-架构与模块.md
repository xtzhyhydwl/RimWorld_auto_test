# 01 · 架构与模块

> **这份文档管什么**：模块清单（28 个）、不变量 I1–I7、每个模块的六栏契约、18 组跨模块类型、信息流图与线程边界、模块间调用顺序。
> **谁该读**：写代码的人（照 §5 建文件、照 §6 建类型）；评审的人（只需背 §2 的七条）。
> **与其它文档的边界**：类别的逐行数据在 `02-类别与来源.md`；文案模板与切分规则在 `03-文案与片段.md`；库与清理在 `04-语音库与清理.md`；设置字段与控件在 `05-设置界面.md`；编码顺序与探针在 `06-编码顺序与验收.md`。本文只说"谁是谁、谁调谁"。
> **标注**：【实测】= 读了本仓代码或 `docs/取证-*.md`（取证为静态 IL/XML，未在游戏里复验）；【推测】= 由结构/IL 推出、无运行时观察；【待验证】= 进游戏或一次编译才能定。
> **路径**（相对 `语音副官/`）：代码 = `Source/*.cs`、`Source/UI/*.cs`。

## 1. 命名规则（一名一义）

| # | 规则 | 落地 |
|---|---|---|
| N1 | 一个概念一个名字 | 存档 GUID 只有 `SaveFingerprint` 一个名字；音色标识只有 `VoiceFingerprint` 一个名字；两者不混用、不简写、不合并叫法 |
| N2 | 名字里写清它是什么 | `NotifyHooks`、`LetterHooks`、`SpokenCategory`、`Switchboard`、`LibraryJanitor`、`ClipAssembler` |
| N3 | 模板键统一前缀 | 单事件 `Phrase_<类别>`；聚合 `Phrase_<类别>_Batch`；裸文本 `Phrase_RawText` |
| N4 | 通道名固定四个 | `incident` / `letter` / `message` / `自算`，不写"事件通道""消息通道"等变体 |
| N5 | 一个模块一个文件 | `Source/<模块名>.cs`；`UI/` 下 6 个文件（1 外壳 + 4 页签 + 1 公共绘制） |
| N6 | 等级名固定三个 | `L1` / `L2` / `L3`，只由 `LibraryJanitor` 判定 |

## 2. 不变量 I1–I7

改任何模块先对照这七条；它们是"改一处"的支点，也是评审时唯一需要背下来的东西。

| # | 不变量 | 违反时的症状 |
|---|---|---|
| I1 | **只有 `SegmentSynthesizer` 跨线程**。后台 `Task` 只碰 `string` 与 `TtsRequestParams`（不可变快照），回 `byte[]`；`Notice` / `Utterance` / `Segment` / `Verse` / `UnityEngine` 对象一概不出主线程 | 后台建 `AudioClip`、读 `Pawn` ⇒ 未定义行为 |
| I2 | **`SpeechLibrary` 是唯一碰磁盘的模块，且只在主线程被访问**（含把磁盘列表 `ListFiles()` 交给清理器） | 两处各写一半文件句柄、孤儿文件对不上 |
| I3 | **删除决策只在 `LibraryJanitor`**。库的 `Put` 只回"当前占用"，**不认识上限**；别人想删只能 `ReportBroken` | 两套淘汰规则互相打脸 |
| I4 | **开关闸只有 `Announcer` 调 `Switchboard`；配置闸只有 `TtsClient` 判**。UI 只读 `TtsClient.LastError`，不自己判"能不能用" | 到处 if；"未配置"有两处判断，说法会分叉 |
| I5 | **中文文案只有一份**（`SpeechCatalog.Phrases`）；**念法规则只有一份**（`SegmentPlanner`：名字清洗、数字处理、切分） | 同一个词两种念法、`鼠条.18` 一处清一处不清 |
| I6 | **音频的唯一样子是磁盘文件 + 按需建 `AudioClip`**：内存里没有 `AudioClip` 池、没有 PCM 常驻；`PlayableUtterance` 播完丢引用 | 3000 条 × 2 s ≈ 288 MB 常驻【实测：24 kHz/16 bit/单声道 = 48 KB/s】 |
| I7 | **启动顺序固定**：`SpeechCatalog`（静态表）→ `VoiceDeputySettings`（构造与 `ExposeData` 遍历 `Entries`）→ `DeputyGameComponent` 由 `Game.FillComponents()` 自动创建（`ctor(Game)`） | 目录表未就绪就去构造 Settings ⇒ 全部开关落默认或抛 |

**三个必须独立存在的模块**

| 模块 | 理由 |
|---|---|
| `ClipAssembler` | 独占"字符串世界 → Unity 对象世界"的边界，并且是**唯一**判"缺哪些片段"的地方：上游全是 `string`/enum，下游全是 `AudioClip`。塞进 `VoicePlayer` ⇒ 播放器要懂缓存键与 WAV；塞进 `SpeechLibrary` ⇒ 存储要懂 Unity；塞进 `SegmentSynthesizer` ⇒ 合成器要懂建 clip 的线程时机 |
| `DeputyGameComponent` | "每帧"必须恰好有一个主人；`SaveFingerprint` 的读写与注入也必须恰好有一个主人 |
| `WavReader` | SiliconFlow 的 WAV 头长度字段是占位值（`data` size = `4294967040`），必须按实际字节重算【实测：`runs/tts-probe/`，未在 Unity 内复验】；这是唯一会随服务端变而改的地方 |

## 4. 补丁点账（8 个补丁点 / 5 个文件）

| 文件 | # | 补丁点（1.6 签名，【实测：`取证-提示信息出口`/`取证-事件真值表`/`取证-死亡播报出口`，未复验】） | 产出的类别 |
|---|---|---|---|
| `NotifyHooks` | ① | `Verse.Messages.Message(Verse.Message, bool)` Postfix — **写全参数类型**（4 个重载，只按名 patch 抛 `AmbiguousMatchException`） | `Rotten`、`BuildPlaceFailed`、`OtherMessage` |
| `LetterHooks` | ② | `Verse.LetterStack.ReceiveLetter(Verse.Letter, string, int, bool)` Postfix — **写全参数类型**（3 个重载） | `Quests`、`OtherLetter` |
| `IncidentHooks` | ③ | `RimWorld.IncidentWorker.TryExecute(RimWorld.IncidentParms)` Postfix，且 `__result == true` 才产出 | `ThreatRaid`、`ThreatSiege`、`ThreatAnimalInsanity`、`DiseaseOutbreak`、`TraderArrival`、`Visitors`、`WeatherExtreme`、`EnvHazard`、`OtherIncident` |
| `PawnHooks` | ④ | `Verse.AI.MentalStateHandler.TryStartMentalState` Postfix（**9 个参数写死类型**：`stateDef, reason, forced, forceWake, causedByMood, otherPawn, transitionSilently, causedByDamage, causedByPsycast`） | `MentalBreak` |
| `PawnHooks` | ⑤ | `Verse.Hediff_Pregnant.StartLabor` Postfix | `Birth` |
| `PawnHooks` | ⑥ | `Verse.Pawn_HealthTracker.MakeDowned` Postfix（private，按显式参数类型写死） | `PawnDowned` |
| `PawnHooks` | ⑦ | `Verse.Pawn_HealthTracker.NotifyPlayerOfKilled(Nullable<DamageInfo>, Hediff, Caravan)` Postfix | `PawnDied` |
| `BlueprintHooks` | ⑧ | **一对补丁算一个点**：`RimWorld.Designator_Build.DesignateSingleCell` Prefix/Postfix 维护"玩家手动放置"静态标记 + `RimWorld.GenConstruct.PlaceBlueprintForBuild` Postfix（配 `CostListCalculator.CostListAdjusted` + `Map.resourceCounter.GetCount` 算缺口） | `BuildMissingMaterials` |

**铁律**：签名必须写全参数类型（`Messages.Message` 4 重载、`ReceiveLetter` 3 重载【实测】）；Postfix 体内 `try/catch` 全包（钩子里抛异常会污染原版调用栈）；钩子只做"取事实、填参数"，切分唯一归 `SegmentPlanner`（I5）。

**死亡覆盖**：殖民者 / 宠物 / 囚犯 / 访客 / 远行队**全覆盖**——前两类发 `LetterDef=Death` 的信，后三类发 `MessageTypeDef=PawnDeath` 的消息，两支互斥且都从 `NotifyPlayerOfKilled` 出【实测：`取证-死亡播报出口` §2.3】，因此 ⑦ 一个点收齐；②①按 def 名把 `Death` / `PawnDeath` 排除，不重复播（丢弃表见 `02` §4.1）。
**本轮不播的死亡路**：食尸鬼（Anomaly 变异体）另走 `Pawn_MutantTracker.Notify_Died` 再发一封 `Death` 信【实测：`取证-死亡播报出口` §2.7】，该路不在 8 个补丁点内，先不纳入。

## 5. 模块契约（六栏：输入 / 输出 / 持有状态 / 明确不负责 / 触发时机 / 失败模式）

> 按职责分五组查表（入口与泵 / 数据与开关 / 钩子与成句 / 音频链 / 界面）；每行一个模块，六栏齐全。方法签名写死，照抄能建出文件。

### 5.1 入口与泵

| 模块 | 输入 | 输出 | 持有状态 | 明确不负责 | 触发时机 | 失败模式 |
|---|---|---|---|---|---|---|
| `VoiceDeputyMod` | `ModContentPack`（主线程，一次性）；玩家点设置页按钮 | `VoiceDeputyMod.Settings`（静态，给 `Switchboard`/UI 读）；`Harmony.PatchAll()`（一次性，装 8 个点）；`new UI.Dialog_VoiceSettings()` 入 `Find.WindowStack` | 只持 `Settings` 引用 | 组件生命周期归 `Game.FillComponents()`（§7.6 自动收养）；缓存目录归 `SpeechLibrary`；每帧驱动归 `DeputyGameComponent` | 进程内一次（Mod 构造）；用户点按钮时 | `Settings` 构造失败 ⇒ 异常冒泡；`PatchAll` 失败 ⇒ `Log.Error` 并整体停用 |
| `DeputyGameComponent` | **框架构造** `public DeputyGameComponent(Game game)`（`Game.FillComponents()` 用 `Activator.CreateInstance(type, new object[]{game})`，无需注册【实测：`取证-GameComponent注册` §2.1】）；每帧 `Update()`；`Announcer.Tick()` / `SegmentSynthesizer.Drain()` / `ClipAssembler.Plan()` 的返回 | 每帧固定顺序：`Drain()` ⇒ 每条 `CompletedJob`（`Playback` 非空）`Plan` ⇒ `foreach (u in Announcer.Tick())` `ClipAssembler.Plan(u, ∅)` ⇒ `Ready` 入 `SpeechQueue`、`Missing` 交 `SegmentSynthesizer.RequestMissing`、`Nothing` 丢弃 ⇒ 本帧有 `Put` ⇒ `LibraryJanitor.CheckLimit()` ⇒ `VoicePlayer.Tick()`；每 2 s `WarmupScheduler.Tick()`；每 `JanitorIntervalSeconds` `LibraryJanitor.Tick()`；读档/新开局 `SpeechLibrary.SetSaveFingerprint` | `SaveFingerprint : string`（存盘键 `voiceCacheId`）；两个计时器（2 s / `JanitorIntervalSeconds`） | 策略全部外置：开关归 `Switchboard`、优先级归 `SpeechCatalog.PriorityOf` + `SpeechQueue`、等级与删除归 `LibraryJanitor`、文本归 `SegmentPlanner`、合成归 `SegmentSynthesizer`；本类只负责调用顺序 | 每帧（`GameComponentUpdate`）；`SaveFingerprint` 在 `LoadedGame` / `StartedNewGame` 里就地铸且幂等（`ExposeData` 晚于 `StartedNewGame`，同样判空补铸【实测】） | 每段各自 `try/catch` + 一条 `Trace`；同一异常 600 帧最多记一次；`Drain` 抛 ⇒ 丢本帧结果，下一次播报重新发起；读档去重归框架（`FillComponents` 自带 `RemoveAll(c => c == null)` + `GetComponent` 判重），本类只提供 `ctor(Game)` |

### 5.3 钩子与成句

| 模块 | 输入 | 输出 | 持有状态 | 明确不负责 | 触发时机 | 失败模式 |

### 6.1 `Notice`（`sealed class`，数组字段构造时拷一份、对外只读）

| 字段 | 类型 | 说明 |
|---|---|---|
| `Category` | `SpokenCategory` | 开关与优先级的挂载点 |
| `Phrase` | `SpeechPhrase` | 用哪条模板（单事件；聚合模板由 `CategoryEntry.BatchPhrase` 给） |
| `Args` | `string[]` | 模板参数，顺序即占位符顺序；已拍平成最终要念的字（钩子不清洗） |
| `Names` | `string[]` | **要点名的**人（0–N），钩子交 `LabelShortCap` 原文；群体事件恒为空数组 |
| `Count` | `int` | **总人数**（与 `Names` 解耦）；无人数概念的事件填 `1` |
| `BatchKey` | `string`（可空） | 非空 ⇒ 进 `BatchAggregator`；合并键 = `(Category, BatchKey)` |
| `Tick` | `int` | 产出时刻（`GenTicks.TicksGame`） |

- 产出：5 个 Hook 文件（主线程，事件驱动）。消费：`Announcer.Receive`。
- **钩子对这张表只做"填值"**：`Category`/`Phrase` 由 `Bindings` 给，`Args`/`Names`/`Count`/`BatchKey` 从现场事实取。
- **不含任何 `Verse`/`UnityEngine` 对象**（连 `LookTargets` 也不带，I1）：出钩子之后全链只有 enum/string/int。

### 6.2 `Segment` / `SegmentKind`

```text
Segment      { Text : string, Kind : SegmentKind }        // 不可变
SegmentKind  = Const(常量) | Enum(枚举) | PersonName(人名) | Number(数字) | RawText(原句) | Sentence(整句)
Segment.Kind —— 只取前 5 个；Sentence 只作 LibraryKey.SegmentKind 的取值
```

| 字段 | 类型 | 谁产出 | 谁消费 |
|---|---|---|---|
| `Text` | `string` | `SegmentPlanner`（唯一产出者） | `SegmentSynthesizer`（送 TTS）、`ClipAssembler`（查库与 `FullText`）、`SpeechLibrary` |
| `Kind` | `SegmentKind`（前 5 值） | `SegmentPlanner`（由模板 `ArgKinds` 决定） | `SpeechLibrary`（键与 `Scope`）、`LibraryJanitor`（等级判定） |

- `Sentence`（整句）只出现在 `LibraryKey.SegmentKind`，不出现在 `Segment.Kind`。
- `Const`/`Enum`/`Number` 是**有限闭集**（模板字面量、原版 def 的 label、数量），`PersonName` 是本存档的人/派系/地名，`RawText` 是原版自由文本（兜底文案、落点原因、死因句，无界）。
- `PersonName` 同时承载派系名、地名：保留策略与殖民者名相同。
- **等级规则见 `04` §4.2**（唯一判定处，本文不复述）。

### 6.3 `Utterance`

| 字段 | 类型 | 谁产出 | 谁消费 |
|---|---|---|---|
| `Category` | `SpokenCategory` | `SegmentPlanner`（`Plan(BatchSummary)` 时透传） | `SpeechQueue`（取优先级）、`VoicePlayer`（记录） |
| `Segments` | `Segment[]`（只读） | `SegmentPlanner` | `SegmentSynthesizer`、`ClipAssembler` |
| `FullText` | **计算属性** `string.Concat(Segments)`（唯一真源，不另存字段） | — | 整句键、最近播报 |
| `BatchKey` | `string`（可空） | `SegmentPlanner` | 日志 |

- 消费链：`Announcer`（成句）→ `DeputyGameComponent`（唯一组装调用者）→ `ClipAssembler.Plan`（→ `Missing` 时 `SegmentSynthesizer` → 再 `Plan`）。
- `FullText` 只有一个真源 ⇒ "怎么拼"只允许在 `SegmentPlanner` 一处发生。

### 6.4 `PlayableUtterance`

| 字段 | 类型 | 谁产出 | 谁消费 |
|---|---|---|---|
| `Source` | `Utterance`（**引用，不拷贝**） | `ClipAssembler` | `VoicePlayer`（`FullText`/`Category` 全从这取） |
| `Clips` | `AudioClip[]`（已归一、已建好，只在主线程） | `ClipAssembler` | `VoicePlayer` |
| `FromSentenceCache` | `bool`（`true` ⇔ 由整句键命中而生成） | `ClipAssembler` | `Trace`、最近播报 |

停顿/音量**不在这里**（`VoicePlayer` 现读 `Settings`）；优先级**不在这里**（`SpeechQueue` 用 `Source.Category` 查）。

### 6.5 `BatchSummary` / `RosterDelta`

| 类型 | 字段 | 产出 | 消费 |
|---|---|---|---|
| `BatchSummary` | `Category`；`BatchKey`；`Count`（成员之和）；`Names`（并集，可空）；`Single : Notice?`（合计 `Count == 1` 时指向原 `Notice`，`SegmentPlanner` 据此走单事件模板） | `BatchAggregator` | `SegmentPlanner.Plan(BatchSummary)` |
| `RosterDelta` | `NewNames : string[]`（消失名单只在清理器内部用，不外传） | `LibraryJanitor` | `WarmupScheduler` |

### 6.6 `LibraryKey`

```text
LibraryKey { VoiceFingerprint : string, Scope : string(计算), Text : string, SegmentKind : SegmentKind }   // 值类型
  Scope  —— 计算属性，不落库、不进构造参数：SegmentKind ∈ {PersonName, Sentence} ? "save:" + SaveFingerprint : "global"
  Value  —— 落盘名 = sha1(VoiceFingerprint + "|" + Scope + "|" + Text)
```

| 成员 | 谁产出 | 谁消费 |
|---|---|---|
| `VoiceFingerprint` | `SpeechLibrary`（由 `Settings.BaseUrl+Model+Voice` 算，唯一派生点） | `Key` |
| `Scope` | `SpeechLibrary`（由 `SegmentKind` + `SaveFingerprint` 推） | `Key` |
| `Text` | `SegmentPlanner` | `Key`、`LibraryEntry.Text` |
| `SegmentKind` | `SegmentPlanner` / `ClipAssembler` | 等级判定（`LibraryJanitor`） |
| `Value` | `SpeechLibrary` | 落盘名、`LibraryEntry.Value`、`DiskFile.Value`、全部删除调用 |

换音色/模型/端点 ⇒ `VoiceFingerprint` 变 ⇒ 旧键查不到；换存档 ⇒ `Scope` 变 ⇒ 不会念上一个存档的名字。

### 6.7 `LibraryEntry` / `DiskFile`

| 类型 | 字段 | 谁产出 | 谁消费 |
|---|---|---|---|
| `LibraryEntry` | `Value`；`Text`；`SegmentKind`；`LastUsedTick : int`；`Bytes : long` | `SpeechLibrary` | `LibraryJanitor`（等级判定、淘汰排序、子串匹配）、UI（经 `LibraryUsage`） |
| `DiskFile` | `Value`；`Bytes` | `SpeechLibrary.ListFiles()` | `LibraryJanitor`（对账） |

**两个键空间、一张索引、一套淘汰**：`SegmentKind.Sentence` 只是同一张表上的取值。**等级不在条目里**：条目只存事实，等级每轮现算。

### 6.8 `LibraryUsage`

| 字段 | 类型 | 说明 |
|---|---|---|
| `Entries` | `int` | 索引条目数 |
| `Bytes` | `long` | 索引里所有 `Bytes` 之和 |
| `Describe()` | `string` | 形如 `1,234 条 / 12.3 MB`【实测】 |

产出：`SpeechLibrary.Usage` / `Put` 的返回值。消费：UI 调试页、`LibraryJanitor` 的超限判据。

### 6.9 `CategoryEntry`

| 字段 | 类型 | 说明 |
|---|---|---|
| `Category` | `SpokenCategory` | 全链 |
| `Group` / `Label` / `Description` | `string` | UI 分组与文案；`VoiceDeputySettings` 的构造与 `ExposeData` 遍历 `Entries` |
| `Priority` | `int` | `SpeechQueue`（插队 + 丢最旧），初值见 `02` §5 |
| `BatchPhrase` | `SpeechPhrase` | 聚合句模板键（只给 `Plan(BatchSummary)` 用；空 = 本类不聚合） |
| `DefaultEnabled` | `bool` | 类别开关的**唯一默认值定义处**，`SetDefaults` 是唯一读者 |

### 6.10 `PhraseEntry` / `PhraseForm`

```text
PhraseEntry { SpeechPhrase Id, SpokenCategory Category, PhraseForm Form, string Template, SegmentKind[] ArgKinds }
PhraseForm  = SingleEvent(单事件) | Batch(聚合) | RawText(裸文本)
```

| 形态 | `Template` 规则 | `ArgKinds` |
|---|---|---|
| `SingleEvent` | 槽位由钩子给的 `Args` 按顺序填 | 每个槽一个 `SegmentKind` —— "哪段是常量、哪段是名字"只有这一个答案 |
| `Batch` | 固定两槽 `{0}=Count`、`{1}=Names 连接` | `[Number, PersonName]`；`Names` 为空时 `{1}` 段整段消失 |
| `RawText` | 试听/手动朗读用 | 整段一个 `RawText` 片段（不入 L1） |

> **加一类播报 = `SpokenCategory` 一行 + `CategoryEntry` 一条 + `PhraseEntry`（单事件）一条 + `PhraseEntry`（聚合）一条 + `SourceBinding` 一行 + `CategorySlot` 一行**，不改任何 `if`。`CategorySlot` 是 `VoiceDeputySettings` 内部的私有 `ref` switch（对外只暴露 `IsCategoryEnabled` / `SetCategoryEnabled`），加类加一行【实测】。

### 6.11 `TtsRequestParams` / `TtsRequest`

| 类型 | 字段 | 产出（线程） | 消费（线程） |
|---|---|---|---|
| `TtsRequestParams` | `BaseUrl, ApiKey, Model, Voice, ResponseFormat : string`（`ResponseFormat` 恒 `"wav"`）；`Speed : float` | `SegmentSynthesizer`（主线程从 `Settings` 拍快照，**不可变**） | `TtsClient`（后台） |
| `TtsRequest` | `Text : string`；`Params : TtsRequestParams` | `SegmentSynthesizer`（主线程） | `TtsClient`（后台） |

### 6.12 `SynthesisResult` / `CompletedJob` / `WarmupJob`

| 类型 | 字段 | 产出（线程） | 消费（线程） |
|---|---|---|---|
| `SynthesisResult` | `JobId`；`Text`；`WavBytes : byte[]?`；`Error : string?`（**单条**） | `TtsClient`（后台）→ 进 `ConcurrentQueue` | `SegmentSynthesizer.Drain`（主线程） |
| `CompletedJob` | `JobId`；`Kind : JobKind`；`Playback : Utterance?`；`DeadTexts : string[]`；`Put : int`（成功落库条数） | `SegmentSynthesizer.Drain` | `DeputyGameComponent` |
| `WarmupJob` | `Kind : JobKind`；`Text`；`SegmentKind`（短语恒 `PersonName`，整句恒 `Sentence`） | `WarmupScheduler` | `SegmentSynthesizer` |

### 6.13 `PcmData`

| 字段 | 类型 | 说明 |
|---|---|---|
| `Samples` | `float[]` | **交错存储**（多声道按 L,R,L,R…） |

| `Channels` | `int` | 同上 |

产出：`WavReader`。消费：`ClipAssembler`（→ `LoudnessNormalizer` → `AudioClip.Create`）。

### 6.14 `SpeechChannel` / `SourceBinding` / `BindingKey`

```text
SpeechChannel = Incident(incident) | Letter(letter) | Message(message) | SelfComputed(自算)
BindingKey    = DefName | Category | RaidStrategyPrefix | ArrivalModeContains | WorkerClass | DefNameContains
SourceBinding { SpokenCategory Category, SpeechChannel Channel, BindingKey Kind, string Value, string TextSuffix }
```

| 成员 | 说明 |
|---|---|
| `Category` | 命中的类别 |
| `Channel` | 该行属于哪个通道；`For*` 只查自己通道的行 |
| `Kind` + `Value` | 判据种类与比较值（语义见 `02` §2.2 的表） |
| `TextSuffix` | 只对 `Message` 通道有效：把宽 def 收窄到一条文案（`Rotten` 用，值由 `MessageRottedAwayInStorage.Translate()` 派生） |

产出：`SpeechCatalog.Bindings`（编译期数据）。消费：`ForIncident` / `ForLetter` / `ForMessage`。

### 6.15 `AssemblyResult` / `AssemblyOutcome`

```text
AssemblyOutcome = Ready | Missing | Nothing
AssemblyResult  { AssemblyOutcome Outcome, PlayableUtterance Playable, Segment[] Missing }
  工厂：Ready(PlayableUtterance) / Missing(Segment[]) / Nothing()
```

| 取值 | `Playable` | `Missing` | 调用方动作（`DeputyGameComponent`） |
|---|---|---|---|
| `Ready` | 非空 | 空 | `SpeechQueue.Enqueue(Playable)` |
| `Missing` | 空 | 非空 | `SegmentSynthesizer.RequestMissing(u, Missing)` |
| `Nothing` | 空 | 空 | 丢弃该句（无可用 clip），记 `Trace("3a","nothing")` |

- 三态互斥：`Enqueue` 永远不会收到 `null`（"整句一句都建不出 clip"落到 `Nothing`）。
- 结构体还是类不限定；`Missing` 数组构造时拷一份、对外只读。

产出：`ClipAssembler.Plan`。消费：`DeputyGameComponent`。

### 6.16 `JobKind`

```text
JobKind = Missing(缺片段合成) | Warmup(预热)
```

| 取值 | `CompletedJob.Playback` | `Drain` 之后的动作 |
|---|---|---|
| `Missing` | 非空 | 二次 `ClipAssembler.Plan`（回路闭合一次） |
| `Warmup` | `null` | 只更新占用；`Put` 成功的条数进 `CompletedJob.Put` |

产出：`SegmentSynthesizer`（登记作业时写死）。消费：`DeputyGameComponent`（分派）、`CompletedJob`。

### 6.17 `UtteranceSource`

```text
UtteranceSource { SpokenCategory Category, SpeechPhrase Phrase, string[] Args,
                  string[] Names, int Count, string BatchKey }
  工厂：From(Notice) / From(BatchSummary) / FromText(string text)
```

| 成员 | 来源 | 用途 |
|---|---|---|
| `Category` | `Notice.Category` / `BatchSummary.Category` | 选 `CategoryEntry`、定优先级 |
| `Phrase` | `Notice.Phrase`；`From(BatchSummary)` 取 `EntryOf(Category).BatchPhrase`；`FromText` 取 `Phrase_RawText` | 选模板 |
| `Args` / `Names` / `Count` | `Notice` 原样；`From(BatchSummary)` 时 `Args=[Count]`、`Names=并集` | 填槽位 |
| `BatchKey` | 透传 | 日志用 |

- 只在 `SegmentPlanner` 内部构造与消费；`Plan(Notice)` / `Plan(BatchSummary)` / `PlanRaw(string)` 是它的三个入口。
- 不可变：`Args`/`Names` 构造时拷一份。

## 7. 信息流

### 7.1 主链：游戏事件 → 扬声器（含"缺片段"回路）

```text
【主线程】════════════════════════════════════════════════════════
游戏事件（Message / Letter / Incident / Pawn / Blueprint）
   │ ①钩子体内：仍是 Verse 对象（Message、Letter、Pawn、Map）
   ▼
Hooks（5 文件 / 8 点）
   │ ★拍平：对象 → Notice{enum + string[] + Count + BatchKey}
   ▼
Announcer.Receive(Notice)              ← 名单已在钩子里拍平（群体事件只给 Count）
   ├─ Switchboard.Enabled(Category)? ──否──► 丢（Trace 2 off）
   ├─ 去重（类别+文案+人数，2000 ms）──命中──► 丢（Trace 2 dup）
   ├─ BatchKey != null ──► BatchAggregator.Add（同 tick 合并，tick 一变即 Flush）
   │                        └ 批内 Count 合计 > 1 ⇒ 聚合模板；== 1 ⇒ Single 走单事件模板
   └─ SegmentPlanner.Plan(notice) ──► Utterance{Segment[], FullText(计算属性)} → ready
                                                    │
                          Announcer.Tick()（每帧）交出 ready
                                                    ▼
                        DeputyGameComponent.Update ★唯一的组装调用者
                                                    │
                                    ClipAssembler.Plan(u, dead = ∅)
                                                    │
              ┌─────────────────────────────────────┴───────────────────────────┐
              │ Ready(PlayableUtterance)                                      │ Missing(Segment[])
              ▼                                                               ▼
   SpeechQueue.Enqueue（优先级 = PriorityOf(Category)）      SegmentSynthesizer.RequestMissing(u, missing)
              │                                                               │ ★出境只有 (JobId, Text, TtsRequestParams)
              │                                        【后台 Task】═════════╪═══════════════════════
              │                                                               │ TtsClient POST {BaseUrl}
              │                                                               │ SynthesisResult → ConcurrentQueue
              │                                        【主线程】═════════════╪═══════════════════════
              │                                                               ▼
              │                                  DeputyGameComponent.Update 每帧：SegmentSynthesizer.Drain()
              │                                    ├ Arrived+Failed == Total 才算完成
              │                                    ├ SpeechLibrary.Put(Key(text,kind), bytes)   ★落盘
              │                                    └ CompletedJob{Playback, DeadTexts}
              │                                                               │
              │                                    ClipAssembler.Plan(u, DeadTexts) ★回路闭合，只走一次
              │                                                   ┌───────────┴───────────┐
              └───────────────────────────────────────────────────┤ Ready                 │ 仍 Missing ⇒ 丢弃该句 + Trace 5.3
                                                                  ▼
                                                         VoicePlayer（独占当前句 + clipIndex）
                                                           dspTime 连播，GapMs/音量现读 Settings
                                                                  ▼
                                                         AudioSource.PlayScheduled ──► 扬声器
                                                                  │ 整句播完
                                                                  ▼
                                                  WarmupScheduler.EnqueueSentence(u)（先 Contains(Sentence 键) ⇒ 命中不排）
```

### 7.2 旁路 1：预热（不发声）

```text
[主线程] 启动第一批：SpeechCatalog.ConstantTexts()（从模板表派生，不另维护词表）
[主线程] LibraryJanitor 每轮扫描 ──► RosterDelta.NewNames
        WarmupScheduler.Tick（每 2 s，按 WarmupJobsPerMinute 限流）
              │ 先 SpeechLibrary.Contains(Key(text, kind)) ⇒ 命中直接出队
              ▼ WarmupJob ──► SegmentSynthesizer.RequestWarmup
              ▼ [后台 TtsClient] ──► ConcurrentQueue
              ▼ [主线程] Drain ──► SpeechLibrary.Put ──► 只落库：不入队、不组装、不出声
```

### 7.3 旁路 2：整句缓存（读 / 写两个方向）

```text
读：[主线程] ClipAssembler.Plan 第 1 步：TryRead(Key(u.FullText, SegmentKind.Sentence))
        ├ 命中 ⇒ Ready(1 个 clip, FromSentenceCache=true)
        └ 未命中 ⇒ 走片段路径（§7.1）
写：[主线程] VoicePlayer 播完一句 ──► WarmupScheduler.EnqueueSentence(u)
        ├ Contains(Sentence 键) 命中 ⇒ 不排
        └ 否则 WarmupJob{Kind=JobKind.Warmup} ──► SegmentSynthesizer ──► [后台] ──► [主线程] Drain ──► Put(整句键)
```

### 7.4 旁路 3：清理（只删）

```text
[主线程] DeputyGameComponent 每 JanitorIntervalSeconds（默认 300 s）──► LibraryJanitor.Tick
          ① 对账：Snapshot()（索引侧）vs ListFiles()（磁盘侧）⇒ RemoveFile / RemoveEntry
          ② 两阶段名单：删"上一轮消失的名字" ⇒ 记"本轮消失的名字"
          ③ 超限：CheckLimit() 与这里跑同一个函数，按 (等级, LastUsedTick) 淘汰
          ④ SaveIndex() + RosterDelta{NewNames} → WarmupScheduler
              ▼ SpeechLibrary.RemoveEntry / RemoveFile / SaveIndex   ← 全 mod 唯一的调用者
[主线程] 每次 Put 之后 ──► LibraryJanitor.CheckLimit()（库不认识上限）
[主线程] ClipAssembler 遇坏文件 ──► LibraryJanitor.ReportBroken(value)（只登记，不删）
[主线程] UI「清缓存」 ──► LibraryJanitor.ClearAll()
```

### 7.5 线程边界总表

| 步骤 | 线程 | 能碰 | 不能碰 |
|---|---|---|---|
| 钩子读游戏状态 | 主线程 | `Message`/`Letter`/`IncidentParms`/`Pawn`/`Map` | — |
| `Notice` 及之后 | 主线程 | enum/string/int | `Verse` 对象 |
| HTTP 合成 | 后台 `Task` | `TtsRequestParams`、`string`、`byte[]` | `Verse`、`UnityEngine`、`Settings`、`Utterance`、`Segment` |
| `Drain` / `Put` / `Plan` / `Enqueue` / 播放 | 主线程 | 全部 | — |
| `AudioClip.Create` / `SetData` | **只能主线程** | — | 后台 |
| `Trace`（含 `5.3`） | 主线程 | — | 后台（不做线程安全） |

### 7.6 启动与关闭顺序

```text
1. Harmony.PatchAll()                          （VoiceDeputyMod 构造，装 8 个点）

     └ SaveFingerprint 判空补铸 → SpeechLibrary.SetSaveFingerprint(id)

```

## 8. 模块间调用顺序

### 8.1 每帧（`DeputyGameComponent.Update`，固定顺序）

| 序 | 调用 | 说明 |
|---|---|---|
| 1 | `SegmentSynthesizer.Drain()` | 拿本帧合成结果（含落库） |
| 2 | 每条 `CompletedJob`（`Playback` 非空）：`ClipAssembler.Plan(job.Playback, job.DeadTexts)` | 回路闭合，只走一次；预热作业（`Playback == null`）跳过组装 |
| 3 | `foreach (u in Announcer.Tick())` ⇒ `ClipAssembler.Plan(u, ∅)` | 新句（含聚合批出句、试听/朗读） |
| 4 | `Plan` 结果分派：`Ready` ⇒ `SpeechQueue.Enqueue`；`Missing` ⇒ `SegmentSynthesizer.RequestMissing` | 唯一分派点 |
| 5 | 本帧有 `Put` ⇒ `LibraryJanitor.CheckLimit()` | 库不认识上限（I3） |
| 6 | `VoicePlayer.Tick()` | 推进/取下一句 |
| 7 | 每 2 s：`WarmupScheduler.Tick()` | 旁路 1 |
| 8 | 每 `JanitorIntervalSeconds`：`LibraryJanitor.Tick()` | 旁路 3 |

### 8.2 事件驱动的调用链（钩子里，同步）

```text
Hook 体内：读 Verse 事实 → SpeechCatalog.For*(…) → new Notice → Announcer.Receive
Announcer.Receive：Switchboard.Enabled → 去重 → BatchAggregator.Add 或 SegmentPlanner.Plan → ready
```

**边界划分**：钩子体内只出现 `SpeechCatalog.For*`、`new Notice`、`Announcer.Receive`、`Trace.Step("1", …)` 四样；`ClipAssembler` / `SegmentSynthesizer` / `SpeechLibrary` / `SpeechQueue` 的调用点全部在 `DeputyGameComponent` 的每帧流程里（§8.1）。
