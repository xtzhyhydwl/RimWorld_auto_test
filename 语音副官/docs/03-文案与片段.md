# 03 · 文案与片段

> **这份文档管什么**：一句话怎么变成有序片段（片段法）、`Segment{Text,Kind}`、模板表 `PhraseEntry` 的全部条目与参数类型、`SegmentPlanner` 的三条入口与切分规则、名字清洗（全文唯一一处）、数字处理、聚合规则、整句缓存、预热。
> **谁该读**：写 `SpeechCatalog.Phrases` 与 `SegmentPlanner` 的人（照 §3 抄模板、照 §4 写切分）；写文案的人（只改 §3 的表格）。
> **与其它文档的边界**：类别与通道归属在 `02`；库的键/等级/淘汰在 `04`；`MaxNamedInBatch` 等设置项在 `05`；模板表属于"编译期数据"，不是设置项。
> **标注**：【实测】= 读代码或静态取证；【推测】= 由结构推出；【待验证】= 需进游戏（编号见 `06` §9）。

## 1. 片段法：一句话 = 有序片段列表

```text
Utterance = [ 片段, 片段, 片段, … ]
片段      = { Text, Kind }        Kind ∈ SegmentKind 的前 5 个取值（Const / Enum / PersonName / Number / RawText）
播放层    = 只消费"排好序的 clip 列表 + 片段间 GapMs"，不关心内容
```

**每个片段独立合成、独立缓存**，键 = 片段原文 + `VoiceFingerprint` + 作用域（`04` §2）。这是整套东西的承重结构：

| 性质 | 后果 |
|---|---|
| 名字片段的复用率极高（同一个人会被播报几十次） | 新名字只花一次合成 |
| 枚举片段（疾病名 / 袭击方式 / 天气 / 派系）是有限闭集 | 预热一次，之后永久命中 |
| 新句子的成本 = 只缺那几个没见过的片段 | 首次延迟 ≈ 最慢的那一个片段 |
| 整句缓存是叠加在上面的第二层（§6） | 同一句话第二次说是连贯音频、零延迟 |

**没有预录资产**：固定短语也全部走 TTS。因此"零延迟"完全依赖**片段缓存 + 预热**，预热是结构性必需（§7），不是优化项。

## 2. `Segment` / `SegmentKind`

| `SegmentKind` | 含义 | 谁产出 | 典型 `Text` | 等级（`04` §4.2） |
|---|---|---|---|---|
| `Const`（常量） | 模板里的字面量（有限闭集） | `SegmentPlanner` 切模板 | `侦测到袭击，` | L1（永不删） |
| `Enum`（枚举） | 原版 def 的 label（有限闭集） | `SegmentPlanner` 取 `Args` | `热浪`、`突袭` | L1（永不删） |
| `Number`（数字） | 数量 | `SegmentPlanner` 取 `Args` | `35`、`8` | L1（永不删） |
| `PersonName`（人名） | 殖民者 / 动物 / 派系 / 地名 | `SegmentPlanner` 取 `Args`/`Names` | `鼠条`、`海盗` | L2/L3（看名字在不在名单） |
| `RawText`（原句） | 原版自由文本（无界） | `SegmentPlanner` 取 `Args` | `被枪杀`、`这里已经被占用。` | L3（可删） |
| `Sentence`（整句） | **只作缓存键**，不出现在 `Segment.Kind` | `ClipAssembler` 用 `Utterance.FullText` | 一整句 | L3（可删） |

- `SegmentKind` 共 6 值；`Segment.Kind` 只用前 5 个，`Sentence` 只出现在 `LibraryKey.SegmentKind`。
- 停顿与语速在播放层，不进片段。
- `RawText` 承载兜底文案 / 落点原因 / 死因这类**无界**原版文本，因此落可删的 L3；`Const`/`Enum`/`Number` 是有限闭集，才能永不删。

## 3. 模板表 `PhraseEntry`

> **改一句话的语序 = 模板 + `ArgKinds` + 钩子 `args` 三处同时改**（三者按下标位置配对，错配不会报错）。

```text
PhraseEntry { SpeechPhrase Id, SpokenCategory Category, PhraseForm Form, string Template, SegmentKind[] ArgKinds }
PhraseForm  = SingleEvent(单事件) | Batch(聚合) | RawText(裸文本)
```

**占位符规则**：`{0}`、`{1}` 按 `ArgKinds` 的顺序取 `Args`（聚合形态的 `{0}` 取 `Count`、`{1}` 取 `Names` 连接）。字面量即 `SegmentKind.Const` 片段，占位符即 `ArgKinds` 指明的那个取值。

聚合模板固定两槽：`{0}` = `Count`、`{1}` = `Names` 连接，`ArgKinds = [Number, PersonName]`。`Names` 为空时 `{1}` 段整段不出现。

| `Phrase_DiseaseOutbreak_Batch` | `DiseaseOutbreak` | `疾病爆发，{0} 人感染。` | `[Number, PersonName]` |
| `Phrase_DiseaseSpread_Batch` | `DiseaseSpread` | `感染扩散，{0} 人。` | `[Number, PersonName]` |

### 3.3 裸文本模板（1 条）

| 模板键 | 类别 | 形态 | 模板正文 | `ArgKinds` | 用途 |
|---|---|---|---|---|---|
| `Phrase_RawText` | 无（`SpokenCategory` 不参与） | 裸文本 | 空（不切分） | `[RawText]` | 试听（固定文本「副官就位」）与手动朗读 |

- 裸文本不走模板：整段文本 = 一个 `RawText` 片段（**不入 L1**，避免任意输入污染永不删的键空间）。
- 裸文本句的 `Category` 取 `OtherMessage`（只为满足 `SpeechQueue` 取优先级，优先级 0）。

## 4. `SegmentPlanner`

### 4.1 三条入口（对外只有这三个方法）

| 入口 | 谁调 | 用哪条模板 | 特殊处理 |
|---|---|---|---|
| `Utterance Plan(Notice notice)` | `Announcer.Receive` | `notice.Phrase`（`PhraseForm.SingleEvent`） | `Args`/`Names`/`Count` 直接用 |
| `Utterance Plan(BatchSummary batch)` | `Announcer.Tick`（批出句） | `batch.Single != null` ⇒ `batch.Single.Phrase`（单事件）；否则 `SpeechCatalog.EntryOf(batch.Category).BatchPhrase`（聚合） | 单事件分支：用 `Single` 的 `Args`/`Names`/`Count`；聚合分支：`{0}=Count`、`{1}=Names 连接`，`Names` 截断（§4.4） |
| `Utterance PlanRaw(string text)` | `Announcer.SpeakDirect` | `Phrase_RawText` | 整段一个 `RawText` 片段，不做任何清洗/切分 |

三条入口在内部都归约成一个 `UtteranceSource{ Category, Phrase, Args, Names, Count, BatchKey }`（`01` §6.17），再由**一个**私有 `PlanCore` 切分——切分逻辑全文只有一处；`Settings.MaxNamedInBatch` 与 `Settings.NumericText` 由入口读出后作为参数传给 `PlanCore`。

### 4.2 切分规则（唯一规则，逐条可判定）

| 步 | 规则 |
|---|---|
| 1 | 取模板 `Template`，按 `{n}` 占位符切成"字面量 / 占位符"交替的段序列 |
| 2 | 每个**非空**字面量段 ⇒ `Segment{Text = 字面量原样, Kind = Const}`（字面量不改写、不清洗） |
| 3 | 每个占位符 `{i}` ⇒ `Segment{Text = 该槽的值, Kind = ArgKinds[i]}`；聚合形态的 `{0}` 取 `Count` 的十进制串、`{1}` 取 `Names` 的连接结果 |
| 4 | `Kind == PersonName` 的段先过名字清洗（§4.3） |
| 5 | `Kind == Number` 的段按数字规则处理（§4.4） |
| 6 | 清洗后 `Text` 为空的段整段丢弃（相邻字面量之间的空段不产生副作用） |
| 7 | `Args` 个数 ≠ `ArgKinds` 长度、或模板查不到 ⇒ 返回 `null`（不播半句） |

- `Utterance.FullText = string.Concat(Segments)` 是计算属性，不另存字段（唯一真源）。
- 模板字面量里该有的标点必须写在模板里（切分不补标点）。

### 4.3 名字清洗（**全文唯一一处**）

输入是 `Pawn.LabelShortCap` 原文或派系名；输出可能**一对**片段（名字 + 编号数字）。

| 步 | 处理 | 例 |
|---|---|---|
| 1 | 尾部编号后缀 `.数字` / `-数字` / `_数字` 拆出来：前缀 ⇒ `PersonName` 片段，数字 ⇒ `Number` 片段（**同一次清洗产出两个片段**） | `鼠条.18` ⇒ `鼠条` + `18` |
| 2 | 删除不能念的符号：`"` `'` `“` `”` `(` `)` `[` `]` `{` `}` `<` `>` `#` `@` `*` | `小畜生-25` ⇒ `小畜生` + `25` |
| 3 | `&` ⇒ `和`；`/` `\` `\|` ⇒ 空格 | `A&B` ⇒ `A和B` |
| 4 | 连续空白折成一个空格，首尾去空白 |  |
| 5 | 结果为空 ⇒ 丢弃该名字（若因此 `Names` 变空，模板只用 `Count` 槽） | `___` ⇒ 丢 |
| 6 | 清洗只作用于 `Kind == PersonName` 的段；`Const`/`Enum`/`Number`/`RawText` 一个字都不改 |  |

- 钩子交出的是 `LabelShortCap` **原文**，不清洗；清洗只在这里发生。改清洗规则 = 只改这套表（`SegmentPlanner` 里的一个纯函数）。

### 4.4 数字与点名截断

| 规则 | 内容 |
|---|---|
| 数字直送 | `Kind == Number` 的段默认**原样送 TTS**（`35` 由 TTS 念成"三十五"）【待验证：P5】 |
| 中文转换开关 | `Settings.NumericText`（默认关）：开 ⇒ `Number` 段经 `NumericText` 纯函数转中文再送 TTS；关 ⇒ 原样送 TTS。转换只在 `NumericText` 一处发生 |
| 点名上限 | `Names.Length > Settings.MaxNamedInBatch` ⇒ 只取前 `MaxNamedInBatch` 个进 `{1}`；`Count` **不变**（总数照样念） |
| 上限为 0 | 只报数、不点名（`{1}` 段整段不出现） |
| 连接符 | `Names` 之间用 `、`；末位不加"等"（"等 N 人"由模板决定是否要写） |

## 5. 聚合：一群人同时出事，不能一个一个念

### 5.1 什么时候聚合

| 项 | 规则 |
|---|---|
| 谁决定可聚合 | `CategoryEntry.BatchPhrase` 非空（`02` §5 的 5 类） |
| 合并键 | `(Category, BatchKey)`；`BatchKey` 由钩子给（`02` §4.5） |
| 时间边界 | **同 tick**：`GenTicks.TicksGame != BatchTick` ⇒ 立刻出句并开新批 |
| 输入形态 | 一条自带 `Count=N` 的 `Notice`，**或**同 tick 多条各带 1 人；两种都按并集处理：`Count` 取成员之和、`Names` 取并集 |
| 出句时机 | tick 末（`Announcer.Tick` 里 `Flush()`）；合并边界固定为"同 tick"，不进设置项 |
| 威胁抢先 | 不归聚合管：威胁类句子的优先级由 `SpeechQueue` 决定（`01` §5.4） |

### 5.2 单事件 vs 聚合（`Count` 合计是分岔口）

| 条件 | 输出 |
|---|---|
| `Names` 非空且 `Count` 与 `Names.Length` 都在上限内 | 点名：`{0} 人…：{1}。` |
| `Names.Length > MaxNamedInBatch` | 取前 N 个名字 + 总数（`{0}` 仍是总数） |
| `Names` 为空（疾病这类"天然没有名单"） | 只报数：模板只用 `{0}` 槽 |
| 批内 0 条 | 不出 `BatchSummary` |

- **群体事件不点名**：疾病爆发 / 扩散 / 腐烂不扫地图、不从 `lookTargets` 补名单，只报 `Count`。
- 一个名字都没有却要念 `{1}` 的情况不存在：`{1}` 段在 `Names` 为空时整段消失（§4.2 步 6）。\n- **批内 `Count` 合计 `== 1`** ⇒ `BatchSummary.Single` 指向那条 `Notice`，走该类的单事件模板（点名 + 原因齐全）；**合计 `> 1`** ⇒ 走上表的聚合规则。因此 `02` §3 的 22 条单事件模板都是可达路径。

### 5.3 四种典型形态

| 场景 | 批内内容 | 念出来 |
|---|---|---|
| 瘟疫（一次爆发 8 人） | 一条 `Notice{Count=8, Names=[]}` | `疾病爆发，瘟疫，8 人感染。` |
| 袭击中连死 3 人 | 三条 `Notice{Count=1, Names=[张三]}`… | `3 人阵亡：张三、李四、王五。` |
| 同 tick 两堆腐烂 | 两条 `Notice{Count=1, BatchKey="rotten"}` | 合计 2 ⇒ `有 2 件物品腐烂。` |
| 单人倒地（不可聚合类） | 一条 `Notice{Count=1, BatchKey=null}` | `鼠条倒地。`（单事件模板） |

## 6. 整句缓存

**唯一目的**：把已经拼好的一整句存下来，下次播同一句直接取连贯音频，省掉重新拼接与片段拼缝。

| 项 | 规则 |
|---|---|
| 键 | `SpeechLibrary.Key(utterance.FullText, SegmentKind.Sentence)`；与片段**共用同一张索引、同一套淘汰** |
| 命中判定 | `ClipAssembler.Plan` 第 1 步：整句键命中 ⇒ 单 clip 播放、`FromSentenceCache = true`，**不再看片段** |
| 未命中 | 走片段路径（缺片段就合成片段），本次不合成整句 |
| 合成时机 | **播完之后**：`VoicePlayer` 整句播完 ⇒ `WarmupScheduler.EnqueueSentence(u)` ⇒ 空闲合成整句 ⇒ 落库 |
| 去重 | 入队前先 `SpeechLibrary.Contains(Sentence 键)`，命中就不排 |
| 作用域 | 整句是 `save:<SaveFingerprint>`（随存档），换存档自然不命中 |
| 可删性 | `Sentence` 恒 L3（`04` §4.2），删掉只影响听感（下一次退回片段拼接），不影响功能 |

- 整句缓存是**可选加速层**：删掉它功能完全不变，只是同一句话第二次听会有拼缝。
- 一条整句多花一次 TTS 调用（按 UTF-8 字节计费，一句话 ~40 字节），只在空闲队列里发生，不阻塞播放。

## 7. 预热（没有预录资产时它是结构性必需）

### 7.1 三个触发源

| 源 | 内容 | 谁给 |
|---|---|---|
| 启动第一批 | `SpeechCatalog.ConstantTexts()`：从模板表切出来的全部字面量（`Const` 片段） | `WarmupScheduler.Tick` 首次调用时自己取 |
| 名单变化 | `RosterDelta.NewNames`：新入队的殖民者 / 动物名、当前派系名 | `LibraryJanitor.Tick` 第 ④ 步 |
| 播完的整句 | `VoicePlayer` 播完一句 ⇒ 整句键进整句队列 | `VoicePlayer` |

- `ConstantTexts()` 是**派生**的（切模板），不另维护词表：改了模板，预热清单自动跟着变——这是"改一处"的硬要求。

### 7.2 顺序与节流

| 项 | 规则 |
|---|---|
| 队列 | 两个 FIFO：片段队列、整句队列 |
| 顺序 | 每 2 s 一次 `Tick`：**先片段队列、后整句队列**；片段队列内部按入队先后（启动批在最前） |
| 节流 | `Settings.WarmupJobsPerMinute`（默认 `100000`）⇒ 实际不节流；调小即生效，**不需要改代码** |
| 查库 | 每个作业出队前先 `SpeechLibrary.Contains(key)`，命中直接丢弃不排 |
| 队列上限 | 常量 `WarmupQueueLimit = 500`，超出丢最旧 |
| 失败 | 作业失败 ⇒ 丢弃、不重排（下一轮名单变化或下次播报会再触发） |

### 7.3 已知延后（明写，不藏）

| 延后 | 代价 |
|---|---|
| 新入队殖民者的名字最坏要等一个清理周期（默认 300 s）才进预热 | 该名字第一次被念时要现合成一次（约 0.6 s/片段） |
| 派系名只在新派系出现后的下一轮清理才进名单 | 同上 |
| 常量片段第一批在进游戏后 2 s 才开始排 | 开局第一条播报可能仍要现合成 |
