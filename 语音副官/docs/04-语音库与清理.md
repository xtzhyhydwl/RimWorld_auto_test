# 04 · 语音库与清理

> **这份文档管什么**：音频库 `SpeechLibrary` 的键、两个键空间、索引、磁盘列表、占用报告（**不判上限、不做删除**）；清理者 `LibraryJanitor` 的等级判定、两阶段名单、超限淘汰、孤儿对账、索引落盘（**唯一删除者**）；存储只落磁盘的读写路径、容量与上限的可调项、故障自愈。
> **谁该读**：写 `SpeechLibrary` / `LibraryJanitor` 的人；写 `ClipAssembler` 的人（读路径在这里）；调容量的人（§6）。
> **与其它文档的边界**：模块六栏契约在 `01` §5.4（音频链）；片段与原句的定义在 `03` §2；设置项与控件在 `05` §5；"播不播"的判断在 `Announcer`。
> **标注**：【实测】= 读代码或静态取证；【推测】= 由结构/量级推出；【待验证】= 需进游戏（编号见 `06` §9）。

---

## 1. 磁盘布局（唯一物理位置）

```text
<mod 根>/Cache/Voice/
    <value>.wav      一个键一个文件；value = sha1(VoiceFingerprint + "|" + Scope + "|" + Text)
    index.json       索引：value → { text, segmentKind, lastUsedTick, bytes }
```

| 事实 | 内容 |
|---|---|
| 只有一个目录 | 存档作用域只体现在**键**上，不体现在目录上：同一个殖民地存 10 次档 = 同一 `SaveFingerprint` = 一份缓存 |
| 目录里没有子目录 | 所有键平铺；`save:` / `global` 只影响 `value` 的哈希输入 |
| 索引是唯一的"库内清单" | 没有索引就当作空库；磁盘上的 `.wav` 由对账收敛（§4.5） |
| 音频不外存第二份 | 内存里没有 `AudioClip` 池、没有 PCM 常驻（`01` 的 I6） |

## 2. `SpeechLibrary`

### 2.1 键：`LibraryKey{VoiceFingerprint, Scope, Text, SegmentKind}`

| 成员 | 值从哪来 | 是否落盘 | 作用 |
|---|---|---|---|
| `VoiceFingerprint` | `sha1(Settings.BaseUrl + "\|" + Model + "\|" + Voice)`，**全 mod 唯一派生点**在本类 | 否（每次现算） | 换音色/模型/端点 ⇒ 旧键自然查不到，不会播成上一个音色 |
| `Scope` | 计算属性：`SegmentKind ∈ {PersonName, Sentence} ? "save:" + SaveFingerprint : "global"` | 否 | 换存档 ⇒ 名字与整句自然不命中，不会念上一个存档的人 |
| `Text` | `SegmentPlanner` 给的片段原文 / `Utterance.FullText` | 是（`index.json`） | 命中判定的主体；改文案 = 换 `Text` = 自动换键 |
| `SegmentKind` | `SegmentPlanner` / `ClipAssembler` | 是（`index.json`） | 决定 `Scope` 与等级（§4.2） |
| `Value` | `sha1(VoiceFingerprint + "\|" + Scope + "\|" + Text)` | 是 | 落盘文件名与索引主键 |

- `Key` 是**唯一的键构造点**：别的模块只把 `(text, kind)` 交进来，不自己拼哈希。
- `SaveFingerprint` 由 `DeputyGameComponent` 通过 `SetSaveFingerprint` 注入，**不进键的构造现场**（构造现场只读本类字段）。

### 2.2 两个键空间、一张索引

| 键空间 | `SegmentKind` | 谁写 | 谁读 | 典型量 |
|---|---|---|---|---|
| 片段 | `Const` / `Enum` / `PersonName` / `Number` / `RawText` | `SegmentSynthesizer.Drain` 落库 | `ClipAssembler.Plan` 逐片段查 | 数百到数千 |
| 整句 | `Sentence` | 同上（预热作业） | `ClipAssembler.Plan` 第 1 步 | 与播报过的句子数同阶 |

- **同一张索引、同一套淘汰、同一个 `LastUsedTick` 字段**：`Sentence` 与片段共用一个库。
- 条目里**只存事实**（`Value` / `Text` / `SegmentKind` / `LastUsedTick` / `Bytes`），**不存等级**——等级每轮由 `LibraryJanitor` 现算。

### 2.3 索引的读写

| 动作 | 谁做 | 时机 |
|---|---|---|
| 加载 | `SpeechLibrary` 静态构造 | 首次访问前；失败/缺失 ⇒ 空索引 |
| 新增条目 | `Put` 成功后写内存索引 | `Drain` 时 |
| 刷 `LastUsedTick` | `TryRead` 命中时 | `Plan` 时（`Contains` **不刷**，避免预热把 L3 续命） |
| 落盘 | `SaveIndex()`，调用方是 `LibraryJanitor` | 清理每轮第 ④ 步 |

### 2.4 `ListFiles()`

返回 `DiskFile[]`（`Value` + `Bytes`），由 `SpeechLibrary` 在主线程读目录得到，交给 `LibraryJanitor` 做对账。

- 只读、不删、不修；读目录失败 ⇒ 返回空数组（对账那一步本轮跳过）。
- 唯一消费方是 `LibraryJanitor`（对账用）；其它模块只读 `Snapshot()` / `Usage`（I2 的单点磁盘访问由此保持）。

### 2.5 占用报告 `LibraryUsage`

| 出口 | 内容 | 谁读 |
|---|---|---|
| `Usage` | `{ Entries, Bytes }` + `Describe()`（形如 `1,234 条 / 12.3 MB`） | UI 调试页（每帧只读） |
| `Put` 的返回值 | 写成功后的最新 `LibraryUsage` | `DeputyGameComponent`（据此决定是否调 `CheckLimit`） |

### 2.6 职责分工（本类只做"按 key 存取 + 报告占用"）

| 事 | 归谁 |
|---|---|
| 判上限 | `LibraryJanitor.CheckLimit`（`LibraryLimit` 只在这里读） |
| 删条目 / 删文件 | `LibraryJanitor` |
| 修索引与磁盘的不一致 | `LibraryJanitor` 的对账步（§4.1 ①） |
| 判"这条值不值得缓存" | 键本身（有 `Text` 就能缓存） |
| 播不播 | `Announcer` + `Switchboard` |
| 合成、解码、建 `AudioClip` | `SegmentSynthesizer` / `ClipAssembler` |

### 2.7 接口一览（全部只在主线程）

| 接口 | 线程 | 谁调 | 刷 `LastUsedTick` | 副作用 |
|---|---|---|---|---|
| `Key(text, kind)` | 主线程 | `ClipAssembler` / `SegmentSynthesizer` / `WarmupScheduler` | — | 无（纯计算） |
| `TryRead(key, out bytes)` | 主线程 | `ClipAssembler` | 命中时刷 | 读文件；文件缺失 ⇒ `false` |
| `Contains(key)` | 主线程 | `WarmupScheduler` | **不刷** | 无（只查索引） |
| `Put(key, bytes)` | 主线程 | `SegmentSynthesizer.Drain` | 新条目写当前 tick | 写文件 + 写索引；返回 `LibraryUsage` |
| `Snapshot()` | 主线程 | `LibraryJanitor` | 不刷 | 返回 `LibraryEntry[]` 副本（只读） |
| `ListFiles()` | 主线程 | `LibraryJanitor` | 不刷 | 读目录 |
| `RemoveEntry` / `RemoveFile` | 主线程 | `LibraryJanitor` | — | 删索引 / 删文件 |
| `SaveIndex()` | 主线程 | `LibraryJanitor` | — | 写 `index.json` |
| `SetSaveFingerprint(id)` | 主线程 | `DeputyGameComponent` | — | 改 `SaveFingerprint`（下次 `Key` 生效） |
| `ValueOf(LibraryKey)` | 主线程 | `LibraryJanitor` | — | 返回 `Value`（坏文件名单只存 `LibraryKey`，删除时换成落盘名） |
| `Usage` | 主线程 | UI / `LibraryJanitor` | — | 无 |

## 3. 存储只落磁盘，播放时按需读

### 3.1 读路径（`ClipAssembler.Plan` 内部，主线程）

| 步 | 动作 | 代价 |
|---|---|---|
| 1 | `TryRead(Key(FullText, SegmentKind.Sentence))` | 一次文件读（整句 WAV 约 100–200 KB）+ 命中刷新 `LastUsedTick` |
| 2 | 逐片段 `TryRead(Key(text, kind))` | 每片段一次文件读 |
| 3 | `WavReader` → `PcmData` | 解析头部、重算长度（不信 header） |
| 4 | `LoudnessNormalizer` 峰值归一到 −3 dBFS | 一次线性扫描，不缓存 |
| 5 | `AudioClip.Create` + `SetData` | **只能主线程** |

- 刚合成好的片段也是**先落盘再读回**，不做"这次直接用内存那份字节"的捷径——音频只有一条来路（库），这样"库里有 = 能播"永远成立。
- 量级：2 s WAV ≈ 96 KB【实测：24 kHz / 16 bit / 单声道】；读 + 解析 + 建 clip 在毫秒级【推测】，相对 0.6 s 合成可忽略。

### 3.2 写路径

| 步 | 动作 | 失败后果 |
|---|---|---|
| 1 | 目录不存在 ⇒ 建 `Cache/Voice` | 建不出 ⇒ `Put` 返回旧占用，该片段算失败 |
| 2 | `File.WriteAllBytes("<value>.wav", bytes)` | 写失败 ⇒ 不入索引，该片段算失败 |
| 3 | 写内存索引（含 `Bytes = bytes.Length`、`LastUsedTick = GenTicks.TicksGame`） | — |
| 4 | 返回新的 `LibraryUsage` | — |

- 写盘发生在 `SegmentSynthesizer.Drain` 内（主线程），因此"写完即可读"不需要额外同步。

## 4. `LibraryJanitor`（唯一删除者）

### 4.1 每轮四步（固定顺序，`Tick()`；①②③④ 的删除动作全部汇到 `SpeechLibrary.RemoveEntry` / `RemoveFile`）

| 步 | 做什么 | 用到的输入 | 失败时 |
|---|---|---|---|
| ① 对账 + 坏文件 | 磁盘有、索引无 ⇒ `RemoveFile`（孤儿）；索引有、磁盘无 ⇒ `RemoveEntry`（失效条目）；**再删"坏文件待删名单"里的每条**（`ReportBroken(LibraryKey)` 登记的，按 `SpeechLibrary.ValueOf(key)` 取 `value` 后 `RemoveEntry` + `RemoveFile`，清空名单） | `Snapshot()` + `ListFiles()` + 待删名单 | 本轮跳过对账，其余三步照做；坏文件删不掉 ⇒ 留在名单里等下一轮 |
| ② 两阶段名单 | 删"上一轮消失的名字"相关条目；再扫本轮名单，把本轮消失的记进名单（**下一轮才删**） | `Map.mapPawns` + `Find.FactionManager` + `Snapshot()` | 本轮整体跳过、**保留上轮名单** |
| ③ 超限 | 判据与 `CheckLimit()` 是**同一个函数**：`Usage.Entries > LibraryLimit` ⇒ 按 §4.4 淘汰 | `Usage` + `Settings.LibraryLimit` | 删文件失败 ⇒ 留待下轮 |
| ④ 落索引 + 交名单 | `SaveIndex()`；`RosterDelta{NewNames}` → `WarmupScheduler` | 内存索引 | 落盘失败 ⇒ 记日志，下轮再试 |

### 4.2 等级判定表（唯一判定处，由 `SegmentKind` 与 `Scope` 推）

| `SegmentKind` | `Scope` | 附加条件 | 等级 | 删不删 |
|---|---|---|---|---|
| `Const` / `Enum` / `Number` | `global` | 恒 | **L1** | **永不删**；条目数超 `L1SoftLimit`（500）只 `Trace` 告警 |
| `RawText` | `global` | 恒 | **L3** | 可删（原版自由文本无界） |
| `PersonName` | `save:<id>` | 文本 ∈ 当前存活名单（玩家派系殖民者 + 驯服动物 + 所有派系名） | **L2** | 名字消失后降 L3（两阶段删） |
| `PersonName` | `save:<id>` | 不在名单（死人的、临时名、旧存档的） | **L3** | 可删 |
| `Sentence` | `save:<id>` | 恒 | **L3** | 可删 |

- 等级**不进条目**：每轮现算，改规则只改这张表。
- 名单的"存活"口径只有一处：`LibraryJanitor` 的名单扫描函数；`WarmupScheduler` 只消费 `RosterDelta.NewNames`，不自己扫。

### 4.3 两阶段名单清理

| 项 | 规则 |
|---|---|
| 为什么两阶段 | 死亡那一刻不删，隔一个清理周期再删：不与正在播的句子抢文件，也不会刚删就要用 |
| 上一轮消失名单怎么用 | 对 `PersonName` 片段：删 `Text == 名字` 的条目；对 `Sentence`：删 `Text` **包含**该名字的条目（子串匹配，中文误伤接受） |
| 新名字 | `RosterDelta.NewNames = 本轮名单 − 上轮名单` ⇒ 交给 `WarmupScheduler` 预热 |
| 名单来源 | `Map.mapPawns`（殖民者 + 玩家派系驯服动物）+ `Find.FactionManager.AllFactions` 的 `Name` |
| 换存档 | 旧存档的条目 `Scope` 不同，本轮名单里天然没有 ⇒ 上一轮全部进"消失名单" ⇒ 下一轮降 L3 被淘汰；清理动作仍由本表的周期驱动 |

### 4.4 超限淘汰

| 项 | 规则 |
|---|---|
| 判据 | `Usage.Entries > LibraryLimit`（条数；字节只报告不设限，因为采样率固定、条数与字节近线性） |
| 排序键 | `(等级降序, LastUsedTick 升序)`：先最旧的 L3，再 L2 |
| L1 保护 | 淘汰永远不取 L1；L3 + L2 清空后仍超限 ⇒ **停止淘汰**并 `Trace` 告警一次（宁可超限，不删骨架） |
| 触发点 | 每次 `Put` 之后 `CheckLimit()`；每轮 `Tick` 第 ③ 步。两处跑同一个函数 |
| 调阈值 | 只改 `Settings.LibraryLimit`（`05` §5），不改代码 |

### 4.5 孤儿对账

| 情形 | 处理 | 代价 |
|---|---|---|
| 磁盘 `.wav` 在、索引没有 | `RemoveFile(value)` | 若它本可用 ⇒ 重新合成一次 |
| 索引有条目、磁盘没文件 | `RemoveEntry(value)` | 无（下次播报重新合成） |
| `index.json` 整体丢失/损坏 | 从空索引开始 ⇒ 全部文件成孤儿 ⇒ 下一轮全部删掉 | 缓存清零，功能不变 |
| 文件被外部删掉一半 | 逐条按上面两行收敛 | 同上 |

### 4.6 删除边界（谁能动库）

| 想做什么 | 谁能调 | 接口 |
|---|---|---|
| 删一个键 | `LibraryJanitor` | `RemoveEntry(value)` + `RemoveFile(value)` |
| 全清（UI「清缓存」） | `LibraryJanitor` | `ClearAll()`：删目录内全部 `.wav` + 清内存索引 + `SaveIndex()` |
| 报告坏文件 | `ClipAssembler` 只**登记** | `ReportBroken(LibraryKey)`（不删，进待删名单，① 里删） |
| 写索引 | `LibraryJanitor` | `SaveIndex()` |
| 其它模块 | 只读 | `TryRead` / `Contains` / `Usage` / `Snapshot` |

- `ClearAll()` 不动 `Settings`（音量、开关、上限都保留），也不动 `VoiceFingerprint`。

## 5. 容量与上限的可调项

| 项 | 类型 | 默认 | 范围 | 唯一读者 | 效果 |
|---|---|---|---|---|---|
| `LibraryLimit` | `int`（设置项） | 3000 | 0–20000 | `LibraryJanitor` | 条数上限；超限按 §4.4 淘汰 |
| `JanitorIntervalSeconds` | `int`（设置项） | 300 | 30–3600 | `DeputyGameComponent`（计时） | 清理周期；也决定名字清理与超限处理的最大延迟 |
| `WarmupJobsPerMinute` | `int`（设置项） | 100000 | 1–1000000 | `WarmupScheduler` | 预热节流；默认值等于"不节流" |
| `L1SoftLimit` | `const int` | 500 | —（常量） | `LibraryJanitor` | L1 条目超此数只告警，不删 |
| `WarmupQueueLimit` | `const int` | 500 | —（常量） | `WarmupScheduler` | 预热队列上限，超出丢最旧 |
| 占用报告 | 只读 | — | — | UI | `Entries` + `Bytes`，不设字节上限 |

- 字节上限不做：采样率固定 24 kHz / 16 bit / 单声道 ⇒ 每条约 96 KB/2 s，条数上限已经等价于容量上限。
- 上限为 0 的语义：`LibraryLimit = 0` ⇒ 每次 `Put` 后立刻淘汰到 0 条（只剩 L1 受保护），等价于"只保留骨架"，用于排查。

## 6. 故障自愈矩阵

| 故障 | 检测者 | 表现 | 处理 | 用户可见后果 |
|---|---|---|---|---|
| `index.json` 缺失 / 损坏 | `SpeechLibrary` 加载 | 空索引 | 下一轮对账把孤儿全删 | 缓存清零，重新合成 |
| 索引有、文件没了 | `ClipAssembler.TryRead` | 未命中 | 该片段进 `Missing` ⇒ 合成 | 该句晚 0.6 s 出声 |
| WAV 解不开（头坏、截断） | `WavReader` 返回 `null` | 该片段算坏 | 进 `Missing` + `ReportBroken(value)` | 下一轮被清理器删掉 |
| 写盘失败（磁盘满 / 权限） | `Put` | 条目不入索引 | 该片段算 `Failed` ⇒ 进 `DeadTexts` | 该句少一个片段或整句丢弃（`Trace 5.3`） |
| 删文件失败（被占用） | `RemoveFile` | 条目仍在 | 留待下轮 | 占用暂时降不下来 |
| 索引与磁盘不一致 | `LibraryJanitor` 每轮 | — | 按 §4.5 收敛 | 无 |
| 目录不存在 | `Put` | — | 建目录再写 | 首次播报无额外延迟 |

## 7. 改动落点

| 需求 | 改哪一处 | 不参与改动的模块 |
|---|---|---|
| 换键的组成（例如加采样率） | `SpeechLibrary.Key` 一处 + `LibraryKey` 字段一处 | 各调用方（它们只交 `text`/`kind`） |
| 调等级规则 | `LibraryJanitor` 的等级判定表（§4.2）一处 | 条目结构（不存等级） |
| 调淘汰顺序 | `LibraryJanitor` 的排序函数一处 | `SpeechLibrary` |
| 调清理周期 | `Settings.JanitorIntervalSeconds` | 代码 |
| 加一个可调容量项 | `05` 字段总表一行 + `SetDefaults` 一行 + 读者模块一行 | 其它 |
| 换缓存目录 | `SpeechLibrary.FolderName` 常量一处 | 各调用方与 UI 文案（UI 读同一个常量） |
