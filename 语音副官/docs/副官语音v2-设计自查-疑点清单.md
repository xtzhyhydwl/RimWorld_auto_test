# 副官语音 v2 · 设计自查：疑点清单

> 用户明确说："让 AI 自己 review 自己写的东西，反馈是一切正常，但实际上不正常。"
> 所以这份清单**只列我怀疑有问题的地方**，不列"一切正常"。
> 按"猜错要付多少代价"排序。2026-10-17。

## P0 · 现在就看得出来是漏洞

### D1 内存 vs 磁盘，文档只写了一层

`SpeechLibrary` 上限 3000 条，但**没区分内存里的 `AudioClip` 和磁盘上的文件**。

- `AudioClip` 是**未压缩 PCM**：24 kHz / 16 bit / 单声道 = 48 KB/s
- 3000 条 × 平均 2 秒 ≈ **288 MB 常驻内存**（还没算 Unity 的额外开销）

**影响**：装了这个 mod，游戏内存直接涨几百兆，且旧 mod 同样的坑（启动时同步解码 275 个 WAV）。
**建议**：内存只保留最近 N 条（如 200 条 ≈ 20 MB），其余按需从磁盘读。磁盘上限 3000 条可以不变。
**这是设计文档里最实的一个漏洞。**

### D2 `Messages.Message` 的噪声率完全未知

取证确认：801 个调用点、441 个类型，我们是**唯一总闸**。开发期 22 类全开 ⇒ 兜底类（`OtherMessage`）
会把所有杂音都念出来。

**影响**：第一次进游戏可能被刷屏，且你分不清"是 bug 还是设计"。
**建议**：加一个**观察模式**（只记日志、不发声），先用它统计一局游戏里各类各有多少条，再决定默认值。

### D3 聚合窗口与"威胁插队"的交互没定义

现在的规则：威胁事件 → flush 当前 batch → 优先播威胁。
但 flush 出来的 batch 可能只有 **1 个人**，于是会播「瘟疫爆发，1 人感染」——很怪。

**建议**：flush 时若 `batch.Count < maxNamedInBatch` 且是"数量型"事件，**合并进威胁句或直接丢弃**。

## P1 · 会在实现时被迫做决定

### D4 拼缝的量化没人算过

「侦测到袭击，机械族，从东边来」= 4 个片段。全未缓存时并行合成 ≈ 0.6 s（实测单次），
但片段之间 120 ms 停顿 × 3 = **360 ms**。听感可能比"小问题"更明显。

**建议**：步骤 4 一能出声，先合成这一句给你听，别等到最后。

### D5 预热 = 持续花钱，文档没提成本

每预合成一条片段就是一次 API 计费。前期几十个名字 = 几十次请求。
"游戏前期事件少，正好慢慢预热"——但没人给过预算或节流上限。

**建议**：设置里给"预热上限（条/分钟）"，默认保守（如 20）。

### D6 `NotifyPlayerOfKilled` 作为钩子的语义没验

取证说 `Pawn.Kill → Pawn_HealthTracker.NotifyPlayerOfKilled`，我们就打算挂它。
但它是"**通知玩家**"的方法——可能被多处调用、也可能在某些死亡路径上不调用。
真正稳的也许还是 `Thing.Kill` + 过滤 `is Pawn`。

**建议**：步骤 3 埋点时打日志，用两种方式对照，别只信一种。

### D7 存档 GUID 的生成时机没覆盖所有开局方式

计划在 `LoadedGame()` / `StartedNewGame()` 补铸。
但"场景开局"、"跟随者开局"、"开发者快速测试开局"是否都走 `StartedNewGame()` —— **未确认**。
漏掉的话那个存档永远没有 GUID，缓存作用域退化成空。

**建议**：`ExposeData` 里发现 id 为空时**当场铸一个并 Scribe**（幂等），不要只依赖那两个时机点。

### D8 L1 永久缓存 vs 文案会改

L1 是"永不删除的骨架片段"。但文案一定会改（"侦测到"改成"发现"）：改完之后**旧片段仍然永久命中**，
玩家会一直听到旧文案，而且清理器**没权删 L1**。

**建议**：L1 的键也要带上"文案版本号"，改文案时版本 +1，旧 L1 自动失效。

## P2 · 只是不放心

### D9 `SpeechCatalog` 的 22 类 vs 取证出的 131 个 IncidentDef

一次 `TryExecute` 钩子能拿到 131 个事件，但界面只有 22 个开关。分类映射表（defName → 22 类）
**还没写**，也没人验证过"其余 109 个落进 `OtherIncident` 会不会很吵"。见 D2。

### D10 中文 TTS 念数字/带点号的名字

旧缓存里有 `鼠条.18`、`小畜生-25` 这类名字。送进 TTS 前清洗规则没定（点号会被念成"点"吗？）。

## 怎么用这份清单

- P0 的三条（D1/D2/D3）**建议在写缓存和聚合之前改设计**，改文档成本远低于改代码。
- P1 的四条可以在实现到那一步时再定，但要知道它们存在。
- 想快速验证 D2，用"观察模式"跑一局最省事——它本身就是个有用的功能。
