## §3 对设计的三条结论

**1）天然只有一个来源，不用做任何去重（10 类）**
`DiseaseOutbreak`（只 `letter`）、`Quests`（只 `letter`，多发射点同一闸）、`TraderArrival`（只 `letter`）、`Rotten`（只 `message`）、`BuildPlaceFailed`（只 `message`，`SilentInput`/`RejectInput` 两个 def 都是同一条通道）——这 5 类是**原版已有文字**的单通道类。
`PawnDowned`、`DiseaseSpread`、`Addiction`、`BuildMissingMaterials`、`BillSuspended`——这 5 类**原版零文字**，只能自算，天然没有第二来源。

**2）确实有两个以上来源，必须选一个并关掉另一个（9 类，附 def 名做白名单过滤）**
- `ThreatRaid`/`ThreatSiege`：留 `incident`（或 `LetterDef=ThreatBig`）；把 **`Message` 通道里的 `ThreatBig` 报文丢掉**（`MessageRaidersBeginningAssault`、`MessageSiegersAssaulting`、`MessageRaidersLeaving`、`MessageSleepingPawnsWokenUp`），并注意 `PawnRelationUtility.Notify_PawnsSeenByPlayer_Letter` 会额外再发一封关系信。
- `ThreatAnimalInsanity`：留 `incident`；把 `Message=ThreatSmall` 的 `MessageAnimalInsanityPulse` 丢掉（或反过来——它只覆盖建筑脉冲那条冷门路径）。
- `PawnDied`：不要二选一，**改挂 `Pawn_HealthTracker.NotifyPlayerOfKilled` 这一个方法**（`LetterDef=Death` 的信与 `MessageTypeDef=PawnDeath` 的消息都从这里出，两支互斥，挂一处即全覆盖）。
- `MentalBreak`：留 `letter`（`MentalStateDef.beginLetterDef` + `MentalBreakWorker.TrySendLetter` 的 `NegativeEvent`）；丢掉 `MessageTypeDef=ThreatSmall` 的 `MessageCaravanMemberHasExtremeMentalBreak`（只影响远行队，可单独映射到"远行队"分类而不算精神崩溃）。
- `Birth`：留 `letter`（`LetterDef=NeutralEvent` 的 `LetterColonistPregnancyLabor` + `LetterDef=BabyBirth`）；`MessageTypeDef=PositiveEvent` 的 `MessageGaveBirth` 改判给"动物生产"或不播。
- `Visitors`：留 `letter`；`MessageTypeDef=NeutralEvent` 的 `SingleTravelerPassing`/`GroupTravelersPassing`（`IncidentWorker_TravelerGroup`）要么并入"访客"、要么按 def 白名单排除，**别两边都播**。
- `WeatherExtreme`/`EnvHazard`：留**开始**那封信（`incident`，`LetterDef=ThreatSmall`/`NegativeEvent`）；把结束时刻的 `MessageTypeDef=NeutralEvent`（`GameConditionDef.endMessage`，如 "The solar flare is ending."）改判成"解除"子类，否则同一件事会播两次。

**3）原版根本不发通知，只能自算或不做（5 类）**
`PawnDowned`（`Pawn.Notify_Downed` 无文字）、`DiseaseSpread`（`ImmunityHandler`/`HediffComp_Immunizable` 无文字）、`Addiction`（`Hediff_Addiction`/`Hediff_ChemicalDependency` 无文字）、`BuildMissingMaterials`（只有灰条/造价读数）、`BillSuspended`（只有 ITab "Suspended" 与 Alert）。
⇒ 这 5 类的"来源通道"只能是 `自算`；其中 `BuildMissingMaterials` 已有原版同款算法可复用（`CostListCalculator.CostListAdjusted` + `map.resourceCounter.GetCount`），其余 4 类要自己定阈值并防抖。
