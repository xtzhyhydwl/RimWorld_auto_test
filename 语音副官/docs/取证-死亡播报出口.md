# 取证 · RimWorld 1.6 死亡播报的出口（角落消息 / 信件）

> 对象：`D:\SteamLibrary\steamapps\common\RimWorld\RimWorldWin64_Data\Managed\Assembly-CSharp.dll`（**1.6.9676.17735**）+ `D:\SteamLibrary\steamapps\common\RimWorld\Data\**` 的 XML。
> 手段：仓库现成只读工具 `tools/asmdump/{AsmDump,IlDump,RefDump}.exe`。**未写脚本、未改任何现有文件、未启动游戏。**
> 标注：**实测** = 本机 IL / 元数据 / XML 直接读到；**推测** = 由 IL 推出、无运行时观察；**未确证** = 没查到。

## 1. 结论速览

1. ✔ **实测**：**会**。玩家派系 pawn（殖民者、驯服的宠物/动物、机械体）**在地图上死亡 → 发 1 封 `LetterDef`=`Death` 的信**（`letterClass` = `Verse.DeathLetter`），发出点是 `Verse.Pawn_HealthTracker.NotifyPlayerOfKilled`；同一条路径**不发角落消息**。
2. ✔ **实测**：**会**。同一个方法里还有 2 处 `Messages.Message(..., MessageTypeDefOf.PawnDeath, historical:true)` —— ①死亡发生在**远行队**（`caravan != null`，文案 `MessageCaravanDeathCorpseAddedToInventory`）；②死者**不是玩家派系但宿主派系是玩家**（囚犯 / 访客 / 被借出的殖民者，文案用 `GetDiedLetterText` 的结果）。
3. ✔ **实测**：`Verse.Pawn.Kill` 方法体里 `Messages::`/`LetterStack::` **出现 0 次**，唯一与 UI 有关的调用是 `IL_06F2 callvirt Verse.Pawn_HealthTracker::NotifyPlayerOfKilled`，且被一个布尔门控（见 2.2）挡住。
4. ✔ **实测（否定）**：**袭击/战斗没有"战斗报告信"**。`Verse.Battle` 只有 `Add/Concern/…`，无 `ReceiveLetter`；战斗记录进 `BattleLog`（屏幕右侧按钮），而 `DeathLetter.OpenLetter` 只是**读** BattleLog 里该 pawn 的最后 5 条事件拼进信正文（"Read more" 按钮）。
5. ✔ **实测（否定）**：**敌方（非玩家派系、非玩家宿主）死亡一个提示都不发** —— `RimWorld.PawnUtility.ShouldSendNotificationAbout` 先返回 false，`NotifyPlayerOfKilled` 根本不被调用。也**没有**"殖民者死亡"专用 Alert（`Pawn.Kill`/`NotifyPlayerOfKilled` 里没有 Alert 调用）。

## 2. 逐条证据

### 2.1 方法签名（**实测**，`AsmDump.exe ... "=Verse.Pawn_HealthTracker" "NotifyPlayerOfKilled" np`）

```csharp
public void Verse.Pawn_HealthTracker::NotifyPlayerOfKilled(Nullable<DamageInfo> dinfo, Hediff hediff, RimWorld.Planet.Caravan caravan)
public static TaggedString Verse.HealthUtility::GetDiedLetterText(Pawn pawn, Nullable<DamageInfo> dinfo, Hediff hediff)  // mod 可复用
```

### 2.2 门控：谁才算"要通知的死亡"（**实测**，`IlDump.exe ... "Verse.Pawn" "Kill"` 的 IL_0157–0192）

```
IL_0158 call RimWorld.PawnUtility::ShouldSendNotificationAbout   ; 为 false → 结果 0
IL_015F/0161/0163  ShouldBeSlaughtered || LordJob_Ritual.pawnsDeathIgnored
IL_0184 beq DamageDefOf::ExecutionCut                            ; 该组合 + ExecutionCut → 结果 0
IL_0186..018F  flag = !pawn.ForceNoDeathNotification
IL_06E6 brfalse IL_06F7 ; flag 为真才 callvirt NotifyPlayerOfKilled(IL_06F2)
```
即：**发不发 = `ShouldSendNotificationAbout && !ForceNoDeathNotification && !(屠宰或仪式忽略 且 伤害为 ExecutionCut)`**。
`RimWorld.PawnUtility.ShouldSendNotificationAbout`（IL 全读）要求：游戏状态=Playing、非生成中、非"世界 pawn（除非在玩家远行队/运输舱/任务借出）"、非 subhuman、非 UnnaturalCorpse、且 `Faction==OfPlayer || HostFaction==OfPlayer`，再排除"已释放的客人未倒地未卧床 / 正离图"。
`forceNoDeathNotification`（public 字段，getter private）全程序集只有 9 处读写（`IlDump --usages forceNoDeathNotification Verse.Pawn`）：写者仅 `JobDriver_DisassembleMech`、`Building_SubcoreScanner.KillOccupant`、`CompTreeConnection`（树精连接）——普通战斗/疾病死亡不受影响。

### 2.3 `NotifyPlayerOfKilled` 的 IL 骨架（**实测**，整方法 200 余行已逐行读）

### 2.4 文案模板（**实测**：IL 里的 key + `Data\**\Languages\English\Keyed`）

- 正文三支（`HealthUtility.GetDiedLetterText`）：`DamageInfo.Def.deathMessage`（伤害类型自定义，如"shot to death"） / hediff 非空 → `PawnDiedBecauseOf`="{PAWN_labelShort} has died. Cause: {1}." / 否则 `PawnDied`="{1_labelShort} has died."。
- 信 label：`Death`（Core Keyed Letters.xml:30 = "Death"）+ ": " + `LabelShortCap`。
- 追加：`LentColonistDied`（Royalty Letters.xml:73，被借出的殖民者）、`SelfResurrectText`（Anomaly Messages.xml）、`LetterPartBondedAnimalDied`/`LetterPartBondedAnimalDiedMulti` + label 后缀 `LetterLabelSuffixBondedAnimalDied`="bonded"（Core Letters.xml:142-144）。
- 「Read more」节点：`ReadMore`、`LastEventsInLife`（Core Letters.xml:8/99）。

### 2.6 `Pawn.Kill` / `Thing.Kill` / `Pawn.Destroy`（**实测**）

- `Verse.Thing.Kill(dinfo, exactCulprit)` 体只有 `callvirt Thing::Destroy(DestroyMode.KillFinalize)` + `ret` —— 基类路径**不发任何提示**；`Pawn` 覆写。
- `Verse.Pawn.Kill` 的 UI 输出只有 2.2 那一个门控分支；其余全是 `Notify_*`（Tale/BattleLog/Faction/Ideo/Quest/Royalty/Scenario…）。`RefDump "=Verse.Thing" "Kill"` → **61** 个真实调用点（伤害、陷阱、处决、debug action 等）。
- `Verse.Pawn.Destroy(DestroyMode)` **不调用** `Kill`，也不调 `Messages`/`LetterStack`（只 `Notify_PawnDestroyed` 等）⇒ 走 Destroy 的 pawn 消失**没有任何死亡提示**（哪些玩法路径会这么走：**未确证**）。

### 2.7 其它会把"死亡"搬上屏幕的路径（**实测**，均为补充，量很小）

- **食尸鬼（Anomaly 变异体）**：`Pawn.Kill` → `IL_0577 Pawn_MutantTracker.Notify_Died` → 若 `MutantDef.deathLetter` 非空且玩家派系，**额外再发一封 `Death` 信**（正文 = deathLetter 标签 + `GetDiedLetterText` + `deathLetterExtra`）。XML 里只有一处：`Anomaly\Defs\Misc\Mutants.xml:215`="One of your ghouls has died."。
- **远行队团灭/只剩奴隶**：`RimWorld.Planet.Caravan.Notify_MemberDied` 有两处 `ReceiveLetter`，def 为 `LetterDefOf.NegativeEvent`（`LetterLabelAllCaravanColonistsDied` / `LetterOnlySlaveCaravanColonistsLeft`），只在"玩家远行队里再没有自由殖民者"这类条件下发，**不是每人一封**。`RimWorld.Faction.Notify_MemberDied` 内 0 处 Messages/LetterStack。
- **救援任务失败**：`Pawn_RelationsTracker.Notify_FailedRescueQuest` → `Messages.Message(MessageFailedToRescueRelative, …, PawnDeath)`（亲属没救回来，不是本人死亡）。
- **战斗场景（问题 4 的答案）**：袭击中**己方每死一人 = 一封 `Death` 信**（可能被 2.2 的门控吞掉，如仪式处决）；**敌方死亡 = 零提示**（`ShouldSendNotificationAbout` 返回 false）；`Verse.Battle` / `BattleLog` 只做记录与 `DeathLetter` 的"Read more"，**不存在"战斗报告"信件**（`AsmDump "=Verse.Battle" "*" np` 全成员里没有任何 Letter 相关方法）。

## 3. 对"播报死亡"的直接含义

- **原版已经有出口，且是"信为主、消息为辅"**：地图上殖民者/宠物死亡 ⇒ 只有 `LetterStack`（`Death`）；囚犯/访客/远行队死亡 ⇒ 只有 `Messages`（`PawnDeath`）。**只挂 `Messages.Message` 会漏掉所有殖民者死亡；只挂 `ReceiveLetter` 会漏掉囚犯/访客/远行队死亡。**
- 推荐"总闸"（按覆盖度排序，均为实测签名）：
  1. `Verse.LetterStack.ReceiveLetter(Letter, string, int, bool)` Postfix，过滤 `let.def.defName == "Death"`（`DeathLetter : ChoiceLetter`，正文读 `((ChoiceLetter)let).Text`，标题 `let.Label`，目标 `let.lookTargets`）—— 覆盖殖民者/宠物/食尸鬼 + 远行队特例信（后者 def 是 `NegativeEvent`，按需另判）。
  2. `Verse.Messages.Message(Message, bool)` Postfix，过滤 `msg.def.defName == "PawnDeath"` —— 覆盖囚犯/访客/远行队死亡。
  3. 若还想拿到"被门控吞掉的死亡"（屠宰、仪式处决、`forceNoDeathNotification`），hook `Verse.Pawn.Kill(Nullable<DamageInfo>, Hediff)` Prefix/Postfix，自己用 `HealthUtility.GetDiedLetterText`（public）+ `Pawn.LabelShortCap` 拼文本；**注意会对屠宰/处决也播报，需按 `dinfo.Def == DamageDefOf.ExecutionCut`、`pawn.ShouldBeSlaughtered` 等自行过滤**。
- **不要**去 hook `Thing.Kill`（61 个调用点、含建筑/物品），也**不要**期望 `Battle`/`BattleLog` 里有死亡摘要可用（那里只有事件流水，无"谁死了"的成品句子）。
- 去重提醒（沿用前阶段实测）：`Messages.AcceptsMessage` 对"同文本+同目标"的存活消息不新建对象，只 `ResetTimer()+Flash()`；`historical=true` 的消息进归档。
