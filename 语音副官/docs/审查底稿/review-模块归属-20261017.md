## 4. 契约缺口

### 4.1 `Utterance`：三处定义，片段到底带不带 `kind`

- 施工图:52 —— "`Utterance.cs` | 一句话 = 有序片段 `{text, kind}` 列表"
- 拼接:37 —— "片段 = `{ text, kind }`    kind ∈ { 常量短语, 枚举值, 动态名, 数字 }"
- 拼接:202 —— "`Utterance.cs` | 一句完整文本 + 片段切分（`string FullText`, `List<string> Segments`）"

`拼接§5` 号称"补上缺的"，却把自己的 §3 定义改写成 `List<string>`：**`kind` 在 §5 里消失了**。
后果：`SegmentSynthesizer`(54) 需要 `kind` 来决定"能不能走预录/要不要并行"，`LoudnessNormalizer` 可能需要按 `kind` 分配音量——
而 `拼接:202` 的 `Segments` 只有字符串。**同一个类型在同一份文档里有两种形状，实现时必然要挑一个，另一个模块就接不上。**

同类：施工图:108-109 把片段分成 `PreRecorded(defName)` / `Synthesize(text)` 两种，
拼接:37 的 `kind` 是四种"语言学"分类。**两套正交的分类共用了一个字段名 `kind`。**

### 4.2 `Notice`：不够支撑聚合点名，且"不许带 Pawn"把唯一的路堵死

- 施工图:45 —— "`Notice.cs` | 一条待播信息 `{Category, Text, Targets}`"，`Targets` 未定义类型
- 施工图:16 —— 架构图上写的是 "把一个 `Notice{Category, Text}` 交给 Announcer"（**只有两个字段**）
- 施工图:67 —— 唯一检查点的样例：`Announcer.Receive(SpokenCategory.IncidentRaid, "侦测到袭击…")`（**两个参数，没有 Targets**）
- 施工图:97 —— "`Notice` 里**不允许**带 `Thing`/`Pawn` 引用（只带 `LookTargets` 可选）"
- 拼接:56 —— "窗口内 同 Category + 同事件标识（如疾病 defName）的受害者 → 累积成一个 Batch"
- 拼接:58 —— 目标句 "「瘟疫爆发，」「8 人感染：」「张三、」「李四、」…"

**缺口**：聚合要念"张三、李四"，就必须在窗口期内持有**受害者身份**。
但 `Notice` 按 施工图:97 不能带 `Pawn`，按 施工图:16/67 连 `Targets` 都可能没有。
于是 `BatchAggregator` 的输入在文档里**没有任何合法来源**。
`LookTargets` 是否等价于"可取出名字的身份"——文档没说；按字面它指向对象，和"不许带引用"是否相容也没说 `[推测]`。

**第二个缺口**：`Announcer.Receive` 的签名（67）与 `Notice` 的字段（45）对不上，
`Announcer` 到底是收 `Notice` 还是收 `(category, string)`，两处都是"正式写法"。

### 4.3 `SpeechCatalog`：三处说法三种东西

| 位置 | 说它是什么 |
|---|---|
| 施工图:43 | "`SpokenCategory` → **中文模板/预录 key** 的表"、"所有文案集中一处" |
| 进度:133（D23） | "**pinned 片段**…`SpeechCatalog` 里的**常量短语 + 有限枚举值**"，约 100 条 |
| 代码:30-54 | 实际只有 `Category/Group/Label/Description`（**UI 标签**），没有任何模板或 key |

三者的差别不是措辞，是**内容**：模板表（拼接用）、pinned 白名单（淘汰用）、UI 标签表（界面用）。
其中"pinned 白名单"这条最关键：`拼接:121` 说 L1 是"组句必须的片段：常量短语（"侦测到"/"袭击"）、疾病名…"，
`拼接:157` 说"跳过 L1"，但**没有任何接口**让 `SpeechLibrary` 问 `SpeechCatalog`"这条是不是 L1"。
按 施工图:43 的 `SpeechCatalog` 职责（模板表）根本答不出"这个片段原文属不属于 L1"。

### 4.4 缓存：`TtsCache` 与"语音库"是不是同一个东西 —— 文档没说，而且路径/键/接口各说各的

| 维度 | 施工图:50（`TtsCache`） | 拼接:§3.7（`SpeechLibrary`） | 代码 |
|---|---|---|---|
| 名字 | `TtsCache` | `SpeechLibrary`（"唯一存音频的地方"，102） | `SpeechLibrary.cs` |
| 路径 | `Cache/TTS/<SHA1>.wav` **+ `index.json`** | `Cache\Voice\`（162）"物理上只有一个缓存目录" | `SpeechLibrary.FolderName = "Cache/Voice"`（代码:41） |
| 条目模型 | 文件 + 一个索引文件 | 一条记录 = 键 + clip + `lastUsed` + 等级 + scope | 无 |
| 键 | `<SHA1>`（哈希什么没写） | 拼接:113 `sha1(voice + "\|" + model + "\|" + text)`；拼接:147 `Sha1(fingerprint + "\|" + scope + "\|" + text)`；进度:138 `sha1(baseUrl\|model\|voice)` | 无 |
| 接口 | 无 | `TryGet(key)` / `Put(key, clip)`（184） | 只有 `Usage` |
| 谁持有 | `VoicePlayer` 依赖它（施工图:48、29） | 其他模块只调 184 的两个方法；`LibraryJanitor` 独占删除（170） | 无 |

**三处键公式的差别是实质性的**：113 不含 `scope`、不含 `baseUrl`；147 含 `scope`、`fingerprint` 里含 `baseUrl`。
按 113，换存档会命中上一个存档的派系名 —— 正好违反 `拼接:134`"换存档→自然不命中"。
按 147，同一片段在两个存档各存一份 —— 正好违反 `拼接:131`"L1 的 scope=global 换存档也不会重复合成"。
**两者不可能同时成立。**

另外 `拼接:155` 说"用户在设置里选**上限**"，`设置草案 §5`(88-93) 只有"显示占用"和"清缓存"，**没有上限字段**；
而 `拼接:173` 说清理"每 5 分钟一次（可调）"，设置草案也没有这个字段。⇒ 文档承认存在的三个可调参数，两个没进 UI 规格。

### 4.5 播放层：`SpeechQueue` / `VoicePlayer` 收到的到底是片段序列还是 clip 列表

- 施工图:24 —— 架构图：`Announcer ── Utterance{ 片段序列 } ──► SpeechQueue`
- 施工图:46 —— `Announcer` 依赖 `SpeechQueue`
- 拼接:40 —— "播放层只消费**排好序的 clip 列表 + 片段间间隙**，不关心内容"
- 拼接:193 —— "一句话的所有片段同时发请求，`Task.WhenAll`，**全部回来才入队**"
- 拼接:209 —— "`SpeechQueue` / `VoicePlayer` 不变：它们只消费'排好序的 clip 列表 + 间隙'"

**没有任何一句说谁把"片段序列"变成"排好序的 clip 列表"。**
候选互相推诿：`SegmentSynthesizer`(54) 表里只写"并行请求 + 失败降级 + 回填片段缓存"，没写"排序/拼装/插间隙"；
`VoicePlayer`(48) 表里只写"`dspTime` 游标连播"；`SpeechQueue`(47) 只写"FIFO + 插队 + 上限"。
⇒ 这是 §3 里 F19【无主】的根源。同理，`F20 gapMs` 与 `F21 响度归一` 也没有落点：

## 5. 结论

### 5.1 回答："这套文档按模块化规范写了吗？差在哪？"

**没有按模块化规范写。** 两份文档是两种不同的写法拼在一起的：
`施工图 §1` 是一张"文件 → 职责 → 依赖"的模块表，`拼接设计` 是一份按主题（片段法/聚合/缓存/清理）写的设计散文，
两者的**模块名有 6 个重复但字段定义不同**，**散文里最大的两个模块（语音库、清理器）根本没进任何表**（§1 M22/M23）。
结果就是：**62 个功能点里 20 条无主或多主、26 条有主但契约不足，只有 11 条（18%）能被一个模块完整认领**（§3）。
最要命的不是"漏写"，而是**同一件事在三处有三种说法**（`Utterance` 字段、缓存键公式、整句缓存做不做），
这种冲突比缺项更难发现——因为它看上去"每处都写了"。
`Utterance` / `Notice` / 缓存键 / "片段→clip" 这四个恰好都在**模块边界上**，也恰好是 §4 里问题最密的地方：
**文档把"模块"写成了文件清单，而没有写清模块之间的数据契约**，这正是用户说的"模块和功能分开来写"。

### 5.2 如果只修 5 处，先改这 5 行（都指向 §3 表里的具体行）

1. **`Utterance` + 片段→clip 的落点**（§3 的 **F11、F12、F15、F19** 四行）：
   删掉 `拼接:202` 那一行（它与 拼接:37 冲突），给 `Utterance` 一个唯一定义（`kind` 是否有 `PreRecorded` 必须选一套），
   并指定**谁**产出"排好序的 clip 列表 + 间隙"（现在四个模块都在推）。
2. **`Notice` 加受害者身份 + 只留一个入口签名**（**F02、F06、F07**）：把 `Announcer.Receive(category, text)`(施工图:67)
   与 `Notice{Category,Text,Targets}`(45) 统一，并明确"聚合所需的身份"以什么形式过线程边界（与施工图:97 的禁令对齐）。
3. **缓存只留一个名字、一个目录、一个键公式**（**F29、F30、F31、F25**）：删 `TtsCache` 这个名字（施工图:50 整行改写为 `SpeechLibrary`），
   二选一保留缓存键公式（拼接:113 或 147），把 `设置草案 §4/§5` 补上"库上限 / gapMs / 清理周期"三个字段。
4. **把三个表外模块补进 `§1` 并写明调用者**（**F32、F33、F36、F43**）：`SpeechLibrary`、`LibraryJanitor`、`WarmupScheduler` 的触发者、
   以及挂 `ConcurrentQueue` 的 `GameComponent`（施工图:40 承诺了"注册 GameComponent"，但表里没有这个文件）。
5. **给"合并 / 聚合 / 插队"三件事划边界并给威胁类一张数据表**（**F05、F08、F09、F40、F41**）：
   明说 `Announcer` 的"合并窗口"与 `BatchAggregator` 的"聚合窗口"是同一件事还是两层；
   明说"点名 vs 报数"由谁做（BatchAggregator 还是 SegmentPlanner）；给出 `威胁类 = {…}` 的清单，否则"丢最旧的非威胁"无法实现。

（顺带必须一并定的：**F54 默认值**两份互相矛盾；**F57** 钩子 5 vs 7。）

### 5.3 模块表支不支撑"加一类播报 = 改 3 处、不加 if"（施工图:76 的承诺）

**不支撑。** 三条独立证据：

1. **承诺的"三处"里有一处不存在**。施工图:76 说"enum + 目录表 + **UI 表**"各加一行；
   但代码里 UI 是**遍历目录自动生成**的（`Tab_SpokenCategories.cs:18-35`、`SpeechCatalog.Entries` 代码:30-54），
   没有"UI 表"可加。⇒ 真正要改的第 3 处是 `VoiceDeputySettings.CategorySlot` 的 `switch`（代码:153-182，22 个 case + throw），
   第 4 处是同一文件的 `ExposeData`（代码:213-220，虽然是循环，但键名依赖枚举名）。文档对这两处**一字未提**。
2. **还有两处隐藏的 if 没有数据表接住**：
   - "哪个 `IncidentDef` 属于哪一类"——疑点:78 明说"分类映射表（defName → 22 类）**还没写**"，也没有模块认领；
   - "哪些类是威胁"——`施工图:84-90` 列了 22 类但没有威胁标记，而 `设置草案:83/84` 的"丢最旧的非威胁""威胁可打断"都要它。
   这两件事都是"加一类播报"必然要动的，且都是 **if/表**，不是"加一条数据"。
3. **加一类的成本还取决于文案**：`SpeechCatalog` 被三处当成三种东西（§4.3），
   如果它真是"模板表"，那"加一类"还要写模板与片段切分规则（`SegmentPlanner` 怎么切），这已经是第 5、6 处。

⇒ 结论：施工图 §2 的承诺只在"**开关判定**这一件事上成立"（`Announcer.Receive` 第一行确实只有一处 if，施工图:73），
在"新增一类播报"这个完整验收上**不成立**。要让它成立，至少要把 §5.2 第 3、5 条修掉，
并把"`defName → SpokenCategory` 映射表"和"威胁类集合"变成两张**数据表**（各自一个文件/一条数据），
而不是留给实现时的 `switch`。
