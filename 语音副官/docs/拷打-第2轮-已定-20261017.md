## 已定

- **R2-01 片段与保留等级**
  - 一句话 = `Segment{ Text, Kind }`，`Kind ∈ { 常量, 枚举, 人名, 数字 }`。
  - **等级判定与淘汰执行全部归清理模块**（`LibraryJanitor`）：存储模块只按 key 存/取/报告占用，**不认识等级**。
  - 不设 pinned 名单；类型里不保留 `PreRecorded`。

- **R2-02 新增独立模块 `ClipAssembler`**
  - 负责"片段序列 → 可播放"这一层。**输入输出待模块 I/O 设计定稿后写。**
  - 用户要求：每个模块都必须有显式的输入/输出契约；这是流程要求，不是可选美化。

- **R2-05 威胁/优先级是数据**
  - 插队机制保留。
  - 类别元数据里带**优先级（威胁等级）**字段；调高/调低某类 = 只改那一条数据，不改代码分支。
  - 细节先不钉，结构先定。

- **R2-06 整句缓存**
  - 唯一目的：把**已拼接好的整句**存下来，下次播同一句直接取，省掉重新拼接。
  - 与片段**共用同一套存储**。

- **R2-07 存储只落磁盘**
  - 不常驻内存 `AudioClip`；播放时按需读文件 + 建 clip。
  - 依据（用户判断 + 量级核算）：2 秒 WAV ≈ 96 KB，读盘+解析在毫秒级，几十~几百 ms 的延迟可接受；不为省这点时间做内存层。

- **R2-08 默认值：开发期全开。**

- **R2-09 默认值最终化：不做"观察模式"。**
  - 做法：全开跑一局 → 用户按体感关掉吵的 → 从存盘读回设置，作为产品默认。
  - 理由：AI 无法评估用户体感。

- **R2-10 死亡**
  - 缓存清理**不挂死亡钩子**：定期扫描"殖民者还在不在"即可，晚清理的代价可忽略。
  - **不单独挂死亡钩子。** 取证结论（`取证-死亡播报出口.md`，全为 IL/XML 静态实测）：地图上殖民者/宠物死亡 → 1 封 `LetterDef=Death` 的信（`DeathLetter`），由 `Pawn_HealthTracker.NotifyPlayerOfKilled` 发，**这条路上没有角落消息**；囚犯/访客/远行队死亡 → 只有角落消息 `MessageTypeDef=PawnDeath`；敌方死亡零提示。⇒ 两个总闸（`LetterStack.ReceiveLetter` + `Messages.Message`）按 def 名分流即可覆盖全部死亡，不需要第 4 个补丁点。
  - 副作用：**补丁点由 7 个减为 6 个**（见 R2-15）。

- **R2-11 倒地 / 工作台缺料**
  - 倒地保留，挂 `Pawn_HealthTracker.MakeDowned`（private，Harmony 写死签名）。
  - 工作台缺料保留这一类，标"**待游戏探针验证**"，现阶段不删。

- **R2-12 预热节流**
  - 结构保留（节流模块 + 设置项），**默认值设成极大 ⇒ 实际不节流**。

- **R2-13 文案风格**
  - 只做一种，不做切换。

- **R2-04 聚合：走钩子，不设时间窗**
  - 事件在**钩子被调用的那一刻**取出，第一时间往下走，不排队等窗口攒。
  - 聚合只发生在"一次钩子调用内能拿到完整集合"的场合：钩子当场把受影响的单位全部解析出来，出一条带名单的 Notice。
  - **R2-04b 聚合节点（按用户 2026-10-17 补充）**：疾病、毒气这类**都是一瞬间的事**（疾病不是慢慢蔓延，是一堆人在那一刻一起得）。所以：
    - 不设可调时间窗；
    - 聚合节点接收"一批"：可能是**一条带名单的 Notice**，也可能是**同一 tick 内的多条同类 Notice**，两种输入都按"同类别 + 同事件"合并成一句，然后在**当前 tick 结束时**立刻出句；
    - 合并键与出句时机固定，不进设置项。

- **R2-14 审查报告与底稿**

- **R2-15 文档整理口径**
  - 决策台账重编为唯一编号 `D1–Dn`。
  - 疑点清单不再单独存在；未消解的项进 `STATUS.md` 待办。
  - 文档内路径全部按新目录改对。
  - 第 3 步写成"**5 个补丁文件、7 个补丁点**"，逐条列：① `Messages.Message` ② `LetterStack.ReceiveLetter` ③ `IncidentWorker.TryExecute` ④ `MentalStateHandler.TryStartMentalState` ⑤ `Hediff_Pregnant.StartLabor` ⑥ `Pawn_HealthTracker.MakeDowned`（倒地，R2-11） ⑦ `GenConstruct.PlaceBlueprintForBuild` + 库存计算。
  - 注：原先的"7 点"里有死亡钩子，现改为两个总闸分流；倒地补上后总数仍是 7。

- **R2-03 `Notice` 形态 = 模板 + 参数（已定）**
  - `Notice{ Category, Phrase, Args[], Names[], Count }`：`Phrase` 是模板键，中文模板与参数类型在 `SpeechCatalog`。
  - **钩子只做两件事：取事实、填参数。** 钩子不切分、不拼中文、不决定哪段是名字。
  - **切分与排列唯一归 `SegmentPlanner`**：吃 `{Phrase, Args, Names, Count}`，吐 `Segment[]`；全文只有这一处有分段逻辑。
