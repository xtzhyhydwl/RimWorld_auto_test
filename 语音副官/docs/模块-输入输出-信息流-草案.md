## 0. 不变量

改任何模块先对照这八条；它们是"改一处"的支点，也是评审时唯一需要背下来的东西。

| # | 不变量 | 违反时的症状 |
|---|---|---|
| I1 | **只有 `SegmentSynthesizer` 跨线程**。后台 `Task` 只碰 `string[] Texts` 与 `TtsRequestParams`（不可变快照），回 `byte[]`；`Utterance`/`Segment`/`Verse`/`UnityEngine` 对象一概不出主线程 | 后台建 `AudioClip`、读 `Pawn` ⇒ 未定义行为 |
| I2 | **`SpeechLibrary` 是唯一碰磁盘的模块，且只在主线程被访问**（含把磁盘列表 `ListFiles()` 交给清理器） | 两处各写一半文件句柄、孤儿文件对不上 |
| I3 | **删除决策只在 `LibraryJanitor`**。库的 `Put` 只回"当前占用"，**不认识上限**；别人想删只能 `ReportBroken` | 两套淘汰规则互相打脸 |
| I4 | **开关闸只有 `Announcer` 调 `Switchboard`；配置闸只有 `TtsClient` 判**。UI 只读 `TtsClient.LastError`，不自己判"能不能用" | 到处 if；"未配置"有两处判断，说法会分叉 |
| I5 | **中文文案只有一份**：在 `SpeechCatalog` 的模板表里。念法规则（名字清洗、数字处理）只有一份：在 `SegmentPlanner` | 同一个词两种念法、`鼠条.18` 一处清一处不清 |
| I6 | **音频的唯一样子是磁盘文件 + `AudioClip`**：内存里没有 `AudioClip` 池、没有 PCM 常驻；`PlayableUtterance` 播完丢引用 | 3000 条 × 2 s ≈ 288 MB 常驻【实测：24 kHz/16 bit/单声道】 |
| I7 | **启动顺序固定**：`SpeechCatalog`（静态表）→ `VoiceDeputySettings`（构造与 `ExposeData` 遍历 `Entries`）→ `DeputyGameComponent` 由 `Game.FillComponents()` 自动创建（`ctor(Game)`，见 §2.2） | 目录表未就绪就去构造 Settings ⇒ 全部开关落默认或抛 |
| I8 | **一个概念一个名字**：`SaveFingerprint`（存档 GUID）与 `VoiceFingerprint`（音色指纹）全文不混用，也不再出现裸的"指纹" | 换音色仍命中旧音频 / 换存档串音，两种 bug 同源 |

### 1.4 新增模块的理由

| 新增 | 为什么必须是独立模块 |
|---|---|
| `ClipAssembler` | 它独占"字符串世界 → Unity 对象世界"的边界，并且是**唯一**判"缺哪些片段"的地方；上游全是 `string`/enum，下游全是 `AudioClip`。塞进 `VoicePlayer` ⇒ 播放器要懂缓存键与 WAV；塞进 `SpeechLibrary` ⇒ 存储要懂 Unity；塞进 `SegmentSynthesizer` ⇒ 合成器要懂建 clip 的线程时机 |
| `DeputyGameComponent` | "每帧"必须恰好有一个主人；`SaveFingerprint` 的读写与注入也必须恰好有一个主人 |
| `WavReader` | 【实测（拼接设计 §8.1，未复验）】SiliconFlow 的 WAV 头长度字段是占位值，必须重算；这是唯一会随服务端变而改的地方，与 HTTP、与 Unity 都无关 |

## 2. 模块契约

> 每块固定六栏：输入 / 输出 / 持有状态 / 明确不负责 / 触发时机 / 失败模式。**方法签名写死**，照抄能建出文件。

### 2.1 `VoiceDeputyMod`

| 栏 | 内容 |
|---|---|
| 输入 | `ModContentPack`（主线程，一次性） |
| 输出 | `VoiceDeputyMod.Settings`（静态，给 `Switchboard`/UI 读）；`Harmony.PatchAll()`（一次性）；设置页按钮 → `new Dialog_VoiceSettings()`。**`DeputyGameComponent` 由框架自动创建，这里不挂**（§2.2） |
| 持有状态 | 只持 `Settings` 引用 |
| 明确不负责 | 不创建/不注册组件（框架负责）、不初始化缓存目录、不做 tick、不读磁盘 |
| 触发时机 | 进程内一次（Mod 构造）；用户点设置页按钮时 |
| 失败模式 | `Settings` 构造失败 ⇒ 让异常冒泡；`PatchAll` 失败 ⇒ 记 `Log.Error` 并整体停用（补丁不全时行为不可预期） |

### 2.2 `DeputyGameComponent`

| 栏 | 内容 |
|---|---|
| 输入 | **框架构造**：`public DeputyGameComponent(Game game)` 由 `Game.FillComponents()` 里的 `Activator.CreateInstance(type, new object[]{game})` 调用（`GenTypes.AllSubclassesNonAbstract` 枚举非抽象子类）—— **不需要任何手工注册**，见 `docs/取证-GameComponent注册.md`；每帧 `Update()`（主线程）；`SegmentSynthesizer.Drain()` 的返回值；`ClipAssembler.Plan()` 的返回值 |
| 输出 | ① 每帧：对 `Drain()` 交回的**播放作业**逐个 `ClipAssembler.Plan(job.Playback, job.DeadTexts)` ⇒ `Ready` 就 `SpeechQueue.Enqueue`；② 每帧调 `Announcer.Tick()`、`VoicePlayer.Tick()`；③ 有 `Put` 发生在本帧 ⇒ `LibraryJanitor.CheckLimit()`；④ 每 2 s `WarmupScheduler.Tick()`；⑤ 每 `JanitorIntervalSeconds` `LibraryJanitor.Tick()`；⑥ 读档/新开局时 `SpeechLibrary.SetSaveFingerprint(SaveFingerprint)` |
| 持有状态 | `SaveFingerprint : string`（`voiceCacheId`，`ExposeData` 落盘）；两个计时器（预热 2 s、清理 `JanitorIntervalSeconds`） |
| 明确不负责 | 不含策略：不判开关/优先级/等级、不切文本、不合成、不组装、不删任何东西。**只负责"调用顺序"** |
| 触发时机 | **新开局：`ExposeData` 在 `StartedNewGame` 之后才跑**（`InitNewGame` 全程无 Scribe ⇒ 首次 `ExposeData` 发生在第一次存盘）⇒ `SaveFingerprint` 在 `LoadedGame` / `StartedNewGame` 里**就地铸且幂等**（`if (NullOrEmpty) Guid.NewGuid().ToString("N")`），`ExposeData` 里同样判空补铸；此后 每帧；预热每 2 s；清理每 `JanitorIntervalSeconds`（默认 300 s） |
| 失败模式 | 每段各自 `try/catch`，记一条 `Trace` 后继续；同一异常 **600 帧最多记一次**；`Drain` 抛 ⇒ 丢本帧结果，不重试；**读档去重由框架保证**（`ExposeSmallComponents` 先整表 `Scribe_Collections.Look` 再 `FillComponents()`，其内 `RemoveAll(c => c == null)` + `GetComponent(type)` 判重）⇒ 本类不写任何"已存在就跳过"的分支 |

### 2.3 `VoiceDeputySettings`

| 栏 | 内容 |
|---|---|
| 输入 | UI 写入（`SetIfChanged` / `SetCategoryEnabled` / `ResetToDefaults`）；读档时 `ExposeData` |
| 输出 | 字段读取（§3.9 的"谁读"列）；`MarkDirty` / `FlushIfDirty` |

### 2.14 `SegmentPlanner`

| 栏 | 内容 |
|---|---|
| 输入 | **唯一入口** `Utterance Plan(UtteranceSource src)`。`src` 有三条构造路径（见下表），模块内部不区分形态；另有 `SpeechCatalog` 的模板与 `Settings.MaxNamedInBatch` |
| 输出 | `Utterance`（`Category` / `Segments` / `EventId` / `TargetKey` / `BatchKey`）；`FullText` 是它的计算属性 |
| 持有状态 | **无**（纯函数） |
| 明确不负责 | 不查开关/缓存、不做 TTS、不判等级、不管线程、不排队 |
| 触发时机 | 每条 `Notice` / 每个 `BatchSummary` / 每次试听一次 |
| 失败模式 | 模板缺失、`Args` 个数与 `ArgKinds` 不符 ⇒ 返回 `null`（`Announcer` 丢弃并记日志），绝不返回半句 |

**三个形态怎么进同一个入口**（U3）：

| 形态 | 谁造 `UtteranceSource` | 模板取哪条 |
|---|---|---|
| 事件 | `Announcer.Receive` 收到 `Notice` ⇒ `UtteranceSource.From(Notice)` | `Notice.Phrase` |
| 聚合句 | `Announcer.Tick` 拿到 `BatchSummary` ⇒ `UtteranceSource.From(BatchSummary)` | `CategoryEntry.BatchPhrase` |
| 试听 / 手动朗读 | `Announcer.SpeakDirect(text)` ⇒ `UtteranceSource.FromText(text)` | `PhraseForm.裸文本`，整段一个 `常量` 片段 |

```text
UtteranceSource { SpokenCategory Category, SpeechPhrase Phrase, string[] Args,
                  string[] Names, int Count, string EventId, string TargetKey, string BatchKey }
```

> `UtteranceSource` 的 `{Phrase, Args, Names, Count}` 就是 U3 划定的输入面；`EventId/TargetKey/BatchKey` 只是透传给 `Utterance` 的路由字段，不参与分段。

**职责线（U3，划清且不许越界）**

- **钩子只做两件事：取到事实、把事实填进参数。** 不切分、不拼中文、不决定哪段是名字（§2.7–§2.11 逐条写了钩子的"明确不负责"）。
- **切分与排列唯一归本模块**：吃 `{Phrase, Args[], Names[], Count}`，吐 `Segment[]`。全文只有这一处能出现"分段"逻辑。
- **"钩子直出片段"不采用**：它不是与"模板+参数"并列的选项，而是把本模块的活搬回钩子，和"取信息"耦合。

**三件只在这里做的事**（I5）：

1. **名字清洗**：把 `Notice.Names` / `Args` 里含 `.`、`-` 等的名字规整成可念文本（`鼠条.18` → `鼠条` + 数字片段）。
2. **数字处理**：数字片段先试直送 TTS；若实测念错再在 `NumericText` 纯函数里转中文（一处开关）。
3. **点名截断**：`Names.Length > MaxNamedInBatch` ⇒ 只留前 `MaxNamedInBatch` 个，`Count` **不变**（总数仍念）；`Names` 为空 ⇒ 模板只用 `{Count}` 槽。

### 2.15 `SegmentSynthesizer`

| 栏 | 内容 |
|---|---|
| 输入 | ① `long RequestMissing(Utterance u, Segment[] missing)`（主线程，来自 `DeputyGameComponent`：`ClipAssembler.Missing` 的那些片段）；② `long RequestWarmup(WarmupJob job)`（来自 `WarmupScheduler`）；③ 每帧 `CompletedJob[] Drain()`；④ `Settings`（**只在主线程**读一次，拍成 `TtsRequestParams`，§3.10） |

### 2.16 `ClipAssembler` ← 本文的核心

| 栏 | 内容 |
|---|---|
| 输入 | `AssemblyResult Plan(Utterance u, IReadOnlyCollection<string> deadTexts)`（主线程；`deadTexts` 为空表示首次） |
| 输出 | `AssemblyResult` 二选一：`Ready(PlayableUtterance)` 或 `Missing(Segment[])`；前者交 `SpeechQueue.Enqueue`，后者交 `SegmentSynthesizer.RequestMissing` |
| 持有状态 | **无。一条都不许有。** 有任何字段就等于复活"内存 `AudioClip` 池"（I6） |
| 明确不负责 | 不合成、不写库、不判等级/不删、不判优先级/开关、不排队、不管音量/停顿（`VoicePlayer` 现读） |
| 触发时机 | 每句两次上限：首次 `Plan(u, 空)`；合成回来后 `Plan(u, DeadTexts)`。UI 试听/朗读走同一入口 |
| 失败模式 | 见下：整句键命中 ⇒ 单 clip；缺片段 ⇒ 返回 `Missing`（**不播放半句**）；`deadTexts` 里的片段跳过；无可用 clip ⇒ `Ready(null)`（该句不出声）；WAV 坏/文件缺失 ⇒ 该片段进 `Missing` + `LibraryJanitor.ReportBroken(key)`（**它自己不删**） |

**`Plan` 的判定顺序（"缺哪些片段归它判"）：**

```text
Plan(u, dead):
  1. k = Library.Key(u.FullText, SegmentKind.整句)
     Library.TryRead(k) 命中 ⇒ return Ready(单 clip, FromSentenceCache=true)
  2. missing = []
     clips = []
     foreach seg in u.Segments:
         if dead.Contains(seg.Text) ⇒ continue                     // 已知失败，跳过
         if Library.TryRead(Library.Key(seg.Text, seg.Kind), out bytes)
              ⇒ clips.Add(Build(bytes))                              // WavReader → Normalize → AudioClip
         else missing.Add(seg)
  3. if missing.Count > 0 ⇒ return Missing(missing.ToArray())        // 等合成，不出声
  4. return Ready(clips.Length == 0 ? null : new PlayableUtterance(u, clips, false))
```

> 代价（明写，因为违反直觉）：刚合成好的片段也是**先落盘再读回**，不做"这次直接用内存那份字节"的捷径——音频只有一条来路（库）。每片段多一次 100 KB 级写+读【推测：毫秒级，R2-07 的量级核算】。
> `LoudnessNormalizer` 每次组装重算，不缓存结果（缓存结果 = 内存层）。

### 2.17 `SpeechQueue`

| 栏 | 内容 |
|---|---|
| 输入 | `Enqueue(PlayableUtterance u)`（主线程）；`SpeechCatalog.PriorityOf(category)`；`Settings.QueueLimit` / `ThreatInterrupts` |
| 输出 | `bool TryTake(out PlayableUtterance u)`（给 `VoicePlayer`；**取出即转移所有权**）；`Count` |
| 持有状态 | `List<PlayableUtterance> pending` —— **只放未开始播的**；每条的 `QueuedTick` |
| 明确不负责 | 不持有当前句、不持 clip 游标（H4：整块归 `VoicePlayer`）、不建/释放 clip、不读文本、不查开关、不做 TTS |
| 触发时机 | 每次 `Enqueue`；`VoicePlayer` 每播完一句 `TryTake` 一次 |
| 失败模式 | 见下三条规则；`PriorityOf` 未知类别 ⇒ 0 |

1. **上限**：`Count >= QueueLimit` ⇒ 先丢"优先级最低、同级最旧"的一条；在队条目优先级全都 ≥ 新句 ⇒ **丢新句**。
2. **插队**：`ThreatInterrupts` 且 `新句.Priority > 正在播那句的 Priority`（或当前没在播）⇒ **插到队首**（`pending.Insert(0, u)`）。
3. **不叠音**：任何时刻最多一句在播（由 `VoicePlayer` 独占保证）。

### 2.18 `VoicePlayer`

| 栏 | 内容 |
|---|---|
| 输入 | `SpeechQueue.TryTake`（主线程，事件驱动）；每帧 `Tick()`；`Settings.MasterVolume` / `TtsVolume` / `GapMs`（**每帧现读**） |
| 输出 | `AudioSource.PlayScheduled(dspTime + gap)`；整句播完 ⇒ `WarmupScheduler.EnqueueSentence(utterance.Source)`；`Trace("4"/"6")`；`RecentSnapshot()`（最近 20 条：时间 / 类别 / 原文 / 是否整句命中 / 用时 ms）；`CurrentPriority`（给 `SpeechQueue` 判插队） |
| 持有状态 | **当前句 `PlayableUtterance` + `clipIndex` + `nextDspTime`**（H4）；自建 `GameObject` + 常驻 `AudioSource`；最近 20 条环形表 |
| 明确不负责 | 不合成、不查开关、不判优先级（只把当前句的优先级报给队列）、不认识缓存键、不管理库、不删任何东西 |
| 触发时机 | 每帧：`current == null` ⇒ 从队列取；否则推进 `clipIndex`（前一个 clip 播完 + `GapMs` 后 `PlayScheduled` 下一个）
| 失败模式 | `clip == null` / `length == 0` ⇒ 跳过该 clip 继续推进；`AudioSource` 丢失（换地图）⇒ 重建；整句播完回调异常 ⇒ 吞掉 + `Trace`；播完把 `current` 置空（clip 引用交给 GC，I6） |

### 2.22 `SpeechLibrary`

| 栏 | 内容 |
|---|---|
| 输入 | `LibraryKey Key(string text, SegmentKind kind)`（**唯一的键构造点**，内含 `VoiceFingerprint`）；`bool TryRead(LibraryKey, out byte[])`（命中刷新 `LastUsedTick`）；`LibraryUsage Put(LibraryKey, byte[] wav)`；`bool Contains(LibraryKey)`（**不**刷 `LastUsedTick`）；`IReadOnlyList<LibraryEntry> Snapshot()`；`IReadOnlyList<DiskFile> ListFiles()`；`void RemoveEntry(string key)` / `void RemoveFile(string key)`（**只允许 `LibraryJanitor` 调**）；`void SaveIndex()`（**只允许 `LibraryJanitor` 调**）；`void SetSaveFingerprint(string id)`（**只允许 `DeputyGameComponent` 调**）；`Usage` |
| 输出 | 读：`byte[]`；写：`Cache/Voice/<key>.wav` + 内存索引 + `LibraryUsage{Entries, Bytes}`；`Snapshot` 给清理器（条目侧）；`ListFiles` 给清理器（磁盘侧，H7） |
| 持有状态 | 内存索引 `Dictionary<string, LibraryEntry>`（**只有** key / text / `Kind` / `LastUsedTick` / `Bytes`）；`SaveFingerprint`；`VoiceFingerprint`（由 `Settings.BaseUrl+Model+Voice` 算，三者变化时重算） |
| 明确不负责 | **不认识等级（L1/L2/L3）**、不认识上限（`LibraryLimit` 一个字节都不读）、不判该不该播、不合成、不认识 `SpokenCategory`、不决定删谁 |
| 触发时机 | `Plan` 时 `TryRead`；`Drain` 时 `Put`；`WarmupScheduler` 查 `Contains`；`Janitor.Tick` 时 `Snapshot`/`ListFiles`/`Remove*`/`SaveIndex`；UI 每帧读 `Usage` |
| 失败模式 | 写盘失败 ⇒ 该条不入索引，`Put` 返回旧占用（调用方当该片段失败）；索引有、文件没了 ⇒ 当未命中；索引与磁盘不一致 ⇒ **自己不修**，等 `LibraryJanitor` 对账；`index.json` 丢失/损坏 ⇒ 从空索引开始，孤儿文件由对账删（代价 = 重新合成，功能不变） |

**键与作用域（H2 / H16 / H17）**

```text
LibraryKey { VoiceFingerprint : string, Kind : SegmentKind, Text : string }      // 三个字段，值类型
  Scope  —— 计算属性，不落库：Kind ∈ {人名, 整句} ? "save:" + SaveFingerprint : "global"
  Value  —— 落盘名 = sha1(VoiceFingerprint + "|" + Scope + "|" + Text)
```

- `VoiceFingerprint = sha1(BaseUrl + "|" + Model + "|" + Voice)`，产出者只有 `SpeechLibrary`；换音色/模型/端点 ⇒ 旧键自然查不到。
- `SaveFingerprint` 由 `DeputyGameComponent` 用 `SetSaveFingerprint` 注入，**不进键的构造现场**。
- 换存档 ⇒ `Scope` 变 ⇒ `Value` 变 ⇒ 不会念上一个存档的名字；旧条目交给 `LibraryJanitor` 的 L3 淘汰。

### 2.23 `LibraryJanitor`

| 栏 | 内容 |
|---|---|
| 输入 | `SpeechLibrary.Snapshot()` + `ListFiles()` + `Usage`（主线程）；`Map.mapPawns` 的存活名单与 `Find.FactionManager` 的派系名单（**自己扫**）；`Settings.LibraryLimit`；`ReportBroken(string key)`（来自 `ClipAssembler`）；`CheckLimit()`（来自 `DeputyGameComponent`，每次 `Put` 之后）；`ClearAll()`（UI"清缓存"） |
| 输出 | `SpeechLibrary.RemoveEntry(key)` / `RemoveFile(key)`（**全 mod 唯一的删除调用者**）；`SaveIndex()`（每轮第 ④ 步）；`RosterDelta{NewNames[]}` → `WarmupScheduler`；`Trace` |
| 持有状态 | 上轮名单快照（两阶段：本轮消失的记下，**下一轮才删**）；坏键待删名单；`L1SoftLimit = 500` 常量 |
| 明确不负责 | 不合成、不读音频字节、不判"值不值得播"、不调度预热（只交新名字）、不判开关、**不认识 `VoiceFingerprint`**（只按 key 字符串操作） |
| 触发时机 | 每 `JanitorIntervalSeconds`（默认 300 s）`Tick()`；每次 `Put` 之后 `CheckLimit()`；UI 清缓存 |
| 失败模式 | 扫描抛异常 ⇒ 本轮整体跳过、**保留上轮名单**（不丢两阶段状态）+ 记日志；删文件失败（被占用）⇒ 留待下轮；`Snapshot` 与 `ListFiles` 对不上 ⇒ 走对账，不抛 |

**`Tick` 每轮四步（固定顺序）**

1. **对账**：`ListFiles` 有、`Snapshot` 无 ⇒ `RemoveFile`（孤儿）；`Snapshot` 有、`ListFiles` 无 ⇒ `RemoveEntry`（失效条目）。
2. **两阶段名单**：删"上一轮消失的名字"对应的条目（segment 删同名；sentence 删"文本包含该名字"的条目，子串匹配，中文误伤接受）；再本轮扫描，把本轮消失的记进名单。
3. **超限**：`Usage.Entries > LibraryLimit` ⇒ 按等级表淘汰。
4. **落索引 + 交名单**：`SaveIndex()`；`RosterDelta{NewNames}` → `WarmupScheduler`。

**等级判定表（唯一判定处）**

| 键空间 | 条件（`Kind` + 名字在不在名单） | 等级 | 删不删 |
|---|---|---|---|
| 片段（`Kind ∈ {常量,枚举,数字}`） | 恒 | L1 | **永不删**；超 `L1SoftLimit` 只 `Trace` 告警 |
| 片段（`Kind = 人名`） | 文本 ∈ 当前存档存活殖民者/动物名或当前派系名 | L2 | 名字消失后降 L3（两阶段删） |
| 片段（`Kind = 人名`） | 不在名单里（死人的、临时名、旧存档的） | L3 | 可删 |
| 整句（`Kind = 整句`） | 恒 | L3 | 可删 |

**淘汰顺序**：`(等级降序, LastUsedTick 升序)` —— 先最旧的 L3，再 L2，最后 L1（L1 受 `L1SoftLimit` 保护）。级别是主键，时间只在同级内部生效。
`CheckLimit()` 与第 ③ 步跑**同一个函数**：判据只有一处。

### 2.24 `WarmupScheduler`

| 栏 | 内容 |
|---|---|
| 输入 | ① `RosterDelta`（来自 `LibraryJanitor`）；② `EnqueueSentence(Utterance u)`（来自 `VoicePlayer`）；③ `Tick()`（每 2 s，来自 `DeputyGameComponent`）；④ **`SpeechLibrary.Contains(key)`**（H13：先查库，命中就不排）；⑤ `Settings.warmupJobsPerMinute` |
| 输出 | `SegmentSynthesizer.RequestWarmup(WarmupJob)`（与播放路径**同一个合成入口**；不入队、不组装、不出声）；`Trace` |
| 持有状态 | 两个 FIFO：短语队列（名字/派系名，`Kind` 入队时补成 `人名`）、整句队列；本分钟已发计数 |
| 明确不负责 | 不合成、不写库（`Drain` 写）、不判开关/优先级/等级、不决定"该不该缓存"（能不能进库由键决定） |

**作业来源三处**：`SpeechCatalog` 的 L1 词表（启动后第一批）、`RosterDelta.NewNames`、`VoicePlayer` 播完的整句（先 `Contains` 查库）。
**已知延后**：新入队殖民者的名字最坏要等一个清理周期（300 s）才进预热；更快的路径需要新的补丁点（不在已定 7 点内）。

## 3. 跨模块数据类型

**名字对照**：`Notice`（钩子→Announcer）· `EventIdentity`（去重键）· `SpeechPhrase`（台词模板编号）· `Segment`（片段）· `Utterance`（一句话，待组装）· `PlayableUtterance`（可播放层）· `LibraryKey`（缓存键）· `LibraryEntry`（缓存条目）· `DiskFile`（磁盘上的文件）· `CategoryEntry`（类别元数据）· `VoiceDeputySettings`（设置）。

### 3.1 `Notice`（`sealed class`，数组字段只读、不共享，H15；形态 = 模板 + 参数，U3）

| 字段 | 类型 | 说明 |
|---|---|---|
| `Category` | `SpokenCategory` | 开关与优先级的挂载点 |
| `Phrase` | `SpeechPhrase` | 用哪条**单事件**模板（聚合/试听模板由目录表按类别给） |
| `Args` | `string[]` | 模板参数，顺序即占位符顺序；已拍平成最终要念的字（钩子不做清洗，`SegmentPlanner` 做） |
| `Names` | `string[]` | **要点名的**人（0–N），钩子交 `LabelShortCap` 原文；U1：群体事件恒为空数组 |
| `Count` | `int` | **总人数**（与 `Names` 解耦，H6）；无人数概念的事件填 `1` |
| `EventId` | `string` | `SpeechCatalog.EventIdOf(defName)` 给的规范化事件 id，跨通道收敛用（H9） |
| `TargetKey` | `string`（可空） | 目标标识：`Pawn.ThingIDNumber.ToString()` / `Map.uniqueID.ToString()` / 空 |
| `BatchKey` | `string`（可空） | 非空 ⇒ 进 `BatchAggregator`；合并键 = `(Category, BatchKey)` |
| `Tick` | `int` | 产出时刻（`GenTicks.TicksGame`） |

- 产出：5 个 Hook 文件（主线程，事件驱动）。消费：`Announcer.Receive`。
- **钩子对这张表只做"填值"**：`Category` 由映射表给、`Phrase` 由映射表给、`Args`/`Names`/`Count` 由钩子从现场事实取、`EventId`/`TargetKey` 由映射与目标算；**钩子不切分、不拼中文、不决定哪段是名字**（U3）。
- **不含任何 `Verse`/`UnityEngine` 对象**（连 `LookTargets` 也不带，I1）：出钩子之后全链只有 enum/string/int。
- `Args` 里可以带"原版文本"（如死因句取自信件正文），此时它已是一段最终要念的中文/英文片段；跨语言由 `SpeechCatalog` 的模板槽位描述，钩子不翻译。
- 不可变约定：`Args` / `Names` 在构造时拷一份、对外只读；后续模块不许原地改。

### 3.2 `EventIdentity`（去重键）`[待确认 Q17]`

```text
EventIdentity { SpokenCategory Category, string EventId, string TargetKey }
DedupeWindowMs = 1500      // Announcer 内常量
```

产出：`Announcer` 从 `Notice` / `BatchSummary` 各算一次。消费：`Announcer` 的去重表。跨通道收敛靠 `SpeechCatalog` 把同一事件的不同 def 名映射到同一个 `EventId`。

### 3.3 `Segment` / `SegmentKind`

```text
Segment      { Text : string, Kind : SegmentKind }        // 不可变
SegmentKind  = 常量 | 枚举 | 人名 | 数字 | 整句
```

| 字段 | 类型 | 谁产出 | 谁消费 |
|---|---|---|---|
| `Text` | `string` | `SegmentPlanner`（唯一产出者） | `SegmentSynthesizer`（送 TTS）、`ClipAssembler`（查库与 `FullText`）、`SpeechLibrary` |
| `Kind` | `SegmentKind` | `SegmentPlanner`（由模板 `ArgKinds` 决定） | `SpeechLibrary`（键与 scope）、`LibraryJanitor`（等级表） |

- `整句` 只出现在 `LibraryKey.Kind`，不出现在 `Segment.Kind`（`Segment` 只有前四种）。
- `人名` 同时承载派系名、地名：保留策略相同（本存档、随名单消失而降级）。
- 等级判据：`Kind ∈ {常量,枚举,数字}` ⇒ L1；`人名` ⇒ L2/L3（看名字在不在名单）；`整句` ⇒ L3。

### 3.4 `Utterance`

| 字段 | 类型 | 谁产出 | 谁消费 |
|---|---|---|---|
| `Category` | `SpokenCategory` | `SegmentPlanner`（`From(BatchSummary)` 时透传 `BatchSummary.Category`） | `SpeechQueue`（取优先级）、`VoicePlayer`（记录） |
| `Segments` | `Segment[]`（只读） | `SegmentPlanner` | `SegmentSynthesizer`、`ClipAssembler` |
| `FullText` | **计算属性**：`string.Concat(Segments)`（H17：唯一真源，不另存字段） | — | 整句键（`SpeechLibrary.Key(..., 整句)`）、最近播报 |
| `EventId` / `TargetKey` | `string` | `SegmentPlanner` | 去重（经 `Announcer`）、日志 |

- 消费链：`Announcer` → `ClipAssembler.Plan`（→ `Missing` 时 `SegmentSynthesizer` → 再 `Plan`）。
- `FullText` 既然只有一个真源，"怎么拼"就只允许在 `SegmentPlanner` 一处发生。

### 3.5 `PlayableUtterance`

| 字段 | 类型 | 谁产出 | 谁消费 |
|---|---|---|---|
| `Source` | `Utterance`（**引用，不拷贝**） | `ClipAssembler` | `VoicePlayer`（`FullText`/`Category`/`EventId` 全从这取） |
| `Clips` | `AudioClip[]`（已归一、已建好，只在主线程） | `ClipAssembler` | `VoicePlayer` |
| `FromSentenceCache` | `bool`（`true` ⇔ 由整句键命中而生成） | `ClipAssembler` | `Trace`、最近播报 |

- `FullText` / `Category` 是 `Source` 的**计算转发**，不存副本（H17）。
- **停顿/音量不在这里**：`VoicePlayer` 播放时现读 `Settings`。
- **优先级不在这里**：`SpeechQueue` 用 `Source.Category` 去 `SpeechCatalog` 查。

### 3.6 `LibraryKey` / `LibraryEntry` / `DiskFile`

```text
LibraryKey  { VoiceFingerprint : string, Kind : SegmentKind, Text : string }   // 值类型，3 个字段
  Scope : string   => (Kind == 人名 || Kind == 整句) ? "save:" + SaveFingerprint : "global"   // 计算属性，不落库（H17）
  Value : string   => sha1(VoiceFingerprint + "|" + Scope + "|" + Text)                        // 落盘名
```

| 类型 | 字段 | 谁产出 | 谁消费 |
|---|---|---|---|
| `LibraryKey` | 见上 | `SpeechLibrary.Key(text, kind)`（**唯一构造点**，`VoiceFingerprint` 在此注入） | `Put`/`TryRead`/`Contains`/`Remove*` 的参数；`LibraryJanitor` 只用 `Value` |
| `LibraryEntry` | `Value : string`；`Text : string`；`Kind : SegmentKind`；`LastUsedTick : int`；`Bytes : long` | `SpeechLibrary` | `LibraryJanitor`（等级表、淘汰排序、子串匹配）、UI（经 `Usage`） |
| `DiskFile` | `Value : string`；`Bytes : long` | `SpeechLibrary.ListFiles()` | `LibraryJanitor`（对账，H7） |

- **两个键空间、一张索引、一套淘汰**：`Kind == 整句` 只是同一张表上的取值。
- **等级不在条目里**：条目只存事实，等级由 `LibraryJanitor` 每轮按 §2.23 表现算（R2-01）。

### 3.7 `CategoryEntry` / `PhraseEntry`

| 字段 | 类型 | 现状 | 谁消费 |
|---|---|---|---|
| `Category` | `SpokenCategory` | ✔ 有 | 全链 |
| `Group` / `Label` / `Description` | `string` | ✔ 有 | UI；`VoiceDeputySettings` 的构造与 `ExposeData`（H18） |

```text

PhraseForm  = 单事件 | 聚合 | 裸文本
```

- `单事件`：`Template` 的槽位由钩子给的 `Args` 按顺序填；`ArgKinds` 给每个槽定 `Kind` —— **"哪段是常量、哪段是名字"只有这一个答案**。

## 5. 待确认 / 待拍板

### 5.1 跨通道去重口径（Q17）`[待确认]`

本文按 **"事件身份 = (类别, EventId, TargetKey) + 1500 ms"** 写（§2.12、§3.2）：同一事件经 incident 与 letter 两条通道进来时，`SpeechCatalog` 把它们映射到同一个 `EventId`，从而收敛成一句。

| 方案 | 做法 | 代价 |
|---|---|---|
| **A 事件身份 + 1.5 s**（本文写法） | 不同 def 名靠映射表归一，1.5 s 内同身份只播一次 | 映射表要为"同一事件的多条通道"各写一条同样的 `EventId`；1.5 s 内两次真实事件会被吞一次 |
| B 只在同类别内按文本去重 | 键 = `Category + Args` 连接 | 跨通道文本不同 ⇒ 收敛不了（一次崩溃可能播 2–3 句） |
| C 不收敛 | 每个通道各播一次 | 最简单；一局下来重复播报明显 |

**影响面**：只改 `Announcer` 的键与 `SpeechCatalog.EventIdOf` 一个函数。

### 5.2 `ResponseFormat` 四选一 vs 只会 wav

设置页有 `wav/mp3/opus/pcm` 四选一【实测 `Tab_Voice.cs`】，`WavReader` 只会 wav。

| 方案 | 做法 | 代价 |
|---|---|---|
| **A 锁死 wav** | UI 去掉四选一，字段只允许 `wav` | 少一个选择；少写三个解码器 |
| B 允许选但禁播 | 选非 wav ⇒ 状态条红字 + 不发声 | 用户能把自己弄哑 |
| C 写解码器 | 引 mp3/opus 解码 | 依赖与工作量都不小，收益接近零 |

### 5.3 `DeputyGameComponent` 的创建方式（已定，非待办）

**注册时机见 `docs/取证-GameComponent注册.md`：自动收养，无需注册。** 一句话落地口径：

- 写成**非抽象** `GameComponent` 子类，提供 `public DeputyGameComponent(Game game)`；
- `Game..ctor` 末尾的 `Game.FillComponents()` 用 `GenTypes.AllSubclassesNonAbstract` + `Activator.CreateInstance(type, new object[]{ game })` 把它造出来；
- 读档时 `Game.ExposeSmallComponents` 先 `Scribe_Collections.Look(ref components, "components", LookMode.Deep, …)` 整表替换，再 `FillComponents()` 补缺失类型；`FillComponents` 自带 `RemoveAll(c => c == null)` + `GetComponent(type)` 判重 ⇒ 不会重复，本类不写去重分支；
- **新开局时 `ExposeData` 在 `StartedNewGame` 之后才跑**（`InitNewGame` 全程无 Scribe，首次 `ExposeData` 发生在第一次存盘）⇒ `SaveFingerprint` 在 `LoadedGame` / `StartedNewGame` 里就地铸、幂等。
