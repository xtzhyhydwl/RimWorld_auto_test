01

七条不变量

改任何模块先对照这七条；它们是「只改一处」的支点，也是评审时唯一要背的东西。
I1只有 SegmentSynthesizer 跨线程：后台只碰 string 与 TtsRequestParams，只回 byte[]
违反：后台建 AudioClip、读 Pawn ⇒ 未定义行为；Notice/Utterance/Verse 一概不出主线程
I2SpeechLibrary 是唯一碰磁盘的模块，且只在主线程被访问
违反：两处各写一半文件句柄、孤儿文件对不上（磁盘列表也只由它交给清理器）
I3删除决策只在 LibraryJanitor；库的 Put 只回「当前占用」，不认识上限
违反：两套淘汰规则互相打脸；别人想删只能 ReportBroken 登记
I4开关闸只有 Announcer 调 Switchboard；配置闸只有 TtsClient 判
违反：到处 if；「未配置」出现两处判断，说法会分叉（UI 只读 LastError）
I5中文文案只有一份（SpeechCatalog.Phrases）；念法规则只有一份（SegmentPlanner）
违反：同一个词两种念法；鼠条.18 一处清一处不清
I6音频唯一样子 = 磁盘文件 + 按需建 AudioClip：没有 clip 池、没有 PCM 常驻
违反：3000 条 × 2 s ≈ 288 MB 常驻（24 kHz / 16 bit / 单声道 = 48 KB/s）
I7启动顺序固定：SpeechCatalog → VoiceDeputySettings → DeputyGameComponent（框架自动创建）
违反：目录表未就绪就构造 Settings ⇒ 全部开关落默认或抛（Entries 遍历空）

18 组类型

跨模块流转的全部类型；只列名字 + 一句话 + 关键字段（全文见 01 §6）。
Noticesealed class

钩子拍平后的唯一消息体：出钩子之后全链只剩 enum / string / int。

Category · Phrase · Args[] · Names[] · Count · BatchKey? · Tick

Utterance

已建好 AudioClip 的可播句；停顿与优先级都不在这里。

BatchSummary / RosterDelta

聚合批的汇总 / 清理器交出的新名字（消失名单不外传）。

LibraryKey值类型

缓存键：音色指纹 + 作用域 + 原文 + 片段种类；全 mod 唯一键构造点。

VoiceFingerprint · Scope（计算） · Text · SegmentKind · Value = sha1(…)

06

探针 P1–P10

每条的「结果会改什么」都只指向一处：一张数据表、一个常量、或一个函数。
P1
验什么疾病突发时 ③ 被调几次：一条自带 Count=N 的 Notice，还是逐人 N 条。
结果会改什么BatchAggregator 走哪条分支；若逐人 —— DiseaseOutbreak 的 BatchKey 与 Count 来源改成成员计数。
进游戏才能做
P2
验什么一局里 Messages.Message 的条数与分类分布：OtherMessage 占比、腐烂文案后缀是否匹配上。
结果会改什么OtherMessage 的默认开关；腐烂的后缀常量；以及默认值定稿流程的输入。
进游戏才能做
P3
验什么工作台缺料挂起是否产生任何提示（ITab / Alert / 消息）。
结果会改什么BillSuspended 的去留：留则新增补丁点（超出 8 点），删则四处各删一行。
进游戏才能做
P4
验什么设置窗口排版、中文渲染（不出现方块/截断）、开关重启后是否读回。
结果会改什么控件布局与字号；若中文截断只改 RowWidgets 的尺寸常量。
进游戏才能做
P5
验什么TTS 端到端延迟、片段拼缝听感、Speed 与 GapMs 的手感；35 是否被念成「三十五」。
结果会改什么GapMs 默认值、NumericText 开关、MaxNamedInBatch 默认值。
进游戏才能做
P6
验什么Unity 能否直接吃 SiliconFlow 的 WAV（头长度字段是占位值）。
结果会改什么WavReader 是否必须重算长度；即便能吃也保留重算（对其它服务端更稳）。
进游戏才能做
P7
验什么一场袭击里 ⑦ 被调几次：会不会一次刷十几条。
结果会改什么PawnDied 的 BatchKey 策略（同 tick + 同派系 → 同 tick）与 QueueLimit 默认值。
进游戏才能做
P8
验什么⑧ 算出的缺口数值与建造 UI 红字是否一致；自动重建 / 样板是否被正确排除。
结果会改什么BlueprintHooks 的成本比较函数（CostListAdjusted 的调用口径）。
进游戏才能做
P9
验什么袭击期间 MessageRaidersBeginningAssault 与第一封信的实际间隔。
结果会改什么message 丢弃表里的 ThreatBig：可能移出并映射到 ThreatRaid。
进游戏才能做
P10
验什么IncidentParms.silent / sendLetter 的真实置位频率；置位时 ③ 是否仍触发。
结果会改什么IncidentHooks 一处：可能给 ThreatRaid 加「静默不播」判断。
进游戏才能做
